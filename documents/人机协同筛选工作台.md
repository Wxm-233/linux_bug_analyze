# 人机协同筛选工作台

## 快速开始

需要 Python 3.10+、Git、本地 Linux Git 工作树。建议使用独立虚拟环境。

```bash
python -m pip install -e ".[review]"
python review_commits.py --settings settings.toml
```

首次安装后，日常只运行第二条命令。也可使用安装后的 `review-linux-commits`。
终端会给出 `http://127.0.0.1:8765/#随机访问令牌`；打开完整链接。
不会自动打开浏览器，不会自动调用付费模型。

配置沿用现有 `settings.toml`：

- `linux_dir`：Linux 工作树。
- `[commit_source]`：ref、since、until、是否排除合并、扫描数量上限。建议固定起止日期。
- `[hash_filter]`：要求 `match = "any"`、`exclude = []`；自定义 include 与最新内置规则取并集。
- `[openai]`：本轮短判断使用这里的 model、base_url、api_key_file；也支持 `OPENAI_API_KEY` 环境变量。
- `[review]`：可选，完整示例见 `settings.example.toml`。

新入口直接扫描 Git 历史，不把旧 `hashes_file` 当作完整总体；否则无法抽查正则未命中的提交。
它不改写原有 `hashes_file`、详细报告目录或历史统计。

```toml
[review]
output_dir = "review_workspace"
port = 8765
training_target = 160
validation_size = 40
random_seed = 42
exploration_every = 5
audit_rate = 0.01
audit_minimum = 100
boundary_sample = 20
max_requests = 100
token_budget = 2000000
workers = 4
```

相对路径以 settings 文件所在目录为基准。

## 服务器上运行，本地浏览器操作

将代码通过 Git 同步到 Linux 服务器，在服务器安装并运行入口。
在本地另开终端执行：

```bash
ssh -N -L 8765:127.0.0.1:8765 用户@服务器
```

再打开服务器终端打印的完整链接。服务只监听服务器的回环地址，不需要开放公网端口。
令牌每次启动更新，不要分享链接。当前为单人、单写入者工作台，不支持多人协同编辑。

## 页面操作顺序

### 可选：自动生成当前篇与下一篇摘要

勾选“自动生成摘要”并确认后，页面自动为当前正在阅读的 commit 生成摘要，
并预取当前排序下的下一篇。所有人工队列都最多预取一篇，不再批量摘要整个队列。
通过搜索或历史记录打开的例子也作为当前篇处理；最后一篇没有后继时只处理当前篇。

摘要在后台运行，不阻塞阅读、填写备注或提交判断。当前篇摘要完成后会单独刷新摘要区，
不会跳转篇目或清空备注。提交判断时撤掉尚未发送的旧预取，排序更新后重新选择当前和下一篇。
“下一篇”只是基于当前模型的预取，不预先假设你的判断结果；新模型可能改变它，旧摘要保留作缓存。

关闭开关、切换队列或点击停止会撤掉尚未发送的预取；已发送请求会完成并缓存，无法撤回费用。
默认不开启，刷新页面后需要重新开启；只查看已有缓存不调用模型。
失败/预算耗尽会暂停自动生成，不循环重试、不自动标注；仍可按原始材料审查。
接口恢复后关闭再开启可重试；预算不足则提高配置上限并重启服务。

摘要使用 `[openai]` 模型，仅读取提交说明、文件路径和 diff，不读取已有模型判定、分层、分数或人工标签。
输出简短中文修改说明、旧问题与修复方式、限制说明及可核对的原文行。
不要求摘要给出相关性结论；它仍可能遗漏或误述，需要人工核对。长材料截断会在页面明确提示。

在 `[review]` 中可设置独立累计预算（不影响短判断预算）：

```toml
summary_max_requests = 500
summary_token_budget = 4000000
summary_diff_chars = 12000
```

材料、模型、接口、提示词或输出设置变化后旧摘要不会错误复用。
`reading_summaries/usage.json` 保存账本，`cache/` 保存有效摘要和证据，
`responses/` 保存模型原始输出。预取窗口随页面与排序实时更新，不再生成批次清单；
旧批次文件不再使用，不删除旧摘要，符合当前指纹的缓存仍可复用。点击停止或 Ctrl+C 后，在途请求完成并保存。

页面会自动显示已有有效摘要。标签本身仍由人工决定，摘要不进入 ASReview 训练特征或直接变成标签。
`labels.csv` 增加 `summary_assisted`、`summary_model`、`summary_fingerprint`，
`summary.md/json` 记录各阶段“标注前已提供摘要”的数量。
仅预取、但尚未在审查页提供的摘要不算已辅助标注；计数不证明人实际阅读。
使用摘要后的复核应称为 **LLM 辅助人工复核**，不能当作完全独立的盲审；
准确率仍表示 LLM 筛选决策与这批人工判断的一致程度，可能受摘要偏差影响。

### 1. 准备候选、人工标注

点击“准备候选”。扫描结果、命中理由、未命中集合会保存在 SQLite 数据库中。
首次扫描发生中断会回滚未完成数据，下次重新扫描；已完成扫描后不再重复。
`HEAD` 被解析成固定提交；之后即使仓库更新，同一实验仍使用原始集合。

规则覆盖架构名称/别名/路径、位宽、大小端、对齐、内存序、页表、DMA 等线索，
以及部分 `CONFIG_*`、`PAGE_SIZE`、架构接口等代码标识符。命中不等于相关。
默认只匹配标题、正文和路径。可以给 `hash_filter.fields` 加上 `"diff"`，
扫描时会读取完整 diff，速度明显降低；这种选择会记入实验快照。

在“训练标注”队列逐条选相关、不相关或不确定，并填写简短依据。
可通过标题/hash 搜索先标少量明确的正负例；至少有一正一负才能学习。
每条保存后更新排序，每 `exploration_every` 条穿插一次随机探索。
标成不确定的记录退出当前未读队列，但不作为负例训练；可在历史列表重新判断。

模型使用 **ASReview 3.0.8 的 Tfidf + Logistic**，不是 LAB 默认模型，
也不是对 LLM 做微调。使用标题、正文、修改路径作为统一排序特征，
避免为数万条候选预先读取所有 diff。人工页面能查看完整 diff；LLM 也会读取实际补丁。
这意味着排序模型仍可能遗漏只有源码才体现的关系，因此保留探索和低分抽查。

人工判断口径与短判断一致：是否具体支持纵向语义失配（公共功能与架构/平台实现
对能力、数据布局或执行语义的预期不一致），或横向回归（为架构 A 修改共享行为，
导致架构 B 回归）？两者任一成立即可，不要求同时修改公共和 arch/ 目录，
也不要求点名第二种架构。可涉及正确性、安全或性能；仅有架构名不能直接作为正例。
证据不足就标不确定；所有阶段都保留改判事件。

### 2. 冻结模型、检查阈值

达到训练阅读目标后点击冻结。默认从未读候选按五个分数区间抽出共 40 条用于阈值检查。
这些标签不加入本轮训练。冻结后训练标签不可修改；新模型/新口径请使用新实验目录。

在“阈值检查”队列标注完毕，再输入阈值并预览：

- 达到阈值、还没有人工确定结论的提交有多少；
- 检查样本在阈值两侧分别有多少正例、负例和不确定；
- 是否需要降低阈值以保留更多可能的正例。

分数未经校准，0.9 不意味着 90% 准确率；40 条只支持试探，不能证明筛选质量。
检查样本用于调阈值，不是独立测试集。完成后确认冻结本轮清单。
人工正例直接进入确认集合，人工负例不重复送 LLM；不确定仍可能按分数进入清单。
低分条目保留为暂缓状态，绝不自动赋予负标签。

### 3. 运行 LLM 短判断

勾选确认后启动。调用复用 `FastScreener`：分级补丁材料、结构校验、保守排除、缓存及共享预算。
不会自动生成长报告，不会把 LLM 判断回灌为人工训练标签。
没有旧入口的默认前 500 条限制；阈值清单全部纳入，按并发数逐条加载补丁。

预算是整个实验目录的累计请求数/token 上限，不是每次按钮点击重新分配。
同一 commit 可能因扩充材料/重试消耗多次请求；上限 100 不代表一定完成 100 个 commit。
用尽后修改 `[review].max_requests` / `token_budget`，重启入口，再点续跑。
模型、接口、研究上下文等改变时拒绝混用旧缓存；应另建实验目录。

“停止派发 / 停止扫描”可中止未完成的初始扫描（回滚后下次重新开始），
或停止后续模型请求；在途请求完成后保存。Ctrl+C 也会等待保存。
不要把失败、预算耗尽未处理或不确定计为不相关。
可以查看 `llm/checkpoint.json`、`llm/summary.json`、`llm/usage.json` 了解积压和用量。

### 4. 抽样盲审与统计

全部清单成功完成后点击生成抽样。失败/未完成条目会阻止抽样，避免只评价容易完成的部分。
原始 LLM 判定和保守规则后的有效判定都保留；统计默认评价有效判定，即实际筛选决策。

- LLM 集合：目标数量为 `min(N, max(ceil(N × audit_rate), audit_minimum))`。
- 按相关、不相关、不确定分层，近似按规模分配；非空层至少抽一条，因此极小预算可能略超目标。
- 另从未被人工标注的低分集合、正则未命中集合各抽至多 `boundary_sample` 条。
- 保存随机种子、总体规模、抽样数量、入样概率；复核列表打乱，页面隐藏模型判断和分层。
- 清单一旦生成就不重抽，且不再运行本轮 LLM。改判可以，换样不行。

复核阶段是额外人工预算，不包含在前期 160 + 40 条中。
例如 LLM 判断 1,000 条，默认抽查 100 条，另加边界检查最多 40 条。

统计中：

- **相关层的人工相关比例**：相当于本轮正例精确率估计。
- **不相关层的人工相关比例**：该被排除集合中的误排比例，不是传统召回率。
- **加权二分类准确率**：按 LLM 正负层总体规模加权；排除 LLM 不确定。
  抽中的正负层样本全部有明确人工结论后才给出；未完成/人工不确定时显示暂不估计。
- 每层提供样本量、人工不确定数和相关比例的 95% Wilson 区间。
  未完成时区间只描述已确定样本；未做有限总体修正，小样本不应解读成质量保证。
- 低分和未命中集合检查用于发现风险，不宣称全流程召回率。

## 输出文件与恢复

| 文件 | 含义 |
|---|---|
| `review.sqlite3` | 样本事实、规则命中、标签、事件、实验状态；恢复的主数据 |
| `dataset.json` | 仓库、固定 ref、规则和扫描范围 |
| `asreview_dataset.csv` | 可另行导入 ASReview LAB 的候选材料；无需日常手动导入 |
| `candidate_hashes.txt` / `regex_rejected_hashes.txt` | 正则保留/未保留集合 |
| `model_snapshot.json` | 训练标签、全部候选分数、组件版本与模型参数说明 |
| `selection.json` / `llm_hashes.txt` | 已冻结阈值和本轮 LLM 清单 |
| `llm/` | 模型结果、原始响应、实际材料、缓存、预算与检查点 |
| `audit_plan.json` | 固定分层抽样方案 |
| `labels.csv` / `label_events.csv` | 当前人工标签 / 历次改判事件 |
| `summary.md` / `summary.json` | 人可读/程序可读统计 |
| `results.csv` | 每条提交的候选状态、分数、人工和模型标签 |
| `confirmed_related_hashes.txt` | 人工确认的正例（包括抽查中发现的漏筛） |
| `provisional_related_hashes.txt` | 仅 LLM 判相关、尚未人工确定的提交 |

每次标注自动保存标签、统计和正例清单。完整 `results.csv` 在阶段完成或点击
“更新全部导出结果”时更新，避免每标一条都重写十几万行。
也可在服务停止后只更新导出文件：

```bash
python review_commits.py --export-only
```

备份时先停止服务，再复制整个实验目录；不要只复制 CSV 或运行中的 SQLite 主文件。
新实验只需更改 `review.output_dir`，不删除旧目录。程序不会替你归档/删除已有报告。
当前还不提供跨项目合并标签、多用户标注、自动判定停止条件或真正的概率校准。

## 参考

本实现借鉴 ASReview 的“少量人工种子 → 学习排序 → 优先阅读 → 人工反馈”思路：
[van de Schoot et al., 2021](https://www.nature.com/articles/s42256-020-00287-7)。
组件接口参考 [ASReview 文档](https://asreview.readthedocs.io/en/stable/technical/reference/asreview.models.classifiers.Logistic.html)。
