# 原材料并发提速与预算预留实验（2026-09-23）

目标是缩短 DeepSeek-V4.1-Flash 短判定的墙钟时间。所有正式比较均保留原研究上下文、原补丁材料、模型、输出上限与分级扩展策略；没有启用规则自动排除、Laya 或材料压缩。每次运行使用独立输出目录和请求/token 上限，原始回复、账本与停点在 Git 忽略的 `analysis_out/speed-benchmark-20260923/` 和 `analysis_out/stratified-batches-20260923/`。

## 同 50 条并发对照

输入为材料压缩实验已冻结的 80 条清单中前 50 条，每组最多 80 次请求、400,000 token。完整命令时间包括 Git 预处理与模型运行；模型阶段来自 `last_run.json`。

| 并发 | 完成/待处理 | 请求 | 报告 token | 模型阶段 | 完整命令 | 接口失败 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 4 | 50/0 | 53 | 254,914 | 34.81 秒 | 41.38 秒 | 0 |
| 8 | 50/0 | 53 | 254,700 | 16.10 秒 | 21.47 秒 | 0 |
| 16，修复预算器后 | 50/0 | 52 | 248,562 | 13.49 秒 | 17.35 秒 | 0 |

同样本中，8 路相对 4 路的模型阶段约快 2.16 倍、完整命令约快 1.93 倍；16 路分别约快 2.58 倍、2.38 倍。8 与 16 路的额外收益较小。4 路与 8 路有 8/50 条标签不同，虽然提示词和材料相同，也不能据单次运行把差异归因于并发或判定质量变化；需要独立人工参考和重复测量。token 用量并未随并发提高而显著下降。

最初的 16 路运行在 29 次成功请求、报告 135,547 token 后，误将并发中的临时最大预留视为预算真正耗尽，只完成 28/50 条并留下 22 条待处理。这不是接口限流。预算器现改为等待在途请求结算；只有所有在途请求结束后额度仍不足才停止。新增离线测试覆盖等待、退款后继续派发，同时保留未知用量的保守扣减。上述失败试跑的用量也已记录，不算入成功对照。

另对第二批做未调用模型的 `--plan-only` 计时，275 条 Git 解析、完整补丁提取与 stable patch-id 共约 10.94 秒。旧 4 路的 `last_run.json` 只计模型阶段；不能把第一批与另外两批的标签、token 或耗时差异解释为同样本因果效应。两批 16 路的成功运行说明在此规模、当前服务状态与预算设置下未出现明显限流，但不能保证数万条持续运行时也如此。

**当前决策：**正式短判定默认并发从 4 调到 16，并在新运行中单独记录 `preparation.json` 的 Git 阶段及 `last_run.json` 的模型与总时间。原研究材料、模型和判断协议保持不变。按两批 275 条的完整命令时间机械外推，118,997 条旧候选约需 7.6 小时；按同 50 条短批次约 11.5 小时。它们只说明当前吞吐的数量级，未计跨数百批的限流、故障恢复、人工复核与长报告，不能承诺全量工期。下一步按预算扩大批次并监测真实吞吐；详细分析仍在筛选后单独进行。
