# 分析器改进计划（2026-11-16）

## 一、目标（用户 11-16 明确）

**任务**：给一批跨架构相关的提交，分析器判断哪一个引入了跨架构缺陷。

**评价**：
- 有缺陷的提交尽量都检出（提交级召回）；
- 正常提交尽量不误判（提交级误报）。

正式评测用户以后用带标注的样本做。现阶段先把分析器做好：效果更好，覆盖的缺陷种类更多。

## 二、现状（截至 11-16）

- 能用的检查：
  - 效果依赖线：受限接口的 R、S、MG、MS 四组，加上接口提升；
  - 新接口族：页大小派生的阶数 × 页缓存上限。
- 这几条检查都是**对整个内核版本扫描**，输出候选表，还不能直接回答“这个提交有没有问题”。
- 历史样本召回：P1 有 15 个样本，15/15；阶数族有 5 个样本，4/5。
- 当前版本候选的误报很高：三张表共 115 条，真问题 3 条；阶数族 59 条，真问题 1 条。

误报的主要来源（来自各轮两人盲判的裁定，条数是大约值）：

| 来源 | 条数 | 例子 |
|---|---|---|
| 调用者保证，跨函数事实接不上 | ~15 | 值经过 `pte_modify`、`mk_pte` 加工后再传给受限接口 |
| 遍历器内部的保证 | ~9 | `page_vma_mapped_walk` 在迁移模式下只返回迁移项 |
| 同一个项的两种写法 | ~5 | `pmd[i]` 和 `pmd + i`，`ptent` 和 `old_pte` |
| 被架构覆盖的通用实现 | ~7 | `pgtable.h` 里带 `#ifndef __HAVE_ARCH_*` 的默认实现 |
| 语境规则太宽 | ~30 | 阶数族里的交换簇代码 |
| 守卫只按整个函数判断 | 漏报 1 | S6：函数别处出现了守卫词，出错的分支被放过 |

## 三、三条改进路线

### A. 提交级模式（为评测做准备，建议先做）

**做法**：输入一个提交 C。在 C 的父版本和 C 上各跑一遍全部检查，只报告 C 新引入的候选。“新引入”指：
- 落在 C 改动过的函数里，或经接口提升落在这些函数的调用者里；
- 并且在父版本上不存在。

**输出**：这个提交是否可疑、分数、证据（接口、出错的架构、缺少的守卫）。

**开发集**：从已有历史样本出发，按修复提交里的 `Fixes:` 标签找到引入缺陷的提交，作为正样本；再从同一时期、同一批文件里抽一些没有被 `Fixes:` 指向的提交，作为负样本。这只用来开发和调参，不算正式评测。

这样后面 B、C 的每一项改进，都能直接用“提交级召回和误报”来衡量。

### B. 降误报（效果）

1. 守卫按分支和 return 判断，不再按整个函数（S6 的教训）；
2. 同一个项不同写法的归一化（数组下标与指针运算；同一把锁下重读的值）；
3. 遍历器模式的知识：迁移模式只返回迁移项；非迁移模式不返回空项；
4. 跨函数事实穿过“加工函数”：`pte_modify`、`pte_mk*` 保留“是不是 present”；
5. 阶数族收紧语境：看是否真的用到 `mapping`、`xas_*` 这类对象，并排除交换簇宏；
6. 编码表补盲区：算不出常量的格子单列为“未知”；用多个页框号探测。

### C. 扩缺陷种类（覆盖）

从 135 个跨架构样本的分类里，挑能用“横向 × 纵向”机械化的几种：

1. **位宽截断（类型一致性）**：
   - 横向：探出各架构上 `long`、`size_t`、`pgoff_t`、`phys_addr_t` 等的位宽（32 位的 arm、mips 和 64 位不同）；
   - 纵向：公共层把 64 位的值存进或传给在部分架构上只有 32 位的类型，中间没有检查；
   - 例子：师兄文档里的 bbc46b23（`clone_flags` 在 32 位架构上被截断）。
2. **页大小硬编码（值依赖）**：
   - 横向：各配置的 `PAGE_SIZE`、`PAGE_SHIFT`（常量表已经有了）；
   - 纵向：公共层在页相关语境里写死 4096、12，或把 `PAGE_SIZE` 当成 4K 用。
3. **默认实现、空实现的依赖（实现一致性）**：
   - 把已有的 effdep 纵向信号，和“哪些架构覆盖了默认实现、覆盖后做了什么”的横向探测接起来；
   - 例子：X1（`tag_clear_highpage`）。
4. **字节序与布局（数据一致性）**：难度大，放最后。

## 四、建议顺序

A（提交级模式和开发集）→ B1～B3（最常见的误报来源）→ C1、C2（新种类）→ B4～B6 → C3、C4。

每一步照旧：先写判据并记 SHA，自测，在开发集上报告提交级召回和误报。
