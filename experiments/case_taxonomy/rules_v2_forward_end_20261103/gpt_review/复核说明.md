# 复核说明：程序在当前内核代码中标出的问题是不是真问题

## 背景

我们用几条程序规则，在Linux内核终点版本`df2908090cda`的RISC-V代码中查找可能的缺陷，共标出22个问题，列在`items.md`中。

每条包括：
- **规则**：这条规则查的是什么；
- **被标记的位置和理由**；
- **调用链**；
- **相关函数在该版本中的代码**。

规则说明：
- **执行上下文**：在关中断、持锁、陷入处理（中断关闭）等不能睡眠的地方，调用了可能睡眠的函数；或者在PREEMPT_RT内核中会睡眠的普通自旋锁；或者在不可插桩（noinstr）的函数里调用了可插桩的函数。
- **Spectre-v1**：对可能来自客体（虚拟机）或用户的下标做了上界检查，却没有用`array_index_nospec`，就拿它去访问数组。
- **同一约定**：三个参照架构的实现都调用了某个函数，RISC-V没有。

## 怎么判断

每条选一个标签：

| 标签 | 含义 |
| --- | --- |
| `a` | 真问题，在这个版本中仍然存在，且在常见配置下就会出现 |
| `a2` | 真问题，但只在特定配置或罕见路径上出现，例如PREEMPT_RT、kexec、休眠 |
| `b` | 不是问题：例如路径实际走不到、锁在调用前已经释放、下标并不受不可信方控制、所有架构都一样所以不是RISC-V的问题 |
| `c` | 判断不了：材料不够 |

注意：
- 程序是按“任一路径”往下查的，调用链上的某一步可能有条件挡住，或者锁已经释放。请看代码确认。
- 理由写一句话即可。

## 交回什么

填写`answers_template.csv`，另存为`answers.csv`：
- `label`：填`a`、`a2`、`b`或`c`；
- `reason`：一句话理由；
- 保留表头和第一列，不改变行的顺序。
