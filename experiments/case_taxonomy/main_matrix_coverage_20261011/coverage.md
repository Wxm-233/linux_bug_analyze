# 从案例到可执行检查：八项主矩阵的证据覆盖

2026-10-11。本轮只重整十份已固定报告和台账，共80665字节。没有新增选样、源码检索或实验执行；以下是**报告层复核**，没有重新认证报告所引用的源码、规范或运行产物。旧矩阵和结果保持原样。

结论是：四类Pattern仍可用于组织检查任务，但“解释一个已知问题”与“让程序发现未知问题”之间还缺少完整的证据提取。八项均有人整理的条件、来源和使用边界；不能据此认定八项都已自动提取，更不能把原型通过当作完整内核运行通过。

## 3. 四类Pattern和两个研究问题的当前答案

四类仍然有效，作用是规定应检查的关系：P1检查单位、范围和可表示性；P2检查双方表示/读写单元的一致性；P3检查当前周期状态在首次消费时已就绪并持续存活；P4检查真实能力/模式是否支持使用或导出。同一因果链可有主类和次类，不按表格行数估计总体频率。

对“怎样提取应添加的检查”，现有进展是局部事实和条件性候选可由程序取得；八项完整的配置、来源、传递与首个真实消费者尚不能自动齐备。下一步应优先补一条完整的提供—传递—消费链，输出来源位置和未知原因，而不是继续增加已经人工写定条件的网格。

对“不同架构理解不一致以什么为准”，应先限定同一版本、配置、模式和实际消费路径，再核对适用格式、ABI、硬件规范或消费者约束。die历史导出规则有报告中的文档和源码支持，但不代表硬件拓扑值正确；NUMA则仍有ABI/产物身份缺口。缺适用权威或可达路径时输出insufficient，不通过多数实现、补丁方向或返回码替代裁定。

10/11配置机制的补充说明也适用于这四类：**实际状态满足有效请求，不保证有效请求保留了环境的全部要求。** 检查须分开依据是否适用、要求是否合法保留、首次消费时是否满足。I3C/KUnit和NUMA为辅助机制/边界，不加入本八行分母；没有新增第五类。

## 4. 下一项：Btrfs单接口字段与首次消费链

选择Btrfs作一次已读开发例的有限补证：它已有真实几何来源、fs_info传递和首次选项解析消费，适合检查程序能否绑定同一字段及顺序。先定位现存同版原物，明确父/修复版本与最小依赖，另冻结范围后再读取；本轮不额外取源码。

验收应分开三层：自动获得赋值、传递、读取与位置；有条件地支持“真实几何先于首次裁剪”的关系；仍未知的可达/失败/运行条件。保留4K、请求未越临时上限、准备失败等对照；找不到同一字段或有效路径则不足。不能仅以语句搬移认定错误，也不能从函数结束的值判断首次消费正确。

这一步不是独立阳性验证。冻结规则后仍需有合格、未参与开发的同机制真实问题和正常来源；没有就保留缺口。真实挂载、首次发现日期和领域纳入继续待办。当前新确认0、独立阳性0，C1–C4、D2整体、D3全部裁定及D4整体仍未完成。
