# N2.16 运行自身的来源候选与两机制收束

2026-10-20。接续N2.15，只复用四次历史运行各自的配置、构建记录、原始观察和已有缓存。未进行新的预处理、编译、内核启动、模型源码调用或新案例搜索。本轮的有限绑定允许有条件的来源候选，**不以解除四个unknown为目标**。

## 核对得到什么

8份完整直接源码分别按两个版本核对：公共topology头、x86/s390架构头与公共driver；每份内容重新计算的Git blob都与该run原有build登记一致。四次运行自己的config和当前缓存相同，autoconf关键设置与config一致。它们都启用SMP、SYSFS且NR_CPUS=4，但x86 NUMA关闭、s390 SCHED_TOPOLOGY关闭，不能借用先前静态defconfig的生效定义。

| 运行构建上下文 | 同配置的直接ID候选 | 同配置的直接mask候选 | 当前运行有效来源 |
| --- | --- | --- | --- |
| old_x86_64 | x86头中的直接实现 | SMP分支中的直接实现 | 两项unknown |
| fixed_x86_64 | x86头中的直接实现 | SMP分支中的直接实现 | 两项unknown |
| old_s390 | 若公共ifndef生效则为fallback | 若公共ifndef生效则为fallback | 两项unknown |
| fixed_s390 | 若公共ifndef生效则为fallback | 若公共ifndef生效则为fallback | 两项unknown |

直接源的事实比借用另一个配置更精确：x86 ID不受NUMA分支限制，mask受SMP限制；完整s390头没有直接die定义，公共头按缺宏条件补回退。修复版在回退之前选择双来源导出政策。当前命令记录也能旁证所选架构路径，但没有独立历史摘要。

仍缺的是运行编译单元的有效定义序列：强制包含、driver前置头、x86后继条件include和s390尾部asm-generic没有展开，头文件guard的实际首次进入也未证明。局部无undef、命令中没直接覆盖，以及完整直接头内没有定义，都不能排除传递依赖的影响。详见[源码复核](source_review.md)。按原定范围到此停止，不继续追整棵头文件树。

## 程序怎样接线

`binding.py`只在本run的版本、配置/autoconf和已审完整源码身份匹配时输出`source_candidate`。这里的布尔仅说明有前提的直接来源解释，候选与`runtime_facts`分开；有效来源两项仍为None、provider审核仍unknown。自称闭合或给候选改名，都不能令其成为运行事实。

`run_binding.py`原样复用N2.15运行观察投影及契约核心，对每CPU的完整三属性分别接线；本轮精确要求CPU 0和1，不用全局“有任一文件成功”代替完整组。原始日志事件先与归档boot核对，并核构建/配置/镜像/init/回执身份。每CPU采样仍是probe read window，不改写为首次内容消费。

父版仍只作修复政策反事实，不能认定旧ABI违约。文件可读或ENOENT也不证明物理拓扑、getter准备效果及最终有效宏。原N2.15结果和六格静态预处理保持不变，本轮不向旧台账回填新结论。

## 本轮执行结果

一次prepare保存四run、每次CPU 0/1共8项输入，再用未改契约核心执行一次。四项条件性直接源候选均通过有限身份与guard核对；四run、8CPU的观察点判定全部不足，8项期限及整体判定也全部不足。文件观察仍为两版x86与旧s390各CPU三属性可读，修复s390三属性均ENOENT。来源候选没有进入有效native事实，结果没有消除运行证据缺口，也没有新增检测成功。

12项不同方法测试通过：首轮11项通过，另1项的测试变异误将`CONFIG_NR_CPUS_DEFAULT`同时改写，因而提前触发歧义拒判；保留首轮记录，仅修测试的精确宏键匹配，复跑受影响1项通过。生产适配器未因此修改。测试分别覆盖身份/配置/源码变化拒判、候选与事实隔离、完整每CPU属性组、缺CPU及采样点与期限分离，不是12项Linux案例。源码、方法和实际输入/输出经独立助手限域复核。

产物为[binding_inputs.json](binding_inputs.json)、[binding_results.json](binding_results.json)及两份方法测试记录。原N2.15输入、结果与核心保持不变；[component_versions.json](component_versions.json)仅登记6项可复用组件和6项特化参考版本，不作全树封存或完整检测方法冻结。
