# 判据：普通交换项编解码保持性的逐位求值（swapsym_20261121）

2026-11-21，Claude。用户：“开始第 3 天”。按第七次规划第 3～4 天，义务和输入域取自 `swapsupply_20261121/README.md`。写于实现和运行之前。

## 一、构建与版本

- `df2908090cda`。构建：riscv64、rv32_abi、x86_64、i386（非 PAE）、arm64（均为已有构建，`toolfix_20261121/inv.py` 的登记），外加 **i386_pae**：从 i386_defconfig 打开 PAE、只做 `make prepare` 的头文件变体（与 pgassert 修订 1 的 arm64 变体同样做法）。变体做不出来就只记录，不影响其余判定。
- 解释器复用 `toolfix_20261121/evalpg.py`（只导入，不改），把其中的三值位向量换成本轮新写的**逐位符号位向量**：每一位是常量 0/1、某个输入（t 或 o）的第 i 位（可带取反），或者来历不明的未知位。按位与或异或、取反、常数移位、截断、零扩展、符号扩展逐位精确；加减乘只在两边都是常数时计算，否则结果全部未知。

## 二、合成函数（每个构建一份）

对输入 `unsigned long t, o`：
- `S_enc = pte_val(swp_entry_to_pte(swp_entry(t, o)))`
- `S_present = pte_present(p)`、`S_none = pte_none(p)`
- `S_flags = pte_val(pte_swp_clear_flags(p)) ^ pte_val(p)`
- `S_type = swp_type(softleaf_from_pte(p))`、`S_off = swp_offset(softleaf_from_pte(p))`
- 常量：`MAX_SWAPFILES`；`S_probe` = `generic_max_swapfile_size()` 的函数体原样抄写（它在 `mm/swapfile.c` 里，不在头文件）；`S_dbg` = `debug_vm_pgtable.c:1229` 的表达式。

## 三、输入域

- t：低 5 位自由，其余位为 0，另加约束 `t ≤ MAX_SWAPFILES - 1`（取自该构建）。
- o：`1 ≤ o`，并且只有低 K 位自由，`K = min(32, K_enc)`。32 来自交换区头部 `__u32 last_page`；`K_enc` 是**本轮自己推出的编码容量**：o 取公共偏移的全部位宽（64 位上 58 位，32 位上 26 位）求一次 `S_off`，从第 0 位起连续“输出位恰好等于 o 的同一位”的位数。
- **不用 `S_probe` 定义域**。它只用来对账：若 `S_probe > 2^K_enc`，说明生产端接纳的偏移超出了编码能保持的范围，记为违反。

真假判断按上面的域精确判定：一组位“全为 0”是否可满足（每位是常量或输入位文字，再加 o ≥ 1、t ≤ MAX-1 两个约束）。判不定的记“未知”，不当作成立。

## 四、义务与判定

对每个构建，在第三节的域上：
- **O1**：`S_present` 恒假，且 `S_none` 恒假。
- **O2**：`S_flags` 恒为 0（编码不占会被清掉的标志位）。
- **O3**：`S_type` 的每一位等于 t 的同一位，`S_off` 的每一位等于 o 的同一位（域外恒为 0 的位，输出也必须恒为 0）。
- **对账**：`S_probe ≤ 2^K_enc`；另记 `S_dbg` 是否等于 `S_probe - 1`（原生测试是否真的测到最大偏移）。

结果分“成立”“违反（附具体输入）”“未知（附原因）”“不支持（解释器做不了）”。违反必须给出一个域内的具体 (t, o)，并且在第五节的具体求值里复现，才算数。

## 五、与编译器的具体求值对账

- 每个构建至少 6 组具体 (t, o)：(0, 1)、(1, 2)、(MAX-1, 1)、(MAX-1, 2^K-1)、(MAX/2, 2^(K-1))、(3, 0x2345 与 2^K-1 相与)，外加 S_probe、S_dbg 两个常量。
- 符号结果代入具体值得到预测；同时用该构建的编译参数让 clang `-O2 -emit-llvm` 编译 `C_i(void) { return S_enc(t, o); }` 等函数，从 IR 里读出折叠后的返回常数。两者逐个比较 `S_enc`、`S_type`、`S_off`、`S_present`、`S_none`。
- **一处不一致就不能给该构建下结论**，要先查明原因（修好重跑，或者把该操作改为“不支持”）。clang 折叠不出常数的（例如半虚拟化调用），记“无法对账”，不计入 6 组。
- 门槛（规划第 3～4 天）：至少 2 种表示不同的布局，各有 ≥ 6 组对账一致。
