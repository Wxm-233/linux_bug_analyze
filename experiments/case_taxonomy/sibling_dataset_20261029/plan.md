# 跨架构兄弟数据集修正：计划（实现前写定，2026-10-29）

按用户“修正数据集”实施。不调用模型。目标是得到一份去重、目标标注修正、可供人工逐对筛选的跨架构兄弟候选集。**本轮不判断兄弟关系**，只准备筛选表，标注由用户或合作者完成。

## 1. 已知缺陷（来自`holdout_diff_20261029/`）

1. **重复提交**：同一内容的T以两个哈希出现（留出第1、2对），被计为两对。
2. **函数名伪目标**：`candidate_bridge.function_spans`取函数名时，把`__attribute__`（如`void __attribute__((...)) f(void)`）和`switch`（`#if`各分支花括号不平衡时，顶层误判出现在函数体中）当作函数名（留出第15、22对）。
3. **配对噪声**：以共同引入提交配对，真兄弟只占少数；来源B中S多为引入点。这一项只能靠人工筛选，本轮把配对类型分开标出，供标注者区分。

## 2. 修正

- **函数名识别**：新模块`linux_bug_analyze/sibling_pairs.py`中的`function_spans_strict`：
  - 只看函数头最后一个语句片段（最后一个`;`或`}`之后）；
  - 在括号深度为0处收集“标识符＋`(`”，排除控制语句、GCC属性、`asm`、`typeof`、`sizeof`等非函数名，取最后一个；
  - 函数头须以`)`结尾，允许尾随限定词和属性；
  - 不满足以上条件时函数名为`None`，即不作为目标。

  `candidate_bridge.function_spans`已被冻结方法引用（M3a冻结清单记录了它的SHA），**不修改**，旧实验可原样重跑。`#if`分支造成的花括号不平衡本轮不修，只保证这种情况下不再产生`switch`之类的伪名字。
- **目标提取**：`body_targets_strict`，与`count_pool.body_targets`相同（T在父提交中函数体内的改动，且该函数在快照S存在函数体），只把函数识别换成严格版。
- **去重**：用`git patch-id --stable`给每个提交算补丁指纹。S与T指纹相同的对（同一补丁），或与另一对的(S, T)指纹完全相同的对，只保留最早提交的一份，其余标记为重复。

## 3. 重建范围与配对类型

范围`v4.0..df2908090cda`。漏斗沿用`xarch_source_20261029/count_xarch.py`：都改`arch/`代码 → T改了S没改的架构目录 → 跨架构有效目标 → 不全是S已改函数。目标提取换成严格版。

| 类型 | 定义 | 对应任务 |
| --- | --- | --- |
| `A_common_cause` | S与T的`Fixes:`指向同一提交X | 修复的兄弟 |
| `B_fix_of_fix` | T的`Fixes:`指向S，且S本身带`Fixes:` | 补全漏掉架构的修复 |
| `B_introducer` | T的`Fixes:`指向S，S本身不带`Fixes:` | 从引入点找漏改的使用方（另一种任务，单独标出） |

每个(T, 类型)只保留一对：A取早于T且最近的S，B的S就是被修复提交。
