# N2.20：先建立可评价的资格，再开展隔离父版分析

2026-10-21，N2.19结果之后制定的下一计划；不是本轮事前协议，也不是已经取得的新实验结果。

## 目的

避免把功能调整当作确认缺陷、把另一架构的实现当作已经证明正常。研究仍围绕N1自动推导跨架构接口要求与N2契约驱动对照；不转向大规模筛选或继续扩I/J源码树。

## 最小执行范围

1. 先固定一个具体公共用途及其待检关系，例如CPU身份经架构映射后供公共逐CPU操作使用。数量、编号空间、实际消费域与启动阶段分别记录；不能用“所有possible都有当前硬件映射”作统一正确标准。
2. 在任何新正文阅读前，根据已有500池元数据和接触记录固定至多两项资格候选、至多一项同用途参考及顺序、材料上限和停止条件。资格批次固定后，不因功能调整、已读、家族重叠或工具不足而补换。新哈希和关键词命中均不是独立性或缺陷依据。
3. 在资格角色读取修复前，冻结父版材料选择规则、通用提示、方法与中性材料编号；父版包由不看资格oracle的角色按固定规则生成，不得根据修复答案补源或选片。由不看受测预测的资格角色阅读必要说明、修改与限定源码，先保存独立资格记录：架构差异来源、实际破坏的接口要求、如何进入公共消费、为何特定架构/配置暴露，以及依据层级。功能调整、同家族、辅助配置例和材料不足均原样保留。
4. 正常参考要给出同用途、同条件下满足要求的有限源码保证。整个实现没有已知补丁、功能被关闭或未运行到消费者，都不能作为正常保证。保证依赖实际配置时，缺配置就保留不足。
5. 只有资格批次得到至少一项合格机制样本和一项有条件保证的同用途参考，才进入下一项父版预测。资格角色先只向主任务返回执行所需eligible/insufficient状态，完整义务、正常保证与修复裁定不进入预测输入；主任务若已读完整oracle，也不得据此调整包或提示。模型只获得预先固定的父版材料和同一方法提示。完整资格oracle在预测保存后解封比较。人工资格审查只确定评价范围，不是自动N1成果或检测成绩。
6. 若资格未达门槛，就以资格不足收束，本项付费模型任务为0；不把它计作检测成功、失败或独立阴性，不为得到阳性而不断补选。

## 比较与停止

比较必须分别报告来源绑定、要求本身是否有依据、对象/编号空间、实际读域与阶段是否匹配，以及程序是否真正支持该条件；引用正确或同一guard不等于语义正确。不能要求所有实现采用同一准备函数，也不能把登记回调当首次读取。

方法开发、同家族和真正独立资格分列。若仅能取得已读案例，只可作开发核对，不追认独立分母。预算和材料协议在后续有资格的模型执行前另行固定，仍按用户单轮1M上限与现有Opus路线；本计划不授权额外实验范围。

不继续SPARC替身或I/J的解析/构建网格；R3暂缓。每轮完成后更新两份工作文档、Windows/WSL镜像与当日日志，保留失败与停点；不改Word或推送GitHub。
