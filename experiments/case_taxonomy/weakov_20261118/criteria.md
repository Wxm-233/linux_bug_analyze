# 实现一致性检查：`__weak` 通用实现对比架构覆盖实现的路径效果（判据，写代码之前定下）

**先说明局限**：规则是看着这个案例设计的，开发样本只有它一个。开发命中不能算召回；独立检验只有下面第六节第 4 步（引入提交）和第 3 步（噪声量级）。

## 一、读入（纯词法，读 git 对象，不编译）

- 版本 rev 下，`arch/` 以外所有 `.c` 文件里的 `__weak` 函数定义，记为通用实现 W（名字 N）。
- 同一 rev 下 `arch/*/` 的 `.c` 文件里，名字也是 N、不带 `__weak`、不是 `static` 的函数定义，记为架构 a 的覆盖实现 O。
- `arch/` 以外调用 N 的地方，记为公共调用点。

## 二、通用实现的效果 E(W)

- W 函数体最外层（不在任何 `if`/循环/`switch` 块里）语句中的函数调用，包括 `return f(...)` 里的调用；但只算第一个 `return` 或 `goto` 之前的。
- 排除不算“效果”的调用：日志（`pr_*`、`printk`、`dev_*` 打印、`*_once`）、断言（`WARN*`、`BUG*`、`lockdep_assert*`、`might_sleep`）、取值宏（`per_cpu`、`this_cpu_*`、`READ_ONCE`、`WRITE_ONCE`、`IS_ENABLED`、`likely`、`unlikely`、`container_of`、`sizeof`、`ARRAY_SIZE`、`min`、`max`）。
- E(W) 为空就跳过 N（通用实现是空函数或只返回常数，属于“覆盖实现可以多做”的那种接口）。

## 三、覆盖实现的路径

- S = E(W) ∩ O 里直接调用到的函数。S 为空就跳过（O 做的是别的事，不归这条规则管）。
- 对 S 里每个效果 e：
  - O 的最外层没有调用 e（只在条件分支里调用）→ 记一条“缺失路径”，条件是包住 e 的 `if` 条件；
  - 最外层第一次调用 e 在位置 p。p 之前，更深一层（在 `if` 等块里）出现的 `return`，或者跳到 p 之后标号的 `goto` → 每处记一条“缺失路径”，条件是包住它的 `if` 条件文本。
- 非 `void` 的 O：缺失路径上的 `return` 返回错误（`-E…`、`ERR_PTR(…)`、`false`、`NULL`、名为 `ret`/`err`/`error`/`rc` 的变量）时，只有存在“忽略返回值的公共调用点”（调用是一条单独的语句）才报；返回 `0` 或什么都不返回的照常报。

## 四、纵向：公共调用点

- 没有公共调用点就不报（只在架构内部用）。
- 记录前 3 个公共调用点（文件:行 函数名），以及调用点是否忽略返回值（`void` 一律算忽略）。

## 五、输出和排序
