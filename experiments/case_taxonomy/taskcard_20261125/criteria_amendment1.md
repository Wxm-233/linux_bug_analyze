## 诊断（`diag.py`）发现的实现错误

1. **局部结构变量被当成全局结构变量。**
   - **原因**：生成器把所有 `struct T v = { … }` 都登记成结构变量节点，包括函数体里的局部初始化（例如 `struct foo data = { … }`）；结构变量又只按名字合并。
   - **后果**：`data`、`args`、`parent`、`ctx` 这些到处都有的局部变量名，把不相干的函数串到了一起。例如 `sys_fault_user → var:args → var:key → var:parent → i915_display_dpt_interface.create → i915_dpt_create → insert_page`，是一条假路径。
   - **数字**：从 `folio_referenced_one` 反向能走到 7824 个入口，其中系统调用 621 个、回调 3551 个。
2. **引用面向用户的回调结构，被当成了调用它的回调。**
   - **例子**：`vma_is_shmem()` 只是比较 `vma->vm_ops == &shmem_vm_ops`，却生成了 `sys_mremap → vma_is_shmem → shmem_vm_ops.fault → shmem_fault`。
   - **应有的做法**：登记在面向用户的回调结构里的函数本身就是入口（第二节第 2 条），不应该再经“引用这个结构”往上走。
3. **运行时开关的“写者”判错了。**
   - **原因**：程序把“调用了某个函数”当成了“写了某个开关”。
   - **后果**：`IS_ERR` 被当成开关，`create_store` 被当成写它的函数。
4. **EC 偏离按函数名找，取不到。**
   - **原因**：EC 的偏离键是按公共接口写的（例如 `SW|public|make_writable_migration_entry|swp_entry_to_pte|…`），不含 `__swp_entry` 本身。
   - **后果**：F 的前置状态是空的。

## 修订

1. **结构变量**：
   - 只登记文件作用域（不在任何函数体内）的结构初始化；
   - `static` 的结构变量按“文件 + 名字”区分，只连同一文件里引用它的函数；非 static 的按名字；
   - 函数体里的局部初始化不建节点，其中出现的函数名照旧按“函数指针”从所在函数连边。
2. **回调结构**：结构类型属于第二节第 2 条的面向用户类型时，不建“函数 → 结构变量”的引用边。这样搜索停在回调函数本身，它就是入口。
3. **运行时开关**：
   - **开关**：判断条件里出现的、文件作用域定义的变量，以及 `DEFINE_STATIC_KEY_*` 定义的静态键；或者条件里不带参数的函数调用，而这个函数体里读这样的变量（只跨一层）。
   - **写者**：
     - 函数体里给它赋值（`=`、`|=`、`&=`、`+=`、`-=`），或者把它作为 `set_bit`、`clear_bit`、`static_branch_enable/disable`、`static_key_enable/disable` 等的参数；
     - 并且这个函数本身，或者它的直接调用者，登记为 sysfs `store`，或者是 `__setup`、`early_param` 的处理函数。
4. **EC 偏离**：按“规律族（特征的第 2 段，如 `SW`、`PT`）相同，且偏离构建属于这一行”取，最多 5 条。
5. **不改的**：入口的排序规则（系统调用 > 回调 > 架构入口，再按距离，最多 20 个）、标准答案、门槛都不改。

如果修正后 T3、T4 仍然不过，照实报告。
