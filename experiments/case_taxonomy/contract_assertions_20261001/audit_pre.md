# 自动生成条件性表示断言：事前方法审计

2026-10-01。本轮只使用已经解封的开发案例和合成反例，不接触新目标选样，不改旧冻结实现、TODO 或日志。本文件先于新生成器代码审计保存。

## 断言必须具有发现错误的可能性

生成程序应让**消费者读取实际生产者写出的字节**，再与独立的输入数值/预期属性比较。生产者要保持所查源码的原始写法；消费者按同版字段契约解码。不能用 schema 同时重造生产端和读端，再用同一个转换函数计算两边，以免断言恒真。

至少要能区分：原始 host 字段直写、只修一个字段、完整修复、已编码输入再次转换以及表示自洽的正常对照。真实旧生产者在相反端序应能使表示断言失败；失败由运行结果产生，不能由生成器预先将已知旧版标签写成失败。零值或字节对称值只作对照，不足以证明所有输入正常。

## 输入报告不是独立权威

生成器须核对原始源码/声明事实与报告一致，包括修订、源文件内容哈希、目标结构与完整字段集合、字段位宽/端序、生产者表达式、源成员绑定、复制入口与对象/长度。篡改报告的 status、表达式、字段、类型或哈希，不能让程序在与原源码不符的前提下成功生成“通过”的断言。证据不足要拒绝生成，不能以默认小端或补全字段的方式制造成功。

特别是只包含部分 payload 字段时，不能生成完整 payload 正确性断言；本轮有界接口应直接拒绝。真实布局应使用原声明片段和编译器的 `sizeof`/`offsetof` 核对；未识别的布局后缀、packed/对齐含义、条件头文件、同名结构/变量声明和复杂字段保持不足，不能自行改成理想布局。编译器引用需要绑定具体声明，不能重演旧全函数同名类型覆盖。

## 最少独立反例

| 边界 | 本轮应验证的事实 |
| --- | --- |
| 混合 16/32 位及 `__be` 字段 | 生产者、字段尺寸和解码端序分别正确；不套用统一 little-endian 假设。 |
| 零值或字节对称值 | 可能掩盖原始错误，必须保留非零且不对称输入；不得据零值通过解除条件冲突。 |
| 已编码值二次转换 | 明确编码源应拒绝错误 source-host 事实或使独立读端断言失败。 |
| 伪造报告 | status、类型、字段、表达式或 source hash 不一致时拒绝，不由报告标签替换真实生产端。 |
| 部分 payload 字段 | 拒绝生成完整 payload 验收；不能把未初始化/未建模字段悄悄删掉。 |
| 未知 packed/布局后缀 | 不改写真实声明为自造的 packed 布局；编译布局不符应失败或拒绝。 |
| 条件头文件、同名声明或 typedef 阴影 | 声明适用性或绑定未证时拒绝；编译缩小探针不替代原翻译单元证明。 |

## 契约层级和验收措辞

schema 只代表**所查版本内核对字段表示的声明契约**。没有外部规范、设备/固件适用性和真实运行链证据时，结果始终是条件性表示检查，不认定硬件故障或已确认新缺陷。普通 GCC 可擦除 `__bitwise` 标签，编译通过并不提供端序类型正确性；大端用户态/QEMU 探针也不等于历史内核执行。

有界验收是保存可复核输入、计划、生成 C、编译/运行命令及失败/通过矩阵，并以具体声明和消费者字节为依据解释输出。代码和依赖在开发完成后按 SHA 锁定，再做最终审计。本轮开发回归和合成反例不计独立留出成功，站点/字段/输入数量不计新缺陷数。
