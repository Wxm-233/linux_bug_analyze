# 根运行器只读复核

复核范围仅为 `run_automatic_checks.py`、`gcc_projection_bindings.py` 和已保存的 `final_run_01`。未重新编译、执行实验或修改规则与结果；另用只读 Python 对已存数据独立重算字节、解码、覆盖和哈希。

**结论：未发现影响本轮已读案例投影结果的阻止事项。结果可作为有条件的工程验证，不能解释为完整内核或协议正确性证明。**

## 独立 oracle 与已存矩阵

Python 使用 `int.to_bytes` / `int.from_bytes`，独立于生成 C 的转换函数、移位解码和 `pass` 标记；同时检查 actual 字节是否符合已核对的 raw/matched producer 关系。因此它既检查消费者 schema，也检查原生产赋值，未用自动制造的正确 encode 替代原 producer。源输入从计划中复算，非活动字段必须为 zero；两组非零输入须非对称，zero 控制和四种变体覆盖完整。

只读复算的 192 条字段检查与结果一致。四份 rows 文件逐行等于命令记录中的实际 stdout；每份为 1 条布局记录及 48 条字段记录，无重复或遗漏。两个字段的记录偏移为 0、2，宽度均为 2，总大小 4。

| 输入与目标 | actual 失败 | reference 失败 | partial_tx_len 失败 | partial_tx_time 失败 |
|---|---:|---:|---:|---:|
| parent / x86_64 | 0 | 0 | 0 | 0 |
| parent / s390x | 4 | 0 | 2 | 2 |
| fix / x86_64 | 0 | 0 | 0 | 0 |
| fix / s390x | 0 | 0 | 2 | 2 |

表中计数为字段检查失败，均发生在非零输入；不是新增案例数。两版的 partial 都是合成缺失转换控制。

该 oracle 的独立性主要在字节计算实现。字段端序和 producer 分类仍来自相同的已验证源码计划，故不能证明 schema 是外部接口的最终权威，也不能证明实际源字段一定是主机数值。两个非零值不能替代完整值域和运行路径验证。

## GCC 绑定核对

当前保存的 actual 函数图与 C 源码一致：目标字段均绑定同一个局部 `cp` 声明节点，来源均绑定同一个 `hdev` 参数节点；字段声明指向对应记录类型。父版直接读取源成员，修复版经 `cpu_to_le16` 调用后写入；生成程序也保留了这些实际赋值。

检查器可核对目标标签、字段、类型别名及来源成员，不应单独当作通用 C 语义门禁。静态审查的边界是：它主要按名称匹配，不强制跨字段绑定到同一 declaration/record 节点；允许成员根为 var 或 parm、直接对象或指针；遍历 RHS 成员不证明转换函数、算术和控制流语义，也没有从函数 body 单独建立执行可达性。因而对任意复杂或人为替换的 dump，不能声称这些检查不可被绕过。未来拓展时可增加声明节点身份、scope/field 所属 record、直接局部对象形状及语句可达关系的检查。

本轮生成器只接受直接、完整的简单字段赋值，actual 函数仅一个对象和明确参数；源文件哈希、实际 GCC 编译图以及数值/字节 oracle 联合使用，已保存图中未出现上述歧义。这里核对的是生成的缩小翻译单元，无法推导原内核全部预处理条件、作用域或 Sparse 端序限定已经通过。

上述边界不改变本轮矩阵所说明的有限事实：自动产生的字段检查在既定主机数值和局部 schema 假设下，能够暴露大端原样写出与不完整转换，并保留小端及 zero 对照。它仍不是新增独立样本、完整协议验证或真实内核执行。
