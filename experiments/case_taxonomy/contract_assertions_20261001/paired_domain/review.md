# 内部读写表示域：生成检查与独立 oracle

日期：2026-10-01。已读 coredump 是开发依据：父版 `25c150ac103a4ebeed0319994c742a90634ddf18` 使用 32 位 host 写/host 读；修复版 `0ab905c3be8c2be368821dd2bd1f8d126064d993` 使用成对的 le 写/le 读。这两组是本轮唯一绑定历史源码的数值投影。16 位、64 位、显式 be 域和混合域用于合成机制对照，不作为新增案例或泛化成绩。

`run_matrix.py` 按宽度、来源域和读端域生成 C 程序。宽度限 16/32/64，域限 host/le/be；每个宽度生成两组不对称非零字节模式及零值。输入通过宽度统一生成，未硬编码各案例的预期输出字节。host 写/读使用对应宽度的 `memcpy`，显式 le/be 通过逐字节移位实现。程序读取真实主机内存字节，核对编译器端序宏，并由运行器核对目标预期端序，避免把小端目标当成大端结果。

## 运行结果

现有 GCC 13.3.0 编译的 x86_64 程序原生运行，s390x 程序由 QEMU s390x 8.2.2 用户态运行。每个目标有 81 行常规矩阵：3 个宽度 × 9 个域对 × 3 个值；另有 1 行故意引入的共同错误变异。下表描述两组非零输入，在三个宽度上行为一致。

| 来源域—读端域 | x86_64 小端 | s390x 大端 |
| --- | --- | --- |
| host—host、le—le、be—be | 还原数值 | 还原数值 |
| host—le、le—host | 还原数值 | 数值失配 |
| host—be、be—host | 数值失配 | 还原数值 |
| le—be、be—le | 数值失配 | 数值失配 |

每个目标的 54 行非零投影中有 24 行预期数值失配；同名域均无数值失配。27 行零值算术对照都还原零。**原 coredump 消费者会拒绝零值**，所以零只是算术上的值敏感性对照，不能说明真实初始化通过。其他输入也未尝试实际分配内存、运行内核队列或验证设备可达性。行数和变异数量都不是缺陷数量。

## 检查的是原生产者输出，而不是参考实现自洽

有用的条件检查是：

```text
payload = P_original(v)
decode_C(payload) == v
```

其中 `P_original` 应绑定待检查版本的写出表达式，`C` 应绑定实际读端。本轮 C 的 host、le、be 实现只是在用户态投影这类表达式，并非原始内核函数完整运行。不能用 `decode_reference(encode_reference(v)) == v` 替代这项检查：参考写读实现即使同时选错端序，也可能仍然还原数值。

因此运行器另用 Python 的 `to_bytes`、`int.from_bytes` 实现独立 oracle，分别核对 C **实际写出的字节**与声明来源域，以及按声明读端域解码实际字节得到的值与 C 读回值。它不调用 C 的编码/解码函数，也不只检查“写后读回等于输入”。常规矩阵的实际字节与读回值均与这两个独立检查一致；不同域的数值失配是预期的契约差异。

变异对照声明 BE/BE，但故意让 C 写端和读端都执行 LE。对输入 `0x01020304`，C 写出 `04030201`，C 读回仍是 `0x01020304`；仅检查往返等式会通过。独立 oracle 要求 BE 字节 `01020304`，并按 BE 读取实际字节为 `0x04030201`，所以两项检查均拒绝这个变异。在两目标上的结果相同。这证明该检查没有仅靠编码/解码共享同一个错误来得到恒真的结论。

## 接口权威与证据边界

`source_card.json` 重新核对同版 coredump 源码的 blob、全文件 SHA-256、摘录行号和原文，保存旧生产者、旧消费者、同主机队列分派及修复两端的证据。内部载荷应以同版、同模式的**实际读端及其来源链**为解释依据。旧 host/host 在同一主机内数值自洽；并未绑定要求固定小端的外部协议，所以不能只看到主机整数原样复制就自动要求 LE。若外部规范、另一实际读端或模式约束与当前链冲突，应先标记契约待决，不能按其他架构多数实现投票。

本轮可生成的检查包括：按消费者域解释原始写出字节，检查是否还原输入；若有独立的固定格式约束，再加“字节符合格式”检查；对只改写端、只改读端及共享错误变异保留对照。没有绑定读端/格式时，生成器只能给条件性数值投影，不能给缺陷结论。

每行结果都区分源码关联投影与合成投影，并保留配置可达性、原访问对齐/别名、队列生命周期和外部协议未知。真实旧读端是指针解引用，本模型用 `memcpy` 避免了对齐和别名问题，故**不能证明旧访问安全**。历史案例仍未增加到已确认跨架构核心集；本轮没有新样本、外部模型或真实内核/设备验证。

`results.json` 保存完整编译/运行命令、编译器版本、所有行、变异结果与源码/可执行文件 SHA-256；历史 Git 查询记录命令及原始全文件 SHA-256，完整的关键摘录在 `source_card.json`。生成的 C 源码为 `domain_matrix.c`。

```bash
python3 run_matrix.py --linux-dir /root/repos/linux
```
