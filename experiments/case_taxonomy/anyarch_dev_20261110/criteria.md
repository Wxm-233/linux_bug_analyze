# 判据：让每个架构都能作为被检查对象（anyarch_dev_20261110）

2026-11-10，Claude 在写代码和运行之前写定，SHA 存入 `criteria_sha256.txt`。

## 一、目的

用户 2026-11-10 修正目标：尽可能找到所有架构上的跨架构缺陷，riscv 只是其中之一。上一轮 `oddarch_stats_20261110` 在已有记录上看到：把比较改成对每个架构都统计是可行的，但有一类固有差异会一直占着结果——同一个数字在各架构含义不同（例如 arm64 的 `O_DIRECT`、`O_DIRECTORY` 取值与通用定义互换），因为生成器给三个架构传的是同一个数字。

本轮改两处，不改方法的其余部分：

1. **比较脚本**：不再写死 riscv。内核表、架构列表从配置文件读入；对每个架构都给出“与众不同”的判定。
2. **生成器**：接口常数按架构换算。

本轮只在当前版本（CUR，没有已知缺陷）上试跑，不评价检出能力，不构建内核。

## 二、比较（写死）

- 配置文件 `kernels_<组>.json`：每个内核一项（名字、架构、镜像路径、构建目录）。任意个架构，至少 3 个。
- 解析、稳定性、PMU 剔除规则与 `diverse_dev_20261110/compare.py` 相同；PMU 配置项表按架构名查，查不到的架构视为“不需要剔除”并在输出里注明。
- **多内核同架构**（样本组的修复前、修复后）：每个“被检查内核”与**其他架构**的全部内核组成一个比较组；同架构的另一个内核不参与。
- 对每个比较组的每个用例：不稳定 → `unstable`；任一内核被剔除 → `excluded`；全部相同 → `same`；恰有一个架构与其余不同、其余全部相同 → `odd_<架构>`；其他 → `split`。
- 回归：用 `diverse_dev_20261110` 的 CUR 日志，结果必须与 `oddarch_stats_20261110/stats.json` 逐项相同。

## 三、接口常数按架构换算（写死）

- **名字从哪来**：事实文件里每个守卫的比较记录了常数一侧用到的宏名。沿用 `hints4.py` 的参数映射，对每个“系统调用的第 p 个参数”收集：与它比较（`==`、`!=`、`&`）的常数一侧出现的宏名，以及这些宏的定义体里展开出的宏名（递归）。
- **各架构的值**：对这些宏名，用 `semhint_dev_20261109/static/macro_values.py` 的探测方法，在三个当前版本构建上各求一次值。探测时包含的头文件：定义所在头文件若在 `asm-generic/` 下，改为包含同名的 `asm/` 头文件（这样各架构取到自己的定义）。
- **换算表**：对每个（系统调用，参数），取其中“三个架构都是整数常量、且取值不全相同”的宏。事实文件来自 riscv 构建，所以用例里的数字按 riscv 的取值理解。
  - 宏在 riscv 上的值只有一个比特位：记为“位换算”，riscv 的这一位 ↔ 各架构的对应位（对应值也必须只有一个比特位，否则该宏不用）。
  - 其他：记为“整值换算”，仅当参数的值恰好等于它在 riscv 上的值时才换。
  - 同一（系统调用，参数）下，若两个宏在 riscv 上取值相同而在某架构上取值不同（有歧义），两个都不用。
- **应用**：只对用例里的整数参数（`i:` 记号）做，结构体字段不做。先看整值换算；否则逐位换算：把值里属于位换算表的比特位取出，换成该架构的对应位，其余比特位不动；若换出来的位与“其余不动的比特位”或彼此重叠，该用例在该架构上不换算并计数。
- 换算只改变输出给各架构的清单；逻辑用例、用例编号不变。
- 回归：关闭换算时，输出的三份清单必须与 `diverse_dev_20261110/gen/cases_CUR_<架构>.txt` 逐字节相同。

## 四、试跑与要报告的数字

- 用例：`diverse_dev_20261110/gen/cases_CUR.json` 原样（8107 个），只是按第三节换算后输出。
- 内核：当前版本三个默认配置内核，每个运行 3 次；执行器、启动脚本沿用上一轮。
- 报告：换算表的规模（多少个系统调用参数、多少个宏）；被换算改动的用例数（按架构）；换算前后每个架构的“与众不同”用例数和簇数；上一轮 arm64 的 3 个 openat 簇是否消失；换算后新出现的簇（全部人工核对，结论分“能解释 / 不能解释（疑点，只记本地）”）。
- 预期（事先写下，不作为通过条件）：riscv 方向不变；arm64 方向至少少掉 3 个 openat 簇；`prctl`、保护位、地址空间类的差异不受影响，因为它们不是“同名不同值”，而是架构专有功能或地址空间大小。
