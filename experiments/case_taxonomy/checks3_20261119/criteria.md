# 三类检查分组层（判据，写代码之前定下）

2026-11-19，Claude。用户：“能不能维持现有的规则，但是可以这么做：把同一类检查的放到一块，形成一个整体，这样效果会和之前一样，在整体上也能更清晰”；“按照这个做吧”。

## 一、原则

- **规则和引擎一条不改**。外面这一层只做三件事：按三类检查分组调度、统一输出、按组统计。
- 每个引擎“新引入候选”和“对位”的判断，都**直接调用这个引擎接入提交级模式那一轮的函数**，或者逐行照搬那一轮的评分代码，不重新实现。
- 只读导入旧轮次的代码。旧代码运行时会写文件的地方（如 `commitmode.check()` 写 `report/`），要改指到本目录，不写进旧目录。

## 二、分组

| 检查 | 引擎 | 新引入与对位的来源 |
|---|---|---|
| 类型一致性检查 | WT、ORD | `commitmode_20261117/commitmode.py` 的 `check()`；留出集按 `heldout_run.py` 加“额外目录超过 30 个就只看基本范围” |
| 实现一致性检查 | P1、XV | 同上 |
| | TLB | `commitmode_tlb_20261117/cmtlb.py` 的 `tlb_new()` |
| | WK | `weakov2_20261118/weakov2.py` 的 `wk_new()` |
| | XA | `xvatom2_20261119` 的缓存 + `commitmode.compare()`，同 `xvatom.score()` |
| 调用上下文检查 | CTX | `ctxeff_20261118/ctxeval.py` 的 `score()` 中按（钩子，架构，效果）求差、按 Fixes 反查对位的那段逻辑，缓存用 CTX3（第三版） |

对位规则沿用各引擎自己那一轮的写法（前 4 个引擎含 WT 的 `A|arg:` 特例；CTX 含 Fixes 反查）。

## 三、统一输出

- **每条候选**：检查类、引擎、文件、函数、行号、签名。
- **每个提交**：三类检查各自的状态（每个引擎是 ok / skip / error / 未评估）、是否报出、是否对位；以及三类合起来的结果。
- **汇总**：每类检查、每个引擎、三类合计，各自的正样本报出数、对位数和负样本误报数。留出集再单独给出干净子集（去掉 `cmtlb.TAINTED` 的 5 个）。

## 四、验收（参考线：不一致 0 处）

在开发集和留出集的每个提交上，逐个引擎对比本层算出的结果和那一轮存下的结果：
- 前 4 个引擎：`commitmode_20261117/results.json`、`heldout_commit_20261117/results.json`。比较每个引擎有没有新候选、新候选个数、是否在对位命中里出现。
- TLB：`commitmode_tlb_20261117/results.json`，比较状态、是否报出、是否对位。
- CTX：`ctxeff3_20261118/heldout_eval.json`（只有留出集），比较状态、是否报出、是否对位。
- WK：`weakov2_20261118/cm_results.json`，比较状态、新候选个数、是否对位。
- XA：`xvatom2_20261119/cm_results.json`，比较状态、新候选个数。

**CTX 在开发集上从来没评过**，本层标为“未评估”，不计入验收；要补跑另说。
