# N2.22：把配置下的真实作用效果接回自动检查

2026-10-22提出，尚未执行。N2.21到此停止，不再扩本例输入网格；R3继续单独暂缓。

## 目的

当前已经能由人工连接来源、范围和阶段，但自动分析尚不能把“调用了一个setter”可靠转换为“实际写入了某个状态”。下一项补这一个受限能力，使模型提出的检查候选可以获得程序层面的作用效果依据。它是N1的支撑组件开发，不是新的独立创新点或完整自动提契约。

## 最小闭环

1. 先核既有gimple_local_flow.py、gimple_cfg_facts.py和原始候选核对接口的支持范围，固定本次待核事实、输入、方法版本和停止条件。若已有能力足够直接复用，不为本例另造第二套语义核心。
2. 只复用N2.21已读setter、声明及必要观察包装，生成真实GCC预处理/GIMPLE。查询目标由研究者事前指定，区分可写变量、编译期常量、直接赋值和仅告警；明确这不是自动找到规范或发现查询目标。没有所需证据则返回不足，不能按函数名或架构名称猜效果。
3. 将受支持的直接写入事实连接到现有局部候选核对；保留原协议/原模型回答和旧不足。任何新增开发实现另存并记录版本，不回改冻结试验结果，不借手工字段声称自动推导成功。
4. 用固定的赋值分支、FORCE常量分支与NR_CPUS1分支检查区别，并加入少量与具体函数名无关的边界输入以检验支持范围。它们是开发/方法检查，不算独立正常样本、新案例或实际配置。执行前登记准确范围；不重跑N2.21的24条记录，不扩大平台/运行矩阵。
5. 分开报告：程序提取的事实、人工给定的查询/用途、模型建议和仍然不足的配置/同对象/阶段关系。若必须支持复杂别名、跨过程或完整内核，停止当前窄任务并记录缺口。

默认不取新内核材料、无项目付费模型调用、无完整内核构建或启动。不通过重复已读案例的模型请求来替代独立评价。

## 再后续的评价入口

该组件与条件抽取/匹配的适用域稳定后，先冻结方法，再固定带可核配置或合法输入依据、未用于方法开发的同用途正例和正常参照。来源/修复家族/接触史必须登记；源码条件保证、合法非空实例和实际运行分层，不要求完整机器所有功能正确，也不能将未见故障当正常。材料不足保留分母与不足，不无限扩同例、不补换凑数。

随后在相同材料和预算下比较直接模型判断与契约检查，报告未知、人工介入、漏报/误报和真正可执行的检查。N2.20原门控不足保持原样；N2.21的三组差异及人工关系不列入独立检出成绩。
