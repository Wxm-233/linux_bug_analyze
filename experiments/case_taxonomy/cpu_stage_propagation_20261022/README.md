# N2.21：早期来源判断到公共范围的配置／阶段传播

2026-10-22。用户恢复后，完成预登记的8次宿主局部构建和12条件×父版／修复版共24条记录。全部首次成功，未重跑。**这是已读平台模式案例的源码片段实验，不是24个案例或真实Xen内核复现。**

## 要回答什么

同一公共CPU范围为何被某种平台来源判断提前缩小？后面已经有Xen例外，为何仍可能来不及？同名setter在不同编译条件下是否真的改写范围？

沿用N2.20的x86/Xen历史候选，父版`0af2f6be1b4281385b618cb86ad946eded089ac8`，修复`8b37357a78d7fa13d88ea822b35b40137da1c85e`。只新增修复版`arch/x86/kernel/acpi/boot.c`全文以提取真实修复函数，其他原文全部复用；没有补换正常参考或扩大LoongArch源码。

## 方法及证据层级

保留两版原`acpi_mps_check`，同父版早期限额、后期`restrict_to_up`、PV枚举和setter的逐字片段；按原setup调用区段和顺序手工接成有限驱动。源行号、摘要及原文见[source_fragments.json](source_fragments.json)。ACPI返回与setter仅增加观察包装，各调用原函数一次。

四组配置投影均定义LOCAL_APIC，分别为可赋值NR_CPUS=4、FORCE常量4、编译期常量1，以及编入MPPARSE的4。配置关闭时不定义宏。它们是明确的预处理分支投影，**未做真实Kconfig与完整内核编译，不认证实际平台组合合法可运行**。

APIC函数替身只保存boot调用和登记尝试，不实现接受、去重、映射或上线。仅PV DomU选择这个提供者；Dom0与native的真实枚举未纳入，不能据其记录报告正常CPU域。没有执行最终possible集合构造或公共SMP消费者。计数和范围结果仅到后续提供者／公共域输入边界。

执行前协议和关系见[protocol_pre.json](protocol_pre.json)、[method_pre.md](method_pre.md)及[前置复核](pre_execution_review.md)；[execution_pre.json](execution_pre.json)固定本轮11份执行输入。首次构建前修正了观察shim未使用警告和异常输出保存，原函数和矩阵未改。固定GCC13.3参数下8次构建无stderr，24次记录均exit0；[execution.json](execution.json)保留每次命令、原始stdout和观察，[analysis.json](analysis.json)为事前窄关系的程序比较。

## 主要结果

下表“范围”是早期限额后的`nr_cpu_ids`，“尝试”是PV普通登记调用次数；均为**父版→修复版**。后期结果0表示`restrict_to_up`返回false，并不意味着前面没发生范围丢失。

| 条件 | 范围 | 登记尝试 | 后期结果 | 有限结论 |
| --- | --- | --- | --- | --- |
| C01 PV DomU，ACPI关闭 | 1→4 | 1→4 | 0→0 | 晚期同样有例外，早期传播不同 |
| C02 PV DomU，ACPI noirq | 1→4 | 1→4 | 0→0 | 同上，另一输入触发条件 |
| C03 PV DomU，ACPI可用 | 4→4 | 4→4 | 0→0 | 此输入不暴露原失配 |
| C04 PV DomU，显式maxcpus=0 | 1→1 | 1→1 | 0→0 | 修复保留用户禁SMP限制 |
| C05 PV DomU，possible上限2 | 1→2 | 1→2 | 0→0 | 去除错误来源限制，仍保留数量上限 |
| C06 PV DomU，预先已有APIC禁用 | 1→1 | 1→1 | 0→0 | 修复不清除其他来源的标志 |
| C07 PV Dom0，ACPI关闭 | 1→1 | 未建模 | 1→1 | 只核本段不变性，不算正常完整路径 |
| C08 native，ACPI关闭 | 1→1 | 未建模 | 1→1 | 同上 |
| C09 FORCE常量4，PV DomU | 4→4 | 4→4 | 0→0 | 旧版请求1并告警，但常量未改写 |
| C10 编译期单CPU，PV DomU | 1→1 | 1→1 | 0→0 | 不应推导能恢复多CPU |
| C11 编入MPPARSE，PV DomU | 4→4 | 4→4 | 0→0 | 本段ACPI错误判断被编译条件排除 |
| C12 native，显式possible上限2 | 2→2 | 未建模 | 1→1 | 非PV提供者未建模；保留本段限制 |

七组适用的可赋值PV DomU输入中，研究者事前登记的局部范围关系在父版有三组不满足（C01、C02、C05），修复版均满足。**这是已知案例下人工窄关系的对照结果，不能换算为检测准确率或独立泛化成绩。**

两种简化判断均不够：只看晚期例外，区分不了C01/C02/C05的传播差别；将所有PV免除一切限制，又会忽略C04/C05/C06的合法限制，也错误扩大到Dom0。C09另说明，“调用setter”不能直接当“状态已经变化”。

## 对研究主线的作用与边界

本例强化了一个带平台条件的共性机制：**某条信息来源不可用，不等于所有提供者都不可用；如果据此提前收窄共享范围，后面的替代来源可能已经被同一范围限制。** 这交叉涉及能力来源、参数范围和准备阶段，不新增一类互斥Pattern，也不能把同ISA平台模式差异写成已证跨ISA结果。

据此，检查候选需要连接来源适用范围、限制的真实写入效果、后续提供者读取的上界，以及生效先后；还要保留用户或其他来源的合法限制。当前关系、阶段连接和替身均由研究者准备，未实现模型自动提取或完整检测。独立审阅结论见[post_execution_review.md](post_execution_review.md)。
