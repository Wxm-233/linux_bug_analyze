## 事后发现：一个新疑点（只记录，不上报）

反例N_046（`arch/riscv/kernel/smp.c:smp_send_stop`）被三次标记：Sonnet V1、DeepSeek V0、DeepSeek V1。
- **arm64的修复**：arm64在2020年修过同一个问题（`d0bab0c39e32`）。当前CPU在上线过程中panic时，它本身还不算在线，`num_online_cpus() > 1`会少算一个，结果可能不去停止唯一的另一个CPU。arm64改为“除自己以外的在线CPU数”。
- **RISC-V的现状**：直到终点版本`df2908090cda`仍是`num_online_cpus() > 1`。
- **定性**：这属于M8（落后于参照的演进）的形态。没有运行验证，只记为新疑点。

## 事后分析（只作描述）

1. **换强模型没有让它“说中”更多，只是让它更谨慎。** Sonnet把DeepSeek的大部分误判，比如零扩展、`__kprobes`，都避开了，但同样没能说中需要函数外上下文的缺陷，比如早期启动不能拿锁、完全有序、开中断。
2. **V1的问法对两个模型都起了反作用。** “必须引用证据，否则算不确定”的要求，加上大量无关差异，使强模型几乎全部给0分或1分。逐条记账的做法，在差异列表质量不高时会把信号稀释掉。
3. **说中的缺陷有共同点。** 两个模型合计说中的A301、A328、A379、A392、A398，问题都在函数内部、看代码就能发现：保存顺序、`__pa`用错、上界差一、少排除一个区域。需要知道函数之外规则的，两个模型都没说中。
4. **由此看到的方向**：
   - 给模型的材料应当包括“这个函数在什么上下文中运行、要遵守哪些约定”的事实，例如是否在关中断或早期启动时被调用、原子操作的内存序要求，而不是更多的代码差异；
   - 这类上下文事实适合由程序预先算出（M5扫描就是一例）。

## 结论

- 按判据，**Sonnet没有让“位置给对时的判断”变得可行**，说中的条数没有比DeepSeek多；主要瓶颈在材料和问法。
- Sonnet的价值在于**误报少**：V0在50个反例中只误报1个。如果以后能把“需要什么上下文”这个问题解决，它适合用在最后的复核环节。
- 下一步的选项（未执行）：

  - 等GPT复核结果回来，再确认“一致”的条数。
