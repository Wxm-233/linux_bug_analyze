**做法**：用 df2908090cda 上第一、二、三、五、六轮的产物作为**替代**。这些产物是函数表、边界边、跨层资源、架构常量和常量性质。

这只是粗估，不是正式召回，因为：
- 用的是修复后的版本，不是父版本；
- 修复函数可能已改名或改了内容，df 里没有的就记“df 中不存在”。

每个样本只取它最好的一个修复函数，按逐级条件归到第一个不满足的那一级：

| 级 | 条件 | 不满足时的结论 |
|---|---|---|
| L0 | 修复函数在 df 的函数表里，且被三个构建之一编入 | df 中不存在 / 三个构建都没编入 |
| L1 | 文件在本框架范围内（mm/*.c、fs/proc/task_mmu.c） | 超出范围 |
| L2 | 函数是边界函数：第一轮的第 ① 类（直接调用架构层，含经宏），或第五轮的常量边界 | 不在边界上 |
| L3 | 第二、五轮在这个函数里提取到了跨层资源（调用点资源或架构常量） | 是边界，但没提取到资源 |
| L4 | df 整版扫描表中，这个函数里已有候选（任一引擎） | 有资源，没有候选 |

L4 满足的，记“能定位到”。

另外，我按已经读过的修复补丁，为每个样本写一句“要查出它，需要什么资源、什么性质”，并对照“常见资源”的分类，以及第二、五、六轮是否提取到了这种资源（人工判断，只作说明，不计分）。
