# 判据修订 1：跟踪字段访问路径（linmap_20261119）

2026-11-19，Claude。**写于看到开发样本结果之后**：btf 修复前报出、修复后不报，符合预期；zswap 修复前没有报出。

## 原因

zswap 的链路是 `zpool_map_handle` → `->map` → `zs_zpool_map` → `zs_map_object`。在 `zs_map_object` 里：

```c
area->vm_addr = kmap_atomic(page);
ret = area->vm_addr + off;
...
return ret;
```

kmap 的结果先存进结构体字段，再从字段取出来。判据第二节第 2 点只跟踪“局部变量”，所以 `zs_map_object` 没被认成来源函数，链路在这里断了。

## 修改

判据第二节第 2、4 点里的“局部变量”，扩为“同一函数内的访问路径”：局部变量，或者由它出发经 `->字段`、`.字段` 组成的路径（如 `area->vm_addr`）。

- 赋值给这样的路径，和赋值给局部变量一样处理：映射来源就标记，否则在同一层或更外层重新赋值时撤销标记；
- 接收者的参数、`return` 的值，如果是这样的路径（或路径加偏移），同样按标记判断；
- 守卫：路径出现在守卫函数的参数里，就不报。

其余规则不变。

## 说明

这条修改是看着 zswap 写的，所以 zswap 在修订后报出，只算开发样本，不算独立结果。自测会补一个字段路径的样例。
