# 判据修订 1：函数级候选按函数挂接；常量只看函数体内、排除属性宏（xconst_20261124）

2026-11-24，Claude。**写于第一次运行看到结果之后**（如实说明），G2 抽查之前。G1 的门槛（47 行中 ≥ 43 行）不改。第一次运行结果保留为 `result_run1.json`、`logs/run_run1.log`。

**第一次运行**：G1 只有个位数通过。原因有两个：
1. **ORD 的候选是函数级的**：它的“行”是函数体开头的 `{`（`orddom.py` 记的是 `line0`），不是常量展开的那一行，所以按“同一行”挂接必然挂不上。判据第三节的挂接方法对这类候选写错了。
2. **常量排行第一的是 `inline`（417 次）**：它是函数声明头部的属性宏（`#define inline inline __gnu_inline … notrace`），经 `notrace` 追到了架构相关配置项，被误当成了架构常量。

**修订**：
1. **挂接**：候选所在行如果是函数体开头（源码那一行去掉空白后只剩 `{`），就按函数匹配——该函数里有架构常量的，挂接记为“同函数（常量）”，并列出常量名和来源链。G1 计数时，“同行”“同行（常量）”“同函数（常量）”都算挂上，名字要求不变（挂上的常量里要有该行“特征”列出的名字）。
2. **常量只看函数体内**：宏展开的位置必须在函数体的 `{` 之后。另外排除宏体为空的宏，以及宏体第一个记号是 `__attribute__`/`__attribute` 的宏。

其余不变，重跑后按 G1、G2 判定。
