# 判据修订 4：补跑 B、C 两格的有效运行（运行之前写下）

2026-11-18，Claude。用户：“补跑 C 格”。

**原因**：修订 3 那一轮（`runs/lk`）的告警次数与预测全部一致：A 3/3，B 0/3，C 0/3。但按判据“每格都要是有效运行”的严格口径，C 格 0/3 有效，B 格 2/3 有效，都是因为开了 lockdep 后运行慢，再加上 IMSIC 环境 stall 而超时。A 格 3/3 有效，不需要补跑。

**做法**：
- 内核和机器参数与修订 3 相同：riscv `dpalk`（B 格加 F8），`-M virt,aia=aplic-imsic -accel tcg,thread=single -smp 4 -m 2G`；B 为 `debug_pagealloc=on`，C 为 `off`。
- B、C 两格同时进行；每格内部一次只跑一个，超时 1500 秒。
- 每格**一次接一次地运行，累计 3 次有效运行就停**，最多尝试 6 次。结果记为 `runs/lk2/<格>.run<i>.log`。
- **有效运行**的定义同修订 1：出现 `@@END`；或出现 `reboot: Power down` 且至少 3 行 `@@WORKER`；或者命中。

**最终判定**：
- A 用 `runs/lk` 的结果，B、C 用 `runs/lk2` 的**全部尝试**（无效运行也计入命中统计）。
- 需要同时满足：A 3/3 命中；B、C 的全部尝试里都是 0 次命中，并且各自有 3 次有效运行。满足就判这个疑点为**确认**。
- 某一格尝试满 6 次仍凑不够 3 次有效运行：判为“环境不支持”，不写“确认”。
- B 或 C 只要出现一次命中：判为**预测不符**，如实报告。
