## 冻结后发现并记录的缺陷（不回填）

- 执行器：追踪全部失败被记为“无实例”（s06、s08、s10、c10；s01只有1/3追踪成功）。
- 执行器：多消费者文件的提交按构建全有或全无，一个文件在某架构编不过即该上下文全部事实不可得（c01、c05：14/14构建）。
- 选样规则：S-F1.1未排除include guard（s01、s09）；`tools/`与selftests下的`.c`被当作内核消费者（s03、s06、s07、s10）。

## 结论

- 按diff形态抽样确实带来了主题相关的样本（3/10，阶段1为0/10），但E4两类模板仍为零命中，并漏掉了唯一的真修复s04。
- 主要差距：（1）模板太窄——从die、shmem提炼的F1b（只认`##`拼接）与F2覆盖不到`__HAVE_ARCH_*`/`ARCH_HAS_*`类特性宏、直接使用的回退宏；（2）选样规则太宽——工具代码与include guard占了大半；（3）执行器的两处缺陷让部分样本不可判。
- 阶段B（后10个样本）若用同一冻结方法，大概率得到同样结论。更有价值的是先登记新方法版本（例如F3“架构特性宏门控的提供者”、恢复直接使用并控噪、修执行器两处缺陷、选样排除tools/与include guard），用die/shmem/s04作回归，再在仍未接触的阶段B上评价。
