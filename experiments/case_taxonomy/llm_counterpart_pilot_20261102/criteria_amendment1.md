# 判据修订1：第二步改为分解式（任何模型调用之前写定）

## 为什么改

原第二步把检索到的RISC-V代码整段交给模型、一次判断完。这样：
- 结果好坏无法归因到具体环节；
- 对应位置只靠标识符检索，仍会遇到上一轮的瓶颈（参照修复常在名字不同的函数里）；
- 没有用上项目已有的工具（路径条件库、约定级列点、机制三要素）。

按用户决定，把第二步拆成“模型拆参照—程序找位置—程序列事实—模型做窄判断”。第一步（筛选）、参照提交窗口、模型与运行参数、评估中的命中定义和对照方法都不变。

## 新的第二步（替代原判据第二节“第二步”）

进入第二步的参照提交超过200条时，用`random.Random(20261104)`抽200条（与原判据相同）。每条参照提交依次：

**2a 拆解参照修复（模型，1次调用）**
- 输入：参照提交的说明和改动（最多300行）；机制目录第二版。
- 输出JSON：
  ```
  {"condition": "在什么条件下出了错（一句话）",
   "guarantee": "修复补上的保证是什么（一句话）",
   "kind": "check|order|barrier|atomic|context|width|lifetime|config|other",
   "hooks": ["公共代码调用、各架构各自实现的函数名，或公共代码中的函数名"],
   "mechanism": "M1–M10之一"}
  ```

**2b 按约定找RISC-V的对应位置（程序，不调用模型）**

在参照提交日期之前的最后一个版本上，按下列三条路线收集RISC-V候选函数，每个候选记下来自哪条路线：
1. **同一钩子**：2a给出的`hooks`和参照改动所在的函数名，在`arch/riscv/`中有同名定义的。
2. **同一调用者**：对参照改动所在的函数和`hooks`中的名字，在公共代码（`arch/`以外的`.c`）中找调用它们的函数（每个名字最多5个调用者）；再看这些调用者的函数体里调用了哪些在`arch/riscv/`中有定义的函数。
3. **标识符检索**（后备）：与原判据相同，从参照改动的行和函数名中取前15个标识符，在`arch/riscv/`（`.c`、`.h`、`.S`）中`git grep -w`，取命中所在的函数。

合并去重，按路线1、2、3的顺序取前6个候选函数，代码合计不超过400行；另附命中的文件和行列表（最多30行）。没有任何候选的，不进入2d，记为“未找到对应位置”。

**2c 列出结构化事实（程序，不调用模型）**

对每个候选函数，用路径条件库（`linux_bug_analyze/path_conditions.py`）列出：
- 函数内每个调用及其所在的路径条件（含提前返回带来的反向条件），最多40条；
- 关中断区间（`local_irq_disable/save`到对应的`enable/restore`）内的调用。

**2d 窄判断（模型，1次调用）**
- 输入：2a的`condition`、`guarantee`、`kind`；参照改动（最多120行）；每个候选函数的代码（带行号）、来自哪条路线、2c的事实。
- 问题：对每个候选，(1) 条件C在这里是否适用；(2) 若适用，这里有没有提供保证G。必须引用候选函数中的行号。可以另外指出候选以外可能的位置，但单独记录。
- 输出JSON：
  ```
  {"verdicts": [{"candidate": "文件:函数", "applies": "yes|no|unsure",
                 "guarantee_provided": "yes|no|unsure", "lines": [行号], "why": "一句话"}],
   "elsewhere": "候选以外可能的位置，或空"}
  ```
- **标记**：某候选`applies`为`yes`、`guarantee_provided`为`no`，且`lines`中至少有一个行号落在该候选函数之内。程序检查行号；引不出有效行号的不算标记。`elsewhere`中的位置不算标记，只记录。

调用量上限：第一步905次 + 第二步200×2 = 400次，合计约1300次。运行前须经用户同意。

## 评估的补充（在原判据第三节之上增加）

1. **分步统计**：2a输出完整（各字段非空）的比例；2b找到候选的比例，以及各路线贡献的候选数；2d中`applies=yes`的比例和标记数。
2. **定位查全**：对2025-01-01之后修复的测试集正例，看是否存在早于修复的参照提交，其2b候选中包含该修复改动的文件和函数（不论2d怎样判断）。分别报告由路线1、2、3找到的条数。这一项衡量“按约定找位置”这一步本身。
3. 原判据的命中、事后验证、对照（改为：2b候选中未被标记者）、人工核对、F1对照方法，均按新的标记定义计算。

## 不变的部分

参照窗口W、P1/P2定义、第一步提示词与判定、模型与运行参数、正例定义、严格与宽松命中、参考线、威胁与限制、不做的事，均与原判据相同。
