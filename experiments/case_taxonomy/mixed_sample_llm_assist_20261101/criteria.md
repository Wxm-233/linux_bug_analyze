# 混合样本上的分类效果：规则、模型、规则加模型（判据，实现前写定）

## 这一轮要回答什么

用户建议：把有bug和没有bug的函数混在一起，用自动检查去分类，看效果；并认为写死的规则判断不了全部bug，必须加入大模型辅助判断。本轮比较三种做法：

| 做法 | 内容 |
| --- | --- |
| R 只用规则 | `mech_state_size_checker_20261101/checker.py`。函数中有强或弱标记，判为有bug；否则判为无bug |
| L 只用模型 | 给模型函数代码及同文件被调函数，要求判断有无bug，并引用行号 |
| RL 规则加模型 | 在L的输入上，再加机制目录（`catalog.md`）和这个函数的规则检查结果，其余要求与L完全相同 |

L和RL的输入只差机制目录和规则结果，判断门槛的措辞一致。这样两者的差别可以归到这两样东西上。

模型：DeepSeek-V4.1-Flash-1017，配置档`deepseek-v41-flash-1017-20261101`，经`模型调用测试/run_kimi_review.py`调用。每次调用独立，不自动重试，最多8路并行。

## 样本（机械抽取，`random.Random(20261101)`）

### 有bug（正样本），30个

- **来源**：`v6.6..df2908090cda`中带`Fixes:`、改动`arch/riscv/`的非合并提交。
- **条件**：
  - 修复只改动`arch/riscv/`下`.c`文件中的**恰好一个函数**，所有改动行都落在该函数内；
  - 改动行（删去与新增）合计不超过30行；
  - 该函数在修复前后都存在，修复前长度为5到200行；
  - 标题不匹配`build|compile|warning|typo|comment|Kconfig|dts|selftest|doc|spell`（不区分大小写）。
- **取样**：取父版本中的该函数。
- **分层**：提交日期在2026-03-01及以后的，最多取15个；其余从更早的提交中补足到30个。若总数不足30，就全取。

### 无bug（配对负样本），30个

同一函数**修复后**的版本，即修复提交中的该函数。已知局限：修复后的版本也可能还有别的问题。

### 无bug（普通负样本），30个

- **来源**：终点版本`arch/riscv/`下`.c`文件中，在`v6.6`和终点版本里文本完全相同的函数（两年多未改），长度8到150行。
- **取样**：优先从正样本所在的文件中随机抽取；不足30个时，从全部`arch/riscv`文件中补足。

### 特别样本（单独报告，不计入主指标）

- 终点版本RISC-V的`huge_pte_clear`：本项目已确认的缺陷，上游尚未修复，模型不可能见过修复；
- 打过`control.patch`之后的同一函数，作为它的配对。

这两条也是规则的开发数据，所以单独列出。

### 交给模型的内容

- 文件路径；
- 带行号的函数代码；
- 该函数直接调用的同文件函数的代码，最多6000字符，超出则截断并注明。

**不提供**：版本号、提交号、提交说明、日期。

## 输出格式与解析

模型须输出一个JSON对象：

```
{"verdict": "bug" | "no_bug", "confidence": 0到1, "lines": [行号], "mechanism": "M编号或none", "requirement": "被违反的要求", "reason": "简述"}
```

`mechanism`字段只在RL中有意义；L中也保留这个字段，可以填`none`。

**解析**：取`final.md`中第一个能解析的JSON对象。解析失败、或调用不完整的，记为“无结果”，按无bug计入，并另行报告个数。

**引用核对**：
- 判为有bug却没有引用任何有效行号（不在所给函数的行号范围内），另计为“无依据的有bug”，并报告个数；
- 主指标按模型原样的判定计算；另报一版把“无依据的有bug”改判为无bug之后的指标。

## 指标

1. **主指标**：在全部90个样本上，计算每种做法的查准率、查全率、F1。
2. **配对区分率**：30对中，“修复前判有bug，并且修复后判无bug”的对数比例。
3. **对普通负样本的误报率**。
4. **定位命中**：被判为有bug的正样本中，引用行号与修复所改行（在父版本中的行号）相差不超过2行的比例。
5. **新旧分组**：正样本及其配对按提交日期是否在2026-03-01之后分组，分别报告L与RL的查全率和配对区分率，用来观察模型是否靠记忆。
6. **稳定性**：对RL随机抽20个样本（种子同上）各重复调用一次，报告两次判定一致的比例。

## 事先写定的判断标准

- **RL有增益**：RL的F1比L高至少0.10，**并且**配对区分率比L高。
- **RL无增益**：RL的F1不高于L。
- **介于两者之间**：分析原因。
- **只用规则**：预计查全率很低，因为它只覆盖一个机制。这是对照，不设通过标准。
- 新旧分组中，若L在旧样本上的查全率比新样本高0.25以上，记为“可能存在记忆效应”。

## 调用量

L 92次，RL 92次，稳定性20次，共204次，在用户授权的约200次范围内。不另做额外调用。

## 不做的事

不构建内核，不对外报告。模型判为有bug的普通负样本，若人工看来可能是真问题，只记录，不对外报告。
