# CPU拓扑接口判定方法与Btrfs机制比较

2026-10-26。范围为CPU-B的已读启动拓扑案例，不代表全部CPU接口。本轮重算既有检查流程并整理判定方法，无新模型、内核构建或启动，无独立样本。未实现统一入口。

## 消费用途与判定依据

公共调度器sched_core_lock遍历cpu_smt_mask(cpu)，逐项锁定cpu_rq(t)->__lock。研究者登记的条件性要求是：若这个循环承担当前目标运行队列的保护，且无其他已证明保护替代，则实际锁集合应覆盖应受保护的目标。用途和保护必要性是外部语义审核输入，不能由告警、修复标签或多数架构行为直接推出。

当前程序只检查更弱的命题：本次归档事件为目标逻辑CPU采样的mask是否包含该CPU。它不是“真实锁对象已受保护”的充分证明。原材料见../cpu_topology_chain_20261023/reviewed_chain.md，输入及代码SHA见inputs.json，归档全部身份核验由原驱动执行。

## 适用条件、提供者与阶段

支持域为父版88b604263f3d6eedae0b1c2c3bbd602d1e2e8775、修复版a052096bdd6809eeab809202726634d1ac975aa1的s390/x86四份已登记启动归档。目标是逻辑CPU1、公共调度启动阶段；共同配置包括SMP/SCHED_SMT/SCHED_CORE。s390为mode=1、facility=0、mtid=0，x86每CPU一线程；不能推广为真实SMT、热插拔或并发覆盖。

旧s390 cpu_thread_map先clear，以cpu_online(cpu)为接受资格，不接受则copy空集合；旧启动顺序在上线/update前notify。修复以cpu_setup_mask为资格，setup→update→notify→online。x86已有通知前准备流程。这说明“准备函数被调用”和“目标有资格被准备”是不同命题；提前调用旧update不能自动消除online资格门禁。

源码明确了资格和局部顺序，但不是完整提供者因果证明：此前写者、所有分支、原语效果、对象别名及无干扰条件仍须按具体范围核实。prepared=-1是未观测，不能当准备失败的实测布尔值。

## 关系及四层结果

令u为本次合法目标CPU，M(t)为相应拓扑集合，L(t)为实际被锁定对象集合。

| 层次 | 目标 | 当前结果 |
| --- | --- | --- |
| 来源资格 | 提供者接受u并实际完成目标集合准备 | 资格及局部顺序有源码；完整效果不足 |
| 采样成员 | u属于M(sample) | 旧s390不满足；其余三格满足 |
| 消费期限 | u属于M(first_content_read)，且必要窗口有效 | 四格均不足；前置快照不能自动代替遍历 |
| 保护用途 | 应受保护运行队列的实际锁对象属于L | 物理别名/目标绑定不足，不能据逻辑成员直接裁定 |

从用途关系到成员条件需要对象对应前提；成员关系、锁次数和最终online状态均不能单独证明完整保护。mask非空或weight>0也不是目标覆盖：集合可以含别的CPU却不含u。后续泛化应保留这一差别，而不是用“非空”替换成员关系。

## 观察限制及判定步骤

原观察源码kernel/sched/core.c:257–261先读mask/self/weight/rq_self/online，264才关本地IRQ，265–268遍历及加锁计数；解锁后打印的是先存值，多字段并非原子快照。rq_self只比较cpu_rq(cpu)->core与cpu_rq(cpu)，没有记录全部实际锁地址。因而日志出现位置不等于取值时间，锁次数也不证明目标物理别名。

1. 固定版本、配置、观察源码、构建与启动回执，核原件SHA及当前记录身份。
2. 外部审核用途、合法目标、来源资格及阶段；未知不得用profile名字或旧判定补齐。
3. 绑定CPU/current、事件、序号、读取表达式和样本值，再交既有核心判成员关系。
4. 单列精确消费、稳定窗口、物理锁对象及完整准备效果的证据；缺失则不足，不将sample改名为consumption。
5. 分轴比较同版跨架构与历史修复，不把最终成功状态当作早期关系真值。

复用候选包括：契约核心的类型与关系求值、证据身份、分层结论及缺证规则。迁移需要替换：提供者资格与原语摘要、CPU角色映射、阶段/事件注册、日志格式及构建绑定、物理锁关系。不得扩充profile名字后就称通用检查器。人工分钟数及跨案例改动行数没有测量，本轮不虚报适配成本。

## 与Btrfs的比较：服务最终统一目标

| 项目 | CPU拓扑 | Btrfs |
| --- | --- | --- |
| 提供内容 | 拓扑集合及目标覆盖 | 文件系统几何缓存 |
| 资格/适用条件 | online/setup、合法CPU及调度用途 | 合法几何/挂载用途，inline另有路径门禁 |
| 消费关系 | 成员覆盖，进一步关联实际锁对象 | min裁剪及权威参考，进一步关联文件布局 |
| 容易误用的证据 | 最终集合、非空、调用在前、预读样本 | 小请求结果相同、后采样几何、写入成功 |
| 关键缺口 | 精确读、稳定窗口、实际锁别名、完整准备效果 | 同对象同消费期限参考、完整用途条件 |
| 对照作用 | 同版架构差异与修复版本轴分离 | 页/扇区配置差异与修复版本轴分离 |
| 共享候选 | 身份/用途/阶段登记、关系与证据分层、拒绝证据升级 | 同左 |
| 不能硬统一的语义 | 集合成员、资格效果及别名 | 数值边界、裁剪敏感性及布局门禁 |

这支持将统一入口、契约表示和证据流程作为长期方向；尚未证明同一自动提取算法能处理两类接口。本轮没有将Btrfs新事件核验模块强行接入CPU，也没有实现通用因果/别名分析。
