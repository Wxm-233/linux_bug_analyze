## 对研究主线的具体补充

公共调度代码按层消费架构给出的CPU集合；ARM64公共拓扑的cluster/package/NUMA来源，与x86缓存共享集合的来源不同。相同名称不保证同一层级语义。检查应核对实际选表、同一CPU、同一有效cpu_map下的相邻消费者视图，而不能要求两架构输出集合逐字相同。

D父版已有`tl->mask`内容读取、与cpu_map求交、子父span包含检查/修补、同层互斥检查和退化层清理。因此，本项目的待证贡献是从架构条件推导并绑定可检查的要求、选择有效对照，不能把已有内核检查重新命名为新机制。

这次还得到一条重要边界：**准备得足够早，并不意味着准备的集合范围或层级一定正确。** D主要是空间/层级关系，不能硬归入首次消费前准备。原来四类Pattern继续作可重叠索引，不是四条互斥且穷尽的检测规则。

另一个边界是契约的版本性。父版在特定条件下允许扩MC后删MC；子补丁改为相等时保留MC、删CLS。不能把新策略当旧版既有义务，也不能把每种保层策略差异都判成错误。
