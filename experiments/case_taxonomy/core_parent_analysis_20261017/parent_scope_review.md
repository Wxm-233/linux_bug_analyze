# N1.4h 父版材料作用域与完整度复核

研究侧独立材料盘点；仅阅读本轮登记协议、文件表及父版源码，未读子提交说明、补丁或模型回答。C 为父版 `5107e3ebb868d99872e1b64b054ccfcdad79d5d7` 的5份文件；D 为父版 `26a2b73a7b15a51ec1409648c9b43882f66fbacf` 的4份初始文件与3份已登记补源，共7份。本记录不是模型输出，也不裁定新缺陷。

## C：公共 CPU 启动入口，完整契约资格仍不足

- **公共用途与提供者**：`kernel/smp.c:897–929` 的 `nosmp`、`maxcpus` 早期参数入口，在禁用 SMP 时调用 `arch_disable_smp_support`；同文件895行为弱默认实现，`arch/x86/kernel/smpboot.c:1271–1277` 给出 x86 实现，继续调用未展开的 `disable_ioapic_support`。`include/linux/smp.h:277–281` 的接口说明亦把该钩子限定到上述参数用途。不能把它与同源文件中独立的 `disable_smp` 混为一条路径。
- **实际公共消费链**：`kernel/smp.c:943–963` 的 `smp_init` 调用 `bringup_nonboot_cpus(setup_max_cpus)`；`kernel/cpu.c:1505–1515` 遍历 present CPU、受在线数量上限约束并调用 `cpu_up`。后者在1419–1451检查 possible、节点、热插拔禁用和 SMT 条件，再进入 CPUHP；589–612的 `bringup_cpu` 调用架构边界 `__cpu_up` 并等待 AP。x86 的 `native_cpu_up` 位于 `smpboot.c:1196–1269`，但本包没有将这个实现与 `__cpu_up` 的有效选择闭合。
- **条件、对象与首次内容读**：能识别 `setup_max_cpus`、目标 CPU 以及每 CPU 的热插拔状态；能定位早期参数、启动流程和部分配置分支。没有实际 `.config`、预处理/最终绑定、所有调用者或 init 段回收边界。接口/函数上的 `__init` 字样不等于已经证明函数何时可用，也不能据候选标题把它标为正常。钩子的实际效果、其结果由谁首次依赖读取，以及是否存在跨阶段使用，目前未闭合。

**决定**：材料足以登记局部接口与调用作用域，但不足以确认本轮 N1 关注的“架构提供者效果—同一对象—首次依赖读取”的完整契约。建议 C 直接保存资格不足，本轮跳过付费父版分析；不为跑满两项继续补 helper、节回收或另一架构。

## D：公共拓扑空间约束，可做有界开发审查

- **公共用途与对象**：`include/linux/arch_topology.h:66–94` 定义每 CPU 拓扑 ID 与 sibling 掩码，并在 `CONFIG_GENERIC_ARCH_TOPOLOGY` 下给出取值接口。`drivers/base/arch_topology.c:657–725` 提供 `cpu_topology[]`、MC/CLS 掩码 getter 及 sibling 写入。返回指针本身不是内容已被消费的证明。
- **实际消费者和可见要求**：`kernel/sched/topology.c:1654–1668` 的默认层次表在配置启用时引用 CLS、MC getter；1540–1597的 `sd_init` 对 `tl->mask(cpu)` 求权重，并将其与 `cpu_map` 求交生成 domain span。2177–2205要求子 domain span 为父 span 的子集，否则告警并合并修正；2211–2241另要求同层非重叠拓扑的掩码相等或不交。两项要求不同，不能把原始 getter 掩码直接等同于求交后的 span，也不能无条件要求所有原始相邻掩码嵌套。
- **架构提供差异**：ARM64 头17行引入公共实现，Kconfig123选择 `GENERIC_ARCH_TOPOLOGY`；1202–1223提供 MC/CLS/SMT 选项，327–328规定 SMP。公共 `cpu_coregroup_mask` 在 `arch_topology.c:660–685` 结合节点、core/LLC 和 cluster 条件选择范围，CLS getter687–690返回 cluster 范围。相同父版 x86 `smpboot.c:688–696` 的 MC/CLS 分别返回 LLC/L2 掩码；537–599给出条件层次表，1366–1396安装默认表并准备 sibling，1480–1490还可按硬件条件替换表。因此存在可审查的不同提供逻辑与同用途公共消费边界，但没有证明任一实际机器的几何关系违法。
- **关键缺口和首次读边界**：未取得实际配置、预处理后的接口选择、ARM64 ID/cluster 的实际填充调用链、硬件/固件拓扑值、所选最终层次表及具体 `cpu_map`。`set_sched_topology` 可在初始化前替换默认表（调度源码1677–1684），故默认表不能充当所有架构的实际表。已看到真实掩码内容读，但前置分配/检查也可能读取；不得把 `sd_init:1556` 宣称为全流程首次读取。当前更贴近**空间范围/层级一致性契约**，不应强行归为首次使用前准备问题。

**决定**：D 足以提出有原文依据的局部、带条件空间契约候选，适合一次有界父版主模型审查；不足以确认完整跨架构违约或哪个架构必然暴露。禁止模型仅凭不同实现、选项存在或函数命名推出缺陷；缺失配置、对象关联或具体条件应明确保留未知。本轮补源已到此结束，不递归展开 getter helper 或固件解析。

## 计数与评价边界

D 的同名 `cpu_clustergroup_mask` 已在旧案例完整源中接触过；版本和函数体不同不恢复独立性。本轮 D 仅计源码已接触的契约资格/开发审查，不能进入独立验证分母。C 不足不等于正常，D 可分析不等于阳性；本轮不新增确认缺陷、实际运行或独立正/正常案例，独立分母仍为0/0。后续模型回答须先保存，再与另行解封的历史资料比较；本盘点不提供修复标签或人工正确答案给模型。
