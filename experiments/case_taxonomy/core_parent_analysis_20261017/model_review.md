# Opus父版分析的语义核对

主模型：Windows原生Claude Code 2.1.301＋AWS-Claude-Opus-5.5。D单次客户端任务完整返回，357.062秒、final 13344字符、exit0、end_turn、无观察到refusal；客户端可见294494 token，保守记账取294494，二者不相加。CLI内部恢复及实际计费未独立观测，不能据一次完整返回宣称长期稳定。C因材料资格不足而跳过调用，不算交付失败。

完整D父版包7文件、274129 UTF-8字节，含研究者选文件和研究用途，未给子提交标题/补丁/说明或旧筛选答案。原final保存在仓库外层已忽略的`模型调用测试/2026-10-17/core_parent_D/`；未修改或重试以取得特定结论。读取修复的次序由`repair_material.json`记录；oracle角色未看该回答。

| 模型内容 | 源码核对与采用范围 |
| --- | --- |
| 找到公共调度表、`tl->mask`内容读取、`cpu_map`求交、相邻span包含和同层相等/不相交检查 | 父版有直接支持；1556的weight读取与1596的求交分开。这些位置并不自动证明是全局首次实际读。内核已有检查/修补，不能当本项目新发明。 |
| 给出ARM64公共字段映射与x86缓存mask来源不同，拒绝把x86直接当正常基线 | 有限材料支持比较动机。x86实际选表、有效配置及物理mask关系未验证，正常/暴露均不能外推。RISC-V绑定未提供，不能仅靠公共文件中的ifdef确认其完整链。 |
| 主要强调DT未写cluster_id、局部core_id及package常量的额外唯一性风险 | 文件内赋值/比较有依据，但缺少store_cpu_topology、实际固件和有效路径。它不是所选D补丁证明的故障；不新增缺陷、不按模型建议扩大DT/ACPI启动矩阵。 |
| 认为节点/cluster范围失配可违反CLS⊆MC | 只能条件式保留：必须考虑`cpu_coregroup_mask`的cluster扩展。节点mask若本身包含于cluster，680–682会把MC扩成cluster；“cluster跨节点”本身不足以推出违约。实际选层、两mask与同一cpu_map求交及部分交叠才是具体核对对象。 |
| 建议在提供者处检查一条原始SMT⊆CLS⊆MC⊆DIE链 | 不能直接升级为强制规则。应限制到实际启用/选中的相邻层和实际消费者视图；原始mask可比求交后span更强，可能误报隔离/分区情形。x86混合表等还可能省略层。 |
| 提出容量更新及cpufreq覆盖不完整的候选 | 仅额外有条件假说，未核实真实平台、完整更新路径和配置，不继续扩成第三实验。 |

模型没有把修复的“相等时保留MC、消除CLS”策略直接认作旧版规则，这是合理边界。oracle进一步说明父版675–682明确允许将MC扩为cluster再消除MC；子补丁改变了这个选择策略。需要区分弱的层级嵌套要求与版本特定的保层策略，不能仅照抄修复形状生成跨版本强制检查。

本轮获得的是一个带条件的空间层级契约候选，以及对模型过推的具体限制；不是首次准备机制的独立检出。D的同名源码此前已读，研究者也手工提供了材料范围。没有把人工预记录、后续oracle意见或修复信息回填到原始模型预测。
