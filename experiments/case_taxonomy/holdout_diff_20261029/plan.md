# 两个样本B3差异的原因分析：计划（分析前写定，2026-10-29）

按用户“查差异原因”实施。不调用模型。**这是事后的描述性分析**，用来解释`holdout_coverage_20261029/`中B3前20召回在P1′样本（52%，26/50）与留出样本（23%，5/22）之间的差距，不作为任何方法的检验。

用户已接受：读过之后，这22对转为已接触，不能再作留出样本。

## 顺序（避免标注受命中结果影响）

研究者至今只看过留出集的汇总计数，没有看过逐对命中。

1. **先盲核**：读留出22对的S与T（标题与`.c/.h`差异），按P1′盲核的同一标准标注：
   - `sibling`（是/部分/否）；
   - `seed_role`（修复/引入点）；
   - 一句机制说明。

   写入`audit_holdout22.json`并记SHA。这一步不看逐对命中。
2. **再算特征**：程序对两组（开发集50、留出22）逐对计算下列特征，与B3前20命中对照。
3. **最后合并**：盲核标签与命中对照；开发集只有前20对有盲核标签。

## 比较的特征（程序计算）

| 特征 | 含义 |
| --- | --- |
| `same_rel_target` | 是否有目标文件与S改动的某个`arch/X/<rel>`同相对路径（B3最直接的成立条件） |
| `same_dir_target` | 是否有目标文件与S改动文件同相对目录 |
| `same_name_target` | 是否有目标函数与S改动函数同名 |
| `b3_pool_empty` | B3候选池是否为空（没有同路径或同目录文件） |
| `b3_pool` | B3候选池大小 |
| `generic_ids` | 通用接口标识符个数 |
| `early` | T早于`v4.19` |
| `s_arches`、`t_target_arches` | S改动的架构数；目标所在的架构数 |
| `s_touches_common` | S是否也改了`arch/`之外的代码 |
| `targets` | 目标函数个数 |

## 输出

- `features.json`：每对的特征、B3命中与盲核标签，只含编号与布尔或数值，不含代码。
- README：两组各特征的分布，以及按特征分层后的B3命中率。

## 解读原则

- 如果某个特征在两组间分布差异大，并且在两组内部都与B3命中强相关（例如`same_rel_target`），就把差距主要归因于样本构成差异，并在论文中把B3的适用条件写清楚。
- 如果分层后同一层内两组的命中率仍有明显差距，就记为“未解释的差异”。
- 样本小，只作描述，不做显著性检验。
