## 一、引擎做了什么（全部自动）

| 步骤 | 程序 | 内容 |
|---|---|---|
| 发现 | `discover.py` → `names.json` | 从 `arch/*/include/asm/`（3394 个头文件）收集在 ≥2 个架构中各自定义的页表/交换项接口，加三个公共头文件里的公共内联函数，共 286 个；记下参数名和每个架构的定义位置 |
| 分类 | `classify.py` → `sigs_<构建>.json` | 每个构建上把每个接口套进约 26 种类型模板，一次批量试编译，按报错行判断签名：构造、观察、修改、编码、解码、交换构造、字段观察、保护常量 |
| 组合与求值 | `mine.py` → `beh_<构建>.json` | 交换族：交换构造 → 编码 → [0/1 个交换修改] → {有效/空判断、交换标志观察、解码 → 字段观察}；映射族：`pfn_T(pfn, 保护常量)` → [0/1 个修改] → 观察。各接口的包装函数在逐位求值器里串起来调用，参数取通用规则给出的合法域，得到每个组合的“行为”（恒 0、恒 1、等于某参数、只保留某参数的低 k 位、其他、不支持） |
| 多数表决 | `vote.py vote` → `laws.json`、`deviations.json` | 同一组合在 ≥3 个可比构建上有一种行为占多数，就是规律；与多数不同的构建是偏离 |
| 复现 | `vote.py repro` → `repro.json` | 截断偏离自动生成 C 表达式（输入取 2^k），clang 折叠验证读回值不等于输入 |
| 报告 | `vote.py report` → `report.json`、`g1.json`、`candidates.md` | 门槛检查、候选表 |

引擎内置的只有通用规则（判据第一节 + 修订）：接口命名空间、类型模板、参数域规则表（交换类型 `< MAX_SWAPFILES`；交换偏移 `[1, 2^min(32, 编码容量, 公共宽度))`；页帧号 `[0, 2^(MAX_PHYSMEM_BITS - PAGE_SHIFT))`，没有时退到 `phys_addr_t` 并记为回退域）。常量都由求值器在各构建上算出。

## 二、修订记录（每条都写于对应运行之前）

| 修订 | 起因 | 规则 |
|---|---|---|
| 1 | `make_writable_migration_entry(offset)` 参数名叫 offset，存的是页帧号 | 按构造结果的种类定域（类型字段随参数变 → 普通交换；常数且 ≥ MAX、`softleaf_has_pfn` 真 → 页帧号；否则域未知）；PMD/PUD 页帧号按大页对齐 |
| 2 | 组合语义 | 层级一致（`__` 开头为架构层）；交换族只用 `_swp_` 接口和有效/空判断；参数域再受公共层宽度限制；编码容量自动推出；包装函数串联求值；优先级规则 |
| 3 | 页表级数折叠的构建上同一接口通过多种级别 | 级别以名字里的 pte/pmd/pud 为准 |
| 4 | arm、ppc32、s390 的 `pte_t` 是整数，模板全部通过，组合爆炸到 35 万～68 万 | 自动识别弱类型构建（恰好识别出这 5 个），其签名取强类型构建的多数 |
| 5 | G1/G2 未过 | 截断须是确定的不同（未知位记“不精确”，**修正了我的判定错误**）；编码对在某构建上读不回类型即不可用、不参加表决（PMD 桩）；含 `pfn` 的观察只用于页帧号种类 |
| 6 | s390 软脏位被当偏离；mips32xpa 6 处对账不一致 | 对任意输入都原样返回的修改接口（空操作桩）不参加表决（实现时先用具体值判断，误伤太多，改为用全符号输入判断）；**求值器修正**：多字段结构体逐字段赋值、未写字段为未知，联合体（字段偏移全为 0）按单一存储处理（冻结的解释器不改，修正写在本目录的子类里） |

修订 5、6 里的两处求值器问题（截断判定、多字段/联合体）都是被 G2 的 clang 对账抓出来的；修正后重跑，207 条全部一致。求值器另在子类里补了 `switch`、`do … while (0)`、按输入域的区间比较、`lpa2_is_enabled` 运行时判断。

## 四、局限

- 映射族精度不够：`other` 占映射族偏离的一半，主要来自保护值里的全局量（如 x86 `__supported_pte_mask`）和条件不定时的分支合并；多数表决把“各架构合理的实现差异”（如 `pte_mkwrite` 是否顺带置脏）也报成偏离。
- 多数表决的前提是“多数架构是对的”。一个功能只有少数架构实现时（如 PMD softleaf 只有 5 个构建），修订 5、6 把桩和不可用的编码排除在外，才能形成规律。
- 求值用的是只生成头文件的变体，没有证明整机路径可达；回退域上的截断都需要人工/第二审查人判平台可达性（这一步和其他引擎一样，留在审查环节）。

## 第二轮后的更正（2026-11-22，ecscan_20261122）

- 第三节映射族 mips32xpa 那行：截断**不只在 `PAGE_KERNEL_NC` 下**。第二轮把“求值不精确”排除出表决后，4 个保护常量下都给出第 22 位截断。原因也不是“缓存属性位与页帧号字段重叠”，而是 XPA 的 `pfn_pte` 按 4K 页拆分（`pte_high` 存低 24 位、`pte_low` 存 `pfn >> 24`），XPA 又要求非 4K 页，16K 页时第 22～23 位丢失。盲审后判平台不可达（树内 XPA 平台没有 64GB 以上内存），详见 `ecscan_20261122/README.md` 第四节。
- 第三节 mips64 映射族那行：盲审判平台不可达。
