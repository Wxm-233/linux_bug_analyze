# 已读跨子系统事实—契约—消费审计判据

2026-10-03。本审计只读已锁定的两项开发材料，不重跑单版工具、编译、网格或模型，不新增病例。primary 限于 ocfs2 `di->i_flags` 读入掩码与 Raspberry Pi PoE PWM get_property 的 `reg` 写出；其他既有读取/赋值只作局部对照，不计独立样本。

1. **可复核事实。** 原始 JSON 必须能追溯到原工具 SHA、单一修订和源码 SHA。新事实表明确哪些项是原工具输出，哪些是人工附加。引用必须绑定同版本完整源码、文件哈希、准确行号及原文，不能仅凭函数/字段名字。
2. **契约权威。** ocfs2 同版本磁盘结构声明及明确 LE 格式说明属于内核源码表示契约；调用点与缓冲区解释属于本地消费证据。PWM 的 `__le32` 声明属于内核消息表示证据；`rpi_firmware_property`/property-list 的 raw copy、mailbox 等属于实际传输代码证据。后者不能替代独立固件协议规范、外部 ABI 或设备支持约定。没有外部规范输入则保持“未核对”。
3. **值源与消费。** 类型名只证明源码标注，不能证明真实 host-value 来源、实际数据流或设备可达。ocfs2 的磁盘缓冲到 dinode、掩码常量到布尔/返回结果，PWM 的调用端参数/常量到初始化、消息到 transport，均需人工逐站引用；人工链不标为自动数据流。
4. **局部正常。** zero/nonzero 只证明这一零测试对字节交换不变。同表示掩码只证明两个操作数在同一编码域进行位运算与布尔判断。显式转换只证明当前写法或读取有对应转换，不推导整个函数、文件、子系统安全，也不证明支持配置下运行正确。
5. **差异与判准。** 父版/修复版 raw counts、primary status、对照表达式须与保存源码一致；解释候选消失不能写成运行缺陷证实或泛化精度。结果允许阴性与不足。必须显式区分“位置已绑定”“表示契约人工已审”“消费人工已审”“外部规范未核对”“支持配置/物理执行未证”。
6. **限制与封存。** 保留语法、include、预处理、宏、别名、控制流和值源限制。原工具和旧产物保持原哈希，新输入在最终审计保存 SHA。checks 用布尔；无法审定的结论列 blocker，范围不足列 limit，不能用空 blocker 掩盖尚未证实的能力。
