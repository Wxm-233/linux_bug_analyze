# 判据修订 1（effdep_dev_20261113）

2026-11-13，Claude。分析脚本第一次在 A274、B485 和当前版本 riscv 上运行后（这三次的结果作废），发现四处实现与判据不符或抽取漏洞，修正如下。判据本身的定义、样本、参考线都不改。

1. **接口集合**：判据第五节写的是“由任一架构提供”的函数或宏。第一次运行误把边界清单中定义在 `include/asm-generic/` 的符号（如 `WARN_ON_ONCE`）也算进来（3500 个接口）。改为只取清单中 `definition_layer` 为 `arch` 的，加上“有通用默认实现且被某个架构覆盖”的。
2. **只有宏、没有函数实现的接口**：横向比对时记为“判断不了”（unknown），不记为“无效果”。
3. **形态合并**：同一位置的多个形态，第一次运行只保留得分最高的一个，导致 F1 计数为 0。改为保留全部形态，得分取最高。
4. **抽取漏洞**：返回值存进结构体字段或经指针写入（如 `state->flags |= arch_get_idle_state_flags(...)`），以及 `|=`、`&=`、`+=`、`-=`，第一次被记为“其他表达式”。改为记成“赋给左侧的基变量”（此例为 `state`），按 F2 处理。改动 `effdep_extract.py` 后，A274、B485、A025 和当前版本 riscv 重新抽取（A025 第一次抽取在修改前已开始）。

我看过的第一次结果只有三个汇总数和 B485 的一个命中（排名 6363，命中的接口是 `WARN_ON_ONCE`，正属于第 1 条的误收）。
