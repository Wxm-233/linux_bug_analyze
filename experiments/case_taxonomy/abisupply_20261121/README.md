## 看出的几点

1. **这一族在历史上就很少**：十年多只有 5 个根因，而且时间上不均匀，设计侧 4 个里 3 个集中在 2020 年。2020 年前后兼容层有一轮大清理（`compat_alloc_user_space` 被去掉，很多兼容入口合并进本机入口），R1、R3 都是这次合并漏了转换。这类缺陷更像一次性重构留下的，不是持续产生的。
2. **astra 选这一族的理由（两个宽度能独立读出来）仍然成立，但供给撑不起“写检查、做独立检验”**。即使写出检查，后期只有 1 个根因，无法检验它对没见过的缺陷有没有用。
3. **同族扩展（单个结构体布局）在设计侧有 11 个根因（13 个提交）**，比主族多得多，但晚期只有 1 个。按判据不能把它并进主族；即使并进去，晚期也只有 2 个根因，仍然不够。
4. **兼容层的修复大多是“缺了什么”**（缺 compat_ioctl、缺某个字段的转换、ioctl 号），不是“共享代码按错 ABI 读”。前者更像遗漏检查，静态上需要的约定输入又不一样。
