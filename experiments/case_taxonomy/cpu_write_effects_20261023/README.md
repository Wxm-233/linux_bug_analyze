## 本轮结果

复用N2.21已固定的`include/linux/cpumask.h:27–40`原文，仅改变三个事前指定的编译分支。三次预处理、三次宿主对象构建均首次成功；没有链接、执行C程序、重跑原24条矩阵或启动内核。

| 编译投影 | 预处理中的目标绑定 | 程序观察到目标直接赋值 | 候选核对 |
| --- | --- | --- | --- |
| NR_CPUS=4、非FORCE | `extern unsigned int nr_cpu_ids` | 原38行`nr_cpu_ids = nr`，1处 | 所选函数内存在直接赋值：observed |
| NR_CPUS=4、FORCE | 宏常量 | 0处；原36行只在替代诊断路径写观察计数器 | 无直接写入观测；不能升级为全局无副作用或已执行设置 |
| NR_CPUS=1 | 宏常量 | 0处；同上 | 同上 |

六项事前绑定/直接写参考核对全部吻合；三项“无条件写入”候选均保留不足。**六项是开发参考核对，不是六个案例或检测准确率。** 无直接写入行的源定位检查为空集合，不当作写入存在证据；采集器另核原函数的源坐标。

新增`linux_bug_analyze/gimple_write_effects.py`复用现有CFG和语句解析，提供精确函数/符号/SHA绑定、直接标量赋值观测和候选检查。条件赋值仍保留分支上下文；函数调用、同名局部/形参、指针、未知效果与无条件要求均不被升级为外部状态保证。相关三个测试模块最终43项通过，含新组件和语法支持的开发测试。

## 失败与有界修复

首次分析因真实dump含`__attribute__((always_inline))`而全部不足，主驱动在保存结果前断言停止；`analysis_initial_failure.json`明确记作同版本事后诊断重放，不冒充首次输出。随后只为真实出现的两个格式补支持：函数签名前精确always_inline属性，以及`[0:0]`人工位置。后者只保留为编译器词法信息，不充当真实源码锚点。未知属性、错误位置仍拒绝。

原解析器、属性修复中间版、原分析驱动、原manifest和原始dump均保留。新版本以`method_manifest_v2.json`冻结，`program_results_v2.json`是修复后的已读开发重放；未重编译，没有将修复后结果回填为首次成功。`parser_repair.json`和`parser_repair_artificial_locus.json`保存对应测试命令、原输出与SHA。

执行前另有两项操作停止：WSL服务在沙箱内访问被拒，后经工具审批恢复；一次调用在独立放行标记尚未完成时被门控拦住，尚未创建采集收据或启动GCC。这些不计编译重试。

## 证据与结论边界

- `protocol_pre.json`、`input_manifest.json`：研究者给定的原文、三个条件、查询及预期。
- `compiler_execution.json`和三profile目录：GCC命令、stderr、预处理、完整GIMPLE/CFG、唯一原函数记录及摘要。
- `method_manifest*.json`、`analysis_initial_failure.json`、`program_results_v2.json`：方法版本、首失败及新版本结果。
- `pre_execution_review.md`、`post_execution_review.md`：独立角色的有限源码/方法核对；不代表人类专家或独立样本评价。

目标函数/符号、配置选择和意义仍由研究者指定；预处理声明定位器只支持本轮有限拼写。WARN_ON使用可见计数替身，不证明历史诊断的全部效果；本轮不是完整Kconfig翻译单元。作用组件的外部对象绑定、真实运行可达和无条件写入证明仍为false。

本轮新增的是候选核对伴随组件，尚未自动接通旧模型协议或生产CLI，也没有完成从公共用途自动推出要求、跨过程实参绑定或首次消费证明。项目付费模型0请求/0token，新内核材料0，完整内核构建/启动0，新缺陷0；正式独立同机制正/同用途正常仍0/0。R3继续单独暂缓，Word/GitHub本轮不改。
