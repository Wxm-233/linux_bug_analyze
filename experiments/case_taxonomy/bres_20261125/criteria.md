## 一、相对分层（解决第九轮发现的“架构越多、公共层越小”）

第一轮的规则：只要代码受“只在部分架构上有”的条件控制，就算架构层（A1）。新规则把这类条件按**控制什么**分两种，按**来源**再分两种：

- **控制什么**：
  - “在不在”：条件包住了整个函数定义（文件级的 Makefile 条件，或者包住函数头的 `#if`）；
  - “体内不同”：条件在函数体里面，各构建编进去的函数体不一样。
- **来源**：
  - 架构相关的**配置项**，例如 `CONFIG_NUMA`、`CONFIG_SECRETMEM`；
  - **架构宏**，例如 `#ifndef ptep_get`、`__riscv`；也就是由架构头文件定义、用来替换通用实现的宏。

**标签**（在 arch/ 下的仍是 A0，没编入的仍是“未编入”）：

| 情况 | 标签 |
|---|---|
| 体内有架构相关的不同（配置项或架构宏都算） | 架构层 A1 |
| “在不在”由架构宏决定（通用默认实现，架构可以替换掉它） | 架构层 A1 |
| “在不在”只由架构相关配置项决定，体内没有架构相关的不同 | **公共层（部分架构）**（新） |
| “在不在”或体内的不同只由公共配置项决定 | 公共层-配置差异 |
| 没有任何不同 | 公共层 |
| 找不到条件 | 未归因 |

**“公共层（部分架构）”仍算公共层**。它对架构的调用仍算边界，只在编进它的那些构建之间比较。

实现方式：把第九轮的 `layer_n.py` 复制成 `layer_r.py`，只改分类和标签这两段，差异单独存档。其余部分（预处理记行、函数识别、边的识别）都不改。

## 二、边界记录和资源记录

对 5 个构建的**全部**编译单元（第一轮排除的 boot、purgatory、realmode、libstub、vdso 仍然排除），凡是有公共层函数定义的，都用 libclang 解析。解析参数用该构建的编译命令。

**边界记录**：公共函数 F 体内的每一处跨层依赖记一条，分五种：

| 种类 | 判定 |
|---|---|
| 调用 | 调用表达式，clang 解析出的被调函数**定义位置**在 arch/ 下，或者那个定义在新分层里是 A0/A1 |
| 宏 | 函数式宏展开，宏定义在 arch/ 下，或者那个宏在新分层里是 A0/A1 |
| 常量 | 对象式宏展开，沿定义链（最多 6 层）追到 arch/ 下的宏或架构相关配置项，规则同第五轮 |
| 布局 | `sizeof` 或 `offsetof` 作用在定义于 arch/ 下的类型上 |
| 包装一层 | 调用了公共层的 static inline 函数 W，而 W 体内直接调用了架构函数。记下 W 的形参到架构调用实参的对应关系（一层摘要） |

每条记录包含：版本、构建、该构建 `.config` 的 SHA256、编译单元、F（文件、名字、起始行）、行和列、种类、接口名、**这个构建里实际绑定到的定义**（文件:行）、绑定依据（clang 引用、宏定义位置、包装摘要）。

**资源记录**：挂在调用、宏、包装三种边界下面。沿用第二轮的分类（一～十）和来源判断，另外补充：

- **方向**：下行（实参）、上行（返回值、出参、G 读写的全局变量）；
- **出参**：G 的定义在本编译单元里可见时，看哪些指针形参被写入（`*p =`、`p->f =`），对应的实参记为出参；
- **返回值的去向**：赋给局部变量的，继续追这个变量在 F 里的后续使用（最多 6 处：条件、解引用、传给谁）；
- **守卫**：包住这处调用的 `if` 条件，以及同一个语句块里在它之前的提前返回（`if (...) return/goto/break/continue`）。只记条件里出现的变量；如果守卫里的变量在守卫之后、这处调用之前被重新赋值，就标“守卫之后被重新赋值”；
- **配置条件**：包住这一行的预处理条件（`#if`/`#ifdef`/`#ifndef` 的原文），供以后的动态验证任务单使用。
