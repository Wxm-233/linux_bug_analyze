# N2.14：条件公共要求与架构准备匹配

2026-10-19。本轮将N2.13公共控制事实与既有提供者条件效果接起来，回答“准备分支在什么前提下满足什么用途”。仍是同一项已读调度拓扑案例的开发分析，不新增独立Linux案例，不继续扩展CFG解析器。

## 本轮得到的三个条件要求

|要求候选|条件与最小强度|不应扩大的结论|
|---|---|---|
|目标锁覆盖|若该锁循环承担保护本次合法目标rq的用途，且没有其他已证明保护，锁集合应包含目标|这是研究者登记的用途前提；自身成员关系不等于完整SMT组、正确初始化或并发安全|
|搜索见证存在|若进入非单成员搜索，且本次用途要求获得合适见证再更新，需要一个实际遍历的非目标自指候选|不是所有成员在入口前均正确；允许的缺见证退出不自动等于实际错误|
|更新后关系检查|在实际到达的成员上，先做可选目标写入，再检查关系|不能将后置检查改成统一入口要求；仅有集合成员关系不能证明字段关系|

这些候选由助手源码复核登记，程序承担受支持的条件比较。用途、角色、API摘要与程序结构事实分别记录，不能称模型自动推导或专家金标准。详细依据见`source_review.md`，精确块/行引用保存在`matching_inputs.json`。

## 架构差异怎样进入公共用途

|架构来源|准备资格|准备与通知的局部顺序|目前能接通与不能接通的部分|
|---|---|---|---|
|旧s390|mapper按online资格过滤；updater将同一逻辑迭代目标的thread_mask交给mapper|本次notify在set_online和update之前|同配置字段/源和局部顺序可对应。若准备被资格拒绝且输出实际用于同目标，空组与目标覆盖、需要见证的用途不相容；不能由代码稍后设online便断言入口一定offline，也不能排除早先写入|
|修复s390|改用setup集合允许准备|setup→update→notify→online|自己的配置lock/getter和条件效果可对应；资格通过不等于准备已完成。没有本轮fixed CFG，搜索/检查要求不借旧CFG改标签迁移|
|x86|既有原始源码说明在通知前更新拓扑；本轮完整lock/getter属于其自身非观测配置|原始smp_callin中map早于notify|有来源/用途和局部意图，缺当前配置的同等级提供者效果；不把另一个带观察配置的值填入|

这解释了为何检查不能只找“更新语句是否在前”：还要检查更新是否接受当前阶段的目标、产生何种结果、结果是否用于同一对象并赶上实际内容消费。各层不能相互替代。本轮没有向新匹配器导入历史运行值；10/13的四格带观察运行仍是独立保存的历史实验，并非本轮新增运行或自动绑定成绩。

## 程序执行结果

薄匹配器`conditional_matcher.py`只比较明确的符号集合保证；实际适配器`run_matching.py`核对原材料SHA、版本，以及提供者/原语/消费者的配置身份，另核topology.i和autoconf身份。角色对应仍是审核假设，不是物理指针身份。

三个要求×既有提供路径按profile配成21个条件比较：**2项条件兼容、3项条件冲突、1项仅搜索路线不适用、15项不足**。这是同一案例的路径/性质组合，不是21次运行、21个样例或检测准确率。

- 两项兼容来自旧/修复mapper在资格通过且非HW时条件写出目标成员，只满足“目标覆盖”的符号条件。
- 两项冲突来自两版资格拒绝后条件写出空组，与目标覆盖用途不相容；另一项是旧配置空组无法满足“需要获得搜索见证”的显式用途目标。
- 唯一不适用是旧配置单元素条件后置集合会绕过所审搜索路线，不表示整个调用正确或真实运行不适用。
- HW前沿、字段/core关系、缺fixed控制绑定、缺x86效果等保持不足。所有21项的实际违约判定与完整契约判定都仍为不足。

14项组件开发测试通过。审查补齐了继续目标前提、非空路径条件、计数/遍历域与稳定性前提，以及适配器配置不能从消费者直接回填的缺口。原12/13项开发记录、未执行的初始接线包均保留；最终执行前审查见`method_review.md`。结果为已读开发，不是独立冻结评估。

## 接口依据新增的限制

仅补读既有两版cpumask.h的短摘录，没有新Git源或底层helper递归。weight用nr_cpumask_bits，遍历宏用nr_cpu_ids，所以把符号集合大小用作搜索条件前，必须显式假定没有遍历域外的置位，并且mask与nr_cpu_ids在相关窗口稳定。提供方原7项摘要前提不能自动代替这些消费者前提。

首摘录没有找到历史header中的next独立文档锚点，失败记录保留；随后保存weight注释/短定义、for_each_cpu注释/宏及next声明，未展开next实现。两版header字节相同但版本适用性分别登记，见`scope_addendum.md`与`api_contract_evidence.json`。
