# 判据修订 1（开发召回之后、两人审查和留出集检验之前写下）

2026-11-18，Claude。

**原因**：开发样本 fb1cf0878328 漏报。诊断（`debug_vert.py`）：`mm/page_alloc.c` 的 `__alloc_pages_bulk` 用 `pcp_spin_trylock` 加锁，循环里有一个提前退出的分支 `if (…) { pcp_spin_unlock(pcp); goto failed_irq; }`。判据三.1 的区间是纯词法的，把这次解锁当成了区间结束，于是主路径上仍在持锁时调用的 `prep_new_page`（→ `post_alloc_hook` → `debug_pagealloc_map_pages` → `__kernel_map_pages`）被判为不在锁内。

**改动**：判据三.1 增加一条：
- 一次“结束”调用（解锁、开中断等）如果所在的最内层 `{ … }` 块不是函数体本身，而且在这次调用之后、这个块结束之前，同一层出现 `goto`、`return`、`break` 或 `continue`，就视为提前退出路径上的结束，**不计入**区间计数。
- 不带花括号的单句分支（`if (x) unlock();` 后面紧跟 `return`）不在此列，仍按原规则处理。

其余不变。

**需要如实说明的一点**：调试这个开发样本时，我看过 fb1cf0878328^ 上的全部候选，其中有一条是 riscv `kfence_protect_page` 的 X2（IPI）。它和留出集要检验的 b3431a8bb336 是同一个问题。这次改动只针对“提前退出分支里的解锁”，和那条候选无关；修改前它就已经被报出，修改不影响它。
