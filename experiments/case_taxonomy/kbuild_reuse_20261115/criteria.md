# 判据：内核构建复用工具的设计与验收（kbuild_reuse_20261115）

2026-11-15，Claude。用户：“先做构建复用”。本文件在写工具和做任何测试之前写定，SHA 存入 `criteria_sha256.txt`。

## 一、要解决的问题

2026-11-15 一天构建了约 28 次内核，编译时间累计接近两小时。原因有四个：

1. 每轮结束时删掉构建目录，下一轮从零编译；
2. 配置分几轮逐步加，同一个版本被反复构建；
3. 变异打错了，没有便宜的办法提前发现（R4 第一批）；
4. 没有内核清单，不知道哪些镜像已经有了。

## 二、设计（写死）

工具 `linux_bug_analyze/tools/kbuild/kbuild.py`（在 WSL 里运行）。配置文件 `profiles.json` 和 `mutations/*.json` 放在同一目录。数据放在 WSL `/root/work/kbuild/`。

1. **纯净源码**：每个内核版本只解压一次，放在 `pristine/<12位提交号>/`，之后只读。
2. **持久构建树**：每个“版本 × 架构 × 配置档”一棵，放在 `trees/<提交号>_<架构>_<配置档>/`，长期保留。
   - `src/` 是纯净源码的硬链接副本（`cp -al`），几乎不占空间；
   - `out/` 是 `O=` 构建目录。
3. **改文件的方式**：凡是要改 `src/` 里的文件（配置档的源码补丁、变异），一律“先删掉链接，再写新文件”，绝不原地改写。这样纯净源码和其他构建树不受影响。还原时同样写一个新文件（内容是原文，修改时间是当前时间），保证下次构建会重新编译受影响的目标，不会留下带变异的旧目标文件。
4. **配置档**（`profiles.json`）：
   - `plain`：defconfig + `TRANSPARENT_HUGEPAGE`，用来判错；
   - `kcov`：`plain` + `KCOV`、`DEBUG_FS` + 调试信息（`DEBUG_INFO_DWARF_TOOLCHAIN_DEFAULT`、`DEBUG_INFO_REDUCED`），并删掉 `mm/Makefile` 中 `KCOV_INSTRUMENT_page_alloc.o := n` 一行（同 `kcov_pa`），用来记覆盖，一次配齐。
5. **变异**（`mutations/*.json`）：每个变异按架构写明：
   - 文件；
   - 锚点（必须恰好出现一次）；
   - 插入或替换的内容；
   - **预检**：一个目标文件名和一个正则。
6. **预检**：打上变异后，先只预处理这一个文件（`make <目标>.i`），在输出里找正则；找不到就还原、报错退出，不做完整构建。R4 第一批的错误会在这一步被拦下。
7. **登记表** `registry.json`：每个镜像一条，键为“版本 | 架构 | 配置档 | 变异”，记录镜像、配置、`vmlinux`（kcov 档）的路径、构建时间、变异内容的 SHA。`get` 命令先查登记表，有就直接返回路径，没有才构建。
8. **登记已有镜像**：把已经存在、来源清楚的镜像登记进去，以后直接复用：
   - `proprules` 的 HEAD plain 三个架构；
   - `kcov_pa` 的 kcov 档六个；
   - `x1loop` 的 X1 修复前、修复后六个。

   这些是复制的已有文件，原文件不动。
9. **同一棵构建树同时只允许一个构建**（`flock`）。

**本轮不做**（以后再说）：
- 用启动参数切换变异（需要改内核代码的写法，单独设计）；
- ccache（需要安装软件，要先问用户）。

## 三、验收测试（写死）

用 HEAD、riscv、`plain` 档，以及 R4 的两个变异（定义写进 `mutations/r4.json`，内容与 `r4_20261115` 修订 1 相同）。

| 编号 | 测试 | 通过条件 |
|---|---|---|
| A1 | 新建构建树并构建 plain 镜像（首次） | 构建成功；记录耗时 |
| A2 | 再次 `get` 同一个 plain 镜像 | 不编译，直接返回登记表中的路径（耗时 < 5 秒） |
| A3 | 用旧的错误写法（只定义 `move_pte`，不定义 `__HAVE_ARCH_MOVE_PTE`）作为变异 `R4a_bad` | 预检失败并报错，没有完整构建；还原后源码与纯净源码内容一致 |
| A4 | 构建变异 R4a（增量） | 构建成功；记录耗时，应明显短于 A1 |
| A5 | 构建变异 R4b（增量） | 同 A4 |
| A6 | 强制重新构建 plain 镜像（`--force`，验证还原后没有残留旧目标文件） | 构建成功 |
| A7 | 在 QEMU 中运行 propsuite4（每个 3 次）：A4、A5 的镜像，以及 A6 的镜像 | A4、A5 镜像上 P1、P2 违反，与 `r4_20261115` 修订 1 后的结果一致；A6 镜像上 15 个模板全部不违反 |
| A8 | 一个只改 `.c` 文件的变异（`mutation3` 的 N2 部分：`mm/memory.c` 的 `tlb_remove_tlb_entries` 换成空语句） | 增量构建耗时记录下来，应在 1 分钟左右 |

另外记录：磁盘占用（纯净源码、构建树、镜像）；登记已有镜像的条数。

## 四、规则

不安装、不联网、不调用大模型、不对外报告；不改 `/root/repos/linux`；不改旧轮次文件，已有镜像只复制、不移动；大文件放 WSL `/root/work/kbuild/`。统计行：模型调用 0；构建 N；新确认缺陷 0；新疑点 0。
