# 判据修订 1：含语句表达式的宏另加一道探针（xrt_20261125）

2026-11-25，Claude。**本修订写于第一次全量运行、看到结果之后**（G1 12/12 已过，G2 覆盖 706/706 已过）。

## 发现的问题

第一次运行里，有 92 条记录在静态初始化探针上报的错误不是“不是编译期常量”，而是“文件作用域里不允许语句表达式”。这些宏本身由常量算出，只是中间夹了 `({ ... })`，最常见的是 `BUILD_BUG_ON` 这种编译期断言（`__compiletime_assert_NNN`）。例如：
- `MAX_PAGECACHE_ORDER`
- `THP_ORDERS_ALL_FILE_DEFAULT`
- `SWP_TB_COUNT_MAX`

按原判据，它们被判成了“运行时·调用”，理由是调用了 `__compiletime_assert_NNN`。但这个函数只有在断言不成立时才会报编译错误，运行时并不会调用，所以这个判断是错的。

原判据的这道题，对这类宏答不出来。

## 修订

1. 静态初始化探针报“statement expression not allowed at file scope”时，**改用第二道探针**：在函数体里写 `_Static_assert(__builtin_constant_p(M), "")`，由 clang 判定 M 能否折叠成常量（函数体内允许语句表达式）。
   - 通过：判为**编译期常量**，备注“含语句表达式”；
   - 不通过：按原判据第二节，用语法树里的原因分类。
2. 统计原因时，不把 `__compiletime_assert_*` 算作函数调用，因为它是编译期断言，不是运行时调用。这条对所有记录都适用。
3. 第二道探针也答不出来、又找不到原因的，判为“未判定”，单独报告。

G1 的 12 项都不含语句表达式，修订后要重跑，仍须 12/12。G2、G3、G4 不变。抽查 G3 在修订后的结果上做（第一次运行还没做过抽查）。第一次的结果保留为 `result_run1.json`、`logs/run.log`。
