# 补上背景事实后，大模型复核规则标记

## 这一轮要回答什么

上一轮（`llm_review_rule_flags_20261103/`）中，Claude-Sonnet-5.5复核规则标记时，能去掉89%的误报，但只留住64%的真问题。被误判的真问题多数需要RISC-V特有的知识。

本轮在提示词中加上一份**通用的背景事实**，看能否在不降低误报去除率的前提下提高真问题保留率。主要检验放在**没核对过的新样本**上。

## 背景事实（`facts.md`）

1. Svpbmt下，`ioremap`、`early_ioremap`按IO属性映射，普通内存中的数据（如ACPI表）应该用`memremap`系列；
2. 从v6.4起，RISC-V的陷入处理在显式`local_irq_enable()`之前一直关中断，这期间不能访问用户内存或睡眠；
3. PREEMPT_RT下`spinlock_t`会睡眠，`raw_spinlock_t`不会；
4. 对来自客体或用户的下标缺少`array_index_nospec`，上游就当作缺陷来修，不要求先证明可利用；但内部常量、固件或调试器提供的值、已校验保存的状态不算；
5. 参照架构覆盖默认实现，如果只为性能或可选功能，RISC-V沿用默认实现不算缺陷；如果为了正确性，才需要看RISC-V是否同样需要；
6. 只是缺少功能或优化，不算缺陷。

这些事实是从上一轮的误判中总结出来的，所以在原来41个问题上的结果偏高，只作参考。

## 新样本

- **来源**：前几轮规则标出、但从未核对过的标记，去重后18个。
- **标签**（调用前写定）：
  - **真问题8个**，都有上游后来的修复作为依据：APLIC 4个、ISA扩展编号、PMU `ctr_info`、`kfence_protect_page`、`arch_cpu_idle`；
  - **误报10个**，标签来自第一标注人：默认实现规则7个，下标来自固件或调试器的2个，异步跨核调用1个。
- **局限**：其中4个APLIC问题与上一轮样本中的APLIC问题同根。

每个新样本问两次：一次不加事实，一次加事实，其余提示词逐字相同。

## 结果

77次调用全部完成，约20万token。

| | 真问题保留率 | 误报去除率 | 复核后精确度 |
| --- | ---: | ---: | ---: |
| **新样本，不加事实** | 7/8 = 88% | 9/10 = 90% | 87.5% |
| **新样本，加事实** | 7/8 = 88% | 9/10 = 90% | 87.5% |
| 原样本，不加事实（上一轮） | 9/14 = 64% | 24/27 = 89% | 75% |
| 原样本，加事实（参考，偏高） | 11/14 = 79% | 25/27 = 93% | 85% |

**按判据判定**（只看新样本加事实的结果）：
- 保留率88%，要求不低于90%，**未达到**，差1个；
- 去除率90%，满足；
- 保留率不低于不加事实时的结果，满足。

三条须同时满足，所以**本轮未达到成功标准**。

**在新样本上，加不加事实，结果完全一样。**
- 两种做法都漏了`arch_cpu_idle`。模型说它在v6.6中“已带`__cpuidle`标注”，但提示词里给出的代码是不带标注的`void arch_cpu_idle(void)`。模型说错了材料中明确写着的内容。
- 逐条看只有两处变化，而且一正一反：
  - `__read_mostly`：不加事实时判为真问题（错），加事实后判为误报（对）；
  - `memset_io`：不加事实时判为误报，加事实后判为真问题。模型认为参照架构覆盖IO拷贝函数是出于正确性。RISC-V到终点版本仍沿用通用实现，后来也没有修复，所以第一标注人维持“误报”，但这一条有争议。

**在原样本上（参考）**：
- 加事实后，上一轮误判的5个真问题中有4个判对了：
  - 未对齐陷入，事实2起了作用；
  - ACPI表映射2条，事实1起了作用；
  - PMU配置下标，事实4起了作用。
- 但同时**倒退了2个**原来判对的真问题：
  - `machine_shutdown`：模型称“先关中断再调用是各架构通用的写法”，与事实不符，arm64并不关中断；
  - `die()`中拿普通锁：模型认为标出的路径是用户态分支，不会进入`die()`。

## 事后分析（只作描述）

1. **事实清单只对“缺的正是这条知识”的问题有用。** 在原样本上，它补上了Svpbmt、陷入入口中断状态等知识缺口，所以有效；在新样本上，模型本来就判对了大多数（保留88%、去除90%），事实清单没有带来变化。
2. **模型的单次判断不稳定。** 同一个问题，换一次提问就可能翻转，例如`machine_shutdown`、`die()`这两条。原样本上的“改进”和“倒退”，有一部分可能只是随机波动。要判断哪种问法更好，需要对同一问题多问几次，看判断是否稳定。
3. **模型会说错材料里写着的事实**，例如`arch_cpu_idle`的标注。这类错误靠补背景事实解决不了，需要让程序检查模型引用的代码事实，例如“函数是否带某标注”。
4. **新样本上，模型复核已经接近可用**：保留率88%，去除率90%，精确度从44%提高到87.5%。

## 结论

- 按判据，**本轮未达到成功标准**：新样本上保留率88%，差1个达到90%；而且加事实与不加事实的结果完全相同，**通用背景事实在新样本上没有带来改进**。
- 在原样本上，事实清单补上了特定的知识缺口，但同时出现了倒退，说明模型的单次判断有波动。
- 大模型复核这一步在新样本上的表现已经不错。下一步应该：
  - 对同一问题多问几次，用多数结果，以减少波动；
  - 让程序核对模型引用的代码事实，例如标注、调用是否存在，以减少“说错材料”的错误；
  - 积累更多独立的新样本。
