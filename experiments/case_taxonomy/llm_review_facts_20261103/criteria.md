# 补上背景事实后，大模型复核规则标记（判据，实现之前写定）

## 这一轮要回答什么

上一轮（`llm_review_rule_flags_20261103/`）中，Claude-Sonnet-5.5复核规则标记，误报去除率为89%，但真问题保留率只有64%。被误判的真问题，多数需要RISC-V特有的知识。

本轮检验：在提示词中加上一份**通用的背景事实**（`facts.md`），能否在不降低误报去除率的前提下，提高真问题的保留率。

## 一、背景事实

`facts.md`共6条，对所有问题完全相同，不针对单个问题：
1. Svpbmt下的内存属性；
2. 通用入口框架下陷入处理时中断的状态；
3. PREEMPT_RT下的锁；
4. 内核对Spectre-v1的判定标准；
5. 沿用默认实现何时算缺陷；
6. 缺少功能不算缺陷。

**说明**：这些事实是从上一轮的误判中总结出来的，所以在上一轮那41个问题上重测，结果必然偏高，只能作参考。**主要检验放在新样本上。**

## 二、样本

**A. 新样本（主要检验）**：
- **来源**：前几轮规则标出、但从未核对过、也不在上一轮41个问题中的标记，由`candidates.py`列出共19个，去掉重复后18个（`kfence_protect_page`在两个快照中各出现一次，保留`v6.6`的那个）。
- **标签**：在调用模型之前定好，写入`heldout_labels.json`：
  - 真问题8个，都有上游后来的修复作为依据：
    - APLIC的`aplic_read_sourcecfg`、`aplic_read_pending`、`aplic_write_pending`、`kvm_riscv_aia_aplic_inject`（`8565617a8599`）；
    - `riscv_vcpu_get_isa_ext_single`（`f9e26fc32541`，修在重构后的`kvm_riscv_vcpu_isa_check_host`中）；
    - `kvm_riscv_vcpu_pmu_ctr_info`（`2dda6a9e09ee`）；
    - `kfence_protect_page`（`b3431a8bb336`）；
    - `arch_cpu_idle`（`8a48ea87ce89`）。
  - 误报10个，标签来自第一标注人：
    - 默认实现规则7个，只是性能差异或可选功能；
    - `cpu_update_secondary_bootdata`的下标来自固件；
    - `dbg_get_reg`的下标来自调试器；
    - `kgdb_riscv_notify`调用的是异步跨核调用，关中断时允许。
- **局限**：其中4个APLIC问题与上一轮样本中的APLIC问题同根，不完全独立。

**B. 原样本（参考）**：上一轮的41个问题。

## 三、做法

- **新样本**：每个问题问两次，提示词分别为：
  - 不加事实：与上一轮相同；
  - 加事实：在问题之前插入`facts.md`。
- **原样本**：只问“加事实”一次，与上一轮“不加事实”的结果对比。
- **模型**：Claude-Sonnet-5.5，凭据配置为`claude-sonnet55-20261103`，8路并行，不自动重试。
- **调用量**：18×2＋41＝77次。

## 四、指标与事先写定的判定

**指标**：与上一轮相同，即保留率、去除率、复核后的精确度。

**成功标准**（只看新样本上“加事实”的结果，同时满足）：
1. 保留率不低于90%；
2. 去除率不低于50%；
3. 保留率不低于同一批新样本上“不加事实”的结果。

**次要指标**：
- 新样本上两种提示词的逐条对比；
- 原样本上加事实前后的对比（参考，偏高）。

## 五、已知局限

- **新样本只有18个**，结论的把握有限。
- **误报的标签只来自第一标注人。** 所以会准备GPT复核材料。
- **模型可能见过上游后来的修复。**
