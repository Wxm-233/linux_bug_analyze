# D2 / N2.26：表示事实投影与原契约核心接线

2026-10-23。**首次完成“选定原文→局部表示事实→有限关系推导/反例→原契约核心”的开发闭环。** 不再由研究者逐条手填判定布尔值；但原文位置、所属对象、格式用途及转换语义仍由外部提供。这是一个已读ocfs2工作单元的局部方法开发，不是新缺陷、完整文件系统复现或独立检测成绩。

## 实际新增

- [representation_source.py](../../../linux_bug_analyze/representation_source.py)：用AST解析完整的选定局部表达式，从给定声明取得__le/__be宽度与存储域，取得常量OR掩码、零/非零操作和注册转换位置。它不自动找全部位置、不证明声明所属结构或生效宏；未知调用、算术、复合条件、重复目标等保留不足。
- [representation_semantics.py](../../../linux_bug_analyze/representation_semantics.py)：对明确的unsigned8/16/32/64位模型，以字节置换及被选择的语义bit集合比较，推导所支持判位家族在全域是否等价，或自动产生一个单bit反例。零性使用置换双射性质。此结论限于该模型家族，不是任意C或运行路径证明。源码前端只认__le/__be16/32/64，不虚构Linux le8宏。
- [run_projection.py](run_projection.py)：本工作单元的接线脚本将自动投影值交给**未修改**的contract_protocol核心。规范、适用条件和角色账本仍是研究者审核输入；核心复用和新增投影不是同一项能力。

这些组件不内置ocfs2函数名或本例掩码。阶段脚本按登记的已读输入组织实验，不是通用生产CLI或完整自动检测器。

## 固定输入及首次结果

复用5份历史父版原文件，4行字段声明、3个if原文位置、5个手选局部表达式；每项取小/大端两个语义条件，共10条记录。3个子表达式来自同一复合条件，仅各自评价，不替整行背书。没有新取源或修复源；输入、方法和判准先保存，再执行一次initial，无重跑或事后调整方法。

| 选定表达式用途 | 小端条件 | 大端条件 |
| --- | --- | --- |
| primary：盘上i_flags直接与主机掩码判位 | 等价 | 自动给出反例 |
| 同字段与转成小端的掩码判位 | 等价 | 等价 |
| i_size只检查非零 | 等价 | 等价 |
| i_clusters只检查等于零 | 等价 | 等价 |
| S_ISLNK模式判断 | 不支持/不足 | 不支持/不足 |

合计7条equivalent、1条counterexample、2条insufficient，不是7个正常案例或一个新漏洞。前四类的8条投影接入原核心后为7满足、1不满足；**实际消费期限与整条路径均仍不足**。

自动反例的存储字节为`20 00 00 00`，格式语义值0x20；大端载入为0x20000000，直接与0xC60相与不命中，而按格式解码后命中。这个值由支持bit集合差异自动产生，未手填“错/对”答案；它只是局部unsigned字段域的见证，不能作为已证明合法、可达filecheck的真实inode。所选位也不证明对应类型实际通过修复入口。

## 测试与证据控制

57项定向unittest首次通过：29项新组件测试（语义11、源码18）及28项既有核心回归。包含独立to_bytes/from_bytes参考、8位所有值/所有掩码的有限域检查、16/32/64位转换、零/对称掩码、同时转换可能失配、溢出和未知语法等。测试组合不是缺陷数量，也不是对任意内核代码的穷尽验证。

另3项构造证据控制分别移除规范依据、错配对象、未审就把样本升为实际消费，全部返回不足。核心只比较生成的投影样本；记录明确basis=synthetic，未将真实源码引用偷换为实际运行观测。

原始执行、测试stdout/stderr、投影全文和事后期望比较都保留在[execution_initial](execution_initial/)；预期文件仅在预测原文保存后用于开发对照，没有作为分析器答案输入。见[method_pre.json](method_pre.json)、[执行前复核](pre_execution_review.md)及[汇总](results.json)。
