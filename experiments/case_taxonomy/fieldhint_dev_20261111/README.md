## 为什么没用

1. **B467：字段太分散，取值也很少落到“未知类型”**。`perf_event_open` 的 44 个字段变体里，改 `type` 的只有 8 个（5 个字段平分）；这 8 个里取到不存在类型的只有 1 个（0xffffffff），其余是 0、1、2 这些合法类型。四类取值里，只有“范围外”和“常数−1”的一部分会得到未知类型。
2. **A181：改坏了结构之间的链接**。变体改得最多的是 `iovec.iov_base`、`iovec.iov_len`、`msghdr.msg_iovlen`——这些是“指针”和“长度”字段，原本指向子缓冲区、记着它的长度。改成 2、9、0xffffffff 这类数之后，`msghdr → iovec → 缓冲区` 的链接断了，A181 需要的输入就被破坏了：G3c 中能触发 A181 的用例，有 1 个被换成了这样的变体。

## 下一版应当怎么改（都是通用规则，尚未实施）

1. **不改链接字段**：生成器里本来就区分“指针”“长度”类字段，变体只改普通标量字段。
2. **对“相等比较”的字段，偏向范围外的值**：内核对一个字段做相等比较或 switch，说明它只认少数几个值；缺陷往往出在“不认识的值”走的默认分支上。范围外的值应当占多数，而不是四分之一。这条规则不针对 B467，但 B467 正好是这一类，要注意过拟合。
3. **按字段的证据强弱分配**：现在所有字段平分；可以让“在架构代码附近被比较”的字段优先，与提示点打分的思路一致。
