# N2.1—N2.2：有限池选配与已选观测回放

2026-10-17。本轮首次把N2的有限池选配做成可执行开发原型，并接上选中观测的回放。**目前是“人工审核输入→程序选择→旧观测回验”，还不是自动推导所有输入或发现新问题。**

## 程序做了什么

新增[contrast_selection.py](../../../linux_bug_analyze/contrast_selection.py)与28项边界测试。程序要求相同版本、公共用途、消费阶段、对象角色和获批的执行上下文，核对实际配置事实的输入绑定及合法性审核，再按契约指定的提供者语义差异与成本选对照。每一格、每一对的排除原因均保留。合法性或语义未知时不入选，不判正常；仅架构名称或源文件路径不同也不够。

合法性、共同用途、准备资格域和准备阶段仍由研究者/助手根据已读证据整理并审核。程序没有自动证明这些语义；摘要绑定只防止输入变动后沿用旧审核。对明显标签、架构名或路径字段的拒绝也不能识别任意换名的结果泄漏，仍需外部语义审核。

## 选择和回验

只用了既有s390实验的4份配置/构建profile，先保存选择，再打开入选两格的归档运行观测。示例成本单位是每格1，不是实测启动时长。

| 阶段 | 结果 | 能说明什么 |
| --- | --- | --- |
| 配置/构建输入 | 4份实际config/autoconf与构建账本核对 | 有来源的归档构建事实，不保证镜像当前仍可启动或能得到有用见证 |
| 预算内选择 | P01/P03：同父版s390与x86，成本2；提供者资格域和准备阶段有已审阅差异 | 程序能按指定条件挑出可比较的一对；并未输出错误/正常标签 |
| 固定选择后回放 | s390 CPU1：self=0、locks=0；x86 CPU1：self=1、locks=1 | 同一公共用途的已存局部观察确有差异；不是本轮新启动 |
| 未选择项 | 同修复版在指定特征上无差异，其他组合因版本/架构等排除 | 不因架构名称不同就配对；未入选不等于正常或不相关 |

两格均为CPU1、CPUHP阶段90、普通双CPU初次启动。这里的self表示目标CPU是否属于其SMT集合，locks是该次实际锁数量。原日志坐标分别149和109。观察仍是关中断前的内容采样，未证明精确循环读、全局首次读取、实际内存地址同一性或全区间稳定；没有真实SMT、下线重入或并发结论。

## 验证与限制

最终28项方法测试通过，并经独立代码及回放复核。修正了身份/成本审核未绑定、显式架构字段冒充语义差异、空白和架构别名问题；24、26项历史测试记录保留，不能把重复执行次数加成测试项或缺陷数。回放只调用旧runner内原样的纯解析函数，没有执行构建/启动入口，也没有用其版本专用预设作真值；相同解析器复现事件不等于独立测量。

本轮N2新增外部API、内核编译、启动、确认缺陷和独立样本均为0。有限池输入来自已知案例，缺少与同预算朴素配对的独立比较，因此尚不能证明第二项创新或检测增益。N1/N2整体不勾选。

下一步优先把N1已保存的资格域/调用阶段事实接入选配输入，减少手工填写；缺少证据时保留不足，不编造特征。之后再冻结方法，安排同预算比较和未参与开发的输入。
