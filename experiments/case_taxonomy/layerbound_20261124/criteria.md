## 一、师兄的定义（原文转述）

- **架构层**：在不同架构下，因架构相关配置项（只可在特定架构下才能打开的内核配置项）、编译条件等不同，导致编入内核的源码产生差异的函数集合。
- **公共层**：在任何架构下都能编译，且源码没有差异的函数集合。
- **边界代码**：① 直接调用架构层代码的公共层函数；② 直接被 ① 中函数调用的架构层函数。

本轮只做分层和边界，不做数据流、不出缺陷候选。

## 三、做法

### 1. 架构相关配置项

对三个架构各跑一次 `make O=<临时目录> ARCH=<a> allyesconfig`（只生成配置，不编译）。某个符号出现在架构 a 的结果里（不论是 `=y`、`=m` 还是 `is not set`），就说它“在 a 上可用”。

**架构相关配置项** = 在三个架构中至少一个可用、但不是三个都可用的符号。三个都可用的是“通用配置项”，三个都不可用的与本轮无关。

### 2. 编译条件与“源码差异”

- 对三个构建的每个编译单元，用编译数据库里的命令加 `-E -dD`（去掉 `-c`、`-o`、`-Wp,-MMD`）预处理，按行号标记记录每个源文件在该构建里**有输出的行**。某个构建里所有单元的结果取并集。
- 对每个源文件解析条件编译结构（`#if/#ifdef/#ifndef/#elif/#else/#endif`），得到各分支的行范围。分支在某构建里“被选中”，是指分支范围内有输出行。三个构建都没有输出的分支，状态记为未知，不参与比较。
- **函数**：在原始源文件上按括号配对找出函数定义的范围。另外把定义在 `arch/` 下的函数式宏，以及公共头文件里出现在架构相关条件分支中的函数式宏，也算作“函数”，因为它们同样实现接口，例如 `pud_leaf` 在某些架构上是宏。
- **函数有源码差异**，指在编入它的文件的构建之间，满足下面任一条：
  - 函数本身是否编入不同；
  - 与函数范围重叠的某个条件分支，选中状态不同。
- **差异归因**：取造成差异的条件分支，看其条件里的标识符：
  - 含架构相关配置项（`CONFIG_X`）、在 `arch/*/` 下定义过的宏名，或编译器预定义的架构宏（`__riscv`、`__aarch64__`、`__x86_64__` 等），算“架构”；
  - 只含通用配置项，算“配置”；
  - 其他，算“未归因”。
- 文件只在部分构建里编译的：
  - `arch/` 下的文件，算“架构”；
  - 公共 `.c` 文件，到所在目录的 Makefile/Kbuild 里找 `obj-$(CONFIG_X) += <文件>.o`，按 `X` 归因；
  - 找不到的，算“未归因”。

### 3. 分层标签

| 标签 | 条件 |
|---|---|
| 架构层（A0） | 定义在 `arch/` 下 |
| 架构层（A1） | 公共文件里的函数，有至少一处差异归因为“架构” |
| 公共层 | 公共文件里，三个构建都编入且没有差异 |
| 公共层（配置差异） | 公共文件里的函数，差异只归因为“配置” |
| 未归因 | 有差异，但没有一处能归因为“架构”，且至少一处“未归因” |
| 未编入 | 三个构建都没编入 |

### 4. 边界

- 对构建 b 里编入的每个公共层函数（含“配置差异”），扫描它在 b 里被选中的那些源码行。凡是“标识符后紧跟 `(`”，且这个名字在 b 里能解析到一个编入的架构层函数或宏，就记一条边界边（公共函数 → 架构函数，构建 b）。只看直接调用，不展开公共宏。
- 第 ① 类边界函数 = 至少有一条边界边的公共层函数；第 ② 类 = 被边界边指到的架构层函数。按构建分别统计，再取并集。
- 名字解析按名字进行，不区分同名静态函数。同名冲突的数目单独报告。
