# 任务：静态分析器报警的误报审查（第二审查人，盲判）

## 背景

这是一个防御性的研究项目：我们在开发一个静态分析器，用来在 Linux 内核源码里找“代码默认了某种架构行为（例如字长、页表编码），换到别的架构就不成立”的**功能正确性问题**，比如 32 位上整数被截断、对非 present 页表项读访问位。这一轮要评估的是这个分析器的**报警准确率**：它在最新主线（v7.4-rc3）上对新增代码报了 16 条警告，我们需要两个人各自独立判断每条警告是**误报**还是确实存在的正确性问题。经验上这类报警绝大多数是误报，统计误报的原因类别就是这一步的主要目的。

说明几点：
- 这和内核维护者平时做代码审查、处理静态检查（如 sparse、Coverity、smatch）报警是同一件事，对象是公开的开源代码；
- 不需要也不要写任何利用代码、测试代码或触发方法，只判断代码逻辑本身是否正确，给出行号依据；
- 如果真有正确性问题，我们会照惯例通过公开邮件列表报给相应维护者（之前已经这样报过一个 DAX + userfaultfd 的问题，维护者已合入修复）。
