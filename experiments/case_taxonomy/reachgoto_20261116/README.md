## 问题是什么（说人话）

分析器是按语句顺序往下推“此处成立的事实”的。遇到 `out:` 这样的标签，旧解析器直接把标签丢掉，标签后面的语句接着用顺序流上的事实。但标签处还能从别处跳过来：

```c
if (c)
        goto out;                 /* 从这里跳到 out：没查过 present */
if (!pte_present(v))
        return;
...
out:
        x = pte_young(v);         /* 旧分析器：顺序流上查过 present → 误以为安全 */
```

`switch` 里的 `case` 也一样：上一个 `case` 里 `if (!pte_present(v)) break;` 得到的“present”，会漏进下一个 `case`。

## 改法

只在新一轮里改，旧文件都没动：语句解析器和函数分析器都用子类，只读导入 `reachsum.py`。

- 标签、`case`、`default` 都解析成语句，嵌套的块也一样；
- 分析到 `goto L;` 时，记下这一刻的事实；
- 到标签 L 时，事实取这几组的**交集**：顺序流上的事实（上一条语句可能落下来时）、每个 `goto L` 处的事实；如果有从后面往回跳的 `goto L`，再交上函数入口的事实；
- 到 `case` 时，事实取 `switch` 入口的事实与顺序流事实的交集；
- if/else 提前退出时，“块之后的事实”只算块里最后一个标签之后的语句。

## 局限

- 标签处只合并了“事实”。变量来源（别名）和布尔别名仍然沿用顺序流，没有按跳转路径合并；
- 往回跳的标签直接退回入口事实，偏保守；
- 召回耗时 21 分钟（reachsum 19 分钟）。
