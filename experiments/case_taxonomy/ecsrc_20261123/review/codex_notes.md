# 第二审查人笔记

基线为 df2908090cda。本次按源码手算修改前后的布尔值。公共层页表自检只作为接口约定的依据，本次没有运行内核。

- M1 的两个构建共用同一套权限位判断。对 PAGE_NONE 直接授予写权限会使无访问权限判定失效。在实际建映射路径，mm/huge_memory.c:1223 以 VM_WRITE 控制加写；NUMA 故障恢复路径在 :2341–2345 先按 VMA 改保护、置访问位，再有条件加写。
- M2 的脏位掩码包括硬件脏位和软件保存的脏位（arch/x86/include/asm/pgtable_types.h:139）。两者原来都是零时清理是幂等操作；任一个为一时清理都能改变观察值。两个 x86 构建恰好都把 PAGE_KERNEL_EXEC 的修改前值记为不确定。
- M3 的已知只读样本足以验证重复写保护的结果；决定能否据此归纳“保持”的反例是 PAGE_SHARED。两个 x86 构建都跳过了它。mm/debug_vm_pgtable.c:202 的写保护检查显式从可写状态出发。
- M4 的共同后置条件是 young 为真。LoongArch 的三个用户保护常量都能表现置位效果，三个内核保护常量都已置位。同一个实现即可产生表中的两种行为。
