# 单旧版源码检查：试验判准

日期：2026-09-28。本文件在新留出修订的补丁正文与历史源码读取前写定研究目标；它**不是**代码或选样冻结文件，运行前还须另存脚本哈希、目标 SHA 与实际文件时间。已读的 bcachefs `3f3ae`、`b07ce`、`2007d28e` 可用于开发和边界反例，不能反复充当独立留出。

## 输入与输出边界

程序的检测输入限定为一个指定 Git 修订的源码树、目标头文件或子系统范围，以及明确的小端/大端编译配置；**不得通过修复提交、后继版本差异或标题来挑选出错类型**。输出必须区分：

- `review_candidate`：旧版本中可由源码和编译探针追溯到的条件性不一致，附具体类型/字段、分支、内嵌/消费位置、配置与行号；这是待审查线索，不等于漏洞。
- `normal_control`：同一规则确实适用且在所查配置满足约束；只针对该规则，不能给整项提交“无缺陷”标签。
- `not_applicable`：目标接口或消费路径经证据确认不启用。
- `insufficient`：版本语法、依赖、配置或权威约束无法确定；编译异常需单列 `runner_error`，不能当正常或证据不足吞掉。

对表示类先试两种不同检查：① 单版本中的条件字节序 packed/显式对齐类型及其直接内嵌位置，在真实小/大端 ABI 上量出 `alignof`、`offsetof`，仅把不相容之处列为复核候选；② 结构字段在条件分支中的名称与同版本共同消费者的访问是否一致。① 的偏移不整除可能是**有意 packed 格式**，须带正常对照和文档/消费者解释；② 的字段缺失可由编译器直接判定，但提取消费者和配置可达性也有限。若本轮只完成①，要明确报告②仍由人工指定，不借用昨天定向探针充数。

## 留出与评价

先在已读开发样本上检查程序是否运行、是否拒绝复杂语法、是否把普通 packed 结构误报；之后冻结源脚本、测试/runner、规则、选样池与哈希。独立留出只能按 SHA、标题、日期、变更路径等元数据预选，先运行并保存原始结果与哈希，再读提交正文/补丁/对应版本的接口规范和消费者。选不出同机制且未读的样本，就报告“泛化未验证”，不拿已读样本或同功能后继补丁冒充独立验证。

评价单位是**一条具有独立因果链的历史修订**，不是嵌入点、编译器调用、条件网格或模型短判定条目。对每条分别记录候选是否与可证实的历史问题相关、范围外问题是否被错判为正常、人工复核与编译层级、同血缘关系及未知项。样本是目的性选择，不报告总体准确率/召回率或全量筛选提速。

topology v3 的对应原则相同：先按该版本的构建规则、属性声明与注册形状选择可解析路径；可选文件不存在且未包含可判“未参与”，被包含却缺失、配置符号不存在或条件不明则拒判。仅在构建、原生提供者和用户可见导出链都可确认时给行为结论。a622/b40 已解封，只作开发材料；任何 v3 修改必须用**另一条未读修订**验证。
