# 方向1：公共代码明写关系的跨架构核算（第一轮：挖掘计数＋取值试点）

## 这一轮要回答什么

已确认的案例中有一类机制叫“数值关系”：公共代码默认架构提供的几个常量之间满足某种大小关系，某个架构或配置却不满足。例如shmem的大块内存阶数不能超过页缓存上限，只有arm64在64KB页时出现13＞11。

以前这类关系靠人工整理。这一轮换个来源：公共代码自己已经写了大量检查，例如`BUILD_BUG_ON(A > B)`、`static_assert(...)`、`WARN_ON(...)`，直接把这些关系读出来，再用已经验证可靠的编译期取值工具，在不同架构配置下算出真实值。

本轮只回答两个可行性问题：这样的关系有多少？能不能算得出来？

## 结果

### 1. 挖掘计数（终点版本）

| 项目 | 数量 |
| --- | ---: |
| 公共代码中的断言类检查点 | 32 626 |
| 条件里含比较 | 14 455 |
| “纯常量” | 7 461 |
| “与架构有关” | 4 577 |
| **候选关系**（三者同时满足） | **2 385**（823个文件；`.c`中1861个，`.h`中524个） |

候选关系几乎都是`BUILD_BUG_ON`（1676个）和`static_assert`（664个），`WARN_ON`类只有6个。

### 2. 取值试点（30个检查点×5种配置：x86_64、arm64、arm64 64KB页、riscv、s390）

| 项目 | 结果 |
| --- | --- |
| 文件在该配置下确实参与编译的组合 | 37个 |
| 其中算出值的 | **21个（57%）** |
| 各配置之间取值不同的检查点 | **0个** |
| 检查被触发的 | 0个 |

按事先定的规则：候选关系有2385个（≥50），但取值成功率57%，介于30%和60%之间。**规则要求先分析失败原因。**

### 3. 失败原因

1. **把局部变量误当成了常量**：30个检查点中有10个，条件里实际引用的是函数内的变量，例如`sizeof(hid->uniq)`、`sizeof(old)`、`typeof(*descriptor)`。分类时规定`sizeof`括号里的内容不检查，所以它们被算成了“纯常量”。取值工具在文件层面求值，看不到函数内的变量，于是编译失败。37个参与编译的组合中有16个因此失败。
2. **抽到的大多是驱动，不在默认配置里编译**：150个组合中有113个是文件不参与编译。
3. **最关键的一点：抽到的关系本来就不会因架构而变。** 几乎都是“某个结构体必须正好是多少字节”这类二进制布局约束，例如`sizeof(struct nvme_identify) != 64`。它们的用途就是保证所有架构上都一样。判据中“与架构有关”的定义太宽，只要出现`sizeof`就算。

### 4. 事后统计（看过试点结果之后，未登记）

- 在2385个候选中，只有21个用到了在3个以上架构里各自定义的宏，而且多是`O_CLOEXEC`、错误码这类用户态接口常量。
- 真正会随架构和配置变化的量，例如`PAGE_SIZE`、`PAGE_SHIFT`，在新内核里由配置项（如`CONFIG_PAGE_SHIFT`）经公共头文件推出，并不在架构目录里单独定义。**按“在哪里定义”判断一个宏会不会变，抓不到这类真正可变的量。**

## 结论

- 公共代码里明写的关系数量很多，但几乎都是二进制布局约束，本来就要求所有架构一致；而且这些检查一旦不成立，编译就会失败，早就会被发现。
- 和“数值关系”这一机制真正相关的关系，例如页大小、页阶数、缓存行大小之间的关系，在这批候选里很少。用现在的语法规则也挑不出来。
- 取值工具本身在能求值的地方是好用的，21个结果都合理。问题出在**选什么关系去算**。

## 可能的下一步（未登记，供决定）

1. **用实测判断“会不会变”，代替语法判断**：先在多种配置下实测一批常见宏的取值，例如`PAGE_SHIFT`、`MAX_PAGE_ORDER`、`PMD_SHIFT`、`THREAD_SIZE`、`L1_CACHE_BYTES`、`NR_CPUS`，只保留确实因架构或配置而变的宏，再筛选涉及这些宏的关系。
2. **范围收窄到每个配置都会编译的核心代码**，即`mm/`、`kernel/`、`fs/`核心、`lib/`、`include/linux/`，避免驱动不参与编译的问题。
3. **除了断言，也看隐含关系**：shmem那个案例本身就不是断言，而是“分配阶数”和“页缓存上限”这两个量之间没写出来的关系。可以考虑数组下标、移位量、阶数与这些可变宏之间的比较或运算。
4. `sizeof`、`offsetof`的参数只接受类型名，排除局部变量。
