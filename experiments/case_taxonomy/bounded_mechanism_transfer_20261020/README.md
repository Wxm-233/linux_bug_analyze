2026-10-20。本轮完成了两项固定候选的父版阅读、两次 Opus 分析、未修改程序的核对，以及预测保存后才开放的修复比较。主要结果是：**模型在 G 中提出了与实际修复一致的关键线索，但检查条件仍过强；H 的真正模式条件未被提出。引用和词法核对不能代替这种语义判断。**

## 固定流程和材料

从既有 500 条中按元数据人工目的性定位 G/H，读新源码后不换例；这不是随机抽样、事前自动排序或总体相关率估计。各输入为精确单父版本的八份完整原文，共十六份；两次符号搜索和补充材料都在回答前固定。不给模型提交标题、筛选标签、子版说明、修复 diff 或研究者目标谓词。输入只有原始源码，没有实际配置、预处理或运行证据。

主分析使用 Windows 原生 Claude Code 2.1.301＋AWS-Claude-Opus-5.5。两份原答、交付回执及程序结果均在[父版预测停点](parent_prediction_checkpoint.json)保存后，才开放[固定修复依据](repair_evidence.json)。原答、格式拒收和定位失败不修写，不重试请求；没有补换样本或增加新解析/CFG能力。

21 项不是 21 个缺陷；17 项绑定不是正确率，3 项词法支持也不是准备效果或完整契约成立。旧定位器不支持若干 `void __init`/`asmlinkage` 声明，另一处含未处理的条件编译；函数实际存在，失败没有算作模型虚构。引用超长也没有被当作语义反证。详见[原预测核对审计](prediction_check_audit.md)和[机器结果](mechanical_results.json)。

G 第一次核对入口因 Windows 物理 CRLF 字节与既有 runner 实际发送的规范化 LF 文本哈希混用而停止，发生在读取 final 之前。保留首版与失败记录后，只修入口比较，使其对齐既有 runner；没有改提示、模型回答或受测组件，也未重发请求。

正式契约核心和对照选择器本轮仅登记版本；这些原始候选没有自动转换为可接受的完整契约，所以**没有执行其完整判定或运行选配**。自动接受的完整要求为 0；这与“所有已执行检查都通过”含义不同。
