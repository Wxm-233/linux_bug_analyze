# Btrfs接口分析 → 自动分析程序

本轮用户要求回归主线。设备清理、日志实现及其他callee追踪不再默认排入下一轮；只有明确改变接口要求或检查结果时才补源。

## 接口问题（研究者登记，规范依据尚未全自动取得）

| 要素 | 本案约束 |
|---|---|
| 共同用途 | max_inline选项裁剪需要本文件系统适用的几何 |
| 差异条件 | 合法页大小/磁盘几何组合；不是ARM名称本身 |
| 提供者 | 磁盘超块读取及fs_info缓存准备路径 |
| 消费者 | max_inline分支首次使用sectorsize缓存的操作 |
| 被检状态 | 实际被消费的缓存值 |
| 正确参考候选 | 同一文件系统在该消费时刻适用的磁盘几何 |
| 候选要求 | cache == disk_at_deadline；尚待语义/时刻参考准入，不能先假定成立 |
| 范围 | 本轮只接既有父/修复64K页、64K磁盘，正2048/8192请求的观测归档 |
| 已有事实 | 实际缓存、后采样磁盘值、有效选项及文件行为；有限区间监测另有记录 |
| 缺失事实 | 已获审核的disk_at_deadline及相应语义依据，不能直接用后采样值替换 |
| 输出 | 候选保持接口问题/不匹配；然后由原核心输出满足/违反/不适用/不足 |

“要求候选表达正确”与“证据足以判定”是两个不同阶段。C不得变成cache==cache；deadline不得从消费改到后采样。A运算自洽和B跨时刻比较仍可保留，但不能冒充C。

## 本轮程序能力

新增interface_intent.py：在已有有限契约DSL之上，接收**单独登记的接口意图**与**候选要求**，检查版本、消费事件、变量语义角色、适用范围和关系表达式是否匹配，再调用原contract_protocol。支持变量改名和eq/ne/and/or交换次序；不判断任意代数等价，不从自然语言或源码自动推导语义。

可信接口卡不能由候选自行覆盖。symbol_bindings是结构化声明，不是机器证明的真实字段绑定，原核心仍要求外部账本/事实审核。结构匹配不能批准缺失证据或提升消费时刻判定；scope/关系超出注册表达式时表示本检查未认可，不说明新提议在科学上错误。

人工依赖：接口卡、候选语义角色及自然语言→结构化转写仍由研究者提供；已有review也仍人工登记。当前改进是将已反复出现的候选问题偏移转为可执行筛选，不是N1全自动推导完成或新增缺陷发现。

## 执行前协议

复用已冻结A/B/C归档及引用完整性检查，从其中4条C事件登记接口意图，不改变原核心、原关系或既有不足账本。
每条事件执行5个结构化候选：原C、等价改名、缓存自比较、后采样改deadline、后采样冒充期限参考。后3个为研究者依模型错误构造的开发控制，不冒充模型原始结构化输出。
预期8个匹配候选进入原核心但仍不足；12个偏移候选在进入核心前被拒绝。另重放4条B用于展示跨时刻诊断与C分开，原B结果不计新发现。

## 下一步沿主线推进

1. 当前入口先固定可复核接口卡→候选检查→事实/账本→原核心结果。
2. 接入模型生成的结构化候选，保留原始输出与自动字段映射，不把研究者改好的候选充自动成绩。
3. 用已声明支持域的另一份开发输入核对自动提取及事实接线；冻结方法后才评价独立问题/正常路径。新输入需先做接触与家族资格审查。
4. 只有特定缺证挡住某个已定义检查时才做有界补证，不追求所有helper或所有内核执行都证明完毕。
