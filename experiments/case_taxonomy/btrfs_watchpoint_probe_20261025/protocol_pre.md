# QEMU写观察点取证能力探针

不用模型、不追加被拒绝请求；本轮为独立最小ARM64程序的工具能力实验，不是Linux/Btrfs运行。现有父版vmlinux有符号表但没有.debug段，系统无gdb/gdb-multiarch；使用Python实现受限GDB远程串行协议客户直接连接本地Unix socket，使用既有交叉汇编器与QEMU TCG。无磁盘挂载、不修改原观测内核。

预设目标0x40100000：初始化0x1234后，在明确arm点安装Z2写观察点；执行同值写、改为0x5678、写回0x1234、邻接地址+4写。预期完整4字节观察点捕获前三次而不捕获邻接写；部分重叠2字节观察点也应捕获前三次。另做无观察点和错误地址(+8)控制，预期均0次。每格独立启动，明确起止断点和最多8次停止上限，保存协议请求/响应、PC、内存值、程序符号与二进制SHA。

实际停止发生在写前/写后不预设，由返回PC/内存值判断；不将无触发自动视为没有写。若控制不符合预期，保留原件并判工具方案未准入。通过只支持本QEMU/单CPU/平坦内存/CPU store组合；不推广到内核MMU别名、DMA、所有CPU、对象释放重用或硬件观察点实现。下一阶段才决定如何核内核虚拟地址与对象身份。
