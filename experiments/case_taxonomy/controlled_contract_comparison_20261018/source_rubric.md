# N2.8 源码语义评分标准

用于在看到新checker结果前评价匿名原始回答M1/M2；之后才归因程序及人工各自增加了什么。两次回答使用相同八题，满分16。本文及JSON不发给模型。

**接触披露：**审核者此前已读这批开发源码、旧n25模型回答/程序结果及历史研究结论，本轮没有重新阅读旧final、semantic_review或candidate_checks，也未查看新回答/新checker。因此只是对新checker结果隔离的开发型助手审核，不称全局盲审、独立验证或人类专家金标准。评分只用原14份文档；不借旧运行、修复标签或包外helper补证。

| 题目 | 源码支持 | 必要前提与仍未知 |
|---|---|---|
| Q1 共同用途与对象身份 | s390 getter连thread_mask，x86连per-CPU sibling_map；共同锁循环按mask成员锁rq | 需同一合法目标/用途/config；实际CPU相等、最终地址与通知外链未证，不要求原始mask相等 |
| Q2 目标rq覆盖及必要/充分 | 锁循环只锁成员，后续在t==cpu时写目标rq关系 | 在该遍历承担目标rq保护的用途下self是必要候选；非空不够，self也不充分证明整组/leader/稳定 |
| Q3 s390资格与条件出口 | mapper按online过滤，存在clear→copy、非HW clear→set→copy；外层为possible循环 | 原语、合法目标/存储、覆盖和无干扰须明示；实际guard/HW效果未知，online≠准备完成 |
| Q4 s390局部期限缺口 | notify在set_online及本入口update前 | 只有通知进入共同消费者且依赖本轮更新才形成条件性缺口；不能推出入口必offline或仅提前调用就够 |
| Q5 x86顺序与准备 | setup集合及自成员处理，map调用→notify；callin→online | 同CPU、目标迭代/原语及稳定未证；调用或setup位不等于全部准备，不要求先online |
| Q6 空组与其他leader | weight1跳过leader；其他路径搜索非当前CPU的self-core leader；空组无leader | 局部分支不是完整规范或真实运行；无WARN不等于满足，存在leader不证明全组硬件语义 |
| Q7 指针/探针/原读/打印 | getter取指针，额外探针在关中断前，之后原循环读；解锁后打印旧记录 | 探针不代替精确原消费或全局首读；采样与循环间稳定未知，标签不充真值 |
| Q8 稳定性与最终等级 | 多次读共享mask可提出快照/协调需求，但unlock体和writer协议缺失 | 保留局部条件候选且whole不足；不强制唯一实现、不由本包宣布A正常/B实败或独立增益 |

每题2分：核心事实及实质相关前提/未知正确；1分：部分正确且无关键反向断言；0分：遗漏核心、仅泛称不足或关键矛盾/过推。无需逐字罗列清单；末尾笼统免责声明不能抵消前文强断言。另列无依据强结论，不把格式、引用绑定或人工改判加到原回答语义分。

精确原文定位、条件、未知、禁用过推与逐题评分字段见source_rubric.json。16分是这批开发问题的覆盖记录，不是检测率或项目总体能力。R3未恢复，未新增源码/运行。
