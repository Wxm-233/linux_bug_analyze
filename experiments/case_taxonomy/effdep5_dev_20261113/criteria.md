## 一、纵向信号是什么

公共层调用架构接口 I 之后，**因为相信 I 已经产生了某个效果，跳过了自己本来要做的同类工作**。X1 是典型：

```
if (zero_tags) {
        for (i = 0; i < 1 << order; i++)
                tag_clear_highpage(page + i);   /* 架构接口：相信它顺带清零了页 */
        init = false;                           /* 于是关掉自己的清零 */
}
...
if (init)
        kernel_init_pages(page, 1 << order);    /* 被跳过的同类工作 */
```

在没有 MTE 的架构上，`tag_clear_highpage` 是空实现，页就没被清零。

## 二、抽取（改 `effdep_extract.py`，另存为 `effdep5_extract.py`；写死）

在上一版事实的基础上增加两项：

1. **调用的守卫变量**：每个调用多记一项，即包住它的 `if`、`while`、`for`、`switch`、`?:` 的条件里出现的变量。只算调用位于语句体内的，调用就在条件里的不算。
2. **常量赋值**：函数中形如 `v = 常量`（右边只由字面量或枚举常量组成，包括 `true`、`false`）的赋值，v 是局部变量或形参。记录位置、行号、变量名和它自己的守卫变量。

范围、配置、构建方式与 `effdep_dev_20261113` 相同（判据第三、四节）。12 个样本的源码和构建已经删除，需要重新导出、部分构建、抽取；当前版本 riscv 只重新抽取。arm64、x86_64 不重抽，本轮不用。

## 三、候选（写死）

在公共代码（不在 `arch/` 下）的函数 f 中，同时满足下列条件，记为一个**纵向候选**：

1. f 调用了架构接口 I（接口集合同第二版，含修订 1，即同一时间点的定义）。
2. 在这次调用之后、相隔不超过 8 行，有一次常量赋值 `v = 常量`。这次赋值的守卫变量是那次调用守卫变量的子集，也就是在同一层或更外层，同一个分支里。
3. 在这次赋值之后，f 中另有一次调用 E：E 的守卫变量包含 v；E 不是 I；E 的效果类别非空（类别和调用闭包的定义同第二版 I1，并沿用第三版 J3，即排除 `_bit` 一类的名字）。

**纵横成立**（师兄文章“性质”的两半）：除了满足上面的纵向条件，同一时间点的源码扫描（第三版的扫描器）中，I 至少在一个架构上是平凡定义（或者该架构用的通用默认是平凡的），并且至少在一个架构上是非平凡定义。也就是说，“这个效果不是每个架构都产生”。

**得分** = 3 × 稀有度（同前）× 补丁证据（同前）×（纵横成立为 2，否则为 1）。按（f, I）去重，取最高分。
