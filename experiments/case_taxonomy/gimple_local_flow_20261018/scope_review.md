# N2.12 两份已存 GIMPLE 消费者的范围预审（2026-10-18）

本审查只读 N2.11 已绑定的完整 `old_s390.consumer.gimple.txt`（222 行）与 `old_x86.consumer.gimple.txt`（231 行），以及上一阶段 `next_step.md`；尚未读 N2.12 新协议/实现/结果，也未调用模型、编译器或取得新 Linux 源。两个文件来自同一既知父版公共函数 `sched_core_cpu_starting` 的两份既有配置表示，并非独立新案例。

可承诺的最小事实层是**可归属的字面结构**：两份输出都显示 `smt_mask = cpu_smt_mask(...)`、`_12 = cpumask_weight(smt_mask)`、两次 `cpumask_next(t, smt_mask)` 调用，以及 `rq->core` 的显式 load/store。s390 的该字段在原源码注解行 5762、5773、5789 为读取，5787 为写入；x86 同样出现这些源码注解行。5769–5775 的搜索循环和 5783–5789 的后续循环在 dump 中有 label、条件 goto 和回边。可以保存每个操作的 dump 字节位置、源码注解和所属 profile，但不能据此证明调用返回、循环确实执行、`rq` 指向同一对象、字段内容正确或架构提供者满足合同。

冻结前建议把以下边界落实到提取协议与拒判规则：

1. **词法层。** `[/root/.../.cache/.../core.c:line:col]` 注解含点号和斜杠，嵌入汇编字符串也含 `.section`、`.pushsection`、`.long` 等；先用保长度的状态扫描分离路径注解、字符串/字符与跨行 asm 操作，再识别代码 token。不能用原行直接匹配 `obj.field` 或把 asm 里的 label/指令统计为 C 字段、控制边。保留原片段/摘要、注解坐标和掩码映射；未闭合或交叠异常返回不足。
2. **GIMPLE 名称与成员。** `D.80198`、`D.81104`、`cpu.358_1`、`cpu.305_1` 是整体的临时/版本标识符，不能拆成对象 `D`/`cpu` 的字段访问。字段事实须限定到明确的 `->core` 等成员语法及可定位的赋值侧；不要从路径 `.c`、临时名称中的点或 asm `.section` 产生字段。两 profile 的编号不同，不能靠原始临时名做跨架构对象同一性。
3. **局部值流。** 只在同一无屏障的直线段中把赋值左侧版本名连到右侧读取，需显式重赋值/kill 与未知值处理。`_5 = rq->core; _6 = rq != _5; __ret_warn_on = (int) _6` 可记录“值依赖”及每条类型转换，但 cast 不保证值等价；`__builtin_expect`、`cpumask_weight/next` 等调用把后续值与副作用留未知。label、条件/无条件 goto、循环回边、call、asm、`try/finally` 均切断跨段自动链；没有 CFG/dominance/alias 证明时不能跨接到第二循环或首次消费期限。
4. **控制边与非返回标志。** `if (_12 == 1) goto <...>; else goto <...>`、`goto unlock` 等可列为*显示的语法控制边候选*，不自动断言目标可达、循环覆盖范围或未知调用/asm 必返回。`__ret_warn_on`、`D.80211`/`D.81117` 等警告/诊断表达式，以及 `flags` 在 finally 的 `{CLOBBER(eol)}`，均不能当作函数返回、已执行的检查成功或错误标签。两份 dump 还有 `void unlock = <<< error >>>;` 的内部打印形状，应按不支持/非语义占位处理，不能据字面认定程序错误。

因此，本阶段若能给出带原文定位的局部 load/store、直线赋值依赖和显示的分支目标，已是有价值的前端事实；完整逐成员合同、能力/期限匹配、调用效果、跨架构因果和自动发现仍须另证。旧 N2.10 冻结结果和独立挑战不因此改变。

## 预登记协议复核

随后只读了本阶段 `protocol_pre.json`，仍未接触独立 source-truth 检查或新方法实现。协议已明确两原片段及 binding 的摘要、旧源开发接触、无名称硬编码、调用/内存写/控制流/asm/try-finally 的局部依赖屏障，以及机器事实与解释分离，范围可实施。实现冻结前需特别验以下点：

- 注解与跨行 asm 的状态扫描必须按语法状态和括号/引号配对，不能用第一处 `);` 或按物理行截断；annotation 只在 asm/string 外解释为源位置。每个 `opaque` 保留原字节区间，不能悄悄从覆盖率分母删除。
- `<D.80225>:`、`unlock:` 与版本变量 `D.80198`、`cpu.358_1` 必须分属 label/identifier 语法；`if (...) goto A; else goto B;` 给两条显示目标边，目标找不到或不唯一均显式 unresolved。只记录文本显示边，不从相邻行推控制后继或调用必返回。
- 局部版本链只跨同一已支持直线段。读 `rq->core` 是内存 load 事件，不凭相同字段字符串判断与后续 `rq->core = core_rq` 同一对象；`rq` 在两循环间重新赋值，必须保留这一事实。调用参数可引用既有版本，但调用结果与副作用未知，链在调用处截断；cast 的依赖只表示语法来源，不做数值等价替换。
- 覆盖率应分别给原文可定位语句、支持事件、明确 opaque/unsupported、跨屏障被拒的查询数；整段源码若只抽出几个 load/store 不能报“已覆盖函数”。独立参考是既有已读源上的源码忠实度检查，不是新 Linux 泛化率。
