## 建议的下一步（按投入产出排序）

1. **实现一致性·横向少数派扩到“原子性”和“present 断言”**（M6、M18）。
   - 做法：同名架构实现（`*_get_and_clear*`、`*_huge_get_and_clear_full` 等）里，多数用 `xchg`/原子操作而少数不用；或者少数在函数里断言 `p?d_present()`，而公共调用方会传入非 present 项。
   - 能复用 xvdom/ctxeff 的少数派机制和 P1 的 present 知识。页表方向，是我们最熟的领域。
2. **实现一致性·提交级“通用实现改了、覆盖实现没跟着改”**（M14，部分覆盖 M16）。
   - 做法：提交改动了 `__weak` 函数，新增了效果（新调用或新条件），而有覆盖实现的架构在同一提交里没改。
   - 直接接在今天的 weakov2 上，代价最小。
3. **页表封装：非 arch 代码直接读写 `pte_t *`/`pmd_t *`**（M9；也解释了 adef440 的真正问题）。纯词法规则，代价小。
4. 调用上下文检查扩大读取范围，加 SIMD 可用性规则（M17）。
5. `__ffs(0)` 和 `access_ok` 两条通用规则（M3、M8）。可做，但 M8 不算跨架构问题，优先级放低。
