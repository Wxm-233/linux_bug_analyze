## 一、改进

1. **条件 typedef**：同一个名字有多处 typedef，其中有的定义处在“只在 64 位上编译”的 `#if` 块里（按第二版的 `line_only64` 判断），就只用不在这种块里的定义。例：ntfs3 的 `CLST` 在 `CONFIG_NTFS3_64BIT_CLUSTER`（依赖 64BIT）下是 u64，否则是 u32，32 位上取 u32。
2. **Kconfig 的 `select`**：一个选项如果
   - 没有提示（定义里没有 `bool "…"`、`tristate "…"`、`prompt`），
   - 没有无条件打开（没有 `def_bool y`、`default y`），
   - 并且每一处 `select` 它的地方，要么选择者本身依赖 64 位，要么 `select … if 条件` 的条件里（按 `&&` 拆开）有依赖 64 位的项，

   那它也算依赖 64 位。和 `depends on` 一起求不动点。
   - **按架构分开算**：`arch/X/` 下的文件用“通用 Kconfig + 架构 X 的 Kconfig”算出的集合；其余文件用全部 Kconfig 算出的集合（某个架构无条件 `select` 了它，就不算）。
   - 例：`MIPS32_COMPAT` 只被依赖 64BIT 的 `MIPS32_O32`、`MIPS32_N32` 选中；loongarch 的 `ARCH_SUPPORTS_HUGETLBFS if 64BIT`。
3. **Makefile 的条件块**：识别 `ifeq ($(CONFIG_A)$(CONFIG_B),yy)`、`ifeq ($(CONFIG_A),y)`、`ifneq ($(CONFIG_A),)`、`ifdef CONFIG_A`（取正向条件，`else` 分支不算），块里的 `obj-…`、`xxx-y`、`xxx-objs` 都带上这些条件。同一个 `.o` 出现在多处时，**每一处**都带依赖 64 位的条件，才算只在 64 位上编译（第二版是任一处就算）。例：bpf `arena.o`。
4. **字段写入来源的值域**（新规则，主攻 A 形态）：
   - 类型是 W（恒 64 位）的结构体字段，如果在**同一个子系统**里，所有写入它的值都是“已知不超过 32 位”的，那么在这个子系统里读它，不算 64 位的来源。
   - 子系统按路径划分：`fs/X/`、`arch/X/`、`kernel/X/` 各算一个（`kernel/` 直属文件算 `kernel`），其余按第一级目录。
   - 写入包括：
     - 赋值 `p->f = 表达式`；
     - 调用 `iget_locked(sb, x)`，算作写 `struct inode` 的 `i_ino`（它在 `fs/inode.c` 里把 x 存进 `i_ino`）。
   - “已知不超过 32 位”指以下任一种：
     - 表达式经过缩小范围的运算（同第二版的 `reduced`）；
     - 表达式里每个基本项都是下面之一：
       - 类型已知为 N 或不超过 32 位的整数类型（`int`、`unsigned int`、`u8`～`u32`、`s8`～`s32`、`__le16`、`__le32`、`__be16`、`__be32`、`bool`、`enum`，typedef 展开后判断）；
       - 全大写的宏常量；
       - 返回值不超过 32 位的已知函数或宏（`le16_to_cpu`、`le32_to_cpu`、`be16_to_cpu`、`be32_to_cpu`、`get_unaligned_le32`、`get_unaligned_be32`、`get_unaligned_le16`、`get_unaligned_be16`、`get_next_ino`，以及第一版类型表里返回这些类型的函数）。

     数字字面量不算基本项。
   - 至少要有一处写入，规则才生效；有任何一处写入不满足条件，规则就不生效。
5. 其余规则同第二版。
