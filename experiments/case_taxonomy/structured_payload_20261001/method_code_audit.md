## 初审发现与处理要求

1. **typedef 数组阴影误绑定（必须修正）**。外层参数 `struct device *dev` 是 host 字段，内层 `encoded_dev dev[1]={{.value=cpu_to_le16(7)}}` 实际是 `__le16` 字段。内层赋值与发送使用该数组的首元素，但提取器忽略 typedef 数组声明，把 `dev->value` 绑定到外层 host 参数，输出 candidate。这不是仅有未知值路径，而是选错了实际声明，须拒判或建立真实绑定。
2. **括号成员预编码未拒判（应修正或明确不足）**。`(dev)->value=cpu_to_le16(7)` 后再将 `dev->value` 写入小端载荷，现有直接成员写检查漏掉括号形式，仍输出 candidate；源字段已明确写入编码值，不能仅靠 host 类型推出缺转换。无须扩大检测语法，保守拒判即可。
3. **条件 include（已见修正）**。父执行者独立发现；本探针中 `#if 0` 与未知 `CONFIG_X` 下的 include 均已输出 insufficient。头文件可达性只是有界拼写，完整预处理与编译适用性仍未证。

阴影反例的 `method_shadow_probe.c` 已以 WSL GCC `-std=c11 -Wall -Wextra -Werror -Wno-unused-parameter -fsyntax-only` 编译，exit 0。该文件是缩小合成源码，typedef/转换宏是审计替身；只证明反例属于合法 C，不证明历史内核或硬件。
