## 二、三种契约（写死）

**架构接口**：同 `depmine`，即当前版本扫描里有架构自己的定义，并且还有通用定义或至少两个架构定义的名字，去掉库函数（共 4868 个）。

**事实**：在每个调用点上，用 P1 检查器的守卫识别逻辑（G1～G4、if/else 链、布尔变量、同一来源的归一），算出此处“已知成立”的判断。判断的写法推广为：
- 条件里的调用 `P(x)` → 事实（P，真，x 的来源）；`!P(x)` → 事实（P，假，x 的来源），只取第一个实参；
- 条件里的裸表达式 `x`、`x != NULL` → 事实（非空，真，x）；`!x`、`x == NULL` → 事实（非空，假，x）。

**K1 前置条件**：对架构接口 A 的第 k 个实参，统计 A 的所有调用点中，同一来源上带有事实（P，极性）的比例。满足下面三条就成为一条契约“调用 A 之前，第 k 个实参要满足 P”：
- 调用点数 ≥ 5；
- 比例 ≥ 0.8；
- P 不是 A 自己。

缺这个事实的调用点就是“偏离”。

**K2 返回值检查**：对架构接口 A，看它的返回值有没有被检查。下面三种算“查过”：直接用在条件里；赋给变量 v，之后 v 出现在同一函数的某个条件里；v 被传给 `IS_ERR`、`IS_ERR_OR_NULL`、`WARN_ON*`。返回值被丢弃，或者赋值后从没进过条件，算“没查”。调用点数 ≥ 5、查过的比例 ≥ 0.8 时成为契约，没查的调用点就是偏离。

**K3 后置效果**：对架构接口 A 的调用点，记下同一函数里、它之后出现的、与它至少共享一个实参来源的调用 E。共享的来源要排除平凡来源：`mm`、`vma`、`NULL`、数字常量、`current`。E 限于架构接口和效果族函数（刷 TLB、刷缓存、屏障、写页表项、清页，以及 `update_mmu_cache*`、`flush_dcache_*`）。调用点数 ≥ 5、比例 ≥ 0.75 时成为契约“调用 A 之后要做 E”，没做 E 的调用点就是偏离。

**排序**：同一调用点上的多条偏离合并成一条。按下面四个键排序：
1. 契约比例（高的在前）；
2. 调用点数（多的在前）；
3. 种类，K1 > K3 > K2；
4. 文件、行号。

**范围**：挖掘和报告都只看公共代码：`mm/`、`kernel/`、`lib/`、`fs/proc/` 的 `.c`，`include/linux/` 的 `.h`，再加上修复改到的公共文件所在目录。源码直接从 git 对象读，不构建。
