# N2.11 独立证据边界复核（执行前）

本复核只读预登记协议，未执行编译器、读取新输出或补充源码。命令安全/输出隔离由另一角色另审，本文件重点约束编译器输出怎样服务研究。协议方向适当：停止把普通C形态适配当作真实Linux分析，用已有配置的完整`.i`检查真实GNU前端和可用表示。

## 可接受的前端结论

若精确登记`.i`经指定目标GCC一次处理成功，最多证明“当前该GCC与保存参数能够处理这份已预处理的配置材料，并产生对应输出”。须记录编译器版本、实际argv、输入/配置前后SHA及输出SHA。它不证明历史编译器精确重放、完整内核可构建/可运行、架构准备效果或自动契约提取成功。两profile是同一已读修复背景的配置材料，不是两个新案例。

这里使用的是协议中`.config`的明确SHA及绑定manifest，不得拿同名profile替换为旧运行配置，或把不同配置的观测倒灌为本次源码证明。即使编译成功，原N2.9/N2.10失败与0比较结论仍不变。此前`.i`/配置来源与当前GCC输入身份是不同命题；保持既有材料的预处理/历史精确性限制。

## sched_core_cpu_starting的输出盘点要求

只截取精确函数本体，保留完整声明、首尾边界、原dump字节偏移/行区间和hash。若名字被克隆/内联、函数未出现或边界不清，保留不足；不混入相邻helper或以另一个同名片段补齐。声明位置、dump行号和GCC给出的原C位置分别记录，不能混作同一种坐标。

按实际GIMPLE分别登记以下结构，不预填其必然存在：

1. `cpu_smt_mask(cpu)`及目标rq地址的来源表达式；GNU per-CPU表达式若被拆成临时量，保存其定义/使用坐标。调用存在或临时量同形不证明最终对象、实际CPU身份或全部alias关系。
2. lock调用和weight单成员短路，以及进入搜索循环的实际guard；loop/goto计数只作结构盘点，不等于循环完整性证明。
3. 搜索中跳过目标、读取某候选rq->core、与自身rq比较、给局部见证赋值后退出的关系。这里可能支持局部“找到一名”条件，不能直接变成所有成员此前都已准备或硬件同核关系。
4. 无见证时的诊断/转移，以及随后循环里“只在t==cpu时写rq->core”与每成员关系检查的先后。RHS字段读取、LHS字段写入、比较与诊断须分开；更新后的逐成员条件不能改写为入口前全称条件。
5. 解锁和退出路径；未展开unlock、mask原语、其他writer与通知外链就保留缺口。若源含观测，也必须与原消费分开；若本份是非观测材料，不从旧运行探针推得本次实际内容。

## 源坐标与关系的核对条件

至少对上面几类关键位置逐项检查：GIMPLE位置是否经原`.i`行标记指向对应函数/原C行，引用语句是否仍保留原意，临时量或MEM写是否可回指原表达式。源行标记只提供出处，不自动证明静态类型、别名、对象同一或内存可见性。`original`、GIMPLE、目标汇编可能处在不同降低/优化阶段，须明确采用哪份表示；不能跨表示挑选最有利片段拼成已验证CFG。
