# N2.12：真实IR局部来源链与公共消费条件（待执行）

目的：从真实配置源码取得公共代码的局部要求，并与架构准备的资格、对象和期限连接。N2.11已解决所查GNU源码的编译器入口；尚未解决来源链和义务推导。

1. 仅复用本轮两份完整GIMPLE区段及既有源码/配置绑定，先注册有限输入与输出协议。从编译器注解中分开代码和源路径/字符串/asm，避免词法字段清单的污染；记录临时变量定义、使用、条件和出口的准确坐标。不给程序手填CPU关系、见证谓词或预期结果。
2. 先做可验证的局部连接：指针由何处取得，何处真正读内容；条件中某值来自哪次字段读取；分支如何选出首个见证；哪些分支写入该关系，之后在哪里检查。真实WARN诊断后可继续执行，不能强制塑成toy的if-return。局部直线定义—使用与跨分支/回边关系分开，不能用最后一次文本赋值代替到达定义。多定义、未知外部调用、per-CPU地址计算、asm及内存别名不足时保留未知，不递归补齐全部helper。
3. 用“存在见证不等于全体此前准备”“指针取得不等于内容读取”和“更新后检查不等于更新前要求”三项已知模型过推作开发反例。保留正常分支、单成员退出和未到达路径；没有源码依据就不输出强制义务。机器事实、模型候选及人工接口依据分别记录。
4. 完成一轮有限接线后再安排同材料模型对照和未参与开发的同用途问题/正常对照。新评价须预登记、先预测再揭示修复，记录已读、初筛及家族接触。本轮已知区段不能再算留出；没有真实架构差异和契约依据就不计跨架构检出。

退出条件：一份可复用局部来源协议、真实区段的程序结果与独立源码核对，明确支持/不足及人工贡献。不能以增加语法测试、模型输出或字段数量代替实质联系。正式独立0/0、N1/N2未完成和R3暂缓状态保留。
