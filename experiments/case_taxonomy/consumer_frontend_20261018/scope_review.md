# N2.10 冻结前范围审查（2026-10-18）

本次只审阅 `protocol_pre.json`；尚未审实现、开发测试或独立挑战的源码与预期。协议将普通 C 组件的有限消费条件提取和真实 Linux 契约判断分开，并将 N2.9 已揭示的 9 个源及 2754 条记录限定为开发材料。此范围可以推进；以下不变量须在方法冻结前由实现与测试落实，不能由协议文字直接视为已验证。

1. **词法入口与身份。** 注释屏蔽应为状态机，区分普通文本、行/块注释、字符串、字符及转义；只用等长空格替换注释的非换行字符，保留 `\r`、`\n` 和原始坐标。原文 SHA、解析视图 SHA 与坐标映射分别留存。字符串中的 `//`、`/*` 不能触发屏蔽；未闭合字面量/注释、行续接、预处理指令及不支持的 GNU 形状均返回不足，不能删除有作用的语句再解析。CRLF、制表符及非 ASCII 输入应明确坐标单位，或保守拒绝无法保证映射的输入。
2. **作用域与求值。** 局部标量拷贝不是指针别名；同名遮蔽若未实现就拒绝。循环体局部声明每次迭代重新进入作用域，`continue`、`break`、`return` 后不得保留上次的值。界限必须是不可变且不与任一循环索引重叠的已初始化标量；隐式 `for` 初始化/递增也算写入。表达式副作用、越界、未初始化读取、未知控制流不能跳过而留下“已证”结论。
3. **搜索与消费条件。** 首次命中的赋值可能仍等于哨兵，因此 `exists(predicate)` 不等于后续守卫通过，也不能在 `break` 后利用较晚的好见证。第二循环只对实际抵达的成员产生观察；跳过成员和空域单列。直接返回及单调标志位路线均按真实执行顺序记录，标志位只允许初始化 0、条件性 0→1 和循环后测试，任何重置或其他写入须拒绝。检查发生在本轮数组写入之前时，不能称为更新后的检查；任意返回码只表示控制流，不自动解释成故障或正常。
4. **观察接口的解释。** `iteration` 是第二循环 0 起计的序号，不自动等于 CPU 编号；`predicate_value` 是实际分支条件真假，不是语义正确性。`writes_before` 必须只数该迭代中检查前实际执行的数组写入，不数静态语句或前轮写入。该数本身不证明写入与检查针对同一对象；IR/trace 还需保存写入目标与被检查对象的可追溯身份，否则只能称时序观察，不能推出同一成员已准备完毕。标志位的循环后判断应与逐轮观察分开。
5. **验证口径。** 冻结前开发测试须覆盖注释/字面量/CRLF 坐标、局部声明重入、首次哨兵命中、`continue` 缩域、直接返回与单调标志、检查前/后写入、越界和不支持输入。独立挑战解封后应报告实际被接受的源数、真正执行比较的输入数、返回值对照与独立 Python 参考观察对照；零比较不得称通过。C 原生运行只交叉核对返回值，Python 观察不能反称 C 原生观测。原 Linux D05/D10 的 GNU 不足仍是有效结果，组件通过不升级为 Linux 自动检测或独立新案例。

结论：协议范围和隔离方式可用。最需要冻结前明确的是 `writes_before` 的对象绑定与坐标单位；若未补，相关输出应只解释为有限执行轨迹，不用于同对象的消费期限证明。
