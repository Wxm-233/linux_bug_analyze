# 怎样用GPT做第二次复核（收紧定义后）

## 文件夹里有什么

| 文件 | 用途 | 交给GPT吗 |
| --- | --- | --- |
| `复核说明（交给GPT）.md` | 任务说明：机制分类、跨架构定义、答题格式 | **交** |
| `全部40条材料.txt` | 40条提交的说明和改动，合在一个文件里（约97KB） | **交** |
| `材料/` | 同样的内容，每条一个文件，便于分批 | 分批时用 |
| `answers_template.csv` | 空白答题表，前三列已填 | **交** |
| `使用方法（给用户）.md` | 本文件 | 不交 |

第一遍的标签不在这个文件夹里（在上一级的`second_sample_v2_key.json`和`labels_v2.json`），**请不要把它们交给GPT**，否则就不是独立复核了。

## 步骤

1. 新开一个GPT对话（不要在有本项目上下文的对话里做，也不要用上一次复核的对话）。
2. 上传三个文件：`复核说明（交给GPT）.md`、`全部40条材料.txt`、`answers_template.csv`。
3. 发一句话，例如：

   > 请严格按照《复核说明》完成40条提交的标注，输出填好的完整CSV（40行，带表头，顺序不变）。

   如果它一次输出不全，可以说“请按同一说明继续第11到20条”，以此类推，最后拼成一个表。
4. 把GPT给出的CSV保存为本文件夹（`second_review_v2/`）中的`answers.csv`（UTF-8编码）。
5. 告诉我已经放好，我运行`score_agreement.py`计算一致率，并列出不一致的条目。

## 需要知道的一点

第一遍标注也是由模型（Claude）完成的。所以这次得到的是**两个模型之间**的一致率，可以检查标签是否稳定、定义是否清楚，但**不能代替人工复核**。报告时会如实写明。若之后有师兄或老师能看几条，最好挑不一致的条目来裁决。
