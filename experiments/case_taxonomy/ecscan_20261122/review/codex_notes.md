# 编码一致性候选独立盲审

审查版本为 `df2908090cda`。34 组中，E01、E02 为可能，其余 32 组排除。判断单位是候选组，组内各构建的限制分别列在 JSON 中。

## 位宽与输入域

普通交换设备偏移受 `mm/swapfile.c:3449` 编码往返得到的容量限制。迁移项则在 `mm/rmap.c:2732` 起按页帧号构造，需要分别核实页大小、编码宽度和可迁移 RAM 的物理地址。RAM 的总容量不能替代最高物理地址。E02 使用 FLATMEM，不能拿仅见于 sparsemem 头文件的 36 位默认值直接排除。40 位 LPAE 格式也不能单独证明高地址处存在 RAM。

E04 的 XPA 行不能概括成仅保留低 22 位。按 `arch/mips/include/asm/pgtable-bits.h:188`，16 KiB 构建的移位量为 10，高半字容纳页号位 0～21；另一半字按第 51 行从页号位 24 开始保存。单测第 22 位可以证实往返失败，无法证实第 24 位也丢失。排除依据是该 Malta 构建的物理地址图。

## 比较前提

RISC-V 的九个 pte_huge 组合共享同一个观察函数。真实 hugetlb 调用已知道映射尺寸，组合表达式丢失了这个条件。折叠 PUD、尚未转为块描述符的 PMD，以及关闭透明大页后的恒假查询，也应分别和相同层级、构造阶段、配置下的实现比较。

本轮按数据包提供的分组和示例核读源码，核对相关构建配置。未逐个重跑组内表达式，未运行内核或验证特定机器的高地址 RAM。
