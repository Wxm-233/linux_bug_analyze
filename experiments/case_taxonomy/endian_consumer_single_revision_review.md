# 单修订版 `__le*` 字段消费检查：开发样本

此原型只给出**待复核位置**。每次调用仅读取指定的一个 Linux Git 修订中的 C 文件，以及两层带引号的本地头文件；不读取其修复提交、提交说明或后续版本来决定该次输出。这里为了检验规则，用此前已经阅读过的 ocfs2 提交 `c9dff86e` 的父版本与修复版本分别运行，属于开发集回放，**不是独立验证**。

运行：

```bash
python3 experiments/case_taxonomy/endian_consumer_single_revision.py \
  --linux-dir /root/repos/linux --revision c9dff86eb78a4b6b02b1e407993c946ccaf9bfb4^ \
  --source fs/ocfs2/inode.c \
  --output experiments/case_taxonomy/endian_consumer_ocfs2_parent.json
```

程序从 `fs/ocfs2/inode.c` 经 `ocfs2.h` 找到同版本 `ocfs2_fs.h`。父版本 `ocfs2_dinode_has_extents()` 的三个复核候选分别是：`inode.c:204` 的 `i_flags` 位掩码（声明 `ocfs2_fs.h:678`，`__le32`）、`inode.c:208` 的 `i_mode` 主机模式测试（声明 `:676`，`__le16`），以及 `inode.c:210` 的 `i_dyn_features` 位掩码（声明 `:693`，`__le16`）。同一个条件里的 `i_size` 非零判断和 `i_clusters == 0` 被记为**该次读取的局部正常**，因为零与非零不受字节交换影响。修复版本的对应三项改为显式 `le*_to_cpu()`，均归入局部正常。

按整个 `inode.c` 计，父版本是 **3 个候选、10 个局部正常、0 个拒判**；修复版本是 **0、13、0**。这 13 次读取不是 13 个独立案例。另有 `ocfs2_populate_inode()` 中的 `fe->i_flags & cpu_to_le32(MASK)` 等五处保持原样；它们将掩码转为与字段相同的磁盘表示，程序正确地未将其当成候选。因此，简单地将所有 `__le*` 字段的直接位运算都判错会产生明显误报。

规则的依据是同版本声明中的 `__le16/32/64` 表示类型与消费处操作所要求的表示：主机模式测试或主机常量位掩码需要先明确转换，零比较和同表示掩码不需要。出现候选并不证明运行时错误、具体架构可达性或该代码应当如何修复；这些仍需架构构建、执行及接口约定核对。程序拒绝不认识的算术表达式；不追踪别名、宏展开、函数间数据流、局部变量或两层以外的头文件，且只检查可解析函数参数中的结构体指针与 `if` 条件。预处理条件也未求值。无候选不能推断整个文件安全。

验证：7 个单元测试通过，包括单修订读取约束、同表示掩码、零比较、歧义拒判，以及已读 ocfs2 父版/修复版回放。尚未用于任何新保留样本；下一步必须先冻结代码、样本选择和结果判准，再做独立源码检验。
