# 源码、镜像和历史发布观察的有限连接

2026-10-27，研究者登记的用途关系，不是自动推导结果。

支持域是die已读案例的原/修复×x86_64/s390四个SMP/SYSFS构建，以及旧PID1观察器选择的CPU0、CPU1。原版本和源码政策见上轮cpu_source_policy_20261027，历史运行身份及观察器规则沿用N2.15/N2.16并重新核原始文件SHA。

本轮连接三项：冻结CPP可生成与旧目标逐字节相同的object；重定位后的属性组、完整表、属性名/回调及初始化回调能在链接ELF中逐项对应；该ELF按固定构建规则变换后与原启动镜像的解压载荷逐字节相同。thin archive实际成员另作输入链记录，不能仅凭成员名证明链接结果。

对同一镜像/config/profile/CPU的历史观察窗口，登记必要关系：published_die_any => compiled_die_any AND linked_die_any。published_die_any只接受完整三项均成功可读或均ENOENT的探针结果；部分缺失、基础文件不可读、身份错配均为不足。作用是核公开观察是否能连接到同镜像中的具体属性及读取实现，不把ELF符号存在当成已发布。

这里的compiled/linked是本轮工件事实，published是历史文件观察；这是明确注明分层取证的组合，既不把新的CPP伪装成当时保存的CPP，也不推断历史文本定义来源。相同二进制也可能由不同宏写法产生，因此历史源文本的原生来源仍unknown。旧版修复政策反事实结果及历史ABI不足保持不变。

读回窗口不是第一次消费期限。静态链接地址不是客体运行地址；initcall和CPUHP参数进入镜像不等于跟踪了回调执行顺序。实际文件读回可证明这些特定路径曾可读/缺失，不能证明物理拓扑、热插拔并发、所有读者或整个生命周期正确。

来源政策、对象/用途对应、重定位支持域及这种组合取证的含义仍需人工审核。统一判定核心保持不变；本轮不启动新模型、完整内核构建或guest，旧运行不计新实验或独立样本。
