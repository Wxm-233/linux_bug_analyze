# CPU信息导出的来源资格与版本化用途政策：限定方法卡

2026-10-27；die开发案例及同上下文package/core正常用途。完成限定开发方法阶段评审，未完成整个CPU家族、自动推导或独立评价。

## 要求及依据

提供者宏“存在”不充分。先按实际版本、配置和include顺序确定两项有效定义，再按具体公共用途决定是否允许这些来源。这里的原生来源不是物理值正确、数据已初始化或对象关系正确的同义词。

修复版die成组政策是 `listed_die_any => native_id && native_mask`。旧版文档允许默认值，给旧版应用修复政策必须标记反事实，历史ABI责任保持不足。package/core的文档默认政策另登记：其默认提供者在已审核用途内可用，不把die政策推广成全局fallback禁令。政策及宏体语义目前由研究者审核，程序不自动认定权威。

## 有限事实提取和检查步骤

1. 固定版本、实际配置、源码blob、工具及观察对象；缺配置/身份不能借用另一配置的结果。
2. 在完整CPP中按define/undef及源位置追踪有效宏，在读取函数展开和完整属性表取状态。按已审核宏体分类，架构头路径不能自动认证原生。
3. 以冻结CPP和原代码生成选项重建目标文件；本轮四份完整object与原文件逐字节相同，x86包含所需objtool后处理。它证明这份重建可生成同一object，不能唯一恢复历史文本。
4. 核thin archive成员及链接ELF的实际指针关系。重定位项逐项检查命名目标或实际字符串内容，其余字节全部相同；核属性组、数组、属性名、读取回调、initcall及CPUHP注册参数。本轮支持ELF64小端x86和大端s390的有限重定位类型，未支持类型直接不足。
5. 从历史启动镜像提取真实gzip载荷，与按固定规则转换的vmlinux整块比较。这样把相关代码/数据连接到已归档镜像；不只信缓存文件名或符号名。
6. 用原始日志、版本/config/image/profile及PID1身份连接历史CPU文件观察。三项都成功可读或都ENOENT才接受完整die组样本，普通拓扑项、CPU选择和结束事件须满足原观察器准入。
7. 在不变公共核心中分别评价用途政策，以及 `published_die_any => compiled_die_any && linked_die_any` 的必要关系。后者是新工件事实与旧发布样本的显式分层组合，不回填为历史宏来源。

## 已支持的结论

上轮四个实际配置CPP给出x86双原生、s390双默认，die表项3/3和3/0。本轮四份object可精确复现；四份镜像载荷匹配。镜像中共73个函数实体、77个数据实体完成有限重定位与字节核对，这些是按构建重复统计的工件实体，不是独立接口/缺陷数。

完整静态路径为initcall→topology_sysfs_init→CPUHP的add/remove回调→topology_attr_group→两张属性表→属性名与show/read函数。它不是实际执行轨迹。八个历史CPU观察上下文的发布必要关系成立，未将这八项计为新运行。两份s390日志另有16项默认值/单CPU列表读回，与审核的默认行为一致；没有补出未读取的package_cpus文件。

正常资格至少区分三种：x86有双来源且保留die；s390无双来源而修复取消die；同一s390默认值仍可合法用于package/core。还需区分来源明确不合该用途、来源未知、用途政策未知和消费者未触发；不能统一当阴性。

## 自动化及人工边界

程序负责受支持格式内的身份、CPP定义轨迹、完整表项、目标字节、指针及重定位关系、镜像载荷、观察准入和显式契约判定。研究者仍负责用途/规范权威与版本、有限宏体含义、对象角色、合法正常资格及证据组合解释。模型可提出候选，不能批准自己的候选；本轮没有新模型交付。

可复用的机制是“消费者用途与版本决定来源资格”，以及“源位置、编译实体、镜像实体和运行对象各自显式绑定”。迁移仍须替换宏体审查、CPP/ELF/观测适配器及用途政策，不是把宏名替换一下就有通用检测器。

## 未闭合与阶段停点

同一二进制可来自不同宏写法；原宏定义的历史文本来源仍unknown，旧binding结果不变。没有物理拓扑参考、首次内容消费/初始化期限、热插拔和并发稳定性证据。合法默认值不等于物理事实正确；initcall进入镜像不等于所有CPU回调执行条件都验证。

本轮13项错误输入控制全被拒判，其中9项实际ELF字节的内存副本变更、2项身份、1项观察列表、1项未知证据审核账本。它们是构造控制，不是独立正常/缺陷。独立正例/正常仍0/0，不报告检测准确率。

这条开发方法的有界评审现在可归档：版本化来源政策及源→object→镜像→发布样本已有具体步骤和可复现拒判。剩余上述问题保留，不能继续以重复相同矩阵来声称解决。下一项按机制队列核CPU身份与启动范围的编号域、数量限制和阶段传播，先复核已有材料与实际运行可行性，再登记最小证据补充；本案例的新平台或物理真值补证单独挂账。
