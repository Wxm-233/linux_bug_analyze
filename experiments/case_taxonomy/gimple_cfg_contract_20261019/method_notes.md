# N2.13 bounded compiler-normal CFG facts

`analyze_cfg(document, local_analysis=None)` accepts exact `{id,path,revision,text}` for the observed GCC early-CFG function record. It returns `status`, document/text identity, `blocks`, `edges`, `branch_polarity`, `loops`, `event_bindings`, `relations`, `branch_arms`, `unknowns`, and explicit false flags for runtime reachability, must-return and alias/contract proof. The root adapter, not this module, validates the shared preprocessing/configuration/revision identities and frozen old fact packet. Text hashes identify bytes/text; they do not establish semantic truth.

## Supported record and graph

The supported prefix contains a unique `;; Function`, declared loop count, loop header/latch or multiple-latches/depth/outer/nodes records, and one `;; N succs { ... }` row per actual body block. Body blocks use `<bb N> :`. Source annotations may include `discrim N`; `[INV]` is retained lexical metadata and never determines branch polarity. GCC annotations, comments, quotes and complete raw multiline asm are separated before block/statement recognition. The frozen N2.12 scanner's asm boundary and statement segmentation/classification are reused without modifying it.

The parser rejects duplicate/missing block or successor rows, unknown targets, unsupported metadata/control shapes, explicit goto or true/false targets inconsistent with successor sets, nonterminal/multiple terminators, malformed lexical input, inconsistent loop membership/parent/depth/latch edges, and more than 256 body blocks. Virtual entry/exit IDs are confined to the observed 0/1 convention and synthetic loop 0. Every edge originates from an explicit successor row. Physical block order is never used to invent an edge. Loop nodes and exits remain compiler-reported normal-graph structure, not an inferred helper iteration domain.

Event `kind` uses the original N2.12 vocabulary. Each block holds its full raw range, statements, source locations, compiler successors and supported terminator. Events retain character offsets, dump line ranges and raw/normalized code. Offsets count Unicode characters and preserve CRLF; source-location columns retain GCC's reported numeric values without reconstructing their tab/display convention. Recognized comment/annotation-only trivia remains in lexical spans rather than being emitted as a fake statement. Unsupported statements/effects remain visible; call and asm effects are unknown. A block containing asm may also contain later statements, so `asm_normal_successors` describes that **block's** successors, not an immediate instruction successor or proof that the asm returns.

## Finite control relations

For each explicit two-arm branch, the method follows each target only while its block has one compiler successor. It stops at a nonlinear block, an opaque block, a revisit, the source branch, or virtual exit. It records these finite chains and stop reasons. If both chains share a block, their first common block is a linear reconvergence cut; only each arm's prefix **before that cut** is used for `branch_to_store` or `branch_arm_asm_rejoins`. The method does not traverse the source branch again to claim that the false arm eventually reaches a store in a future iteration. Nor does this finite prefix establish full-function domination, postdomination, must-execute, path feasibility or returning call/asm behavior.

`branch_arm_exits_loop` separately reports a direct branch target outside a compiler-reported non-root loop, its target assignments and successors. Assignment names do not establish a witness, successful search or valid selected object. `asm_normal_successors` and asm-prefix reconvergence report compiler-normal continuation candidates, retaining `asm_returns_proved=false`. No CPU, scheduler, field or function name is hardcoded; the later source interpretation supplies the research meaning.

## Cross-IR binding

Old local events bind only when their document ID agrees, both sides have exactly one event with the same full source-location set and normalized supported shape, and discriminator information is comparable. Two old statements merged to one new statement and two new candidates for one old statement are both insufficient. If the CFG reports `discrim N` absent from the old event, the result is `insufficient_discriminator_not_comparable`, even if the path/line/column and code otherwise match. Paths and temporary names are not renamed to force a match. Branch/goto targets are omitted from cross-pass shape because the CFG uses BB targets; branch conditions remain exact. Asm shape uses its raw statement hash. Missing locations or unsupported shapes remain unbound.

These bindings place existing local facts in blocks; they do not add any cross-block reaching definition, memory alias, builtin semantic summary or consumer obligation. A CFG branch may therefore have clear compiler polarity while its old event binding remains insufficient.

## Development and stopping point

`development_tests_initial.json` preserves the first **14-method** targeted run, command, exit 0, stdout/stderr and exact module/test hashes. Cases cover successor/explicit-target consistency, physical layout independence, multiple latches and exits, future-iteration exclusion, source/discriminator/two-sided uniqueness, a real known multiline-asm component, annotation pollution and unsupported input. Review identified discriminator and two-old-to-one-new ambiguity before this first run; both fail-closed tests are included. No complete real-source runner or independent reference was read/run by the implementation role.

The two current Linux configurations are already-known development, not new independent defects or a detector evaluation. Root ran 29 combined method/regression tests and received the method review before executing the two complete records; this explanatory note was saved just after that output. There was no separate preregistered method_baseline.json, so this is a reviewed development replay, not a frozen independent evaluation. This stage stops at local compiler-normal control facts; the next research step is to connect a small number of conditional public requirements to existing architecture-provider qualification/object/deadline evidence, without expanding a general CFG engine.
