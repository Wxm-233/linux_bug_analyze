# 方向4第四轮：RISC-V页表遍历家族深挖（判据，读取任何修复内容之前写定）

## 背景

方向4在大页家族上有两点发现：

- “参照arm64找该覆盖而未覆盖的钩子”和“与arm64比较实现步骤”都有效；
- 但第三轮发现，“跟随arm64修复”推广到全部家族时无效，有效范围限于与arm64结构相似的家族。

页表遍历是下一个结构相似的家族：RISC-V和arm64都是多级页表，公共代码通过同一组页表辅助函数遍历它们。另外，第三轮在事后查看中发现了一条线索：RISC-V的`show_pte()`疑似存在arm64刚修过的无锁遍历问题。

本轮按方向4前两轮的方法：先读懂已确认的修复并归纳机制，再按机制写检查，做回溯检验，最后用在当前代码上。

## 第一部分：已确认案例

### 范围（用程序筛选）

v4.15到终点`df2908090cda`之间，带`Fixes:`、改动`arch/riscv/`的提交，满足以下条件之一：

- 改动了`arch/riscv/mm/`下的`pgtable.c`、`pageattr.c`、`fault.c`、`ptdump.c`、`kasan_init.c`；
- 改动了`arch/riscv/include/asm/pgtable*.h`或`arch/riscv/mm/init.c`，并且增删行中出现页表遍历相关的写法。

页表遍历相关的写法，指出现以下任一标识符：

- `pgd`、`p4d`、`pud`、`pmd`、`pte`加上可选的`p`，再接`_offset`（含后缀）、`_leaf`、`_bad`、`_none`、`_present`、`_get`、`_page`、`_pgtable`、`_table`；
- `pgtable_l4_enabled`、`pgtable_l5_enabled`；
- 含`walk`的标识符。

不含只改`hugetlbpage.c`的提交，那部分已在大页轮次处理。符合条件的超过40个时，用`random.Random(20261031)`抽40个。

### 归因（研究者逐个阅读后写定，之后才运行检查）

| 类别 | 含义 |
| --- | --- |
| **层级折叠** | 与RISC-V运行时决定页表级数有关：Sv39/48/57，`pgtable_l4_enabled`等；被折叠的层级上，辅助函数的行为与公共遍历代码的期望不一致 |
| **叶子与坏表项判断** | `pXd_leaf`、`pXd_bad`、`pXd_present`、`pXd_none`的语义与公共遍历代码的期望不一致 |
| **读取与并发** | 重复读取表项、没有用`pXdp_get`/`READ_ONCE`读取、无锁遍历与页表释放并发等 |
| 公共约定改变 | 公共遍历接口的约定改变，RISC-V未跟进 |
| RISC-V自身逻辑错误 | 与公共约定无关 |
| 其他 | 以上都不是 |

前三类是事先假设的机制。归因写入`cases.json`并记录SHA。

## 第二部分：检查

### 检查A：参照arm64找该覆盖而未覆盖的页表钩子

`include/linux/pgtable.h`中由`#ifndef 名字`或`#ifndef __HAVE_ARCH_*`保护、名字以`pgd`、`p4d`、`pud`、`pmd`、`pte`开头的可覆盖钩子。`arch/arm64/`覆盖了、`arch/riscv/`没有覆盖的，标记出来。覆盖的判定方法与大页第一轮相同。

### 检查B：同名函数的遍历步骤比较

比较对象：`arch/arm64/mm/`与`arch/riscv/mm/`下`.c`文件中的同名函数（不含`hugetlbpage.c`），以及`arch/arm64/include/asm/pgtable*.h`与`arch/riscv/include/asm/pgtable*.h`中的同名函数。函数内容取函数体，加上一层同文件被调函数。

| 特征 | 含义 | 判断方法 |
| --- | --- | --- |
| W1 只读一次表项 | 用`pXdp_get(`或`READ_ONCE(`读表项 | 出现`(pgd\|p4d\|pud\|pmd\|pte)p_get\s*\(`或`READ_ONCE\s*\(` |
| W2 无锁偏移 | 用`*_offset_lockless(`，或把已读出的表项传给下一级 | 出现`_offset_lockless\s*\(` |
| W3 先判叶子 | 下行前判断是否为叶子 | 出现`(pgd\|p4d\|pud\|pmd)_leaf\s*\(` |
| W4 判空或判坏 | | 出现`_(none\|bad)\s*\(` |
| W5 关中断或RCU | 遍历期间关中断或进入RCU读侧 | 出现`local_irq_(save\|disable)\s*\(`或`rcu_read_lock\s*\(` |
| W6 判存在 | | 出现`_present\s*\(` |

标记条件：arm64有、RISC-V没有。

### 回溯与当前代码

- **回溯**：对归入前三类机制的案例，在修复的父版本上运行A与B，看被修的钩子或函数是否被标出。
- **当前代码**：在终点版本上运行A与B，全部标记由研究者逐条核对，归为三类：
  - (a) 疑似问题；
  - (b) 有合理原因；
  - (c) 判断不了。

  疑似问题只记录，不对外报告。

## 事先写定的判断标准（描述性案例研究）
