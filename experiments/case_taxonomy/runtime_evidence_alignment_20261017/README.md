# N2.4：旧版架构对照的运行配置源码对齐

N2.3发现原非观测源码取证配置与归档运行配置不一致。本轮只对已经选过的旧s390/旧x86补取有效源码视图，未重新选择对照，也未将局部源码关系升级为准备完成。

从保留的五份`.o.cmd`恢复原编译参数，只移除依赖输出、将对象编译改成`-E`，通过无shell子进程在原build工作目录执行。没有运行make、重新生成配置、编译对象、链接或启动内核。五次预处理均成功；原协议的11个函数区域均取得。随后另行登记补充选择，从已生成的x86材料提取`smp_callin`一个定义，没有第六次预处理。初始11项与后补1项分别记录，不能称为事前冻结12项实验。

执行前核对归档的两套config、image、initramfs及观测源码摘要；执行前后38个受保护文件未变，其中包括全部10个既有对象。完整`.i`保存在WSL新缓存，项目内保存准确函数区域、编译器行号、摘要和执行参数。材料是带观测代码的当前预处理，历史构建时并未完整记录编译器与所有头的摘要，因此不能称精确重现了全部历史编译上下文。

## 本轮补强的关系

| 位置 | 旧s390 | 旧x86 | 可确认层级 |
| --- | --- | --- | --- |
| 公共`cpu_smt_mask(cpu)` | 展开为`&cpu_topology[cpu].thread_mask` | 展开为对应CPU的`cpu_sibling_map` | 配置下的准确词法来源，非运行地址等同证明 |
| 架构准备路径 | `update_cpu_masks`把对应`thread_mask`交给`cpu_thread_map`；后者按`cpu_online`限制准备 | `set_cpu_sibling_map`使用setup集合；包含明确的自身成员处理 | 有界源码关系，循环到达与helper效果尚需条件 |
| 通知前后 | `smp_start_secondary`先通知，再上线、更新mask | 补取的`smp_callin`包含准备与通知的先后关系 | 配置下的局部顺序，非完整跨过程效果证明 |
| 公共用途 | 两架构均保留`cpu_smt_mask`→`sched_core_lock`中的成员遍历/锁操作 | 同左，但per-CPU展开和锁底层不同 | 同用途消费见证，不要求两架构预处理文本相等 |

这支持继续围绕“架构提供的数据在共同消费之前必须满足什么条件”研究，而不只是检查某个初始化调用是否在前。需要同时核对资格集合、目标对象和准备期限；CPU最终online不能替代首次消费前的准备。

上述表格是研究者依据限定区域的综合，不是桥接模块自动推导出的正式特征。本轮没有重跑旧运行观测、读取未选运行结果、改写原N1事实或N2.1–3输出。两项正式字段仍不足；没有新增缺陷、独立样本或检测效果指标。
