# 判据：按被跳过的效果选规则（effrule_20261115）

2026-11-15，Claude。用户：“扩展规则映射”（上一轮给的选项是“按被跳过的效果系统扩展规则映射：写页表项 → R4，清页 → R1，刷 TLB → R2，刷缓存 → R3，然后统计当前版本还剩多少转人工”）。本文件在写新映射代码、做任何统计之前写定，SHA 存入 `criteria_sha256.txt`。

## 一、背景

流水线把每个静态候选（“公共层调用架构接口后把某标志置成常数，跳过了后面的某个调用”）映射到一条性质规则，再看有没有模板在 QEMU 里实际执行到它、性质是否成立。四条规则：

- **R1**：交给用户的内存必须先清零或初始化（模板 Z1～Z9）；
- **R2**：撤销映射或降低权限之后，旧的地址翻译必须失效（T1～T3）；
- **R3**：写入的代码在执行之前，指令缓存必须一致（I1）；
- **R4**：页表搬移之后内容保持（P1、P2）。

现在的映射（`r4_20261115/analyze_r4.py` 的 `r4_rule`）：被跳过的调用里有写页表项的函数就给 R4，否则用旧的 `rule_of`。`rule_of` 的问题：

1. 它看的是 `skipped_cats`，即被跳过的调用往下**三层闭包**里出现过的效果类别。`mem` 类只要求“有写操作”，几乎所有函数都有；三层闭包又很大。例如 `convert_ctx_accesses` 跳过 `bpf_patch_insn_data`（重新分配 BPF 指令数组），因为闭包里某处出现了刷缓存，被映射成 R3。
2. R1、R2 还要求资源名原样属于 `page, folio, pte, vmf, vma, addr`。上一轮 `rulemap2` 放宽资源名，新映射 0/2 合理，不采用。

本轮不再看资源名，改为**看被跳过的调用本身做了哪种效果**，只认四种与规则一一对应的具体效果，并且只取离被跳过调用**最近**的那一层。

## 二、新映射（写死）

1. **被跳过的调用集合 S**：候选的 `same_res_calls`，没有就用 `skipped_all`（与 `r4_rule` 相同）。
2. **四个效果族**，按函数名（完整匹配）判断：
   - **写页表项 → R4**：`^(__)?set_(pte|pmd|pud|p4d)s?(_at)?$`、`^set_huge_pte_at$`、`^(pte|pmd|pud|p4d)_clear$`、`^\w*ptep?_get_and_clear\w*$`、`^get_and_clear_ptes$`
   - **清页 → R1**：`^(clear_page|clear_pages|clear_user_page|clear_huge_page|memzero_page)$`、`^\w*clear_\w*highpage\w*$`、`^zero_user\w*$`、`^folio_zero\w*$`
   - **刷 TLB → R2**：`^\w*flush_tlb\w*$`、`^\w*tlb_flush\w*$`、`^\w*flush_\w*tlbs?(_\w+)?$`、`^sfence_vma\w*$`、`^\w*tlbi\w*$`、`^arch_tlbbatch_\w+$`
   - **刷缓存 → R3**：`^\w*flush_(dcache|icache|cache)\w*$`、`^\w*dcache_(clean|inval)\w*$`、`^\w*icache_inval\w*$`、`^caches_clean_inval\w*$`、`^\w*sync_icache\w*$`

   `memset`、`memcpy` 这类通用写不算任何一族，因为不看参数就不知道它写的是不是交给用户的页。
3. **最近效果**：
   - 第 0 层是 S 里的名字本身；第 1 层是 S 中各函数在该树事实文件里的直接被调者；第 2 层是第 1 层的直接被调者。最多到第 2 层；
   - 从第 0 层往下找，**在第一个出现任一效果族的层停下**，这一层出现的族就是“被跳过的效果”；
   - 事实文件用该树自己的：样本树用 `/root/work/effdep5/facts/<id>_pre.json.gz`，当前版本用 `CUR_riscv.json.gz`。事实文件里没有定义的函数不展开，只按名字判断，并记录下来；
   - 名字形如 `*_bit`、`*_bits` 的跳过（与 effdep 相同）。
4. **选规则**：最近层只有一族，就用该族的规则；有多族，按 R4 > R1 > R2 > R3 取一个，其余也记下来。一族都没有，规则为“无”。
5. **不再看资源名**，也不再看 `skipped_cats`。

4. **合理性**：对规则变了的每个不同候选（按“函数、接口、被跳过的调用”去重），读内核源码判断：
   - **合理**：被跳过的调用确实做了这种效果，而且作用在候选所说的那份资源上，跳过它会破坏该规则说的性质；
   - **不合理**：效果找错了（例如最近层命中的函数与候选资源无关），或者性质不是这条规则说的；
