# 大模型复核规则标记：程序核对模型引用的代码事实

## 这一轮要回答什么

前两轮中，模型复核规则标记时剩下的错误多是系统性的，其中一类是**说错材料里写着的代码事实**，例如说`arch_cpu_idle`“已带`__cpuidle`标注”，但代码中并没有。

本轮的做法是：
1. 让模型把判断所依据的代码事实，写成程序能查的格式；
2. 程序在该版本的代码上逐条核对；
3. 有不符的，把核对结果反馈给模型，请它重新判断。

| 文件 | 说明 | SHA |
| --- | --- | --- |
| `criteria.md` | 判据，实现之前写定 | `bf80951a…` |
| `factcheck.py` | 核对4种事实：函数是否带某标注、是否调用某函数、两个调用的先后、某调用所在的条件 | 见`delivery_manifest.json` |
| `build_step1.py` → `items.json` | 第一步提示词：在上一轮“加事实”的提示词上，只把输出要求换成带事实声明的格式 | 同上 |
| `check_step2.py` → `checks.json`、`step2_index.json` | 核对第一步的声明，为有不符的样本生成追问提示词 | 同上 |
| `run_calls.py` → `run_step1.log`、`run_step2.log` | 第一步59次、第二步3次 | — |
| `score.py` → `scores.json`、`answers.json` | 评分 | 同上 |

**核对程序的自测**：用7条已知结论的声明测试，第一版的“条件”核对把肯定和否定混在一起（例如`user_mode(regs)`与`!(user_mode(regs))`被当成相符），已改为同时比较条件内容和是否取反，改后7条全部正确。

## 结果

62次调用（59＋3）全部完成，约20万token。

**事实声明**：
- 模型共写出84条：
  - 相符81条；
  - 不符3条；
  - 无法核对0条。
- 有23个问题，模型一条声明也没写。
- 类型以“是否调用某函数”为主（63条），“带某标注”只有1条。
- **3条不符都不是模型说错了事实**，而是条件写法与程序对不上。例如模型把条件写成`else`；又如实际条件比模型写的更长，模型写的只是其中一部分。这3个问题的判断本来就是对的，追问之后也都没变。

**判断结果**：

| | 第一步：保留 | 第一步：去除 | 最终：保留 | 最终：去除 | 最终精确度 |
| --- | ---: | ---: | ---: | ---: | ---: |
| **新样本**（18） | **8/8 = 100%** | **10/10 = 100%** | 100% | 100% | 100% |
| 原样本（41，参考） | 12/14 = 86% | 25/27 = 93% | 86% | 93% | 86% |

前几轮的对照：

| 新样本 | 保留 | 去除 |
| --- | ---: | ---: |
| 不加事实（单次） | 88% | 90% |
| 加事实（单次） | 88% | 90% |
| 加事实，5次取多数 | 88% | 90% |
| **本轮：加事实并要求写出可核对的事实（单次）** | **100%** | **100%** |

**按判据判定**：新样本最终保留率100%（要求不低于90%），去除率100%（要求不低于50%），**本轮达到成功标准**。

## 改进从哪里来（事后分析，只作描述）

1. **不是来自程序纠错。** 新样本上没有一条声明被判为不符，所以一次追问都没有发生；原样本上追问了3次，判断都没有变。
2. **来自“要求写出可核对的事实”这种提问方式本身。**
   - `arch_cpu_idle`：上一轮5次中3次判错，理由都是“已带`__cpuidle`”。本轮模型写出了声明“不带`noinstr`”，这一条核对相符，模型据此判为真问题。要求写出可核对的事实，似乎让模型真的去看了函数签名。
   - `memset_io`：上一轮5次都判为真问题，本轮判为误报，但这一条模型**没有写任何声明**。这一处变化更可能来自提示词变化带来的随机差异，不能归功于事实核对。
3. **原样本上没有改进**：最终结果与上一轮5次取多数时相同（保留86%、去除93%）。仍然判错的几条，例如`die()`、`arch_ftrace_update_code`，模型写出的声明都是相符的，错在对内核行为的一般性判断上，而不是代码事实上。
4. **只跑了一次。** 上一轮显示单次运行的保留率会在75%～100%之间浮动，这一次正好落在100%，**需要重复几次确认**，才能判断这种提问方式是否稳定有效。

## 结论

- 按判据，**本轮达到成功标准**：新样本上留住了全部8个真问题，去掉了全部10个误报。
- 但改进来自“要求模型写出可核对的代码事实”这种提问方式，而不是程序纠错；程序纠错在本轮几乎没有被触发。
- 只跑了一次。下一步应先**对同样的提示词重复几次**，确认结果稳定，再考虑把这种提问方式作为复核这一步的标准做法。
