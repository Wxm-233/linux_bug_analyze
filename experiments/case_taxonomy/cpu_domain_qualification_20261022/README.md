## 得到的机制与边界

P01在特定Xen PV DomU条件下，将ACPI/MPS状态用于关闭APIC，早期限额因此可能先把`nr_cpu_ids`压到1；平台提供者随后按这个已收窄的上限枚举。后期虽已有Xen例外，也不能直接恢复前面被截断的域。这是**限制依据的适用范围与生效阶段不一致**的条件链，连接平台提供者与公共SMP使用，不是原始CPU号必须相等。

独立收尾复核补出关键配置前提：同一个`set_nr_cpu_ids()`在`NR_CPUS==1`或`CONFIG_FORCE_NR_CPUS`分支只告警、不赋值。上面的“上限变1”必须限定实际可赋值分支、原上限>1等条件。不能由函数名或词法先后推断所有配置有同一效果。

该例主要是x86内的guest/平台模式，未证明CPU ISA因果；作者提供历史回归说明，本轮没有实际Xen配置和运行。它不计新发现、正式独立CPU跨架构阳性或新的已运行复现。见[机制与五维卡](mechanism_card.md)。

P02能支持明确前提下的局部引理：若合法OF/SMP分支、非空接纳输入和初始映射/位图条件满足，最终possible域可以保持多槽。但是两个固件节点不等于接纳两个节点：其硬件ID还受`cpuid<nr_cpu_ids`过滤。本批未落实必要前提与指定公共域保证，故不能采用为正常对照。

**正常不足不是因为没有完整物理复现或所有secondary成功，也不要求另一架构采用相同Xen入口。** 原oracle提及PPTT/完整启动的未验证范围，不作为新增硬门槛；后续以[收尾复核](qualification_review.md)的窄理由为准。条件性源码保证、合法前提已认证和实际运行是不同层级。
