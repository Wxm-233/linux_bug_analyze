## 架构机制与仍未闭合的环节

旧s390按online资格准备，而且notify在上线/update前；修复改用setup并在notify前update。x86已有通知前准备路径。它们通过同一公共调度用途交接，说明要核对实际资格、目标和期限，不能只看更新调用是否在前。

但本轮没有逐条观测mapper写入或自动建立全部因果：

- 旧s390的`prepared=-1`表示未测，不改成false。研究者的原语解释不能冒充本轮完整准备效果。
- lock_snapshot的mask在local_irq_save和遍历前采样，解锁后才打印；不是精确遍历快照，多字段也非原子。
- 日志CPU/current及本地读取支持逻辑样本角色，不能据rq_self=1证明实际锁地址/所有对象别名。
- 离散采样相等不证明连续稳定；旧foundation旗标名称中的first_consumption或stable不改变这一限制。
- 非观测配置的摘要、旧配置CFG、修复运行材料不跨包拼接。新适配器只支持这四份归档，不能改名当通用检测器。

因此四项`relation_at_deadline`与`whole_path`保持insufficient；完整准备效果、物理锁对象、精确消费值和稳定性也明确为不足。N1/N2完整能力、生产链及独立评价未完成，正式独立正/正常仍0/0。
