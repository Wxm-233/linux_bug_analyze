## 结论与限制

- 按更正口径，以`Fixes:`为纽带可以凑出40个干净的严格跨架构缺陷兄弟（按T去重）；都带`Fixes:`标签，且没有一对出现在P0b的同作者池里，弥补了P0b池的盲区。
- 余量为零：后续质量核查只要发现一个不是同类缺陷的兄弟（例如两次修复只是修了同一引入提交的不同方面），有效样本就会低于40。
- 来源A中，“修同一引入提交”不保证修的是同一种问题；P1曾出现的兄弟关系质量问题可能在这里重现。
- 对这些对，同文件基线B1按定义为0，P1′的主比较应改为B2，以及“其他架构同一相对路径”的基线B3（例如`arch/x/kernel/foo.c`对应`arch/y/kernel/foo.c`）。B3在跨架构场景下可能很强，必须事先登记。
- 想留出余量，可以把范围向前扩展（例如从v4.19开始），并在登记前用同一脚本重新计数。
