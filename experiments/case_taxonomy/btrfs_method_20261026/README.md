# Btrfs接口判定方法：准备、裁剪与文件行为

2026-10-26。一个已读开发案例的方法收束；本轮只复核历史材料，没有新内核运行、模型调用或独立样本。程序输出见results.json、reconstructed_observations.json；原件绑定见inputs.json及source_audit.json。

## 消费用途与依据

目标是挂载选项max_inline消费几何缓存时，使用适合当前文件系统的上限。历史修复6f93e834的提交说明明确指出临时4096导致64K系统的上限错误，并将superblock几何读取和缓存准备前移至选项解析前。这是已知修复的开发依据，不是从未读源码独立推导出的规范。min表达式仅证明如何计算，不单独证明其操作数应该来自哪里。

历史父版0d977e0与修复版6f93e834、ARM64的三种页/扇区配置为本文支持域；不推广到所有版本、重挂载或全部Btrfs路径。旧模型完整候选与未决条件不改。

## 适用条件与目标关系

令r为合法请求，c为实际裁剪消费的缓存，d为同一对象在消费期限的权威几何参考，v为裁剪结果。

| 层次 | 关系与用途 | 当前判定边界 |
| --- | --- | --- |
| 运算事实A | v=min(r,c) | 旧插桩四条操作数支持局部算术；不批准规范 |
| 准备契约C | c=d，且d在消费期限属于对应文件系统 | 缺独立期限参考，仍不足；不能用后采样补齐 |
| 请求行为D | v=min(r,d) | 需要相同身份/期限参考；本轮仅用离线磁盘几何做诊断，不是正式D裁定 |
| 文件行为E | 在适用路径及全部门禁下观察inline/regular | 几何相等只是必要入口条件之一；成功写入和读回不保证inline |

对非负整数，min(r,c)=min(r,d)当且仅当c=d或r<=min(c,d)。证明：c=d显然；若c<d，r<=c时两边同为r，r>c时右边严格大于c；c>d对称。因此D在单次小请求上成立不能推出C。程序枚举0..32的35937个三元组仅作边界健全性检查，不是新案例或自动定理发现。C没有被弱化为D，旧候选没有被替换。

## 提供者、对象和阶段

准备源是所选文件系统superblock的sectorsize；消费者使用fs_info缓存。现有源码记录给出初始化4096、几何读取/赋值、parse的版本化位置，旧运行有对象/事件绑定。赋值的词法顺序不等于全部控制流支配，非零指针不等于跨挂载生命周期相同。需要核实参考来源属于当前对象、准备对该消费可见、路径是否合法且已到达目标事件。

## 正常几何对照及实际核查

从原验证器只重用初始化和第一层日志解析循环，逐字节SHA核原始boot/tree/super/result；6条观测和36条文件记录与历史结果完全一致。四份构建配置与build.json哈希一致，init.c来源一致；每个版本的4K/64K配置revision相同。此处验证归档构建记录，未重新核WSL当前Image文件。

| 页/扇区 | 请求2048（父/修复） | 请求8192（父/修复） | 文件行为意义 |
| --- | --- | --- | --- |
| 64K/64K | 2048/2048 | 4096/8192 | 6144及8192文件在8192请求下regular→inline |
| 4K/4K | 2048/2048 | 4096/4096 | 6144及8192文件均regular；不能期待超过几何上限 |
| 64K/4K | 2048/2048 | 4096/4096 | 此历史普通写回路径几何门禁不满足，全部regular不能视为准备缺陷 |

12条请求诊断只有父版64K/64K、8192这一条不等于min(请求,离线磁盘几何)。这是已知差异回验，不是新增缺陷。其余11条一致不代表11个准备契约正常例。1024文件在页=扇区配置为inline、subpage为regular；全部36条持久化读回成功。未插桩归档不提供消费缓存值，不能从裁剪结果反推出唯一缓存。

源码inode.c:1100的start==0 && sectorsize==PAGE_SIZE决定该普通写回inline尝试的入口；361–368还有文件范围、扇区边界、节点空间上限和max_inline门禁，后续仍可能回退。subpage配置的“不适用”仅指本inline诊断路径，不指整个文件系统或max_inline解析不适用。

配对政策分开：父/修复是历史版本对照；同版4K/4K与64K/64K同时改变页及扇区，不是单因素；同版64K/64K与64K/4K改变扇区且改变inline入口资格。三者均为ARM64，不能冒充不同CPU架构。正常几何可用来检查裁剪诊断的过强规则，但不能全都作为同用途inline正常对照。原选择器不改，本轮不新增选择器。

## 判定步骤与自动化分工

1. 程序验证原件身份、版本、实际配置和运行终态；人工登记来源权威、用途及合法条件，未知保留不足。
2. 将消费、结果写回、后采样事件分开，使用既有事件引文核验与观察能力检查；错误引用不由其他字段借用修复。
3. 按目标分别收集A/C/D/E所需证据。C/D缺期限参考时停止正式判断，另报明确标注的离线诊断；E未进入目标路径不当满足或违反。
4. 在外部审核的合法请求池上用已支持的min语义选择控制和区分探针；先说明改变哪些因素，再核实实际观测。
5. 输出关系、适用性、证据、人工输入和不足原因；模型仅提出候选，不自批来源、范围或期限。

本轮新增的是归档复核脚本、方法说明和边界计算，没有新增通用源码提取器。已有类型、引用、契约、观察能力及有限探针组件可复用；min、对象角色、期限登记、几何合法性和文件extent解析仍需接口适配。直接沿用旧候选并不表示N1自动推导已完成。旧111项测试数量不重计，本轮执行的是归档断言与算术边界检查。
