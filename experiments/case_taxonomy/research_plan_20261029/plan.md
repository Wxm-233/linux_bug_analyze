共同教训：**“从零推导要求”是瓶颈；“给定关系后判定”是可靠的。**新路线因此改为从**已有修复**（规格来源）和**多配置统计**（候选来源）获得关系，再交事实层与核心判定。

## 2. 新组合的定位

- **B 修复引导的变体分析（主线）**：把一个已合入的跨架构修复视为该修复所确立政策的规格，由模型把父/修差异泛化为受限模式（作用实体、架构条件、所需保证），程序在当前主线中实例化并逐架构判定，找出“同一政策下尚未修复的兄弟实体”。依据：die修复同日上游又以`e795707703b3`修了cluster（M2b主线标注已实测），说明这类问题成族出现、补丁易漏兄弟。
- **A 跨配置异常挖掘（检查引擎）**：在多架构多配置事实上挖“多数上下文成立、少数不成立”的关系与“同文件同类实体处理不一致”，**只用于生成与排序候选**，最终判定仍须经条件化契约与规范依据（遵守文稿第2、5.1节“不以多数派替代规格”）。
- **C 跨架构运行时差分（确认手段）**：同一主线内核在多架构QEMU中启动，导出sysfs/procfs等可见接口逐项对比，作为A/B候选的运行时见证与独立线索。

## 3. 待办（按阶段，每阶段有进入/退出门槛，均须用户同意后启动）

### P0 回溯可行性（不调用模型、不新增构建）
1. **历史变体对数据集**：从主线历史程序化挖掘“兄弟修复对”——同一补丁系列或相近日期、同文件或同子系统、主题相似、涉及架构路径的修复对（如die→cluster）；登记抽取规则后再运行，划分开发/留出集。退出门槛：得到至少20对可用的留出对。
2. **A的回溯检验**：在die、shmem、s04、C15的已有事实上实现关系挖掘（同号宏关系、来源回退、预定义宏对Kconfig、同类实体门控一致性），看已知问题能否排进前列。退出门槛：在4例中至少3例进入前10。

### P1 B原型（少量模型调用）
3. **修复→模式**：登记受限模式语言（实体类别＋架构条件＋所需保证，映射到已有事实查询），模型读父/修差异输出模式，程序校验可执行性；开发用例die→cluster、s04。
4. **留出集召回**：在P0留出对上，用前一个修复生成模式，看能否找回后一个兄弟修复对应的位置（以后者的父版为检查对象）。退出门槛：召回显著高于随机/仅同文件基线，记录误报。

### P2 前瞻发现（核心产出）
5. 选近12—24个月未接触的跨架构修复，按冻结方法在当前主线找未修复变体；输出保存后人工确认；整理可报告问题，是否外报由用户决定。指标：候选数、确认数、复核成本、与“同文件同类实体”简单基线对比。

### P3 运行时差分（需批准安装QEMU多架构包）

## 4. 与文稿方向的共性与区别

**共性（可以直接沿用）**
- 研究对象与核心概念：条件化隐含契约（P ⇒ R，带版本、配置、角色、阶段限定）；提供者能力相对于用途解释（die的“来源资格vs导出政策”）。
- 判定框架：四态判定（满足/违反/不适用/证据不足）与“非空洞成立”要求；模型提候选、程序核事实的分工；已实现的事实层是文稿第4节“提取提供者保证”的具体化。
- 方法学规范：防泄漏评估、接触登记、证据分层、修复家族标注、不把回放计作新缺陷。
- 版本边界：文稿强调修复确立的新政策不能倒推为旧版违约；B正好以修复确立的政策为规格、只检查**修复之后**的主线，天然满足这一点。
- 运行时对照：C与文稿“由条件差异驱动对照选择＋运行时观察”一致，只是从配置选择扩到多架构可见接口差分。

**区别（需要在文稿中改写）**
| 方面 | 文稿当前方向 | 新组合 |
| --- | --- | --- |
| 要求从哪来 | 从公共消费操作（锚点）反推要求，模型辅助 | 从**已合入修复**确立的政策泛化而来；多配置异常只做候选排序 |
| 主要目标 | 兼容性判定准确性与契约驱动的对照选择收益 | 在当前主线**发现未修复的兄弟变体**（前瞻新问题） |
| 多数派的角色 | 明确不以多数派替代规格 | 仍不替代规格，但作为候选生成/排序信号（需在第2、5.1节说明边界） |
| 覆盖的契约类型 | 侧重生命周期/准备期限（s390调度拓扑）与来源资格 | 侧重编译期可得的来源、取值、门控、Kbuild适用性；期限类只能靠C或保留为案例研究 |
| 评价 | E1要求推导、E2给定要求检查、E3选配收益 | 变体召回（留出兄弟修复对）、前瞻确认数与复核成本、与简单基线对比；E1—E4与M4的负结果作为“为何不能从零推导”的动机证据 |
| 新颖性来源 | 条件化判定与对照选择的结合 | 修复作为规格的跨架构变体分析＋条件化判定（与Engler“deviant behavior”、补丁变体/重复缺陷检测工作对比） |

**对文稿的具体影响**：第1、3节（问题与发现）基本保留；第2节相关工作需补充“偏离行为推断”（Engler SOSP'01）与补丁变体/重复缺陷检测方向；第4节方法改为“修复→模式→实例化→条件化判定→运行时确认”；第5节挑战中的“规范歧义”改为讨论“修复政策的适用边界与兄弟实体判定”；第6节如实写入E1/E4/M4的登记式负结果，并以P1—P2结果替换“预期结果”。
