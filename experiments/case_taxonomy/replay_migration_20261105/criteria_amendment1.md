# 修订1：应用检查加上“忽略hunk行数”一级（开发阶段，看完开发集的应用结果之后写定）

## 问题

开发阶段20个补丁中，`git apply --check`只通过7个。查看失败原因，多数是`corrupt patch`：模型写的hunk头（`@@ -a,b +c,d @@`）中行数数错了，补丁的上下文和改动本身与代码一致。这是格式问题，不是迁移内容的问题。

## 修改

判据第三节“能否应用”改为三级，依次检查、分别报告：
1. **严格**：`git apply --check`；
2. **忽略hunk行数**：`git apply --check --recount`，只按上下文和改动匹配，不看hunk头的行数；
3. **模糊**：`patch -p1 --fuzz=3 --dry-run`。

参考线“能应用的不少于80%”按第2级计算。

另外，检查改为在只含补丁涉及文件（取`T^`中的内容）的临时目录中进行，不再为每个补丁建工作树，结果相同，只是更快。

迁移提示本身不改。
