# 函数识别库函数的修正

承接`spans_defect_audit_20261031/`：此前各轮的主要结论都不受影响。用户随后决定正式修正库函数。

## 改了什么

| 文件 | 修改 |
| --- | --- |
| `linux_bug_analyze/candidate_bridge.py` | 新增`header_window(lines, n, window=None)`，负责取出函数开头`{`之前的函数头文字；`function_spans`改用它 |
| `linux_bug_analyze/sibling_pairs.py` | `function_spans_strict`和`named_spans`改用`header_window` |
| `tests/test_candidate_bridge.py`、`tests/test_sibling_pairs.py` | 新增4组测试，见下 |

新的取函数头规则：从`{`所在行往回找，遇到下列行时停下，最多往回15行：

- 以分号或右花括号结尾的行；
- 空行；
- 预处理行（`#`开头）；
- 整行注释（`//`开头，或以`/*`、`*`开头且以`*/`结尾）。

另有三条补充：

- `{`与函数头之间隔着的空行跳过；
- 如果已经取到的部分里右括号比左括号多，说明还在参数列表中间，此时不管遇到什么行都继续往回取；
- 拼接前，逐行去掉`//`注释和`/* */`注释。

**兼容旧结果**：三个函数都增加了可选参数`window`。传`window=4`时，完全按2026-10-31之前固定看4行的方式执行，冻结方法和此前各轮的原始结果可以据此精确复现。不传时用新规则。

## 修正过程中发现并补上的情况

评估时用的修正版（`spans_defect_audit_20261031/wide_spans.py`）不能直接用作库函数，因为它会在下列几种情况下认错或漏认。正式实现针对每一种都加了处理和测试：

| 情况 | 例子 | 问题 | 处理 |
| --- | --- | --- | --- |
| 函数上方的注释里有花括号 | `/* Handle {get,set,swap}_context operations */`紧挨着`SYSCALL_DEFINE3(...)` | 往回取到了注释里，截取时切在注释里的`{`上 | 遇到整行注释就停；只截取最后一行`{`之前的部分 |
| 函数头与`{`之间有空行 | `set_gic_ap0r(...)`，空一行后才是`{` | 遇到空行就停，一行函数头都没取到 | 还没取到函数头时跳过空行 |
| 函数头上一行是`//`整行注释 | `//#if 0`后紧跟`usb_get_report(...)` | 拼接后，`//`把后面的内容全部当成注释 | 遇到`//`整行注释就停，拼接前逐行去掉`//`注释 |
| 参数列表中间夹着整行注释 | `inputfifo_send_data(`、`/* ... */`、`unsigned int a,` | 遇到注释就停，没取到函数名 | 参数列表未结束时，不管遇到什么行都继续往回取 |

## 核对

### 单元测试

`tests.test_candidate_bridge`与`tests.test_sibling_pairs`共14个测试全部通过，覆盖以下情况：

- 长函数头；
- 上方注释含花括号；
- 函数头与`{`之间有空行；
- 函数头上方是`//`注释；
- 参数列表中间夹注释；
- `window=4`复现旧行为。

WSL中的全量测试：除`test_consumer_obligations`和`test_consumer_obligations_v2`两个模块因环境缺少`pycparser`而无法导入（与本次修改无关，修改前同样如此）外，全部通过。

### 全树对照

在终点版本的全部37 347个`.c`文件上，对比新规则与旧的4行窗口：

| 实现 | 旧版识别出的有名函数 | 新版 | 旧版有、新版没有的函数名 |
| --- | ---: | ---: | --- |
| `sibling_pairs.named_spans` | 666 884 | **695 467**（多28 583个） | 52个 |
| `candidate_bridge.function_spans` | 659 143 | **687 591**（多28 448个） | 其中确为该文件所定义函数名的158个 |

研究者抽查了旧版有、新版没有的那些名字，属于两种情况：

1. **旧版的误标**：旧的4行窗口从前面的注释、宏调用或注解里抓到一个词，安在了别的范围上。例如`them`、`WRAP_DIR_ITER`、`memcpy`、`nsecs`、`__must_hold`、`__acquires`。`c_stop`那个例子中，旧版还把紧随其后的结构体初始化`cpuinfo_op = {`错标成了`c_stop`。
2. **文件中花括号计数被打乱**：例如注释里有不配对的`{`，使范围划分整体错位。新旧两版在这类文件里都不准，旧版只是碰巧把名字贴在了错位的范围上。例如`emit_kfunc_call`、`xe_engine_snapshot_print`。这是另一个已知局限，本次没有处理。

## 影响

- 今后用到这两个库函数的脚本，默认使用新规则。此前各轮的脚本如果重跑，结果会与存档略有不同。影响已在`spans_defect_audit_20261031/README.md`中评估过，主要结论都不变。要精确复现旧结果，传`window=4`即可。
- 方向4第二轮的`steps.py`和评估轮的`wide_spans.py`仍然使用各自本地的实现，没有改动。

## 统计

不调用模型；构建0；新确认缺陷0。
