# 判据：修改 Z5 模板，使它在 QEMU 的 riscv 上也能看到多页过期条目（z5fix_20261115）

2026-11-15，Claude。用户：“先改 Z5 模板”（`mutation3_20261115` README 下一步第 1 条）。本文件在改程序和运行之前写定，SHA 存入 `criteria_sha256.txt`。

## 一、为什么要改

`mutation3_20261115` 查明：riscv 每次缺页后对该地址执行 `sfence.vma`，而 QEMU 8.2.2 的效果是整体清空 TLB（从行为推断）。原 Z5 的做法是“写满 64 KiB → `MADV_DONTNEED` → 从第一页读”。写的过程中，每次缺页都清掉前面各页的条目；读第一页时又缺页清空一次。所以 N2（解除映射不记录刷新范围）这样的缺陷，在 QEMU 的 riscv 上看不到。在解除映射前先把每页读一遍，就能补回条目，而读不会引起缺页。诊断程序已验证：补回后，2 页、8 页时每页 20/20 都读到旧数据。

## 二、改动（写死）

- 把 `../proprules_20261114/propsuite.c` 复制为本目录的 `propsuite2.c`（旧轮次的文件不改）。
- 只改 Z5：在 `memset(p, 0xCC, 64 KiB)` 之后、`madvise(MADV_DONTNEED)` 之前，加一个循环，逐页读一次（每页读第 0 个字节）。
- 判错标准不变：`MADV_DONTNEED` 之后读到的 64 KiB 中有非零字节，就算违反。

依据的公共语义也不变：私有匿名映射被 `MADV_DONTNEED` 之后，再读必须是 0。其余 12 个模板一字不改。
