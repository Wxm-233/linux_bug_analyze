## 三、定义

### 3.1 对照补丁

- **来源**：内核仓库中，提交日期不早于 2019-01-01、`--no-merges`、改动了 `arch/x86/` 或 `arch/arm64/` 下文件、提交说明中有 `Fixes:` 行的提交。
- **时间截止**：评估一条样本时，只用提交日期（committer date）早于该样本 riscv 修复提交作者日期（author date）的对照补丁。评估当前版本时，用到 HEAD 为止的全部对照补丁。
- **补丁中的函数**：对 `arch/x86/`、`arch/arm64/` 下每个 `.c`、`.h` 文件的每个改动块（`-U0` 下的 hunk），取 git 改动块标题中的函数名，即标题文本里最后一个“标识符加左括号”的标识符。取不到的改动块跳过，并计数。

### 3.2 补丁元素

对每个改动块，从“+”行和“−”行分别提取：

- **调用**：形如 `标识符(` 的标识符，去掉 C 关键字（`if`、`for`、`while`、`switch`、`return`、`sizeof`、`typeof`、`__typeof__`、`defined`、`__attribute__`、`asm`、`__asm__`）、该函数自己的名字，以及诊断类名字（前缀 `pr_`、`printk`、`dev_`、`WARN`、`BUG`、`panic`、`dump_stack`、`trace_`、`lockdep_`、`kasan_`、`kcsan_`、`kmsan_`、`netdev_`、`seq_printf`、`snprintf`、`sprintf`、`scnprintf`）；
- **字段写入**：`.字段` 或 `->字段` 后紧跟赋值运算符（`=`、`|=`、`&=`、`^=`、`+=`、`-=`），且不是 `==` 的字段名；
- **错误码**：形如 `-E大写字母或数字` 的记号。

**新增元素**：“+”行中有、同一改动块的“−”行中没有的元素。

### 3.3 riscv 目标

对照补丁中架构 X 的改动块所在函数 h，它在 riscv 上对应的目标：

1. riscv 事实中名为 h 的定义（包括 `.c` 中的 static）；
2. 候选接口 g 的 riscv 实现，条件是 h ∈ ReachX(g)。
   - 候选接口：`checks2_xarch_20261109` 判据 3.1 的候选名（三个修订边界池中 public_to_arch 函数的并集）；
   - ReachX(g)：在 X 的当前版本事实（`/root/work/checks2/current/facts_<X>.json.gz`）中，g 的定义，加上沿直接调用 3 层能到达的、定义在 `arch/X/` 下的函数名；
   - riscv 实现：按 `checks2_xarch_20261109` 判据 3.1（非 static，或 `.h` 中的 static）。

### 3.4 riscv 侧是否已有

对 riscv 目标 t，取 t 的定义，加上沿 riscv 事实中的直接调用 3 层能到达的定义，作为“t 的范围”。从相应版本的源码中取出这些定义的文本：从定义所在行开始，按花括号配对到函数体结束。

- **调用 e 已有**：e 在 t 的范围的调用名集合中，或者 e 作为完整单词出现在范围文本中；
- **字段写入 f 已有**：t 的范围的写集合中有以 `.f` 或 `->f` 结尾的资源键，或者范围文本中出现 `.f` 或 `->f` 后紧跟赋值运算符；
- **错误码 E 已有**：E 作为完整单词出现在范围文本中。

### 3.5 标记

对照补丁 P 的某个改动块，有新增元素 e，P 的某个 riscv 目标 t 的范围中没有 e，就报一条标记 `(t, 元素种类, e)`。证据为 P 的提交号、架构、h。同一个 `(t, 种类, e)` 合并为一个不同问题，证据合并列出。

## 四、指标（开发集上，只作描述）

对每条有函数可命中的样本，在修复前的 riscv 事实和源码上、按时间截止运行：

- **宽松命中**：有一条标记的目标 t 是该样本的修复函数，或者 t 沿 riscv 直接调用 3 层能到达某个修复函数。修复函数取 `../boundary_closure_20261108/sample_match_v2.json` 中该样本 `entities` 里种类为 function 的名字；
- **精确命中**：宽松命中的标记中，有一条的元素 e，也是该 riscv 修复提交在修复函数里的新增元素（按 3.2 的同一方法提取）；
- **噪声**：当前版本的不同问题数；人工核对不超过 60 个时全部核对，超过则随机抽 40 个，种子写在当次迭代的记录里。分类与 `checks2_xarch_20261109` 第六节相同：疑似真问题、不是、判断不了。
