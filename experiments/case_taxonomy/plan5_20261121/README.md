## 一、astra 的要点

1. **到头的部分**：

   - 两周内不立第十个引擎，也不做人工 MSR 总表；
   - riscv `ALTERNATIVE`、arm64 cpucaps 只能说明“某实现在什么条件下被选中”，推不出“缺这项能力时这个操作不合法”。
2. **换问题**：两周内回答“三类静态检查指出边界之后，借助已有的接口规范和多架构功能测试，能否以可负担的人时，把其中一部分判成可独立确认的错误”。历史召回保留为原问题的欠账，本轮报 null。

4. **第二道试验（第 5～10 天）：发现效率**。从 rc3 九项输出里，把“有可运行自测”的根因候选随机配对，分成普通组（只看静态证据）和增强组（多一份功能配对结果），各给 8 审查人时，比较每人时确认的新根因数：

## 二、我的方案

### 采纳的部分

- 不再写新的静态规则去追历史召回；历史召回冻结在 0/23，不再追。
- 主产出改为**当前版本上能独立确认的新缺陷**。
- 第一道试验照做：先验证“在 QEMU 上开关 CPU 能力、用已知答案的自测比较结果”这套测量本身可靠。

### 调整：把第二道试验换成“能力屏蔽发现”

astra 的第二道试验要从九项候选里找“有可运行自测”的，至少凑 4 对。按以往的审查经验，九项候选大多落在 mm、页表一类代码，很少有现成的功能自测能直接覆盖，凑不够 4 对的可能性很大。

我建议把第二道试验换成更直接的一件事，它和 capsupply 的发现正好对上：
- **能力前置条件缺陷样本很多**（晚期 27 个根因），但静态上找不到约定；
- 这类缺陷的共同特征是**在缺少某项能力的机器上才暴露**；
- QEMU 恰好能逐项关掉 CPU 能力。

所以第二道试验做一次**能力屏蔽发现**：在 v7.4-rc3 上，每个架构逐项关掉可选能力（每次只关一项，再加一个“最小 CPU”配置），启动内核，跑树内的自测套件，收集 WARN、Oops、自测失败和错误返回。两人分诊，按 astra 的分栏计分。设计侧的 M1（camellia 在没有 AES-NI 的 CPU 上注册）、M2（没有 XPA 的 MIPS）、M9（没有 FP/SIMD 的 arm64）、M10（没有 SMAP）都是这种场景下会直接暴露的。

### 具体安排

**第 1～3 天：测量可靠性（astra 第一道试验，门槛照它写的）**
- 用 kbuild 为 v7.4-rc3 构建带自测的 x86_64 和 riscv64（再看 arm64）镜像：打开加密自测（`CRYPTO_SELFTESTS` 一类，含额外测试）和 lib 的 KUnit（crc、raid6、lib/crypto）。配置一次配齐，只留可复用的部分。
- 接口候选（第 1 天先写判据，按固定顺序选）：
  - 加密算法：arch 加速实现和通用实现，加密自测会对每个注册的实现跑已知答案；
  - crc 和 raid6：按 CPU 特性选实现，KUnit 和 raid6 自测都有已知答案。
- 能力开关：x86 已确认 QEMU 8.2 能逐项关 aes、avx2、sha-ni、pclmulqdq、smap、pku；riscv 的 v/zbc/zvk* 和 arm64 的 sve 第 1 天核实。
- 合法对照：关掉加速能力后，通用实现接手、自测照样通过，应判为合法。

**第 4～8 天：能力屏蔽发现（第一道过线才做）**
- 能力矩阵：每个架构列出 QEMU 能关的可选能力，逐项关；另加一个“最小 CPU”。每格冷启动 3 次。
- 观察项：启动是否完成、WARN/Oops、自测失败、模块加载错误、实际选中的实现。
- 分诊：我先判并记 SHA，Codex 盲判，裁定。只有能复现、能指出公共约定和同一对象、排除了 QEMU 模拟缺陷的，才计“确认”。QEMU 自身没模拟好的特性单列，不算内核缺陷。
- 继续条件：至少确认 1 个此前未登记的根因，才扩展到更多架构或配置。0 个就只保留这套设施，停止扩展，并报告覆盖了哪些能力和测试。

**第 9～10 天：如果有余力**，按 astra 的第二道试验，在九项候选里找有自测的条目，做小规模的普通组和增强组对照；凑不够 4 对就只报覆盖率。

### 评测口径

- 主报：新确认的独立根因数，以及每人时的确认数（含准备时间）；
- 分栏：直接由测试暴露的、人工顺着线索推出的、上游已知未合入的、只有静态证据的；
- 历史召回报 null，0/23 冻结；
- 封存样本一律不用。v7.4-rc3 已经做过增量审查，本轮只能说“固定版本上的前瞻发现”。

### 风险

- 加密和 lib 代码在上游有不少测试机器人覆盖，可能很难找到新问题；能力屏蔽在 QEMU 上的覆盖面，取决于 QEMU 能关哪些能力。
- QEMU 模拟缺陷会混进来，需要分诊时排除，必要时换 QEMU 版本或换架构复核。
