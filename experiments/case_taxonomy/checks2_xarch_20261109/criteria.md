## 三、定义

### 3.1 候选与家族

- **候选名**：`../boundary_audit_20261107/revised/` 下 riscv、x86_64、arm64 三个修订边界池（`symbols_runtime_<arch>.json`）中，`direction == "public_to_arch"` 且 `kind == "function"` 的符号名的并集。也就是说，只要任一架构自己提供了这个函数，它就是候选。
- **实现**：对候选名 N 和构建 B，B 的事实中名为 N 的定义，只要满足下面任一条，就算 N 在 B 中的实现：
  - 非 static；
  - static，且定义在 `.h` 文件中（头文件里的 static inline）。

  `.c` 文件中的 static 函数是文件私有的，不算。同一构建中有多个实现时，**合并**它们的事实（并集），不只取一个。
- **家族**：riscv 有实现、且至少一个对照架构有实现的候选名。riscv 没有实现的候选名，只计数，不比较。

### 3.2 每个实现的派生事实

对构建 B 中名为 N 的实现（合并后），计算：

- **形态**：archbound 的 `bodyKind`：`empty`（空函数体）、`const`（只有一句返回整数常量）、`normal`；`void` 视同 `normal`。多个定义合并时，有一个是 `normal` 就记 `normal`。
- **直接写** `Wd`：事实里的 `writes`。archbound 已去掉架构私有的资源，也就是结构体定义在 `arch/` 下的字段、定义在 `arch/` 下的全局变量。
- **传递写** `Wt`：`Wd`，加上沿 B 中的直接调用往下 3 层，被调函数 `writes` 里的**全局键**。全局键指 `结构体名.字段` 和 `g:名字` 两种；`p#N` 开头的参数键只算本函数的。被调者按名字在 B 的事实中解析，解析不到的不展开。
- **传递调用** `Ct`：沿直接调用往下 3 层，能到达的被调函数名集合。
- **直接公共调用** `Cd`：直接调用的被调函数中，“纯公共函数”的集合。纯公共函数指在 B 的事实中有定义、且没有任何定义在 `arch/` 下的函数。
- **常数实参** `A[F][i]`：对每个直接调用的公共函数 F 和实参位置 i，所有调用点上该实参的整数常量值集合。
- **错误码集合** `E`：所有 `return` 中值为负数的整数常量。
- **危险使用与检查**：事实里的 `dangerUses`（`param#N` 加下标、长度、移位、解引用）和 `checked`（在比较中出现过的参数）。

### 3.3 标记

对每个家族 N 和每个对照架构 X，riscv 记作 R，下面任一条成立就报一条标记：

| 标记 | 方面 | 条件 |
| --- | --- | --- |
| `stub` | ① | R 的形态是 `empty` 或 `const`，X 的形态是 `normal` |
| `write-missing` | ② | 某资源键 k ∈ X 的 `Wd`，且 k ∉ R 的 `Wt` |
| `call-missing` | ② | 某纯公共函数 F ∈ X 的 `Cd`，F 在 X 中的定义有非空的 `writes`，且 F ∉ R 的 `Ct` |
| `arg-diff` | ② | 某公共函数 F 同时在 R、X 的 `Cd` 中，某位置 i 上 `A_R[F][i]` 与 `A_X[F][i]` 都非空且不相交 |
| `errno-diff` | ③ | R、X 的 `E` 都非空，且 X 的 `E` 中有 R 的 `E` 里没有的值 |
| `param-check` | ④ | 某参数 p、某种危险使用 u：X 有 `p:u` 且 p ∈ X 的 `checked`；R 有 `p:u` 且 p ∉ R 的 `checked` |

- 每条标记记录：标记类型、家族名、细节（资源键、F 与位置、错误码等）、对照架构、R 和 X 的定义位置。
- **去重**：`(标记类型, 家族名, 细节)` 相同的，算一个“不同问题”，对照架构合并列出。

## 四、保障口径

- **相对于以下模型不漏报**：第三节的候选名、实现与合并规则、archbound 的语法级事实、按名解析的 3 层直接调用、第三节的标记条件。在这个模型下，任何“对照架构直接做了、riscv 在 3 层内都没做”的写、公共调用，以及上表的其余差异，都会被报出，允许误报。
- **已知不在保障内**，结果中逐项计数：
  - 只以宏提供的边界（三个池中 `public_to_arch` 的宏数）；
  - riscv 没有实现的候选名；
  - 只有一个架构有实现、无从对照的候选名；
  - 间接调用、内联汇编、汇编实现；
  - 不同名但作用相同的实现；
  - 路径条件（“必定写”只按“可能写”近似）；
  - archbound 的 `checked` 不判断支配关系；
  - ① 中的 Kconfig 和链接判断，⑤，⑥。
