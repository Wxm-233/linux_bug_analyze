# 判据修订 1（在任何数据集统计之前写下）

2026-11-18，Claude。

**原因**：在当前版本上抽查可行性时发现，沿用的 `parse_kconfig`（位宽截断第三版）漏解析了两种默认值：
- `def_bool $(cc-option, -fsanitize=kernel-address)` 这类带空格的宏：正则 `(\S+)` 匹配失败，默认值整条丢失，于是 `CC_HAS_KASAN_GENERIC` 被当成“永远为 n”，`mm/kasan/shadow.c` 在所有架构上都被判成不可编译；
- `def_bool MIGRATION && ZONE_DEVICE` 这类表达式：同样整条丢失，于是 `DEVICE_MIGRATION` 被当成“永远为 n”，`mm/migrate_device.c` 被判成处处不可编译。

位宽截断那一轮只关心少数 64 位符号，这个缺陷不影响它的结论。本轮只修改自己的副本，不改那一轮的文件。

**改动**：判据一.1 的“解析方式沿用 `parse_kconfig`”，改为本轮复制一份，只修改 `default`、`def_bool`、`def_tristate` 的解析：

| 默认值写法 | 处理 |
|---|---|
| `y`、`m`，可带 `if 条件` | 条件满足时为开 |
| `n`、`0`、`""` | 不算开 |
| `$(…)` 宏（编译器检测等） | 视为开，条件照常 |
| 其他表达式，例如 `A && B`、`X` | 视为“表达式成立时为开”：用 `&&` 连接的正向符号加入条件；含 `||` 的视为没有约束 |

其余部分（`depends on`、`if` 块、`select`）不变。

**状态**：写这份修订时，只在当前版本上做了可行性抽查（`sanity_check.py`），还没有对任何数据集做统计。
