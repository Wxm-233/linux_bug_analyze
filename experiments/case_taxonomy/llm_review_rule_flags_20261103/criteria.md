# 大模型复核程序规则的标记（判据，实现之前写定）

## 这一轮要回答什么

在整体流程中，大模型判断有一项职责是复核程序规则给出的标记，去掉误报。本轮检验这一步能不能做到：
- 把规则标出、并已核对过真假的问题交给Claude-Sonnet-5.5；
- 看它能否**留住真问题、去掉误报**。

## 一、样本

**来源**：前几轮规则检查中已经人工核对过的标记：
- 执行上下文规则在`v6.12`上的27个标记：`ctx_rules_riscv_20261103/manual_review.json`；
- 四机制规则在`v6.6`上抽查的34个标记：`mech_rules_riscv_20261103/manual_review.json`；
- 第2版规则在终点版本上的22个问题：`rules_v2_forward_end_20261103/manual_review.json`。

**取舍**：
- 只取标签为(a)、(a′)或(b)的，即真问题或误报。(c)“判断不了”的不用。
- **去重**：同一个问题被多次标出时只取一次，以最早的一轮为准。同一问题的判定规则如下：
  - 执行上下文规则：所在函数相同，且违规操作相同；
  - 推测执行越界规则与同一约定规则：所在函数相同；
  - 默认实现规则：默认实现名字相同。
- **标签可信度**：给每条注明标签的依据：
  - 上游后来有修复；
  - 在模拟器中运行确认；
  - 只有第一标注人的判断。

  报告时分别统计。

## 二、交给模型的材料

每个问题交给模型的材料包括：
- 规则说明；
- 被标记的位置；
- 程序给出的理由；
- 调用链；
- 相关函数在**该快照版本**中的代码：
  - 所在函数，以及调用链上最多3个函数，每个最多80行；
  - 默认实现规则：默认实现和一个参照架构的版本；
  - 同一约定规则：RISC-V的实现和参照架构的实现。

材料中**不给**以下信息：之后的修复、第一标注人的标签和理由。

**问题**：这个标记在该版本的RISC-V内核中是不是真问题？请具体检查：
- 这条路径实际能否走到，是否有条件挡住；
- 那个状态（关中断、持锁）在那时是否真的成立，被调函数里有没有先开中断或释放锁；
- 下标是否真的来自不可信的一方；
- 这是RISC-V特有的问题，还是所有架构都一样。

**回答格式**：
```
{"verdict": "real|false_alarm|unsure", "reason": "一句话", "lines": [行号]}
```

## 三、调用

- **模型**：Claude-Sonnet-5.5，凭据配置为`claude-sonnet55-20261103`。
- **调用参数**：`--max-output-tokens 65536`，`--wall-timeout 1800`，8路并行，不自动重试。
- **调用量**：每个问题1次，预计约48次。
- **中断与失败的处理**：首批8次都没有结果时停止；中断的调用如实记录。

## 四、指标与事先写定的判定

**指标**：
- **保留率**：真问题（a或a′）中，模型**没有**判为`false_alarm`的比例；
- **去除率**：误报（b）中，模型判为`false_alarm`的比例；
- **复核后的精确度**：在没被判为`false_alarm`的问题里，真问题所占的比例；同时报告复核前的精确度作为对照。

**成功标准**（同时满足）：
1. 保留率不低于90%；
2. 去除率不低于50%。

**次要分析**：
- 按标签依据分别统计，看“上游后来有修复”的真问题和“只有第一标注人判断”的误报上的表现；
- 按规则分别统计。

## 五、已知局限

- **样本是规则已标出的问题，** 只能检验“复核”这一步，不能检验模型能否找到规则覆盖不到的问题。
- **误报的标签大多只来自第一标注人（模型Claude）。** 第一标注人与被测模型同属Claude系列，可能存在偏向，所以会准备GPT复核材料。
- **模型可能见过上游后来的修复，** 真问题上的保留率可能偏高。
