# 大模型复核程序规则的标记

## 这一轮要回答什么

在整体流程中，大模型判断有一项职责是复核程序规则给出的标记、去掉误报。本轮检验这一步：把规则标出、已核对过真假的问题交给Claude-Sonnet-5.5，看它能否**留住真问题、去掉误报**。

| 文件 | 说明 | SHA |
| --- | --- | --- |
| `criteria.md` | 判据，实现之前写定 | `fd165203…` |
| `criteria_amendment1.md` | 修订1：更正两条PMU标签（`ctr_start`、`ctr_stop`由a改为b），在任何调用之前写定 | 见`criteria_sha256.txt` |
| `build.py` → `items.json` | 汇集样本、去重、生成提示词 | 见`delivery_manifest.json` |
| `run_calls.py` → `run_calls.log` | 41次调用 | — |
| `score.py` → `scores.json`、`answers.json` | 评分 | 同上 |
| `gpt_review/` | 41条盲复核材料，不含标签和之后的修复 | 同上 |

模型输出在`模型调用测试/2026-11-03/llm_review_rule_flags_20261103/`。

## 样本

- **来源**：从前三轮规则检查中已人工核对的标记里，取能确定真假的问题，去重后共41个。来源包括：
  - 执行上下文规则，`v6.12`；
  - 四机制规则抽样，`v6.6`；
  - 第2版规则，终点版本。
- **真问题14个**：
  - 13个上游后来有修复：`die()`的锁、未对齐陷入、APLIC 6个函数、PMU配置、ONE_REG、ACPI表映射2个、`arch_ftrace_update_code`；
  - 1个在模拟器中运行确认：`machine_shutdown`。
- **误报27个**：标签来自第一标注人（模型Claude），其中2个是本轮修订1更正的。
- **给模型的材料**：规则说明、位置、理由、调用链、当时版本的代码。不给之后的修复，也不给标签。

## 结果

41次调用全部完成，约8.9万token。

| | 结果 |
| --- | --- |
| 真问题保留率（未判为误报的比例） | **9/14 = 64%** |
| 误报去除率（判为误报的比例） | **24/27 = 89%** |
| 复核前精确度 | 14/41 = 34% |

## 被误判为“误报”的5个真问题

| 问题 | 模型的理由 | 实际情况 |
| --- | --- | --- |
| 未对齐陷入中访问用户内存 | 用户态分支是普通进程上下文，可以睡眠 | 这时中断仍是关着的，上游的修复正是在这里开中断 |
| ACPI表用`early_ioremap`映射（2条） | 和`early_memremap`只是页属性不同，功能等价 | RISC-V开启Svpbmt扩展后，按IO属性映射会读到错误数据 |
| PMU配置中的下标 | 只是写一个常量，没有可利用的泄露路径 | 上游的Spectre-v1修复正是在这里加了防护 |
| `arch_ftrace_update_code`沿用默认实现 | 沿用默认的停机打补丁方式是有意且正确的 | RISC-V后来自己实现了这个函数，修正IPI时的打补丁问题 |

**共同点**：
- 模型**缺少RISC-V特有的知识**，例如Svpbmt扩展对内存属性的影响、陷入入口框架下中断的状态；
- 或者按“能不能利用”而不是“是否违反约定”来判断。

这和判断小测中的观察一致：需要函数外或架构特有知识的问题，模型判不准。

## 一个意外发现：模型纠正了第一标注人的一个判断

模型把`kvm_age_gfn`（参照修掉的写法规则，`v6.6`）判为真问题，而第一标注人原来判为误报。核对之后，**模型是对的**：
- **arm64的修复**：arm64在`df6556adf27b`中修过这个问题。用户态可以用非大页对齐的地址来支撑客体内存，这时缺页老化的范围不一定正好是一个页或一个块，于是`kvm_age_gfn`中的`WARN_ON`会误报；而且只取一个叶子页表项，会漏掉大页后面页的访问。
- **RISC-V的现状**：到终点版本`df2908090cda`，`kvm_age_gfn`和`kvm_test_age_gfn`仍是同样的`WARN_ON`加“只取一个叶子页表项”的写法。
- **定性**：这是“落后于参照”（M8）的形态，记为**新疑点**，只记录，未上报，未运行验证。
- **对指标的影响**：按判据，指标用事先定好的标签计算，不改。若把这一条改为真问题，事后的保留率为10/15=67%，去除率为24/26=92%，结论不变。

另外，模型把PMU `ctr_stop`（修订1更正为误报）判为真问题，理由是`fevent_code`来自客体设置的`event_idx`。但这个值在配置时已经校验过才存入，客体无法传入越界值，所以仍判为误报。

## 结论

- **去掉误报这件事，模型做得很好**：89%的误报被识别出来，而且理由多数正确，例如“锁在`cond_resched`前已经释放”“只有一个CPU在线时走本地路径”“只是缺少优化，不是缺陷”。复核后，精确度从34%提高到75%。
- **但会误伤约三分之一的真问题**，主要是需要RISC-V特有知识的问题，例如Svpbmt、陷入入口的中断状态。按判据，本轮未达到成功标准。
- **模型还能帮助发现标注错误**：`kvm_age_gfn`这一条，让第一标注人的一个误判得到纠正，并多出一个新疑点。
- **下一步可以考虑**（未执行）：在提示词中补上RISC-V特有的事实，例如“开启Svpbmt时，`early_ioremap`按IO属性映射”“陷入处理在开中断之前一直关中断”。这些事实由程序或人确定，而不是让模型自己推断。然后在新的样本上检验保留率能否提高。

## 统计

模型调用41次（Claude-Sonnet-5.5，约8.9万token）；构建0次；新确认缺陷0；**新疑点1**（RISC-V KVM `kvm_age_gfn`、`kvm_test_age_gfn`仍有arm64已修掉的写法，只记录）。
