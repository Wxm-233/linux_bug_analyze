2026-11-15，Claude。用户：“把 P1 做成静态检查”。本文件在写检查代码、做任何统计之前写定，SHA 存入 `criteria_sha256.txt`。

## 一、要检查什么

`depmine_20261115` 里有一类跨边界依赖缺失（P1）：公共层拿到一个页表项的值，没先确认它是 present（页在内存里），就调用了只对 present 条目有定义的架构接口。页表项不 present 时（交换项、迁移项、device-private 项、uffd 标记），这些接口读到的位是另一种编码，各架构的结果不同。例子：

- `26e7888a0c89`：`follow_pfnmap_start()` 对没查过 present 的 PMD 调 `pmd_leaf()`。loongarch 的 `pmd_leaf()` 只看 `_PAGE_HUGE`，而交换项总带这一位；
- `43e7f189769c`：`set_pmd_migration_entry()` 对 device-private 的 PMD 交换项调 `pmd_write()`。x86 上软脏位和可写位是同一位。

它对应师兄结论里的“一侧写、另一侧不检查就直接使用”，属于**调用上下文检查**里的“对象是否就绪”：调用接口时，传进去的页表项必须已经是 present。

## 二、定义（写死）

**只对 present 条目有定义的接口**（下称“受限接口”），固定为下面这些名字：

- `pte_`：`write, dirty, young, special, exec, soft_dirty, uffd_wp, protnone, devmap, pfn, page`
- `pmd_`：`leaf, write, dirty, young, special, soft_dirty, uffd_wp, protnone, devmap, pfn, page`
- `pud_`：`leaf, write, dirty, young, special, devmap, pfn, page`

选取依据：它们读的是 present 条目里的权限、状态、大小位或页框号，交换项另有 `*_swp_*` 版本。不收 `pmd_trans_huge`、`pud_trans_huge`，因为它们按约定自己会先查 present（`26e7888a0c89` 的提交说明里写了这一点）。

**确认 present 的判断**（下称“present 判断”）：`pte_present, pmd_present, pud_present, p4d_present, pgd_present, pmd_trans_huge, pud_trans_huge`，判断为真时条目一定 present。

**页表项的来源**。对每个受限接口调用 `A(e)`，先把实参 `e` 归一成“来源”：
- `e` 形如 `ptep_get(x)`、`pmdp_get(x)`、`pudp_get(x)`、`p4dp_get(x)`、`*_get_lockless(x)`、`huge_ptep_get(…, x)`、`READ_ONCE(*x)`、`*x`：来源是指针 `x`；
- `e` 是一个局部变量 `v`：在同一函数里、调用之前最近一次对 `v` 的赋值如果是上面这些读法，来源是对应的 `x`，否则来源是 `v` 自己；
- 其他写法（结构体成员等）：来源是 `e` 去掉空白后的原文。

两个表达式“指同一来源”：归一后的来源文字相同；另外，局部变量 `v` 与它赋值时的来源 `x` 视为同一来源。

**守卫**。下面任一情况成立，就说这次调用“有 present 守卫”：
- G1：调用在 `if (C)` 的 then 分支里，C 按顶层 `&&` 拆开后，有一项是对同一来源的 present 判断（不带 `!`）；或者调用在 else 分支里，C 按顶层 `||` 拆开后，有一项是带 `!` 的 present 判断；
- G2：在同一个块或外层块中、调用之前，有语句 `if (C) S`，C 按顶层 `||` 拆开后有一项是带 `!` 的 present 判断，而 S 是 `return`、`continue`、`break`、`goto`，或以这些结尾的块；
- G3：同一表达式里，调用前面有 `P(…) &&`（P 是 present 判断）或 `!P(…) ||`，或者调用在 `P(…) ? A(e) : …` 的问号分支里；
- G4：调用在 `while (C)` 或 `for (…; C; …)` 的循环体里，C 满足 G1 的 then 条件。

守卫与调用之间如果对作为来源的局部变量重新赋值，这个守卫作废。

**来源分级**（用于排序，不影响是否报出）：
- O1：来源是从页表直接读出来的（上面的读法）；
- O2：来源是函数的 `pte_t`/`pmd_t`/`pud_t` 参数；
- O3：其他（结构体成员等）。

**报出**：没有 present 守卫的受限接口调用，每处报一条，带文件、函数、行号、接口、实参、来源分级。

## 三、实现方式

- 只做词法和语法层面的分析，不编译：去掉注释和字符串，按花括号切出函数体，在函数体里认 `if/else/while/for`、语句和表达式。`#if/#ifdef` 的各分支都当作代码看（偏向不漏，允许误报）。
- 不跨函数：参数（O2）是否由调用者保证 present，本版不追。
- 分析范围：公共代码 `mm/`、`fs/`、`kernel/`、`lib/` 的 `.c`，以及 `include/linux/` 的 `.h`。
- 源码直接从 git 对象读（`git show <提交>:<文件>`），不需要检出、不需要构建。
