# 修订说明二：链接绑定、C→汇编证据和候选池

我在逐条核查与16个单元抽样后发现了两个可复现的工具缺口：

1. B446 的公共强实现 `fs/aio.c` 与公共弱桩 `kernel/sys_ni.c` 同时存在。旧解析器只处理公共弱→架构强，因而把架构系统调用表的引用报成歧义。链接绑定与实现所在层无关，应先按唯一强提供对象及最终 ELF 的强绑定消歧，再判断是否跨层。
2. C 中调用 `memcpy` 等架构汇编实现时，C AST 只有声明。旧工具的对象证据只处理汇编的未定义引用，没有把 C 的引用接到汇编提供对象上。

本次在**本轮**提供 `repair_policy.py`、`remerge.py`，不修改旧 `enumerate.py`、旧判据或旧产物。只复用旧解析缓存，不重新解析全内核。核查输入摘要必须与原轮一致；新工具/修订摘要也绑定到本轮检查点。

具体规则先固定如下：

- 内置内核范围内，archive 中一个强提供对象且最终 vmlinux 有强绑定时，选择它；无强对象且只有一个弱对象且最终绑定为弱时才选择弱对象。多个强或多个弱对象不得任选。仅对含强/弱竞争的名称覆盖旧 C 解析，保留原来的 USR/类型与定义规则。
- 唯一提供对象的编译条目若是 `.S`/`.s`，保留实际 C 引用位置、原声明、提供对象、汇编源文件及 nm 类型，输出独立的 `c_to_asm_*.jsonl.gz`。汇编定义行号未知时写 `null`，不伪造一个 C 定义或与 AST 点数直接相加。层内关系也保留，`direction=null`；跨层关系另外计数。只对 archive/vmlinux 范围作确定解析，模块不借用内核的 winner。
- 原始 AST 点保留；运行时候选另输出 `boundary_runtime_*`。其中把 `@build/.../*.mod.c` 使用点放入排除池，并排除明确来自 scripts/、tools/ 主文件的 host 工具单元。公共生成代码、架构生成 syscall 表均保留；不将全部 `@build/` 排除或归架构。host 工具识别仍是有限路径规则，不声称完整。
- 原始19点自测的预期完全不变；增加公共强/弱竞争、C→汇编双方向层判定、非唯一提供者拒绝消歧、模块不套用内核 winner、生成文件分池的回归用例。只有小夹具可以本轮运行。

该修订只修已证实且可局部验证的两类解析缺口及分池。嵌套宏依赖（A058）、回调/描述表、架构接口内部的传递实现、配置/Kconfig、汇编段与函数属性、硬件字宽/对齐/内存模型仍未实现。它们需要另定数据结构与判据；不能用这次自测通过声称“三类检查不漏报”。全量重合并交给 Claude，重合并数值本轮写 `null`。
