# 方法补充：RISC-V 没有合并检查点

固定判据后，probe.py 确认 RISC-V 缓存目录没有 *.pickle：上一轮 RISC-V 用非分阶段 merge。四层各4单元的抽样不变。

我改为针对抽中16单元引用的外部名称，从既有 vmlinux.a 符号表查提供对象，只读取这些提供对象的既有缓存来恢复所需 C 定义索引；不解析其他源码、不重跑全量扫描。对模块单元，补查既有 direct_calls 与边界符号中已经解析成功的定义；必要时查其目标缓存。恢复的 definition_not_found 计数必须逐单元等于旧 units 报告；不等时保留未决，不把近似当精确。没有在汇编对象中找到源码定义，不等于没有实现；nm 证据单独记录。

原判据的“按频次前20组”和“每层100处”保持；分类可引用所有同组重复项的共同定义证据。对不完整结构体，完整定义是否在本单元可见，用重新解析16个单元的声明节点验证；只有跨单元同名文本、没有同一 USR 的证据，不冒充准确解析。宿主工具混入构建数据库也是审计发现，另列出来。
