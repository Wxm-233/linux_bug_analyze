## 一、astra 的要点

1. **诊断**：根本限制在“判错依据”。同一接口可以按架构提供不同保证，另一侧也可以合法补足；多数实现一致只能提示方向，不能给少数实现直接定错。只有把“公共代码需要什么、哪个架构条件改变了保证、上层是否真用到”连起来，差异才有诊断意义。
2. **停掉**：输出参数比较、按十种形态逐条补规则、从任意差异或多数票自动挖规格；暂缓把“功能全开配置、补建一批架构、通用间接调用分析”当独立里程碑。

### 第 1 步（约 3 天）：证据卡 + 等预算排序对照（采纳 astra 第一周，做三处调整）

- **调整 1：证据卡的反证字段先做我们已经踩过的那几类误报**：
  - 调用前初始化：`memset`、指定初始化器，省略的成员也会被清零；
  - 功能关闭时的空桩：差异由配置开关独立解释；
  - slab 构造函数清零；
  - 局部变量里的标志或常量（`flag |= __GFP_ZERO`、`gfp = GFP_PGTABLE_USER`）；
  - 写在辅助判断函数里的请求位（`want_init_on_alloc`）。
  这些在前几轮审查里都实际出现过，能写成确定性规则。
- **调整 2：预算按条数算，不按分钟算**：审查是我和 Codex 做的，分钟数对我们意义不大。两榜各审前 12 条（重叠的只审一次），我判完后 Codex 盲判，完整线索和每类至少一条排除项都要两人一致或经裁定。
