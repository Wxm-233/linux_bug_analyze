# 判据修订 1：符号化时剔除非函数符号（kcov_20261115）

2026-11-15 10:10，Claude。写于当前版本三个内核构建完成后、任何 QEMU 运行和符号化之前。

## 发现

`llvm-nm -n vmlinux | grep -i ' [tw] '` 得到的符号表，各架构行数差别很大：

| 架构 | 行数 | 最多的几类名字 |
|---|---|---|
| riscv | 815515 | `.Lpcrel_hi*` 122579 条，`.Ltmp*` 30496 条，`.LBB*` 数万条 |
| x86_64 | 149622 | 正常函数名；另有 `__pfx_*`（函数前的填充区） |
| arm64 | 69960 | 正常函数名；另有 `$x.*`、`__kvm_nvhe_$x.*` 等映射符号 |

`.L*` 是编译器的局部标号，`$x`/`$d` 是 ARM 的代码/数据映射符号，都不是函数。判据第四节第 1 条要求“把每个地址对到包含它的函数”。如果保留这些符号，riscv 上大多数地址会被对到 `.Lpcrel_hi123` 这样的名字，而不是所在的函数。

## 修订

`symbolize.py` 读取符号表时，跳过以下符号：
- 以 `.L` 开头的；
- 名字里含 `$` 的；
- 以 `__pfx_` 开头的（x86 函数前的 16 字节填充，不会被执行）。

其余判据不变。这只是让实现符合判据的原意，不改变比较方法和参考线。
