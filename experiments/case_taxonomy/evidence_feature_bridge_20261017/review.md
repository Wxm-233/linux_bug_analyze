模块按 JSON payload 的实际摘要和指针取值，核对事实条目与原始已保存函数片段的 document、revision、path、function、函数文本 SHA；架构目录与 profile 架构族独立匹配。已枚举入口路径要求各有唯一且直接绑定的准备/通知调用，事件行列必须按源码顺序递增；守卫候选要求目标参数绑定、无记录的名称遮蔽、唯一的匹配守卫、守卫位置早于作用调用，并保留 unsupported frontier。配置绑定还检查独立的 arch、revision、完整 `.config` 摘要及原文件摘要。初审发现的跨架构借用、原文摘要未重算、事件重排翻转顺序、异常形态输入未结构化返回等问题，均在最终代码及针对性测试中修正。任何局部诊断都明确标记 effect、实际可达性和目标对象覆盖未证明，不能升格为 `ready`。

`run_bridge_example.py` 仅读取协议允许的七个 JSON 数据源；另读 N2.1 的选择回执及原选择文件只做身份核对。原 pool SHA 与既存回执吻合，原选择在本轮结束时仍未改变；七个 N1/N2 输入 SHA 与本轮结果记录相符。应区分证据等级：这七个摘要是在本轮读取时生成的指纹，**不是**七份输入在开发前逐一冻结的摘要；source CFG 与局部路径完整性仍信任已有提取器，桥接器没有重新解析内核源码。集成脚本给不同架构挑选预审的函数角色与守卫规则，但这些规则来自助手审阅和手写映射，不是从源码自动推导出的接口要求，也不是人类专家认可的真值。

同一版 s390 非观测构建与归档运行构建的若干关键配置开关相同，但四份配置完整摘要不同，运行构建标记为插桩。有限对比详见 `config_comparison.json`；不能以共同开关或相同 revision 自动转移 `.i/.o` 的语义与运行时效果。原子操作摘要本身还有显式前提、未支持循环以及实际分支/消费期限未知，因此本版拒绝把调用顺序或守卫候选当作效果证书，是与当前证据相符的限制。

在上述**已读开发案例、局部结构诊断、正式特征保持不足**的范围内，未发现阻止本轮阶段结论使用的新增代码问题。下一步若要得到可供 N2 正式选择的特征，需要独立绑定目标运行配置中的提供者效果、实际入口到共同消费的调用链、消费者期限及审阅后的契约依据；不能仅更新 profile review 或把已有守卫文字归一成最终值。
