# N2.3：机器事实接入选配输入

新增纯函数`project_provider_features(profile, artifacts, rules)`，把既有N1的有界事实与精确来源接入N2。输出区分局部结构诊断、正式语义字段和待重新审核的profile；清空原手填特征，不保留旧审核。

最终24项方法测试通过。真实四profile获得3项局部调用顺序、2项资格守卫候选，但没有证明目标准备效果：两s390原取证配置不同于运行配置，x86材料也不完整。因此四项profile的两个正式字段均不足，原契约未放宽，实际选配结果为0对。这不是零个Linux缺陷，也不是独立检测结果。

独立复核修正了架构归属、原文摘要、事件顺序和畸形结构等问题。七份输入的路径白名单事前登记，摘要仅为执行时身份指纹，不声称事前逐项冻结。原pool、selection和旧回放保持。详见[方法说明](method_notes.md)、[实际输出](bridge_results.json)和[独立复核](review.md)。

后续[N2.4](../runtime_evidence_alignment_20261017/README.md)已补齐旧s390/x86的配置源码视图；这不能自动补上跨过程准备效果。本轮无模型请求、新对象编译或内核启动，未增加确认案例或独立正/正常。
