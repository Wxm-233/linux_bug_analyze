# 方法一第二版：只比较有语义的关键步骤

## 这一轮要回答什么

方法一第一版以公共钩子为锚，比较所有架构的实现，但拿全部调用名比较，噪声太多：163条标记，召回10%。本版只比较5类事先定义的**约定步骤**，按类别而不是按名字比较，并展开两层同文件被调函数，同时把汇编中的屏障和刷新指令也计入。

| 类别 | 例子 |
| --- | --- |
| K1 内存屏障与原子 | `smp_mb`、`cmpxchg`、`xchg`，汇编中的`fence`、`dmb` |
| K2 TLB与缓存刷新 | `flush_tlb_*`、`flush_icache_*`，汇编中的`sfence.vma`、`tlbi` |
| K3 有效性与存在检查 | `*_present`、`*_none`、`*_bad`、`pfn_valid`、`access_ok` |
| K4 加锁、关中断与上下文保护 | `spin_lock*`、`mutex_lock`、`local_irq_*`、`preempt_disable`、`ftrace_test_recursion_*` |
| K5 释放与引用计数 | `kfree`、`vfree`、`*_put`、`iounmap` |

按类别比较的好处是：RISC-V用`local_flush_tlb_page`、别人用`flush_tlb_page`，会被看作同一类步骤，不算缺失。

召回到的3条都是真问题：

- ACPI表解除映射缺释放（K5）；
- 大页`set_huge_pte_at`缺有效性检查（K3）；
- `kprobe_ftrace_handler`缺防递归保护（K4）。

## 原因分析（规则要求）

### 噪声大幅下降，但召回没有上来

- 标记从163条降到26条，人工可以全部看完；人工核对中也没有出现疑似问题。按类别比较确实去掉了大部分写法差异。
- 剩下的26条，几乎都是工具层面的假标记或设计差异：
  - **跨文件实现**：RISC-V的KVM把加锁、释放放在其他文件的辅助函数里，同文件展开两层看不到，占了15条；
  - **词表或展开没覆盖到**：`local_flush_icache_all`没有被`flush_icache*`覆盖；关中断写在汇编的CSR指令里；原子操作的LR/SC汇编经宏拼接，没识别出来；
  - **有意的不同设计**：RISC-V的`flush_cache_vmap`采用“先标记、在异常入口再刷新”的延迟方式；
  - **假钩子**：`SYSCALL_DEFINE3`是宏名，被当成了钩子。

### 回溯漏掉的12条

- **RISC-V自己特有的做法**：例如KVM的向量上下文、kfence保护页、ftrace初始化时加`text_mutex`、IPI处理。这些都不是“别人都做了”的步骤。
- **大页钩子**：实现它的架构少，只有5个；而且其他架构的刷新步骤放在别的文件里，所以K2在修复前没有成为多数类别。

### 结论

- 以公共钩子为锚、看关键步骤类别，**噪声问题基本解决了**，但能召回的仍只是少数“别人都做了、RISC-V漏了”的问题。
- RISC-V的多数修复，修的是RISC-V自己特有的实现细节，不在“多数架构共识”的范围里。这一点与方向4的结论一致：“参照别的架构”只能覆盖一部分问题，即架构共同承担同一约定的那部分。
- 结合方法一两版和方向4的结果，可以较有把握地说：**跨架构比较能指导检测的范围，是“多个架构共同承担的同一约定”，并且要比较的是有语义的关键步骤。** 它对RISC-V特有的机制无能为力。

## 单独记录（不属于五类关键步骤，读代码所得，未运行验证）

对比`kprobe_fault_handler`时注意到：arm64当前实现有两处RISC-V没有的判断。

- 模拟执行的探针（没有单步指令槽）中发生的缺页，直接交回普通缺页处理；
- 处于单步状态时，只有当出错地址正是当前探针的单步指令时，才按单步引起的缺页处理，否则（例如在调试异常路径中调用的perf或tracing代码里出错）也交回普通处理。

RISC-V在单步状态下发生的任何缺页，都会把`epc`改回探针地址。sh那次的教训说明，读代码得到的疑点必须运行验证，所以这里只记录为“值得进一步核查”，不下结论。
