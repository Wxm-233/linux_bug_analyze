## 分层改了什么（R1）

第 2 轮的规则是：函数体里只要有一处条件编译因架构而不同，整个函数就算架构层 A1。本轮改成：
- 体内差异来自架构**宏**（实现替换），才算 A1；
- 体内差异只来自配置项（包括架构相关的配置项），记为新标签“公共层（体内架构配置）”，仍然算公共代码，照常记边界。

有 383 个函数因此从 A1 改成了公共层：

| 位置 | 个数 |
|---|---|
| `include/linux` | 129 |
| `mm` | 68 |
| `kernel` | 64 |
| `drivers` | 60 |
| 其他 | 62 |

按种子抽了 10 个读源码（`r1_review.json`），全是公共代码，体内的差异都来自配置项：`CONFIG_COMPAT`、`CONFIG_64BIT`（如 `atomic-long.h` 的包装）、`CONFIG_ZONE_DMA32`、`CONFIG_KMAP_LOCAL` 等。

**判据里预先写明的副作用**：这些函数被调用时，不再算架构层。
- 边界上的接口名从 2254 个降到 1993 个。少掉的 307 个里，约 300 个就是这类函数，比如 `raw_atomic_long_*`、`i_size_read`、`__cond_resched`。原来公共代码调用它们会被记成边界，这本来就是误记。
- 所以 EC 的任务集合 T 从 2275 个接口降到 2002 个，但由任务发起的规律仍是 3120 条，40 行候选一行没少。
- 新增的 46 个接口大多是 uffd 相关的，比如 `pte_uffd`、`pmd_swp_uffd`，也来自新开的配置。

## 还没解决的

- **P1 认不出两类保护**：断言式前置条件，以及 `pte_same` 比较时已隐含 present。要解决就得改 P1 的判断代码，本轮没做。
- **P1 的 178 个“未知”**：本轮没处理。
- **`mm/mapping_dirty_helpers.c`**：要靠驱动 select 才会编进来，没编入。
- **arm、powerpc 不支持的配置**：`PAGE_TABLE_CHECK` 在这两个构建上没开，arm 上 uffd-wp 也没开。这是架构本身不支持，不是缺口。
