# 跨架构兄弟筛选表标注说明

适用于`../sibling_dataset_20261029/screening_sheet.csv`（103行）。用Excel打开即可，文件为UTF-8带BOM编码。

## 每行是什么

- **S（seed）**：一个已经合入的提交，改了某些体系结构目录（`arch/X/`）。
- **T（target）**：之后合入的另一个提交，在S**没有改过**的体系结构目录（`arch/Y/`）中改了某个已有函数的函数体。`xarch_targets`列出这些函数（文件:函数名）。
- **type**：程序按`Fixes:`标签给出的配对方式：

  | type | 含义 |
  | --- | --- |
  | `A_common_cause` | S和T的`Fixes:`指向同一个提交 |
  | `B_fix_of_fix` | T修的是S，而S本身也是一个修复 |
  | `B_introducer` | T修的是S，S本身不是修复，通常就是引入问题的提交 |

  配对方式只说明两者有联系，**不保证是同一种问题**。

查看方法：在内核仓库（WSL中`/root/repos/linux`）执行`view`列中的命令，即`git show <S>`与`git show <T>`。

## 需要填的两列

### sibling：T是不是S的“同类缺陷兄弟”

判断问题：**T在其他架构上修的，是不是和S同一种问题？** 也就是同一条要求、同一种错误用法、同一项迁移漏掉的那一处。

| 标注 | 标准 | 已读过的例子 |
| --- | --- | --- |
| `yes` | 同一种问题，换了一个架构。看过S的人，应当会去T改的那个位置检查 | powerpc与sparc上OF创建的PCI设备都要初始化`msi_addr_mask`；s390与mips的perf事件初始化都错误拒绝了cpu为-1的按线程事件；ARM与arm64的module-plts都改用`module_init_layout_section()` |
| `partial` | 有明确联系，但不是同一个缺陷：同一项迁移中的不同错误，或同一项清理策略（不是缺陷修复） | sparc32与csky在`lock_mm_and_find_vma()`转换中各犯了不同的错；printk现代化、改用`pr_cont`之类的清理 |
| `no` | 只是修了同一个引入提交带出的另一个问题，或者T是全树范围的接口改动，或者两者无关 | arm64 hugetlb的小修复配上了全树范围的`set_huge_pte_at()`加参数改动；UML、h8300、Blackfin上互不相关的问题 |

### seed_role：S本身是什么

| 标注 | 标准 |
| --- | --- |
| `fix` | S本身是一个修复，修的是它所在架构上的问题 |
| `culprit` | S是引入问题的提交（新功能、重构、接口改动），T修的正是S带来的问题 |

`B_introducer`类型的S大多是`culprit`。这一类对应的是另一种任务：从引入点出发，找出漏改的使用方。例如S去掉了某个架构钩子、引入了新约定，而powerpc和x86的使用方没有跟着改。这类对同样有价值，照实标注即可。

## 其他约定

- **note**：一句话说明理由，或者指出问题，例如“目标函数名不对”“T与另一行内容重复”。
- 拿不准时标`partial`，并在note里写明原因。
- **不要先看`claude_labels.json`**：那是Claude此前对其中42对的单人标注，放在一边，以便和你的标注比较一致性。
- 接触标记（`dev_used`、`holdout_read`、`contacted_other`）只表示这一对以前在实验中用过，与标注无关。
- 标完后保存为同目录下的`screening_sheet_labeled.csv`（或另起文件名），交给Claude计算一致性，并按真兄弟子集重算覆盖率。原表不要覆盖，它的SHA已记录。
