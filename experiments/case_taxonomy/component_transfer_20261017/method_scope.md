# 冻结组件迁移协议 v1

日期：2026-10-17。目标是检验受限组件能否迁移到未用于其开发的历史材料，**不是冻结或宣称已经实现完整自动检测器**。本轮只读候选元数据及既有接触记录，没有解封新正文、diff、源码或模型assessment。

## 固定的能力边界

| 核心组件 | 固定输入/能力 | 输出不能替代 |
|---|---|---|
| source_conditions | 完整单函数的有限语法子集；局部调用、条件和参数版本 | 调用副作用、可达性、真实C类型或接口规范 |
| forward_guards | 向前分支/goto路径，保留循环等frontier并记录守卫结构分支；不实际求值 | 实际分支选择、循环完成或目标覆盖 |
| preprocessed_evidence | 指定名称及精确源路径的唯一词法区域，保留GCC坐标和声明层级 | 通用类型/别名分析、宏定义展开栈或全路径 |
| finite_set_effects | 显式IR、独立审核原语摘要和显式假设下的逻辑集合效果 | 真实对象、实际函数效果或消费期限值 |
| contract_protocol | 独立审核的契约和同context事实之有限求值 | 自动产生权威规范、实际全路径正确性 |

五核心及五份对应测试在component_versions.json固定。c.3的全局声明行模式/符号选择、c.4的原形参角色投影、三路径预期和s390原语登记是已读特化适配/审核输入，分列记录；它们不能直接改名套到新案例后称自动迁移。

源分析基线环境为Windows Python 3.12.14、pycparser 3.0；WSL Python 3.12.3采集环境未安装pycparser，仅承担本地Git/readelf取证。缺解析器是能力不足，不得静默当分析成功。后续变更环境或实现需登记新版本，保留原冻结方法的结果。

## 四类仍未闭合的义务

1. **目标覆盖**：当前启动对象是否真的进入准备循环及正确分支。
2. **最终对象**：字段和ET_REL符号可对应，是否足以连接目标对象；最终链接及实际地址仍须另证。
3. **首次消费**：准备是否赶上真正内容读取；notify入口、指针取得、最终online都不是同一事件。
4. **稳定性**：写后到读取间的writer、重入/并发、未支持HW等路径是否影响关系。

逐项标已建立、显式假定或未知。条件出口不自动填平四类义务；提供方online/setup资格也不能进入消费者scope以排掉疑似违约。

## 元数据选样与独立性

预登记protocol_pre.json在读取本轮新候选标题前规定：固定原500 manifest，只用标题中的CPU/调度/拓扑及问题/整理词线索，两队列各按固定种子SHA排序取2项，最多4项；审计后不补选。band/stratum仅保留来源，不使用模型相关性标签挑选。标题队列不是真值分层。

接触维度分别登记：初筛材料接触、源码/方法开发已读、模型主分析、同修复家族、审计范围。没有命中只可记not_found_in_checked_records，不能声称全局未读。筛选模型曾接触的样本也不能称对所有LLM全新。

本轮一项已读NUMA边界隔离，另三项仅在有限记录未见此前明确方法阅读。两项同作者/相似清理主题的家族关系未裁定，暂按一个疑似相关组，每轮最多推进一个。四项都没有根据标题确认同机制阳性或同用途正常，当前两个正式分母保持0。

正常对照必须有同用途消费者、合法有效路径及有依据的满足关系。配置关闭、另一用途、没有告警、材料不足或标题写cleanup都不是正常真值。正例须有架构差异来源、跨层传播、破坏的要求与暴露原因；仅一个普通CPU代码错误或仅设备差异不能直接纳入核心CPU跨架构正例。

## 下一阶段的解封与材料顺序

当前未解封。本协议只提出下一轮最多两项资格阅读：问题标题队列未隔离项0c2f6d…，以及疑似组排名在前的a8c73b…。9e9af8…保持同组暂缓，5ebf512…保持已读对照，不替换。

1. 先保存接触状态、父提交、材料范围和所需人工字段。仅按该范围收集父版完整函数、相关调用者/消费者、配置和版本化API依据；修复diff、旧模型标签与预期谓词不给父版分析器。
2. 记录谁选择文件/符号、提供了哪些参数角色、谓词、摘要、配置和依据。允许的人工材料定位必须事前登记；临场删除循环、换配置、修改核心或补答案均使该轮退出原冻结验证，转为开发。
3. 主分析/组件结果落盘后，再由分开的复核步骤阅读修复说明和必要diff、裁定同机制/同用途/研究范围及家族。不合格或冲突如实排除，完整分母保留；资格阅读本身不是检测成功。
4. 如果在预测前必须由研究者阅读补丁才能选出关键函数或写出谓词，登记为资格/开发材料，不能同时称原方法的独立自动提取。未读标准针对方法开发，初筛接触另列。

父版所需函数尚未由本轮元数据确认，不能现在预写路径上的具体检测结果。首轮资格阅读可能全部不满足核心条件，不为凑正例追加或放宽。

## 模型与组件的公平对照

后续若调用主模型，沿当前Windows原生Claude Code 2.1.301、ISRC Messages、AWS-Claude-Opus-5.5；本轮调用0。每个任务另登记材料及预算、保留未知内部用量。拒绝、空正文、截断和错误型号不能算完整分析，不为恢复拒绝内容改写请求。

- **组件迁移评价**：比较对象若已经给定契约、角色和审核摘要，直接模型也必须获得同样内容及相同源码/配置/接口依据。输入版本和材料范围相同，单列格式及可读性转换。不让程序额外拿到研究者答案，再宣称优于从零推断的模型。
- **自动提取评价**：模型原始谓词/角色/依据单独保留；研究者补写或修改的部分不计自动提取。不得混用这两种任务的指标。
- **组件对照**：移除资格/期限等信息后被门槛判不足，只是依赖与拒判检查。是否减少无依据断言、错误排除或漏项，需独立语义裁定，同时报告增加的不足、人工字段/工作量和未覆盖路径。

同后端、同预算约束、同裁定口径；当前只是设计，未执行新基线或消融。

## 结果及冻结纪律

每个样本依次报告适用范围、结构提取、条件效果、契约绑定与真实消费证据。unknown/insufficient、not_applicable、协议失败、明确违反及明确满足分别统计；未知不算真阴性，合成输入和多个配置不算新案例。只有源码裁定且资格合格后才增加独立正/正常分母，不能用模型标签替代。

component_versions.json仅记录指定代码/测试与已读参考的版本，不做全项目封存。verify_components.py核对这些文件、协议和源分析环境；变化则停止沿用原冻结结果。新适配器/摘要若作为允许输入加入，单独记录人工来源和版本；若改变受测算法或看到答案后补规则，转开发并保留旧结果。

当前没有独立检测结果、完整N1/N2、真实内核新增验证或新缺陷；R3继续暂缓。
