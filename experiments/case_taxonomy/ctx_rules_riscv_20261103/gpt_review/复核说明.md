# 复核说明：程序标出的“执行上下文”问题是不是真问题

## 背景

我们写了一个程序，在Linux内核v6.12的RISC-V代码中查找“在不能睡眠的地方做了可能睡眠的事”这类问题，以及违反“不可插桩（noinstr）”约定的地方。程序共标出27处，列在`items.md`中。

每条包括：
- **问题种类**：
  - **可能睡眠**：例如拿互斥锁、访问用户内存、跨核调用并等待；
  - **普通自旋锁**：在PREEMPT_RT内核中，不带`raw_`的`spin_lock`会变成可睡眠的锁；
  - **不可插桩约定**：标了`noinstr`的函数里，不能调用会被跟踪、插桩的函数，除非放在`instrumentation_begin()`和`instrumentation_end()`之间。
- **为什么认为这里不能睡眠**：例如处于关中断区间、陷入处理时中断关闭、作为`stop_machine`的回调执行。
- **调用链**：从被标记的函数，一路调用到那个可能睡眠的操作。
- **相关函数的代码**。

## 怎么判断

每条选一个标签：

| 标签 | 含义 |
| --- | --- |
| `a` | 疑似真问题：在实际运行中，这条调用链确实可能在不允许睡眠（或不允许插桩）的状态下执行到那个操作 |
| `b` | 不是问题：例如那条路径实际不会走到（有条件挡住）、那个状态实际已经解除、或者那个操作在这里是允许的 |
| `c` | 判断不了：材料不够，需要更多上下文或运行验证 |

注意：
- 程序是按“任一路径”往下查的，所以调用链上的某一步可能有条件挡住。请看代码中的条件，判断这条路径能否真的走到。
- 只判断是不是问题，不需要给出修法。
- 理由写一句话即可。

## 交回什么

填写`answers_template.csv`，另存为`answers.csv`：
- `label`：填`a`、`b`或`c`；
- `reason`：一句话理由；
- 保留表头和第一列，不改变行的顺序。
