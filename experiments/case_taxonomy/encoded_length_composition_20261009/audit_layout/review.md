父版 C 文件 32–36 行定义 `RTL_RELAY_TAG_LEN=(ETH_ALEN)`、`TAG_HDR_LEN=4`、`MAGIC_CODE_LEN=2`。应从宏定义读取数值和符号，而不从名字推单位。`ETH_ALEN` 的定义不在这些保存材料中，必须保留符号 E，不能代入 6。父版 C 文件 SHA-256 为 `0310bf04241d497049337252be03ce69746f47ad4f1c9713295c36d72e0233e6`。

在生产者 447–479 行，缓冲区为 `unsigned char tag_buf[40]`，450 行把本地 tag 指向该缓冲区；448 行令旧内容长度初值为 0，453 行在存在旧 tag 时令其来自 `ntohs(pOldTag->tag_len)`。471 行写入 `htons(MAGIC_CODE_LEN+RTL_RELAY_TAG_LEN+old_tag_len)`。以 L 表示该长度变量、E 表示未知的 `ETH_ALEN`，可以保存写入表达式 `encode(2+E+L)`，但编码函数实际绑定和舍入/截断行为尚未验证。

476 行从 `tag_data+2` 复制 E 个 C 字节；461–462 行只在旧 tag 分支从 `tag_data+2+E` 复制 L 个 C 字节。对 E、L 为非负且算术和源范围有效的情形，这两处写入形成相邻的区间 `[2,2+E)`、`[2+E,2+E+L)`。474–475 行是经 `unsigned short *` 的写入，准确的符号宽度是 `sizeof(unsigned short)`。宏 `MAGIC_CODE_LEN=2` 本身不能证明这次写入恰好占 2 个 C 字节，也不能证明其对齐有效。

## 可提出的有条件检查

若另有证据确认实际参与编译的布局是两个 16 位存储字段、CHAR_BIT=8、packed 和零长尾数组按预期生效，则 `tag_data` 的前缀偏移为 4 个 C 字节。这时，若编码写入及对应解码无截断，且两处复制和第一项写入覆盖的范围有效，局部组成关系为：payload 数量 `2+E+L`，从结构基址复制的候选总数量为 `4+(2+E+L)`。不能仅凭 `tag_len` 或 `TAG_HDR_LEN` 的名字推得该关系，更不能把它提升为完整协议长度契约。

受限机器规则可把“源码声明形状 → 编码字段写入表达式 → payload 写入区间 → 以结构基址复制的消费表达式”连接为条件卡。任何必需前提未满足时，输出待证条件或证据不足；保留 E、L 和 `sizeof(unsigned short)`，不补常识值。真实存储宽度、编译绑定、运行范围等仍未知。

## 必须保留的拒判边界

- `__be16` 实际 typedef、CHAR_BIT、编译器扩展及实际私有 include 绑定缺失，因此不能认证前缀为 4 或这就是驱动使用的结构声明。
- `ETH_ALEN` 定义缺失；C 整数宽度、溢出、编码/解码实际绑定和截断未证。符号相等仅是条件代数关系。
- 旧 tag 分支的 454–458 行有 `L+4+2+E <= sizeof(tag_buf)` 的反向退出检查；没有旧 tag 的分支不经过该检查。不得推广为所有路径都已检查缓冲区。
- 指向旧内容的读取范围、skb 来源与容量、`unsigned short *` 的有效性、其他调用副作用和所有实际执行路径均未验证。
- 修复版的显式解码可改善局部表示，但不自动证明完整长度正确。漏加头长度等情况不能仅靠编码域检查认证为正常。
- 本地生产者与消费表达式一致不等于外部接口权威已确定；共同错误仍有可能。不能用多数架构或既有修复标签代替契约证据。
