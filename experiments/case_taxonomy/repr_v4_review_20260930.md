# 表示写出规则 v4：宏证据补全与冻结验证

日期：2026-09-30。研究任务为 D2：检验案例中的表示契约能否指导自动提出检查。本轮完成一个有界实验；未调用付费模型，也未恢复全量筛选。

## 结果与结论

此前已读 hisi_sas 案例中，检查器只能定位写入，无法解释宏的整数类型。v4 现在能够从源文件定义自动取得宏链、C 整数类型、移位值和目标端序字段，提出有依据的局部写点候选。对错误版和修复版的开发回放分别得到目标候选和局部正常结果；dw_mmc 的不同描述符格式没有被合并为统一端序错误。

**这证明了一个已知语法缺口可以修复，尚未证明独立同机制检出或通用检测能力。**冻结之后的两条元数据预选没有产生目标候选，源码解封显示当前字段写入规则没有覆盖其实际修订目标；固定池中的严格补丁配对又未找到新目标。不能把零站点、开发回放或模式不适用计作独立正常/阳性成功。

## 自动提取的检查与权威边界

输入是一版源码及同版有界声明，不输入修复补丁。程序提取：目标字段 `__le/__be` 声明 → 写入右值及源文件内可见宏定义 → ILP32/LP64 类型与值域 → 是否经过匹配的转换。两个整数模型均能证明时，才能提出“写入该端序字段前应编码主机整数”的候选检查。

以已读目标为例，`hdr->dw0 |= CMD_HDR_FORCE_PHY_MSK` 的目标为 `__le32`，宏由 `0x1U << 17` 得到 unsigned 32 位值 131072；程序保存宏定义、字段声明和两种模型证据。修复增加 `cpu_to_le32()` 后，该站点满足局部表示约束。正常对照包括匹配的显式转换、无类型阴影的同表示复制、零值及字节交换不变掩码。

局部字段声明是此次检查的依据；它没有自动证明设备模式、构建配置、消费者格式或硬件首次使用。dw_mmc 的 32 位描述符有 `__le32`，另一种 64 位描述符这里是 `u32`，不能因为名字相同就要求相同转换。**不同架构解释不同时，先确认版本、模式、提供者声明和实际消费者，再裁定共同约束；无法确认的保留复核，不按多数实现投票。**
