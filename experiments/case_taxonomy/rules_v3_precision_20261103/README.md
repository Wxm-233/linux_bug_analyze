# 第3版规则：提高精确度

## 这一轮要回答什么

第2版规则在终点版本上标出22个问题，人工核对后只有2个是真问题，占9%。本轮针对误报的成因修改规则，形成第3版，检查两件事：
- 误报能减少多少；
- 之前确认过的真命中会不会丢掉。

**性质说明**：要修的误报就来自终点版本上的核对结果，所以本轮在终点版本上的精确度属于**调参之后的结果，不是独立评估**。第3版的标记已经冻结，等终点版本之后出现新修复时，再做独立检验。

## 改了什么

| 编号 | 改进 | 针对的误报 |
| --- | --- | --- |
| P1 | 沿调用链往下查时，被调函数如果先开中断、释放锁或恢复抢占，就不再往下查 | `handle_page_fault`会先开中断；`mmu_split_huge_pages`在`cond_resched`前释放锁 |
| P3 | R7只认由函数参数赋值得到的变量，不再把“结构体字段”一律当作输入 | PMU中来自已校验状态的`fevent_code` |
| P4 | R7判断“调用点全为常量”时跳过函数声明 | `incr_fw`的头文件声明被误当成调用点 |
| P5 | R10中，被调函数里间接调用了也算有 | `vmemmap_populate`经`vmemmap_populate_hugepages`间接调用基础页版本 |

实现时出过一个错误，已修正：第一次打补丁时，正则中的`\b`被转成了退格字符，R7一个都标不出来。重写函数后检查过，两个文件中都已没有控制字符。

## 结果

### 1. 真命中保留检查（判据第1条）：全部保留，没有回退

| 窗口 | 应保留的命中 | 第3版 |
| --- | --- | --- |
| `v6.12` | A118、A122、A158、A175（CTX）；A215、A225（R7）；A344（CTX） | 全部保留 |
| `v6.6` | A068（CTX）；A112（R10） | 全部保留 |
| 终点版本 | `machine_shutdown`（CTX）；PMU `cfg_match`中的`event_code`（R7） | 全部保留 |

### 2. 终点版本上的问题（调参后，非独立）

| | 第2版 | 第3版 |
| --- | ---: | ---: |
| 问题数 | 22 | 17 |
| (a) 真问题 | 1 | 1 |
| (a′) 真问题，限特定路径 | 1 | 1 |
| (b) 不是 | 11 | **6** |
| (c) 判断不了 | 9 | 9 |
| 真问题占比 | 9% | 12% |

- **去掉的5个都是误报**：
  - P1去掉3个：`console_lock`、`mmu_split_huge_pages`、`hugetlb_fault`；
  - P4去掉1个：`incr_fw`；
  - P5去掉1个：`vmemmap_populate`。
- **没有新增问题。** 第3版的17个问题都已在第2版中出现，标签直接沿用第2版的核对结果。

### 3. 还剩的6个误报

- **PMU中的`fevent_code`，4个，P3没有去掉。**
  - 原因：`pmc = &kvpmu->pmc[cidx]`中的`cidx`是函数参数，按P3的写法，`pmc`也算“由参数得到的变量”，从`pmc->event_idx`读出的值就跟着算了进去。
  - 要去掉它们，需要进一步规定：经由指针读出的字段不算输入，即使指针本身来自参数。判据已经写定，本轮没有再改。
- **休眠时的`flush_tlb_all`、`flush_icache_all`，2个。** 只有一个CPU在线时走本地路径，规则还不能识别这类“由运行时条件决定”的情况。

## 结论

- **判据第1条满足**：所有已确认的真命中都保留了。
- **误报从11个降到6个**，问题总数从22个降到17个，真问题占比从9%升到12%。
  - 因为是在同一批核对结果上调整的，这个提升不是独立的证据。
  - 但它说明，误报的主要来源（被调函数内部改变了上下文、把声明当作调用）确实可以用规则去掉，而且不损失召回。
- **(c)类仍有9个**，主要是noinstr约定类，以及所有架构共有的公共路径。要提高精确度，下一步应该：
  - 让noinstr类问题有更好的判断依据，例如参考上游对同类问题的处理；
  - 或者暂时不单独报告这类问题。
- 第3版在终点版本上的标记已冻结（`flags_df2908090cda.json`）。等以后有新修复时，可以在不再调整规则的前提下，独立检验其中哪些被修。
