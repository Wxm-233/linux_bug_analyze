1. **通用空桩的守卫条件**：扫描通用定义（`include/linux/`、`include/asm-generic/` 和 `arch/` 以外的定义）时，记录每个平凡定义外层的预处理条件（`#if`、`#ifdef`、`#ifndef`、`#elif`；在 `#else` 分支里的取反），从中取出 `CONFIG_` 符号，作为该接口的**守卫符号**。
2. **各架构选了哪些特性**：同一时间点 `arch/<架构>/` 下所有 `Kconfig*` 文件里的 `select 符号`（带 `if` 条件的也算选了），加上在这些文件里定义且 `def_bool y` 的符号。

## 三、改动（写死）

**J1 按特性开关定性。** 对“riscv 缺”的接口（定义同第二版 I3），按顺序取第一个适用的：

1. **特性未开启**：守卫符号里有至少一个被某个“有实现的架构”选了，而 riscv 一个都没选 → 设计如此，系数 0.3，不算定性成立。
2. **特性已开启却缺实现（Q-特性）**：守卫符号里有被 riscv 选了的，而 riscv 仍然缺 → 系数 4，定性成立。
3. **riscv 自己写了空实现**：riscv 在自己目录里有该接口的定义，但是平凡的 → 视为有意为之，系数 0.5，不算定性成立。
4. **公共层已用能力判断保护**：该接口在公共代码中的每个调用位置，所在函数里在它之前都有一次返回值用作条件的调用，名字匹配 `arch_has_\w+|\w*supports?_\w*|\w*_enabled|\w*_available|static_branch_\w+|static_key_\w+|\w*cpu_has\w*|\w*has_feature\w*|IS_ENABLED`（按源码顺序近似，不判支配关系）→ 系数 0.5，不算定性成立。
5. 其余照第二版：n_impl ≥ 3 为 Q-多数（系数 3），1～2 为特性专有（系数 0.5）。

**J2 函数体里的 `#ifdef`。** 判断定义是否平凡时，先去掉函数体里的预处理行；剩下的语句如果都是 `return 常量;`，算平凡。例如 riscv 的 `syscall_get_arch`。

**J3 类别正则排除只改值的函数。** 名字以 `_bit` 或 `_bits` 结尾的调用（如 `set_pte_bit`、`clear_pte_bit`）不算 pgtable 或 mem 类效果。

**J4 Q-类别只看有副作用的实现。** riscv 的实现如果既不写任何形参指向的对象、也不调用任何函数（纯值函数，如 `pte_mkclean`），不判 Q-类别。

经函数指针的回调仍然看不到，这个局限不在本轮解决。
