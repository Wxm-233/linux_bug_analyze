# M4设计澄清1（实现前写定）

2026-10-29。补充`m4_design_20261028/registration_m4_design.md`（SHA `124e1839…`，不改）中未写死的细节；在写任何变化点代码、跑任何开发用例之前写定。

1. **截取优先级**：每个消费者文件按类型V2 → V5 → V4 → V3 → V1依次取变化点（语法标记明确的类型在前，V1最宽在后），同类型内V2/V5/V4按行号、V3按调用次数降序、V1按宏使用次数降序，合计至多16个。
2. **变化点粒度**：V2为一条预处理条件行（含其块的行范围）；V5、V4为一行；V3为一个被调用函数（含其全部调用行）；V1为一个宏（含其全部使用行，`##`拼接名记调用行）。
3. **架构名集合**：`CONFIG_<ARCH>`中的`<ARCH>`取父版源码树`arch/`下目录名的大写形式及其常见变体（`X86_64`、`X86_32`、`ARM64`、`PPC`、`PPC64`、`SPARC64`、`SPARC32`、`UML`）；编译器架构预定义宏取`__x86_64__`、`__i386__`、`__aarch64__`、`__arm__`、`__s390__`、`__s390x__`、`__sparc__`、`__riscv`、`__powerpc__`、`__powerpc64__`、`__mips__`、`__loongarch__`、`__ia64__`；另加`__HAVE_ARCH_*`、`HAVE_ARCH_*`、`__ARCH_HAS_*`、`ARCH_HAS_*`、`BITS_PER_LONG`、`CONFIG_64BIT`、`CONFIG_32BIT`。
4. **V3判定**：被调用函数在追踪上下文间“定义所在文件不同”或“某些上下文在编译单元内有定义、另一些只有声明”，或定义位于`arch/`下。
5. **V4判定**：函数体内含比较运算（`<`、`>`、`<=`、`>=`）的行，且该行含一个在追踪上下文中定义为宏、名字以`_ORDER/_SHIFT/_SIZE/_NR`结尾或含`MAX`/`LIMIT`的标识符。
6. **覆盖判定**：修复在该消费者文件中的每个diff块，取其父版行范围（纯新增块取插入位置行）；任一变化点的任一行落在该范围±5行内即“覆盖”。同时报告截取后与截取前的覆盖，及覆盖的类型。
7. **`expr_value`冒烟检查**：只对开发用例中“覆盖到修复位置”的V2/V5/V4变化点，在三个追踪上下文求其条件或比较中常量表达式的值，确认事实可得；不做判定。
