## 四、静态阶段：提示抽取（规则写死）

### 4.1 输入

- **源码与编译命令**：每个组“提示取自”的那棵树，用 riscv 构建的编译命令（修复前内核的 `.cmd` 文件经内核自带的 `gen_compile_commands.py` 生成；当前版本用已有的 `compile_commands.json`）。
- **范围**：源文件在 `kernel/`、`mm/`、`fs/`、`net/`、`ipc/`、`lib/`、`arch/riscv/kernel/`、`arch/riscv/mm/` 下的编译单元。解析失败（有 error 级诊断）的单元计数并列出，不静默跳过。
- **边界项**：当前版本 riscv 修订边界池（`boundary_audit_20261107/revised/riscv/…/symbols_runtime_riscv.json`）中方向为 `public_to_arch`、种类为 function、macro、object、enum_constant 的符号，按名字匹配。用当前版本的名单匹配历史树，是本轮的局限。

### 4.2 抽取的事实（每个函数定义一份，按 USR 合并）

- **参数**：名字与类型。
- **调用**：被调函数，以及每个实参引用了调用者的哪些参数（实参表达式里直接引用的参数；经过下面“局部变量”一层传递的也算）。
- **局部变量**：函数内对局部变量的初始化和赋值，记录右侧引用的参数和边界项；迭代到不动点。
- **守卫**：`if` 语句，且其 then 分支含错误出口：`return` 一个负常量、`goto`、或把负常量赋给变量。记录条件中的比较（`< <= > >= == !=` 和按位与 `&`）：每一侧引用的参数（含经局部变量传递的）、边界项、以及该侧能否求值为整数常量（libclang `clang_Cursor_Evaluate`）。
- **宏**：条件和局部变量定义范围内的宏展开（libclang 的 MACRO_INSTANTIATION，按源码位置落入范围判定），名字在边界项里的算作边界项。
- **定义体展开**：对条件中出现的“函数型”边界项（函数，或带参数的宏），读其定义体的记号，收集其中出现的**无参数**边界宏；最多展开 2 层（宏→其中的函数或宏→其中的无参数宏）。定义找不到的记为“未知”。

### 4.3 系统调用与参数映射

- **入口**：名为 `__do_sys_<名>` 的函数定义；系统调用参数就是它的参数。
- **映射**：从入口沿调用边最多 4 层，把被调函数的参数映射回系统调用参数（实参引用了哪个系统调用参数）。映射不到的参数不产生提示。
- **伪调用 raw_nr**：把“系统调用号”当作一个参数。`arch/riscv/kernel/` 下函数的守卫或普通 `if` 条件里，若比较的一侧含 `NR_syscalls`（边界项或宏），则对 raw_nr 产生提示。这是给入口代码开的进入渠道（Codex 审查要求入口必须有渠道）；我知道 A310 在入口代码里，这条规则受它启发，在此注明。

### 4.4 提示点与提示取值

**提示点**：某系统调用 S（沿 4.3 可达）中，一个守卫的条件同时满足：(a) 引用了某个映射到 S 参数的值；(b) 引用了一个“可能分歧”的边界项。“可能分歧”指：函数或带参数的宏；或无参数宏、对象、枚举常量，其在 riscv、arm64、x86_64 三个构建上的取值不全相同或有一个不是编译期常量（取值见 4.5）。

每个提示点为相关参数产生下列取值（去重，按参数类型截断）：

| 类型 | 规则 | 取值 |
| --- | --- | --- |
| K1 阈值 | 比较另一侧可求值为常量 c | c−1、c、c+1；若为按位与，取 c、0、c 的每个置位（最多 8 个） |
| K2 跨架构取值 | 条件里（或 2 层定义体里）出现的无参数边界宏 M，各架构取值为 v_a | 每个 v_a 的 v_a−1、v_a、v_a+1；若该参数是地址类（第五节），另取“有效缓冲区地址按位或 2^k”，k 为各 v_a 的最高位位号 |
| K3 入口 | raw_nr 的提示 | NR_syscalls 的 −1、0、+1，以及有符号/无符号边界 −1 |

K2 中“地址按位或 2^k”这一条受 A171 启发，在此注明。

### 4.5 边界常量的各架构取值

对 4.4 需要的每个无参数边界宏，在组内三个构建（riscv 取“提示取自”的那棵树；arm64、x86_64 取组内参照的树）上，各编译一个探测文件：包含固定的一组头文件，把该宏转换为 64 位整数做静态初始化，`-S` 输出后读出数值。编译失败记为“非常量”，未定义记为“未定义”。

### 4.6 点位集合

每个组的**点位系统调用集合 T**：至少有一个提示点的系统调用（含 raw_nr，若有 K3 提示）。

## 五、生成（四组，同预算）

- **系统调用全集 U**：组内 riscv、arm64、x86_64 三个内核版本的系统调用表的交集，加上 raw_nr，去掉黑名单。黑名单是会影响全局状态、挂起或终止测试进程的调用（reboot、kill 系列、exit 系列、execve 系列、clone 系列、vfork、mount 系列、pivot_root、chroot、swapon/off、kexec、模块加载卸载、改时间、acct、quotactl、syslog、sethostname/setdomainname、ptrace、process_vm_writev、prlimit64、setrlimit、rt_sigsuspend、rt_sigreturn、pause、setsid、setpgid、setuid/setgid 系列、capset、unshare、setns、seccomp、bpf、personality、reboot、vhangup、io_uring 系列、userfaultfd），以及 riscv 上没有 `__do_sys_` 入口（签名取不到）的调用。
- **参数类**（按 riscv 签名的类型和名字机械判定）：指针、路径字符串、fd、大小/长度、标志/模式/命令、pid、uid/gid、地址型整数（名字为 addr、start、brk、uaddr、uaddr2、new_addr、old_addr 等）、其他整数。
- **通用取值表**（G0–G2 全用它；G3 中没有提示的参数也用它）：

| 参数类 | 取值 |
| --- | --- |
| 整数 | 0、1、2、−1、7、8、16、64、255、256、4096、65535、65536、2^31−1、2^31、2^32−1、2^32、2^63−1、2^63、小随机数（<256）、64 位随机数 |
| 大小/长度 | 0、1、8、64、4096、8192、2^31、2^32、−1、随机数（<65536） |
| 标志/模式/命令 | 0、1<<k（k 随机 0–31）、32 位随机数、−1 |
| pid | 0、自身、−1、99999 |
| uid/gid | 0、−1、65534 |
| 指针 | NULL、缓冲区、缓冲区+1、缓冲区末尾前 8 字节、64 位随机数 |
| 地址型整数 | 0、缓冲区地址、缓冲区地址+1、2^30、2^32、64 位随机数 |
| 路径 | `/tmp/f`（普通文件）、`/tmp/d`（目录）、`/tmp/nonexist`、空串、NULL |
| fd | 普通文件、目录、管道读端（有数据）、管道写端、unix 流套接字对（对端已发数据）、unix 数据报套接字对（对端已发数据，带一个 SCM_RIGHTS 文件描述符，接收端开 SO_PASSCRED）、eventfd、memfd、未绑定的 UDP 套接字、−1、1000（未打开）；名为 dfd 的另加 AT_FDCWD |

- **缓冲区**：每个指针参数一个 2 页的缓冲区，后接一个不可访问页。填充方式三选一（各 1/3）：全 0、全 0xAA（哨兵）、“指针图”（每 8 字节一格，各 1/2 概率填另一个哨兵缓冲区的地址或 64，嵌套最多 2 层）。指针图让结构体参数里的指针字段有机会有效。
- **区间状态模板**（所有组共用）：系统调用同时有地址型参数和大小/长度参数时，用例另带一个模板，三选一：无；占用（调用前在地址向下页对齐处用 MAP_FIXED_NOREPLACE 映射 1 页）；相接（在地址+长度处映射 1 页）。
- **四组**（每组预算 B = 1000 个用例，随机种子 1、2、3 各生成一份）：
  - **G0 均匀**：系统调用在 U 中轮转，每个用例的每个参数从通用取值表随机取；
  - **G1 随机定向**：从 U 中随机取 |T| 个系统调用作目标集（随种子变）；80% 用例轮转于目标集，20% 轮转于 U；参数同 G0；
  - **G2 只按点位定向**：目标集为 T，其余同 G1；
  - **G3 点位加语义提示**：目标集为 T，比例同 G1；目标集中的用例，有提示的参数各以 1/2 概率取提示值，同一提示点涉及的多个参数以 1/2 概率一起取提示值；其余参数和非目标用例同 G0。
- 每组的用例按生成顺序编号 1…B，“首次检出成本”就是第一个检出用例的编号。若 T 为空，G1–G3 退化为 G0，照实报告。
- 四组的用例取并集、按内容去重后统一执行，结果按编号分回各组。每个用例在新的子进程里执行，彼此独立。

## 六、执行与观测

- 同一份 C 源码静态编译为三个架构的 `/init`，从 initramfs 读入本组用例，逐个执行，串口输出 JSON，跑完关机。执行前保留上一轮的探测段（sysfs PMU 列表、PMU 事件、cpuinfo）。
- 每个用例：fork 子进程，子进程重建 `/tmp/f`、`/tmp/d`，按需建 fd、缓冲区、区间模板，用原始系统调用号（各架构查本版本的表）发起调用。限时 0.5 秒。
- **观测**：
  - 返回值规整：负值记错误码名；非负值若等于某个参数的值记 `argK`，小于 65536 记原值，否则记 `big`；子进程被信号终止记 `SIG<名>`；超时记 `timeout`；
  - 缓冲区：对每个缓冲区，记录调用后与调用前不同的字节**位置**集合（不记内容，避免地址、pid 等随机值），输出位置数和位置集合的哈希。
- 结束时记录 `/proc/sys/kernel/tainted` 是否变化，只记录，不参与比较。

## 七、判定（沿用上一轮）

对每个 riscv 内核 R、每个用例 c：

1. 在组内 4 个内核（CUR 组为 3 个）的 3 次运行中结果不完全相同的用例，记为**不稳定**，不参与比较；
2. **能力/环境剔除**：`perf_event_open` 的用例，若属性缓冲区的前 4 字节（type）为 0、3 或 4（硬件、缓存、原始事件），要求该内核有 `hw_pmu`（上一轮的探测规则），不满足者剔除；剔除理由按 `.config` 分“能力”“环境”。其余用例无前提；
3. 剔除后：两个参照一致而 R 不同为**强**与众不同；只剩一个可比参照且 R 不同为**弱**；参照之间不一致为**参照分歧**；没有可比参照为**无参照**；R 与参照一致为**一致**。

## 八、评价

- **检出缺陷 X**：存在用例 c，在 X 的修复前内核上为强或弱与众不同，在 X 的修复后内核上为“一致”（稳定、未剔除、有可比参照）。强、弱分开报告。
- **确认**：对每组每个种子中第一个检出用例，我人工核对：同一用例修复前异常、修复后恢复，且公共接口约定（手册或参照架构的行为）支持“修复后的结果是对的”。只有确认的才计入主指标。
- **主指标**（每组）：3 个种子各自确认检出的缺陷数、合计数；每条缺陷的首次检出成本（3 个种子的中位数，未检出记为 B+1）。
- **当前版本**（CUR 组）：每组强、弱与众不同的用例数；按（系统调用，riscv 结果，参照结果）聚类；从四组的并集中用固定种子 20261109 抽 40 个聚类（不足全看）人工核对，分为疑似失配、环境/能力、版本、riscv 合法差异、测试自身问题、判断不了。
- **分环节诊断**（只用于诊断，可以使用修复说明）：对每条缺陷记录
  - 候选覆盖：修复所改的函数或宏，是否出现在该组某个提示点的边界项（含定义体展开）里；
  - 输入映射：这样的提示点是否映射到了某个系统调用参数；
  - 关键条件覆盖：我按修复说明写出触发条件（例如“某系统调用、某参数满足某条件”），在执行前写进 `diagnosis_conditions.md` 并记 SHA，再统计每组有没有用例满足；
  - 可观察差异：满足关键条件的用例，在修复前后是否出现差异；
  - 实际触达：本轮不测，记 null（跟踪内核已建，留到后续）。

## 九、参考线（事先写定）

- **G3 显示增益**，当且仅当满足下列之一，并且 G3 每条确认检出的缺陷在 3 个种子中至少 2 个出现：
  - G3 的确认检出合计（3 个种子相加）大于 G0、G1、G2 中最大者；
  - 合计相同，但在 G3 与“合计最大的另一组”都检出的缺陷中，至少一半的缺陷 G3 的首次检出成本中位数不超过对方的一半。
- 否则记为“未显示增益”。只有提示点或映射数增加，记为“桥接进展”，不算增益。
- **G2 对 G1 的比较**同样按上面两条判定，回答“点位定向本身是否有用”。
- 稳定性：每个内核 3 次运行，不稳定用例单独列出。
- 统计行：模型调用 0；构建 N；新确认缺陷 0；新疑点 N。
