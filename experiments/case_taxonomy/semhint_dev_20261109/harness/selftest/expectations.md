# 执行前固定的自测检查

我只运行本目录手写的自测，不运行 gen/。本文件在第一次 QEMU 运行前写定。

- 三个指定内核各运行一次：complete=true、taint_changed=0；每个输入 id 恰有一条结果，所有建 fd、映射和发送消息的准备步骤成功。
- getpid 的参数全部为 0，结果是正十进制数，不是 argK；另用 s:self 检查相同返回值规整为 arg0。
- 从已有 16 字节数据的非阻塞管道读入 b:a:0，读取上限 64，返回 16，主缓冲区恰改写偏移 0–15。独立计算小端位置序列的 FNV-1a，而不借用 C 实现。
- syscall(-1) 返回 ENOSYS；空阻塞管道的 read 超时，耗时至少 500 ms；exit_group 正常退出但不写结果，记 noresult。
- occ 模板的 mmap 占用提示地址后继续调用；adj 模板在提示区间的末尾映射。二者成功时 t=1。另覆盖映射冲突 t=0 和 none 的 t=-1。
- 每个已有 f/p/b/o/i/s 记号均覆盖，z/a/g 三种填充、b 的偏移 0/1/8191、o 的 bit 0/63、64 位整数全位模式均覆盖。f:pipeblockrd 是单独的自测扩展，不改变 piperd/pipewr。
- 同 id 的指针图将指针转换成槽号，按已固定的 xorshift64 13/7/17 顺序独立重算；比较三个架构的所有 g 主缓冲区前 8 个字和池中所有字节。另核对 g 外字节仍为 0xAA、池 0–31 只指向 32–63、池 32–63 全为 0xAA。
- recvmsg 用 f:udgram+b:g:0，原样传随机图，不修改为合法 msghdr；调用的错误结果不作为 harness 自测失败。另通过自测调试检查已排队数据报包含 16 字节、SO_PASSCRED 与一个 SCM_RIGHTS。
- 对信号路径可使用已授权的自测扩展在子进程准备后 raise(SIGSEGV)，不伪造系统调用引发的信号；只有明确开启自测调试时允许。若没有实现，SIGSEGV 路径写未验证。
- 平均每用例耗时：CLOCK_MONOTONIC 从 fork 前到 waitpid 回收结束，包含准备、快照、调用、观测、IPC 和轮询，不包含内核启动和关机。每个架构仅一次，报告该次的平均数，不宣称性能稳定性。
