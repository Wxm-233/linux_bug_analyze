# 修订 2：伪调用 raw_nr 的取值按各架构的表尾解释

2026-11-09 19:40，Claude。写于静态抽取运行期间，此时**没有生成任何用例、没有运行任何测试**，也没有看到任何提示抽取结果。

## 问题

判据第四、五节把“系统调用号”当作伪调用 raw_nr 的一个参数，但没有写取值在三个架构上怎么对应。三个架构的系统调用表不同，同一个原始编号在各架构上是不同的系统调用（例如 0 在 riscv、arm64 上是 `io_setup`，在 x86_64 上是 `read`）。如果原样传入，比较的是不同的调用，结果没有意义。

## 规定

- raw_nr 的“编号”参数统一解释为**相对各架构表尾**的值：
  - 取值 v ≥ 0 时，实际编号 = 该架构内核的 `NR_syscalls` + v（落在表外）；
  - 取值 v < 0 时，实际编号 = v（负数在三个架构上含义相同）。
- 各架构的 `NR_syscalls` 用判据 4.5 的探测方法从组内该架构的构建读出；读不到时取该架构系统调用表中最大编号加 1，并在结果中注明。
- 判据 4.4 的 K3 取值（NR_syscalls 的 −1、0、+1，以及 −1）按此解释为相对表尾的 −1、0、+1 和绝对值 −1。其中“表尾 −1”落在表内，是各架构的最后一个系统调用，彼此不同；它会产生不可比的结果，我按规则保留它，并在结果中单独标出。
- raw_nr 的其余 6 个参数按“其他整数”类取值。
- 通用取值表用于 raw_nr 的编号时同样按上面的规则解释。

其余判据不变。
