# N2.15：原生来源与公共拓扑导出的已读迁移

日期：2026-10-19。仅复用已读die案例，不是新案例、独立验证或自动发现。评估核心`linux_bug_analyze/contract_protocol.py`保持原SHA `42d37cc48d1c87a4c4b938d67a5acaedcc685ceb207deae3f72d7dcc88da830e`，没有将mask专用判定复制为新规则。

## 研究问题及架构因果链

接口名称相同，不表示提供的信息具有相同依据。所查x86 SMP配置提供实际ID与mask定义；s390配置由公共头补默认定义；x86无SMP则只提供架构ID，mask仍回退。公共driver通过同一组getter把这些来源序列化并纳入die属性组。最终宏都存在，因而单纯检查“宏已定义”或“这是x86”会掩盖配置与来源差别。

本轮采用修复版的成组政策：**选择导出任一die属性时，同时需要经审核的原生ID和mask来源**。程序表达为`!listed_any || (native_id && native_mask)`，适用范围只取实际SYSFS配置；原生来源缺失不用于关闭消费者范围。此要求是研究者明确登记的政策情景，不是程序或模型自动推导。

关键权威边界：旧接口文档明确允许ID=-1、mask为给定CPU的默认定义。双原生条件由该修复的成组导出政策确立，不能追认为旧版已有的ABI禁令。父版仅作“如果采用修复政策，会有什么差别”的反事实评价，`historical_normative_verdict`保持不足。个别ID值的语义也不能无条件等同于整个三属性组的要求。见[接口源码复核](source_review.md)、[政策卡](policy_card.md)和[同版修复源码](policy_evidence.json)。

## 方法与材料边界

- `projection.py`从归档宏定义的唯一来源、预处理位置、完整属性数组和声明重算事实，不读取旧结果中的expected/PASS标签。来源路径只作候选分类，另与已审核的原文短体及版本身份核对：修复版架构头沿用已核同blob，回退短体另与修复摘录一致；架构头转发fallback不能被当作原生实现。
- 六个静态上下文分别绑定自己的版本和实际配置SHA。在编译属性表处采样，不把表项、符号或函数名出现当成注册执行或文件可读。
- 四个运行上下文独立核对构建READY、镜像/配置/init身份、首次结束的QEMU回执、命令与原始日志事件、uname和案例标记。普通控制属性、挂载、在线CPU及完整三项读取另行重算。`all_success`只表示三个文件open/read成功，未重新解释其ID或mask数值，更不证明物理拓扑。
- 静态defconfig与既有最小运行配置不同，本轮不互借提供者事实。运行配置尚未在当前适配器中重建两项原生来源，因此runtime的`native_id/native_mask`保持unknown。文件缺失也不等于来源明确不存在。
- 采样点与潜在内容消费期限分开。即使采样关系成立，也不证明首次消费或整个生命周期成立。来源、对象、配置、用途和规范来源由研究者/助手复核，程序只核验已登记的有限关系。

`transfer_inputs.json`在评估前保存10条记录和必要输入摘要；`transfer_results.json`保存核心原始状态，不把旧版的政策差别改写为旧ABI错误。`protocol_pre.json`保留本轮范围，`final_review.md`记录独立方法复核。

## 首次实际评价结果

| 独立绑定的静态配置 | 原生ID / mask | 父版表项→修复表项 | 父版的反事实政策关系 | 修复版政策关系 |
| --- | --- | --- | --- | --- |
| x86 SMP | 是 / 是 | 3→3 | 满足 | 满足 |
| s390 SMP | 否 / 否 | 3→0 | 不满足 | 满足 |
| x86无SMP | 是 / 否 | 3→0 | 不满足 | 满足 |

六项的核心`relation_at_observation`为4 satisfied、2 violated。两项violated包装解释明确为`counterfactual_policy_mismatch_not_old_ABI_fault`；不是两个新增缺陷。修复版无原生来源时不选择此组属性，是符合所选政策的合法选择，不要求架构新增实现。

归档运行视图中，两版x86及旧s390在两CPU上三文件均open/read成功；修复s390在两CPU上三文件均ENOENT，普通属性可读。它们的观测基础齐备，但当前四行两项原生来源都未知，因此核心结果**4 insufficient**，没有凭文件缺失或静态defconfig替其填值。原文件值随事件保留，本轮未重新认证数值意义。

所有10项的`relation_at_deadline`与`whole_path`均不足。当前迁移支持“同一核心可以评价另一类已审核条件关系”，不证明自动得出条件、运行全链或独立泛化。

## 验证和计数

10项投影方法测试、5项适配器边界测试及28项既有核心测试通过。投影器开发首轮9项、修后10项及最后复核记录均保留；适配器日志绑定修改后单独复跑5项，不相加宣称新增测试数量。边界包括不完整三属性不能以残留bool进入判定、运行来源未知不能被逻辑短路掩盖、架构头fallback正文不能认证为原生、回执/版本/镜像/init/日志归属不能混用。

没有新的项目模型调用、Git源码获取、编译、内核构建或启动；两项修复源码仅从已有缓存按登记blob核对摘录。新确认缺陷0，正式独立正/正常0/0。测试组合、源码配置与归档运行视图均不计作新增缺陷。
