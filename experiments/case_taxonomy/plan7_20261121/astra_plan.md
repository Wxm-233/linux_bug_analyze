# 第七次规划：先核实判定，再把公共性质用于实际使用的值

**我的决定是：WT 退回审查线索，保留原表和绑定工具，暂缓跨函数摘要。页表 basic tests 冻结为回归集。下一周主攻一个小问题：公共层交给架构编码的普通交换项，在同一构建读回来之后，公共使用者需要的类型和偏移是否保持。** 先用已有构建和半天源码盘点确认这个问题比原生测试多测了什么。满足条件才实现。历史回放先做供给盘点，本轮不批准为一批修复逐个完整构建父内核。

这会把投入从“多解释一些候选、多跑几种配置”转到一个能作决定的实验。对**当前版本发现**，我要看静态程序能否直接指出一个违反明确约定、且在该版本有合法输入和使用者的独立根因。对**未见缺陷召回**，我要看冻结的程序能否从未见父树中指出真实错误。一个新根因足以证明这项检查有发现价值；一百个通过的构建单元也不能估计它的召回率。

## 二、复用前先处理两个工具的正确性边界

以下是我从实现中读出的判定条件，本次没有执行这些例子，也没有证据说它们已造成那八条报警或某个架构格子的错误结论。它们会改变哪些输出有资格作为自动反证。

- **WT 的“源不比目标宽”只对部分类型成立。** `rng.py:262` 在 `sw <= dw` 时直接返回“放得下”，忽略已经取得的符号信息。例如同宽的无符号 32 位源可以超过有符号 32 位目标的上界，有符号负值也不能原值存入无符号目标。未来应比较源区间是否包含于目标区间。原池报告里，ext4 和 kdb 走这条捷径的记录分别为相同的无符号类型，这两条本身没有展示上述反例。另一个问题在 `Eval.var`：用源码偏移和“前面有退出”近似支配；外层条件可能绕过该检查，then 分支内被检查的变量也可能再赋值。缺少控制流与到达定义证据时只能记未知。`overall` 又只汇总已经取得的转换，相关构建解析失败或同一候选的一个签名没找到时，需要显式保留缺项。[值域判定](../wtrange2_20261121/rng.py) · [全池逐构建结果](../wtrange2_20261121/pool_rng.json)
- **页表解释器存在会给出确定值的近似。** `evalpg.py` 的 `Interp.binop` 对未知的无符号 `x`，在简化 `0 - x` 时可能返回 `x`；固定宽度下两者通常不同。运行时判断的 `oracle` 又以函数名作键，同一判断函数查询不同特性时可能被强制取相同真假值，漏掉合法组合。已有的空输入检查很好；还要检查**抽象解释有没有排除真实输入**。在新轮把这些分支限制为已校准语义，不支持的返回未知；运行时谓词要有“函数＋有效实参＋构建”的身份，组合只在有可行性证据时才可作反例。先按本轮所用操作做小型、可穷举位宽的抽核，用编译器具体求值作对照。涉及上述路径的旧结论列为待核，未走这些路径的格子无需重跑。[静态求值实现](../pgassert_20261121/evalpg.py)

这项复核限 **1 人日**，在新实验目录做。对 WT 至少覆盖同宽异号、可绕过的外层分支、分支内重新赋值、相关构建缺项；对页表至少覆盖固定宽度减法、两个不同谓词、空输入域、合法与不适用配置。任何“可确定”的抽象结论都必须与对应具体值一致。到点仍有冲突，就把有关操作标为不支持，不借本轮重写通用 C 解释器。复核若改变既有结论，交付按条目的差异表，旧轮次文件保留原样。

## 三、WT 的去留：先估算摘要能解决多少，再谈实现

**不把 WT A 类当作下一轮主要审查队列；保留其作为候选来源以及专门核对某个转换的用途。** AMD 案例说明一条真正有配置依赖的窄化值得追踪。WT 第三版的 `compute_bounded` 已按子系统、结构体、字段名汇总所见写入；再加一遍“我见到的赋值都小于 32 位”，会重复它的能力。尤其是磁盘读入、间接写入、指针逃逸、其他翻译单元写或构建选择的另一种实现，都会使这一推理失去前提。[WT 第三版代码](../widthtrunc3_20261117/widthtrunc3.py)

若用户专门要降低 WT 审查负担，我只建议做一次 **1 人日的收益上限盘点**。可用未双人审查的原 24 条作诊断，不能再用作未来独立验收。两人先不看新算法输出，逐条填写“数值受什么约束、证据在哪、一个有界摘要能否独立取得它”。明确区分：

| 非局部知识 | 可自动化的第一版边界 |
|---|---|
| 直接被调函数的所有正常返回均落在可证区间 | 最多一层，按同一构建绑定唯一实现，对**所有**可达返回的区间取并。存在外部定义、未解调用或无法证明的返回，就记未知。频率在真机上通常不大，本身不构成源码上界。 |
| 私有结构字段只经有限个写入点赋值 | 须证明对象不逃逸且所有写入可枚举，包括初始化和整结构复制；每个写入都能取界。先限同一翻译单元的私有对象。不得从子系统内没有搜到其他赋值推全局封闭。 |
| `*pos - vbo`、磁盘格式、文件系统上限 | 两值之差往往需要两者的相对关系，两个各自的上界未必有用。磁盘值需找到读取后的校验，配置常量需找到它实际约束此对象的路径。把这些单列，不能计入“加一层返回摘要就可解决”。 |

重新开工的门槛是 **24 条中至少 6 条可新增证明，且其中至少 4 条靠同一种摘要机制、分布在至少两个子系统**。人工须写出完整证据；“经验上安全”计未决。若过线，只实现贡献最大的一种机制。冻结后在另取的至少 24 个未审根因簇上，与修正后的局部基线逐条配对，要求净增至少 6 个正确反证、错证为 0、额外审核和摘要准备工时计入后仍省时。旧 8 条和已看过的非局部例子只作回归。全池已有冻结版输出，评审者可以对**新标签和新方法**设盲，不能再宣称这个版本从未被看过。不做这项盘点也不影响下面的主线。

## 四、页表下一步选什么

**优先换性质及其应用位置，先用已有架构。** 我在本地目标树读到一个可以当天核实的切口。`mm/debug_vm_pgtable.c` 的 `pte_swap_tests` 已经用 `swp_entry_to_pte` 构造条目，检查解码后属于普通 swap，再检查“PTE → 架构交换项 → PTE”的字节往返。它的普通交换项用 `MAX_SWAPFILES - 1` 和探得的最大 offset 构造。因此，“再测一次最大 offset 的往返”没有多少新增内容。

值得盘点的是**相反方向以及生产代码真正读取的字段**。同版 `include/linux/swapops.h` 声明普通交换项保存类型与偏移，`include/linux/leafops.h:47` 起说明从 PTE 恢复公共表示，对 present/none 有专门约定，转换时会清掉 PTE 的附加标志。`mm/swapfile.c:2552` 有公共代码对实际条目解码。拟检查的等式是：对该构建**确实接纳的普通交换类型和页偏移**，经公共构造、架构编码和公共解码后，普通交换类别、类型和偏移分别保持。必须核对生产端谁接纳这些输入、消费端谁按这些字段选对象。类别相同不等于偏移相同；字节往返能保住某个已经编码的 PTE，也不保证两个不同公共输入没在编码时合并。原生测试的既有覆盖和新性质的区别可以据此逐格记录。

有两条关键限制：

1. **输入域独立核对。** 目标树 `mm/swapfile.c:3449` 的 `generic_max_swapfile_size()` 本身用编解码探测上限，另有架构覆盖；生产端采用的上限必须尊重。由同一对辅助函数算出最大值，再用它证明编码容量正确，会形成循环。应从有效配置、启用的普通 swap 类型、生产端接纳的页数与保留项规则取得合法域。只主张该域内的字段保持。若某个中间偏移实际能否使用没有独立证据，就退回有证据的具体输入。对齐、保留槽位、交换区大小、MAX_SWAPFILES 的构建差异均进入适用记录。**只有测试范围外多了输入或配置，且有公共使用语义，才算扩展。**
2. **避免测错对象。** 第一轮只做普通交换项。present、none、迁移项、设备私有项和附加标志均单列；不要求被有意清掉的标志逐位相等。初始枚举取合法的内部类型和偏移、相邻合法值、位边界两侧，附输入出处。不把软硬件任意组合或任意非 present 位串当作生产输入。不需要模拟页表写入或构建可启动镜像。

| 备选投入 | 本轮决定及重新考虑条件 |
|---|---|
| powerpc、s390、LoongArch 的 basic tests | 只扩大 ISA 能检验可移植性，未必增加新性质。若现有配置上已证明有额外有效覆盖，且对某个新 ISA 的**目标版本**静态核对表明它有不同编码或实现选择，再选一个。优先选能由配置、生成头和一个翻译单元明确选定实现的目标；powerpc 的 hash/radix 若只能靠未建模运行时选择，先做单模式可确认的配置，不能据架构名合并两种结果。 |
| advanced tests | 暂缓涉及页表写入、同步及别名的通用内存模拟。这里的 swap 检查虽然也在 basic 清单之外，所需转换主要是纯值，改造成本较低。若将来有契约只读写一个可精确绑定的对象，而且有历史供给，再研究单对象的小范围模型。 |
| 其他自测、kernel-doc、Documentation/ABI | 优先配对“同版、明确的输入输出约定＋独立生产者/消费者＋现有自测未验的合法域”。注释先经两人裁定对象、条件、单位和例外，再机械求值。swap 盘点未过线时只记录这套筛选标准，本轮不临时改题直到碰巧出现结果。 |
| BUILD_BUG_ON 等编译期断言 | 对已构建的正常配置，编译器已经检查。适合验证新配置或校准求值器；重报同一构建会失败的断言不算发现。 |
| 整条线收手 | 若候选性质只能复述已有向量，或无法从生产代码取得独立输入域，结束本轮发现实验。basic tests 仍可用于以后比较编译器、配置或架构改动；不再从其“通过格子数”推断检测能力。 |

## 五、接下来八个工作日的执行顺序

以下阈值是建议写入下一轮 `criteria.md` 的工程决策线，均未实测。以一名实现者为主，另预留独立评分者合计约 1 人日。若只有一周，做到第 5 天；WT 摘要盘点与历史构建均可推迟。

|---|---|---|

**第 10 天历史回放仍有研究价值，但价值在检验迁移，优先做不需要构建的那部分。** 对原 basic 检查和新交换项性质分两张表，不拿后者的命中给前者补分。评分者从本地已公开修复史按时间、公共接口和架构实现的改动范围建池，兼收改变实现、调用或前置条件的修法；以同根因、同修复系列、回移和近复制实现聚类。排除已登记、设计时读过及既有封存样本；设计者只拿去重计数、预算和可执行性。记录修复父树里是否已有性质、是否能定位对象，旧版本缺少后来命名的接口时只接受父树中独立存在的等价证据。在候选出分前冻结真值和分母，不能只挑“恰好新增某个 helper”的修复。

保留第六次规划的供给门槛：对准备评价的检查，至少 **5 个未见真实根因、涉及至少 2 个接口族或不同语义操作组**，才值得动用历史构建预算。先做同版配置和 `make prepare`、需要的生成头，以及代表性翻译单元；编译命令必须能证明来自该版本的有效构建。只有确需比较原生自测并且预算允许时才构建可启动镜像。给准备和回放 **2 人日**，评分者按冻结清单执行，基线和新程序使用相同输入，旧树不兼容记未知。只够做两个样本时叫回放可行性检查，报告完成数和严格命中数；不能外推五个样本的召回。在准入分母上较九项净增至少 2 个严格根因且跨至少 2 组，才投入第二批历史回放。原生测试未跑的格子不能宣称静态预测胜过原生。

## 六、评测与隔离

- **当前发现**按版本、固定人时、去重根因计。记录直接由静态性质报出、人工顺线追到、已有上游修复或仅有静态线索的区别。原生固定向量通过而新合法域中发现违反，还要让独立判定者核实该输入能由真实公共路径产生。QEMU 有现成环境时可补功能证据；跑不起来就保留证据等级。七个既有登记仍作回归。
- **未见召回**保持旧基线 0/23。专题以独立根因为单位，同时报全体、父树已有约定、能构建、能求值、严格命中五个数；不能构建和未知仍保留在全体分母。严格命中要指出同一对象、被违反的性质及对应实现。位置命中、修复后消失、相对九项的净增和相对原生的增益分别列。未获得独立样本时召回为 null，完成有效回放而没有命中时才是 0。
- **隔离**设计只用开放材料，封存库、历次晚期样本和模型运行记录继续隔离。离线第二评审可用 Codex；检测程序和排序不调用模型。所有冻结后的阈值改动另写 amendment；因结果才增加的性质、新架构或输入示例归到下一轮开发记录，不回写成独立命中。

如果现在只做一个决定，我建议批准**一天复核判定语义、一天核对真实交换项的输入域**。这两天可以给出比“再建一个内核看看”更直接的答案：我们究竟取得了一条对公共使用者有意义、原生测试还没有覆盖、而静态程序能够独立判定的性质，还是已经把现有证据能支持的范围做完了。
