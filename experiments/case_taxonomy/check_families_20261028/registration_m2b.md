## 写定前已知的信息（如实列出）

- M2/M2a在两例的命中与持续观察（README结论表）。
- 登记前查到上游`e795707703b3`（2021-11-29，“export cluster attributes only if an architectures has support”）对cluster属性做了同类门控；主线v7.3-rc2的`drivers/base/topology.c`对die、cluster、book、drawer有`TOPOLOGY_*_SYSFS`门控，对core/package/thread等属性没有。

## 收紧规则（M2b = M2 ＋ M2a门控规则 ＋ 下列两条）

1. **F1b**：只保留`##`拼接调用产生的实例（`kind = pasted`）；顶层函数直接使用可覆盖宏的实例（`kind = direct`）不再生成。
2. **F2b**：上限宏L的展开链（深度≤3）必须**包含G本身**（M2只要求与G的展开链有交集）。

其余（追踪上下文、可覆盖宏定义、实体判定、门控函数、契约模板、判定上下文）不变。M2b实例是M2实例的子集，复用M2已采集的事实，不新增构建。

## 主线结局标注（标注，不是收紧，也不是独立评价）

对M2b在父版与修复版**都报**的每条观察（实例×上下文），在主线`df2908090cda`（v7.3-rc2）同一上下文重新采集同一实例的事实并判定：
- 主线不再报 → 标“主线已解决”；
- 主线仍报 → 标“主线仍存在”；
- 主线事实不可得或构建失败 → 标“主线不可判”。

主线采集沿用两例的判定上下文，但**不使用die的riscv旧编译参数**（主线已含上游修复，参数可能冲突），其余配置相同。门控函数若在主线不存在，按M2a规则从析取中去掉；实体或宏改名会使结局标注失真，记为局限。

## 报告指标

每例：父版独有、修复版独有、两版都报（按结局标注分三类）的观察数（格），以及与M2/M2a相比被去掉的实例与格数。

事先预期：die不变（全为拼接实例），两版都报的观察中cluster两组实例应标“主线已解决”，core/package/thread等标“主线仍存在”；shmem去掉F1直接使用28格，F2b去掉`TASK_SIZE`配对，父版独有仍为目标1格。

## 不做

不调用模型；观察不称缺陷；“主线已解决”不计独立正例（两例已深度接触）；M2b是否进入冻结待用户确认。
