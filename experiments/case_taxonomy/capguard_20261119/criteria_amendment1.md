# 判据修订 1：B2 只认“能力不满足就提前返回”这一种保护（capguard_20261119）

2026-11-19，Claude。**写于看到开发样本结果和当前版本候选分布之后，独立召回运行之前。**

## 原因

当前版本（df2908090cda）共 76 条候选，其中 B2 71 条。71 条里 54 条的能力判断是 `in_compat_syscall()`，集中在 netfilter 的 `ip_tables`、`ip6_tables`、`arp_tables`、`ebtables`。

这些代码的写法是 `if (in_compat_syscall()) { 走 compat 路径 }`，是在选分支，不是在判断能力。compat 路径和普通路径都会调用 `cleanup_entry` 这类本文件函数，于是被当成“判断不一致”。

两个开发样本靠的都是“能力不满足就提前返回”这种保护：`hugetlb_init`、`hugetlb_report_meminfo` 等都是 `if (!hugepages_supported()) return ...;`。

## 修改

判据第二节第 3 点“被保护的调用处”去掉 `if (X(...)) { ... }` 块这一种。只保留：
- 函数最外层 `if (!X(...))`（或其中一个 `||` 分支是 `!X(...)`），紧跟的语句里有 `return`，此后的调用算被 `X` 保护；
- 以及由此传递得到的保护（`static` 函数所有调用处都被保护）。

B1 不变。
