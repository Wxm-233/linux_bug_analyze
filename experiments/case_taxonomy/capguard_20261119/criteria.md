# 判据：能力判断检查（capguard_20261119）

## 一、要找的问题

有些架构能力要在运行时判断，比如“能不能改直接映射”“支不支持大页”。内核用**可被架构覆盖的判断函数**表示这类能力：公共头文件里有一个默认实现，用 `#ifndef X` 包着，部分架构自己定义 `X`。下面统称“能力判断”。

两种缺陷形态：

- **B1 静默成功**：某个架构对接口 `F` 的实现，在能力不满足时什么也不做，却返回成功（开头是 `if (!X(...)) return 0;` 或 `return;`）。公共代码调用 `F`，又没在任何地方检查 `X`，就会把“没做”当成“做了”。例子：arm64 的 `set_direct_map_invalid_noflush()` 在 `!can_set_direct_map()` 时直接返回 0；`mm/secretmem.c` 从不检查 `can_set_direct_map()`。
- **B2 判断不一致**：同一个文件里，某个本文件定义的函数 `G`，有的调用处在能力判断 `X` 的保护之下，有的调用处不在。没被保护的那一处，就可能在能力不满足时照样做事。例子：`mm/hugetlb.c` 的 `hugetlb_hstate_alloc_pages()` 在 `hugetlb_init` 里位于 `hugepages_supported()` 判断之后，在 `hugetlb_bootmem_alloc()` 里却没有判断。

属于实现一致性检查（存在与选用、能力）。

## 二、规则

1. **能力判断集合**（逐版本机械得出）：名字 `X` 同时满足下面三条，就算能力判断：
   - `include/` 下的头文件里有 `#ifndef X`，紧接着（10 行内）给出 `X` 的默认定义（`#define X` 或 `static inline ... X(`）；
   - 至少一个 `arch/<a>/` 下的头文件或 `.c` 文件定义了 `X`（宏或函数）；
   - 全树至少有一处 `if (X(`、`if (!X(`、`&& X(`、`&& !X(`、`|| X(`、`|| !X(` 这类条件用法。
2. **B1 静默成功**：
   - 在 `arch/<a>/` 下找函数 `F` 的定义：函数体最外层有 `if (!X(...))`，紧跟的语句是 `return 0;`、`return;` 或 `return false;`，其中 `X` 是能力判断；
   - 对每个这样的 `F`，在公共代码（不在 `arch/` 下的 `.c`，去掉 `tools/`、`scripts/`、`samples/`、`Documentation/`、`usr/`）里找对 `F` 的调用；
   - 如果调用所在文件里**任何地方都没出现 `X`**，就报出这处调用。
   - 记录：文件、函数、行、接口 `F`、能力判断 `X`、静默成功的架构列表。
3. **B2 判断不一致**（只看公共代码的 `.c` 文件，逐个文件）：
   - **被保护的调用处**：
     - 函数 `g` 最外层有 `if (!X(...)) return ...;`，此后 `g` 里的调用都算被 `X` 保护；
     - `if (X(...)) { ... }` 块里的调用，也算被 `X` 保护；
     - 一个 `static` 函数，如果本文件里有调用它的地方，而且所有调用处都被 `X` 保护，那么它里面的调用也算被保护。反复传递，直到不再变化。
   - **报出**：对本文件定义的函数 `G`，如果它在本文件里既有被 `X` 保护的调用处，也有没被保护的调用处，就报出没被保护的那些调用处。
   - 记录：文件、函数、行、`G`、`X`、一处被保护的调用作为对照。
4. 不编译，直接读该版本的 git 对象。签名不含行号：`CAP|B1|F|X` 或 `CAP|B2|G|X`。
