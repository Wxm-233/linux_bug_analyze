## 二、改进项（写死）

**I1 效果类别（解决“只认写内存”）。** 一个实现的效果集合，是它自身及其调用闭包（按函数名在同一棵树的事实里展开，深度 3）中出现的下列类别之一：

| 类别 | 判定（调用名，正则全匹配） |
|---|---|
| mem | 原摘要的 `writes` 非空，或调用 `memset`、`memcpy`、`clear_page`、`copy_page` 等写内存函数（沿用上一轮的 `WRITE_FN`） |
| tlb | `\w*flush_tlb\w*`、`\w*tlb_flush\w*`、`sfence_vma\w*`、`\w*tlbi\w*`、`arch_tlbbatch_\w+` |
| cache | `\w*flush_(dcache\|icache\|cache)\w*`、`\w*dcache_(clean\|inval)\w*`、`\w*icache_inval\w*`、`caches_clean_inval\w*` |
| pgtable | `set_(pte\|pmd\|pud\|p4d\|pgd)\w*`、`__set_pte\w*`、`(pte\|pmd\|pud)_clear\w*`、`set_memory_\w+`、`\w*change_page_attr\w*`、`apply_to_page_range`、`\w*set_direct_map\w*` |
| barrier | `(smp_)?[rw]?mb`、`dsb`、`isb`、`fence\w*`、`\w*_mb__\w+` |
| register | `register_\w+`、`list_add\w*`、`hlist_add\w*`、`rb_insert\w*`、`xa_store\w*`、`idr_alloc\w*` |

实参资源 R 的效果：原规则判为“有效果”的，仍为“有效果”；原规则判为“判断不了”的，若效果集合非空，改判为“有效果（类别）”。返回值资源不变。

**I2 只返回常量的判定收紧。** 原摘要“只返回常量”的函数，如果函数体里有检查（`checks` 非空），不算“只返回常量”。例如 `perf_reg_validate` 按掩码返回 `-EINVAL` 或 `0`。

**I3 多数架构对照（区分“漏写”和“不需要”）。** 对每个接口，在同一时间点的源码中统计每个架构目录（`arch/` 下的全部架构）是否有自己的定义（函数定义或 `#define`），以及定义是否“平凡”（函数体为空或只有一条 `return 常量;`；宏展开为空、`do { } while (0)` 或单个常量）。定义：

- **n_impl**：有非平凡定义的架构数（不含 riscv）；
- **riscv 缺**：riscv 没有自己的定义且通用默认是平凡的或不存在，或者 riscv 的定义是平凡的。

**I4 横向定性改为“本架构缺、多数架构有”。** 一个位置定性成立，需满足下面两种情况之一：

- **Q-多数**：riscv 缺，且 n_impl ≥ 3；
- **Q-类别**：riscv 有实现，但它的效果集合缺少某个类别，而 arm64 和 x86_64 的实现都有这个类别（I1）。

原来的“有的架构有效果、有的没有”不再单独算定性成立。只有 1～2 个架构实现的接口记为“特性专有”，不算定性成立。

**I5 检查的判定。** 变量出现在条件里，但它在该行只是作为某个调用的实参（同一行有该变量的 `arg` 使用），不算对该变量的检查。例如 `if (... kasan_unpoison_pages(page, ...))` 不算检查了 `page`。

**I6 返回值用在更大的表达式里（`expr`）。** 记为 F2，资源为返回值，之后的使用取“同一行之后第一次使用”。因为抽取时没记被赋值的变量，所以只看同一行是否位于检查之内：同一行有检查就不算候选。

**I7 按接口聚合。** 人工建议改为每个接口一条：列出所有调用位置，得分取各位置的最高分。路径统一规范化（`kernel/../mm/internal.h` 改为 `mm/internal.h`）后再去重。

**得分**：位置得分 = 形态权重（F2、F3 为 2，F1 为 1）× 稀有度 × 补丁证据（同上一轮）。接口得分 = 位置得分最大值 × 定性系数：Q-多数为 3，Q-类别为 2，不成立为 1，特性专有为 0.5。
