# 修复策略的独立检验（判据，收集样本之前写定）

## 这一轮要回答什么

`fix_strategy_20261104/`从样本集135条跨架构缺陷的修复（RISC-V，`v6.6..df2908090cda`）中，为8类机制归纳出修复策略。这些策略是从同一批修复归纳出来的，`fix_strategy_demo_20261104/`的演示用的也是我分析过的疑点，所以至今没有独立证据说明“按机制的修复策略能指对修法”。

本轮在**归纳时没有用过的修复**上回答两个问题：
1. **策略能否覆盖新修复**：新的跨架构缺陷修复，有多少正是该机制的策略所描述的修法？
2. **策略能否帮助写出修法**：只给缺陷、不给修复，让模型预测修法。给策略和不给策略各做一次，比较哪个更接近真实修复。

修复策略在本轮冻结为`strategy_table.md`（内容照抄`fix_strategy_20261104/README.md`的“修复策略”表和两项检查，SHA见`criteria_sha256.txt`），本轮不改。

## 二、第一标注人的标注（模型调用之前完成并冻结）

逐条阅读提交说明和改动（超过60行的读统计和相关部分），沿用已有定义：

| 字段 | 依据 |
| --- | --- |
| 跨架构C/R、对应物种类K1/K2/K3与位置、修复时其他架构的状态S0–S3 | `cross_arch_sample_set_20261102/criteria.md`及修订2（`criteria_amendment2.md`）。L类中“其他架构”包括RISC-V |
| 机制M1–M10、X1、X2 | `catalog_v2.md`及修订2 |
| 构建错误、非C代码 | 同样本集 |
| 修复动作（主动作A0–A11）、`follow`（F1–F4）、`layer` | `fix_strategy_20261104/criteria.md`及修订1 |
| **策略覆盖** | 只对C类、机制有策略的条目：**Y** 修复正是该机制策略的“典型修法”；**P** 修法属于策略所说的方向，但策略没写到关键一步，或落在策略的“反例或注意”中；**N** 修法与策略无关；**—** 机制没有策略（M2、M6、X类） |

- 对应物位置写成“文件:函数”，在修复前一版（`修复^`）中用`git grep`核实，程序据此提取对应物代码。
- 全部标完后记录`labels.json`的SHA，之后不改；确有错误另写修订。

**评估集**：C类、机制属于有策略的8类（M10、M7、M1、M8、M5、M9、M3、M4）、不是构建错误的条目。其余只作描述。

## 三、模型预测修法（需用户授权后调用）

### 3.1 问题描述（去掉修法）

提交说明通常同时写了问题和修法。为了让预测时看不到修法：
- 每条用一次模型调用，把提交说明改写为只描述问题的文字：现象、出错的条件、在哪个函数，**不写怎么修**；
- 改写后我逐条检查，删去仍透露修法的句子，删改逐条记录在`redact_edits.json`；
- 程序检查最终描述中不含修复提交号和修复提交的标题。

### 3.2 预测（两种条件，各一次）

| 条件 | 输入 |
| --- | --- |
| **N：不给策略** | 架构；问题描述；机制及其定义；对应物种类和位置；修复前一版中出错函数的代码（每个最多200行）和对应物的代码（最多200行）；修复动作A0–A11的定义 |
| **S：给策略** | N的全部输入，再加`strategy_table.md` |

模型输出：主修复动作（A0–A11之一）；是否照对应物改（照／另行实现／无可照做法）；修法说明（不超过10行，可附示意改动）。

- 模型：Claude-Sonnet-5.5（配置`claude-sonnet55-20261103`），8路并行，不自动重试；第一批8个都没有答案就停止。
- 两种条件的提示除策略段落外逐字相同，程序检查。

## 四、评分

| 指标 | 怎么算 |
| --- | --- |
| **策略覆盖率** | 评估集中第一标注人标Y的比例，以及Y＋P的比例 |
| **主动作命中** | 预测的主动作等于标注的主动作（程序） |
| **是否照对应物命中** | 预测“照”对应标注F1、F2；预测“另行实现”“无可照做法”对应F3、F4（程序） |
| **修法一致** | 预测的修法说明与真实改动比较，记**同**（改的是同一处、同一种做法，细节可不同）、**部分**（方向对，但漏了关键一步或多改了错误的东西）、**不同**。由我在**不知道条件**的情况下判：程序把两种条件的预测打乱顺序、隐去条件，答案放在单独文件，判完再合并 |
| 程序基线 | “按135条中该机制最常见的主动作预测”的主动作命中率，用来看模型和策略是否比简单查表好 |

R、L分开报告，再报告合计。两种条件按同一条目配对，报告“S对N错”“N对S错”的条数。

## 五、参考线（看结果之前写定）

- **策略能覆盖新修复**：评估集中Y＋P不少于60%，且Y不少于40%。
- **策略能帮助写出修法**：条件S的“修法一致（同）”不低于50%。
- **策略对模型有增益**：条件S比N的“修法一致（同）”高出不少于10个百分点；不足10个百分点记“增益不明显”。主动作命中同样报告，但只作描述。
- 评估集少于30条的，只作描述，不按参考线下结论。
- L类的结果单独看架构上的推广；R、L结论不一致的照实写。

## 六、其他规定

- 只读提交、标注和调用模型，不构建、不运行内核。
- 新发现的问题只记录，不对外报告。
- 测试只运行一次；之后若改提示或策略，算作新一轮，不覆盖本轮结果。
- 收尾用`round_close`。
