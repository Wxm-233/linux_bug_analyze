# 函数识别缺陷的影响评估

## 缺陷是什么

项目里有两个“找出代码中每个函数”的实现：`candidate_bridge.function_spans`和`sibling_pairs.named_spans`。

它们找函数名的方式相同：遇到函数体开头的`{`时，只看这一行和前面3行。如果函数头（返回类型、函数名、参数列表）在`{`之前写了4行或更多，函数名就落在这个范围之外。这样的函数会被整个丢掉，当作不存在。

这个问题是在`mech_riscv_hugetlb_steps_20261031`中发现的：RISC-V的`set_huge_pte_at`、arm64的`clear_flush`等函数都被漏掉了。

本轮按事先写好的计划（`criteria.md`，SHA `a75784d2…`）评估它对此前各轮的影响。修正后的识别（`wide_spans.py`）往回找到上一个以分号或右花括号结尾的行、空行或预处理行为止，最多15行，其余规则不变。

## 结果

### 1. 有多普遍（终点版本全部37 347个`.c`文件，`prevalence.json` `0e6d0e7d…`）

| 目录 | 被漏掉的函数占比 |
| --- | ---: |
| 全部 | **3.9%**（约26个函数漏1个；8431个文件至少漏1个） |
| fs | 9.4% |
| net | 6.3% |
| drivers | 3.8% |
| mm | 3.1% |
| kernel | 2.9% |
| arch | 1.8% |

RISC-V中被漏掉的例子有：`elf_kexec_load`、`image_load`、`machine_shutdown`、`acpi_numa_get_nid`。

### 2. 对各数据集目标函数的影响（`targets.json` `670c1d8c…`）

用原实现重算，每个数据集都能逐对复现已存的目标，说明重算本身可靠。换成修正实现后：

| 数据集 | 配对数 | 目标集合有变化 |
| --- | ---: | ---: |
| P1′样本 | 50 | 7 |
| 留出池 | 22 | 2 |
| 兄弟数据集 | 105（去重前） | 8 |
| 约定变化跟进配对 | 305 | 6 |

- 约定变化跟进的配对漏斗中，有效配对从305增加到**312**，多出的7对原本因为目标函数被漏掉而没有进入样本。
- RISC-V方向的24对，“改已有函数”从6对变为**8对**（`riscv_cases_wide.json` `8072bf2d…`）。新增的2对是KVM的`kvm_arch_prepare_memory_region`和BPF的`__arch_prepare_bpf_trampoline`。

### 3. 对主要结论数字的影响（候选和目标都用修正实现重算）

| 轮次与结论 | 原数字 | 修正后 | 变化 | 事先规则下的结论 |
| --- | --- | --- | --- | --- |
| P1′：模型写规则 对 同路径基线（50对） | 30% 对 52%，p=0.019 | 30% 对 54%，p=0.008 | 2个百分点 | 不变（方法仍明显不如基线） |
| 兄弟数据集：真兄弟47对上，结构与接口候选合起来（前20） | 37/47（79%） | 35/47（74%） | 4.3个百分点 | 不变（未超过5个百分点） |
| 兄弟数据集：全部103对，合起来 | 56（54%） | 55（53%） | 1个百分点 | 不变 |
| 留出池：结构基线前20（22对） | 5（23%） | 5（23%） | 0 | 不变 |
| 约定变化跟进v1：全部候选覆盖（208对） | 44.2% | 44.2% | 0 | 不变（仍低于50%） |
| 约定变化跟进v2：全部候选覆盖（208对） | 51.4%，池中位数174 | 51.9%，池中位数175 | 0.5个百分点 | 不变（仍以很小余量通过） |
| 约定变化跟进抽检30对：真实跟进中v1/v2覆盖 | 7/21、12/21 | 7/21、12/21 | 0 | 不变 |

输出：`rescore_p1prime.json` `894287fb…`、`recompute_cov.json` `aca574da…`、`ccp_recompute.json` `9815e50a…`。

**结论：缺陷确实存在，全树约漏掉4%的函数，但此前各轮的主要结论都不受影响，所有变化都不超过5个百分点。**

有一点值得注意：修正后，候选覆盖有时反而略降。原因是候选列表里补进了原先漏掉的函数，有的目标因此被挤出了前20名。

### 4. 没有重算的环节

| 环节 | 为什么没重算 |
| --- | --- |
| P1（40对同作者兄弟） | 与P1′用的是同一套判分和函数识别。P1′的结论没变，P1预计也不变，但没有实际重算 |
| E4检查族、M4变化点等早期库模块 | 这些结论来自少量已读案例（例如E4的5个真修复全部漏检），且缺陷只影响约4%的函数。没有重算 |
| 程序规则判定、模型判定试点 | 它们评价的是对给定候选的判定能力，候选生成的覆盖已经重算过，不受影响。没有重算 |
| 方向4第一轮（大页钩子检查） | 没有用这两个实现 |
