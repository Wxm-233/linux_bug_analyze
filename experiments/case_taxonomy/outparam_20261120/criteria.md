## 二、第 1 天：比较单位和分母（输出 `scope.csv`）

1. **调用方翻译单元**：`mm/`、`kernel/` 下、至少在两个构建的编译数据库里出现的 `.c` 文件。
2. **预处理**：用该构建的原编译命令改成 `-E`（去掉 `-c`、`-o`、依赖文件参数），在原目录运行，保留行标记。只在内存里解析，不落盘全文。
3. **调用点**：函数体的行标记来源是这个 `.c` 文件本身的函数里，所有形如 `名字(` 的直接调用。成员调用 `x->m(`、`x.m(`、`(*p)(` 记为**间接调用**，单独计数，本轮不追。`__builtin_*` 不计。
4. **每个构建里的绑定**：
   - 这个翻译单元的预处理结果里有这个名字的函数定义（包括头文件里的 `static inline`），就绑定到它；
   - 否则在该构建编译数据库所列的 `.c` 文件里找非 `static` 定义（词法扫描原文件；有非 `__weak` 定义时忽略 `__weak`）：恰好一个就绑定；没有记为**缺席**；多于一个记为**未知**。
   - 绑定记录：定义所在文件和行（按行标记还原）、预处理后函数体的哈希。
5. **单位** = 调用点（调用方文件、函数、行、被调名字）。状态互斥：
   - **双侧可绑定且不同**：至少两个构建都能唯一绑定，且定义位置不同或函数体哈希不同；
   - **双侧同实现**：能绑定的构建都绑定到同一位置、同一哈希；
   - **一侧缺席**：调用方只在一个构建入选，或其他构建缺席；
   - **间接调用**；
   - **解析未知**：其余（多个定义、预处理失败、函数解析失败）。
   每个状态计数并保留位置。**接口**按被调名字计。

## 三、第 2 天：输出参数比较（输出 `pairs.csv`、`reports.jsonl`）

只看“双侧可绑定且不同”的单位，且限于：
- 调用方传的是**局部对象地址**：实参是 `&v`、`&v.f`、`&v->f`（`v` 是调用方函数体内声明的局部变量，不是形参、不是全局）；
- 调用之后，同一函数里读了 `v`（标量）或 `v.f`。

**被调实现一侧**（每个构建绑定到的那份定义）：对实参对应的形参 `p`，逐条走正常返回路径（复用 `p1check` 的语句树）：
- **正常返回**：返回 `int` 的函数是 `return 0` 或非负常量；返回 `bool` 的是 `return true`；`void` 是任何返回或走到末尾；返回指针的是非 `NULL`、非 `ERR_PTR`。返回一个变量且判断不了时，记为“成功与否未知”。
- **写入**：`*p = …`（整体）、`p->f = …`、`p[…] = …`（整体）、`memset/memcpy/memmove(p, …)`（整体），或把 `p` 传给一个能唯一绑定、且在所有路径上都写这个形参的辅助函数（最多一层）。把 `p` 传给判断不了的调用，或取 `p` 的别名，记为“未解析”。
- 每个字段 `f`（或整体）的状态：**必写**：所有成功路径都写；**明确未写**：有一条成功路径没写，而且这条路径上没有“未解析”；**未知**：其余。

**调用方一侧**：用同一语句树走调用方从调用到读点的路径：
- 成功分支：返回值被 `if (ret)`、`if (ret < 0)`、`if (IS_ERR(x))`、`if (!x)`（指针）判为失败的分支不算；`if (!ret)`、`if (ret == 0)`、`if (ret >= 0)`、`if (g(...))`（`bool`）为成功分支；没检查返回值的全算成功分支，并标“未检查”。
- 记录：调用前这条路径上是否已初始化 `v` 或 `v.f`（声明初值、赋值、`memset`）；调用后到读点之前是否补写。

**报告**：一个单位里，对调用方读的那个字段，两个构建的实现状态不同，就出一条报告，给出被调接口、两个构建、两份定义的位置、字段、两侧状态、明确未写路径的条件和行、调用方读点、初始化和补写情况。

## 四、两种排序（同一张报告表）

- **粗排**：只要求两侧对该字段的写入状态不同。按 `SHA256("20261120|" + 接口键 + 位置)` 排序。
- **证据排序**：三项，各记 0/1，按满足的项数从多到少：
  1. 双侧都绑定，且两侧的成功条件可比（返回类型相同，调用方的检查方式相同）；
  2. 一侧明确未写，对侧必写；
  3. 调用方在成功分支上读同一字段，调用前、返回后都没有补写。
  未知不加分。同分按上面的 SHA256 排序。
- **合并重复**：按（接口、参数序号、字段、明确未写的那份实现）合并，见证点全部保留。

## 五、四份微型对照（事先写定预期，不计发现数）

用一份人工写的小翻译单元，模拟两个构建各选一份实现：
1. 成功路径漏写、调用方成功后读：三项都为 1，算“完整”；
2. 只在失败路径漏写：第 2 项为 0；
3. 调用方调用前已初始化：第 3 项为 0；
4. 漏写路径上调了一个判断不了的辅助函数：第 2 项为 0（未知）。
后三份都不能列为完整证据。
