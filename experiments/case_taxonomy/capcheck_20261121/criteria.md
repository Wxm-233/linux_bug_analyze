## 一、思路

规则 B 失败的原因是只认 `if (!X()) return 0` 和“同文件同函数”。这次不预先认定哪个操作依赖哪项能力，而是**从全树的写法里推断**：
- **推断 A：操作多数保护**。同一个操作在大多数调用处都被同一项能力判断保护，剩下没被保护的调用处是候选。
- **推断 B：同类入口多数检查**。同一目录下、用同一种方式注册的入口函数，大多数一开头就检查某项能力，剩下完全不查能力的入口是候选。

## 二、定义（确定性规则，冻结后不改）

**版本与文件**：对给定版本，读 `tools/ scripts/ samples/ Documentation/ usr/` 以外的全部 `.c` 文件（用 `git` 读对象，不检出、不构建）。

**能力判断**（词法）及其“能力身份”：
- `boot_cpu_has / static_cpu_has / cpu_feature_enabled / this_cpu_has / cpu_has(…, X)` → 身份是特性常量 `X`（如 `X86_FEATURE_IBPB`）；
- `cpus_have_cap / cpus_have_const_cap / cpus_have_final_cap / alternative_has_cap_likely / alternative_has_cap_unlikely(X)` → `X`；
- `cpu_has_feature(X) / mmu_has_feature(X) / firmware_has_feature(X) / riscv_has_extension_likely / riscv_has_extension_unlikely(…, X) / riscv_isa_extension_available(…, X) / test_facility(X)` → `X`；
- `x86_match_cpu(T)` → 表名 `T`；
- 不带参数的 `system_supports_*()`、`arch_has_*()`、`*_supported()`、`*_available()`、`has_transparent_hugepage()`、`can_set_direct_map()`、`radix_enabled()`、`pgtable_l4_enabled()`、`pgtable_l5_enabled()` → 函数名；
- 不带括号的 `cpu_has_*`、`MACHINE_HAS_*` 宏 → 宏名。

**被保护**：一个语句位置被能力 P 保护，当且仅当满足下列之一：
1. 位于 `if (C)` 的“真”分支内，C 的顶层 `&&` 合取项里有肯定形式的 P；
2. 位于 `if (C)` 的“假”分支（`else`）内，C 的顶层 `||` 析取项里有否定形式的 `!P`；
3. 同一函数里在它之前、函数体顶层有 `if (C) { … return/goto … }`，C 的顶层 `||` 析取项里有 `!P`；
4. **调用方挡住**：所在函数是 `static`，在本文件里至少被调用一次，且所有调用处都被 P 保护（只传一层）；
5. **模块挡住**：所在文件里有用 `module_init / *_initcall / __setup / early_param` 注册的函数，其函数体顶层按第 3 条检查了 P（即整个文件在没有 P 时不会被初始化）。

**操作**：调用表达式 `f(…)`（含函数式宏）。操作键有两种，同时统计：`f`，以及 `f` 加首个实参（首个实参是全大写常量标识符时，如 `wrmsrl(MSR_X, …)`、`mtspr(SPRN_X, …)`）。

**推断 A**：对每个操作键 O，数全树调用处总数 n，以及被同一项能力 P 保护的调用处数 g(P)。若存在 P 使 **g(P) ≥ 3 且 g(P)/n ≥ 0.6**，则 O 被推断为“依赖 P”；O 的每个**不被 P 保护**的调用处是一条候选（A 类）。`n > 200` 的操作（如 `printk`、`kfree`）不参与。

**推断 B**：入口组 =（注册方式，入口所在文件的前两级目录），注册方式分 `module_init`、`*_initcall`、`__setup/early_param` 三种。组里有 **≥ 4 个入口**，且其中 **≥ 60%** 在函数体前 5 个顶层语句内检查了任一能力判断（第 3 条的形式，或整个函数体被第 1 条包住）、并且同一项能力 P 至少被 3 个入口检查，则组里**完全不检查任何能力**的入口各是一条候选（B 类），以 P 为推断能力。

**排除**：候选所在文件属于 `arch/<a>/`，而推断能力 P 的前缀明显属于另一个架构（`X86_FEATURE_` 属 x86，`ARM64_` 属 arm64，`CPU_FTR_/MMU_FTR_/FW_FEATURE_` 属 powerpc，`RISCV_ISA_EXT_` 属 riscv，`MACHINE_HAS_` 属 s390，`cpu_has_` 宏属 mips/loongarch）时，不报（这种文件在那个架构下不会编译）。

**输出**：每条候选给出类别（A/B）、文件、行、所在函数、操作键或入口组、推断能力 P、g/n 或组内比例。按 g/n（或组内比例）从高到低、g 从多到少排序。
