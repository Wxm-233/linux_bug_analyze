# 两项确定性契约检查的冻结小试验方案

日期：2026-09-26。本方案在阅读新候选的补丁正文和结果之前固定。来源仅为已知 die sysfs `2c4dcd7fd57b`、shmem `9fd154ba926b` 及 [`interface_contract_matrix.md`](interface_contract_matrix.md)；新样本不参与下述判据设计。目标是验证**给定可追溯源码事实后，检查能否输出可复核的契约候选**，不宣称自动发现未知 P/C、已证实的真实故障或总体准确率。

## 统一判定单位与四类输出

每条记录是一组 **`接口 × Git 版本 × 架构/配置 × 路径/策略`**，不是一个提交就只有一个标签。先保存相关的源码位置、Kconfig/预处理条件、提供者、消费者及适用路径；遇到不同版本的用户工具与内核，分成不同组合，不默认同版。

1. `hit`：适用路径可达、所需权威来源已确定，且源码或函数运行证明接口暴露/选择时违反下面的具体蕴含式。这只是**需复核的契约候选**。
2. `normal`：同一接口和适用路径可达，蕴含式成立；包括有能力时正常导出、没有能力时被门控，或页阶在范围内仍被选择、越界时被拒绝。
3. `not_applicable`：该构建或输入没有目标接口/消费路径，例如相关 Kconfig 不可达、策略根本不选 PMD 页，或下游不用对应 xarray 页缓存。不能计入通过率。
4. `insufficient`：接口路径可能相关，但能力的原生来源、导出/选择守卫、数值边界、版本关系或下游消费者无法独立解析。不得按 `normal` 处理。

## 冻结规则 C：公共 die 属性的能力门控

仅对历史 `die_id`/`die_cpus`/`die_cpus_list` 家族及结构可比的**另一个属性家族**试用。对每种架构和 `CONFIG_SMP` 组合，在通用 fallback 宏**定义之前**求原生能力声明，并检查：

`export(target attributes) ⇒ native(required ID provider) ∧ native(required CPU-map provider)`。

已知 die 家族的两项分别是 `topology_die_id` 与 `topology_die_cpumask`。对另一属性家族，必须先从接口定义和调用者找对应提供者，记录具体宏/函数，不能用 die 的名字硬套，也不能把同名 fallback 当原生声明。如果不能确定该家族是否确实要求这两类提供者，输出 `insufficient`，**不推断缺陷**。`export=false` 只有在目标接口所属子系统仍可达且守卫可解析时算 `normal`；整个接口未构建算 `not_applicable`。

已知案例仅用于校准：历史 die 旧版 s390/ARM64+SMP 暴露而缺原生提供者应为 `hit`，修复后被门控应为 `normal`，x86+SMP 继续导出且两项原生提供者存在应为 `normal`。没有启动历史内核时只称源码/预处理结果。

## 冻结规则 R：PMD 页阶与 xarray 页缓存上限

仅当源码能建立“某入口在该配置/策略可能选择 PMD 级页，且下游确实交给受 `MAX_PAGECACHE_ORDER` 约束的 xarray 页缓存”时，检查：

`select_PMD ⇒ HPAGE_PMD_ORDER ≤ MAX_PAGECACHE_ORDER`。

需要按目标版本的 `PAGE_SHIFT`、PMD shift、`XA_CHUNK_SHIFT` 和选择策略求值；宏或下游路径不清时输出 `insufficient`，而非沿用已知 shmem 版本的常量。关闭大页策略或不走该页缓存时 `not_applicable`。即使配置下 `order > bound`，若选择门禁已拒绝则为 `normal`。已知 shmem 的普通 4K 启用策略是 `normal`，64K 启用策略的旧版为 `hit`、修复版为 `normal`；这些只作规则校准。

## 独立选例、复核和停止条件

在上述判据冻结后，先只凭**提交哈希、标题、修改路径与接口存在性**寻找未用于制定规则的可比家族/提交，优先固定 500 条内的提交；同一家族有多个合格项时按 `SHA256("20260926-contract-v1:<hash>")` 最小者选一条。选定后才读完整补丁、旧/新源码并填证据表；保留所有 `hit`、`normal`、`not_applicable` 和 `insufficient`，不因结果不理想换样。若固定池没有结构可比项，可在本地 Linux Git 另设检索池并记录检索式、候选数和选样顺序，**不得混称固定 500 条留出**；仍找不到则明确报告该规则没有独立验证对象。

复核至少记录：人工识别提供者/消费者耗时与修改次数；目标配置可达性；旧/新是否只改了规则相关关系；正常和不适用对照；实验是源码条件、编译函数、内核启动还是硬件；另写一栏“基于该样本能否归入跨架构核心范围”。同一已知提交的配置网格再大，也不等于独立样本。若新接口的权威契约有争议，停在 `insufficient` 并交领域人员，不通过改规则追逐该提交的补丁标签。
