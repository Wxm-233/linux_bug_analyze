# 独立运行前 oracle：I3C端序模式局部投影

本表在投影实现与执行前，独立读取父版 core.c、同版 kconfig.h 和 ARM 的 CPU_BIG_ENDIAN 条目后手工推导；未读投影实现或结果，未取新 Git、patch，未编译或运行投影。属于说明知情开发验证，不是新盲测。

同版 helper 明确 IS_ENABLED = IS_BUILTIN 或 IS_MODULE。旧符号和两种 _MODULE 宏均不定义；CPU 属性宏只在 BE 注入1、LE不定义。因此原谓词 selector 在8格都为0，CPU属性谓词在BE为1、LE为0。undefined的结果以这些注入条件和同版helper为准，不推断历史真实配置恒为undefined。

核心推导依据是 core.c 663–685：进入模式区间先读一次；初态与selector相同就不写、不回读；不同则尝试写一次并读回一次。接受写时最终模式变为selector；拒绝时模式保持初态，回读不满足分支要求，返回 -EOPNOTSUPP。其它位由源程序的按位 OR/AND 保持，且硬件模型另约定它们不变化。数值 -95 是 harness 的 errno 约定。

成功契约是“局部返回0且最终数据位等于注入CPU模式”。这严格区别于单独的模式匹配。例如原谓词、BE、初态1、拒绝写这格，最终位虽然仍为1，但代码返回错误，不能记成功。错误返回只称局部受控拒绝，不声称整个设备或后续消费者安全。

这里的0是投影wrapper到达区间末尾的成功哨兵；原函数之后还有逻辑，不能据此称完整初始化返回成功。所有16格均假设已经到达该模式区间；没有跑到此处不算通过。无写入时，“接受/拒绝”标签并不触发硬件响应。

预期原谓词8格：3格局部成功且模式正确、3格返回0但模式不一致、2格受控拒绝。CPU属性谓词8格：6格局部成功且模式正确、2格受控拒绝。总共24次模式寄存器读、8次写；这不是硬件性能数据或独立样本准确率。

ARM声明说构建大端内核，并明确板级必须正确启用相关特性；它支持条件CPU模式解释，并不证明实际配置、模式可达、硬件规范和完整数据消费契约。仍缺真实内核/设备运行，未增加确认案例或独立阳性。
