# 事前协议：两项有限新输入的表示检查

2026-10-03。前项两接口事实清单与独立审计已完成并锁定。用户要求直接继续下一项。本轮不修改旧consumer/producer，不运行模型、编译、内核或设备。目的仅是看原窄规则能否在固定的新输入定位检查线索，并与解封后的人工源码判断对照。

## 支持范围与启用门槛

consumer只支持可解析函数中结构指针成员在if条件的直接`__le16/32/64`读取，声明需在目标文件或两层quoted include中。producer只支持可见结构字段的端序声明、可识别同宽标量赋值或指定初始化、以及同函数的随后对象传参。宏/别名/复杂绑定、声明不可见、局部变量等超范围形状可能零站点或不足，不等同正常。

机器候选不直接是行为错误：人工须另查该版本的字段格式、值源/值域、实际运算/复制消费者、入口与支持条件。零或其他交换不变的值、同域运算、未到边界、配置不适用分别记录。缺外部规范或运行证据时只保留局部源码依据。正常标签只限具体表达式，重复访问及宽前缀匹配限制保留。

## 有限元数据池与确定性选样

固定本地Linux HEAD。只查询2020-01-01至2025-01-01之前、非merge、提交说明匹配`endian|byte.?order`的历史元数据：fs和drivers两通道各按原Git log顺序最多32条，合计最多64条。保存原命令、输出和池；不看补丁或源文件内容选样。

先尝试rg；WSL不可用时用现有grep，在已有case_taxonomy、documents、日志及当前代办中查各完整SHA和12位前缀（排除本轮目录）。命中过旧研究材料的修订保守排除，不把“未命中”认证为人类从未见过；记录这是本地记录可见范围的新输入。已读家族ocfs2/bcachefs/btrfs、Raspberry Pi固件/PWM以及原hisi_sas/mpt3sas/dw_mmc/idpf/fsl_raid/dw-axi/Tegra241等文件不入选。

每通道选第一条标题含fix、且修改1至3个C文件的合格提交；只读name-only文件列表，选该通道下按字典序第一个C文件。fs通道运行consumer，drivers通道运行producer。标题只作选样线索，不预置阳性真值；文件列表/完整SHA是元数据暴露。最多两项，无合格项则记录空选，不扩大日期或池、不补第二套模型。

## 顺序及停止

1. 保存协议、规则/直接本地依赖、runner、HEAD、池、排除记录、选择及SHA。形成`freeze_pre.json`后才能运行选定父版；每项一次原CLI，完整保存原JSON及stdout/stderr。
2. 所有选定父版输出锁在`parents_lock.json`后，才可解封提交说明/补丁及保存修复版。修复版每项一次；不调整规则、参数或输入，不按结果换文件/换例。
3. 解封后人工定位补丁所修目标，区分“原工具目标候选→修复局部正常”“候选与目标无关”“范围拒判”“零站点/漏覆盖”“并非该机制”。若目标不在选定文件，保留未覆盖，不能偷偷改到另一个文件。
4. 各项仅补必要同版源/声明/直接消费证据，保存原文行号和blob/SHA。首次发现日、故障引入及真实支持条件缺失就留未知，不追加确认案例。
5. 两项或明确空选/失败原因完成后停止。没有独立目标命中也如实收尾；不从这两项目的性样本算准确率、Linux总体频率或提速。不新增输入网格。

本轮“未参与源码开发”只指本地记录及本轮执行顺序；现有提交标题可以提供机制信息，因此不是无提示的盲测。父版原始结果先于补丁解封，是需要验证的程序顺序。旧冻结材料、固定12条6/5/1不变，Word和GitHub不写。
