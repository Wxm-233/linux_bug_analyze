## 本轮程序新增什么

原提取器对含 `goto`／循环的 mapper 整体保留不足。本轮增加独立模块 `linux_bug_analyze/forward_guards.py`：完整函数经语法树展开为有限前向结构，支持分支、向前跳到函数顶层标签和早退；到达循环、回跳、嵌套标签、间接调用或其他不支持节点时，**只把该路径停在显式边界**，不删除节点后接到后面的代码。

不透明调用按正常返回处理；分支真假只是结构备选，不是实际运行见证。调用事件只列独立语句调用，guard 内的直接调用仍保留为不透明条件；不计算 helper 效果，不声称空集合、self 成员或正确复制已经自动证明。局部参数记录来源声明及直接写入版本，命名对象地址与内容分开，静态 `mask` 明确是共享静态对象。复杂字段／间接写入、嵌套调用或条件写入均保守停止，防止错误复用值版本。

另一个通用词法模式只找相邻的 `p=&base[i]; fill(&p->field,i);`。匹配后保留原文、行号、索引／字段拼写和外层头部，标为候选；没有证明宏循环语义、迭代包含目标、支配关系、调用者／被调用者身份或真实对象内容。

`protocol_pre.json`在执行前固定范围。`collect_sources.py`只从本地历史 Git 读取两版公开源码，20个完整原函数保存在`source_material.json`：包含两版 mapper／启动／update、公共与x86参考及有限 helper。每条有版本、路径、原行号、完整文本和指纹。

旧／修复 `update_cpu_masks` 分别从各自 Git 对象提取，正文恰相同，均为 `topology.c:251–287`，没有直接给旧体换修复标签。`cpu_online`有两种条件定义，初次唯一性检查拒绝采集后，显式保留两分支和 `#if/#else/#endif` 引用，不静默选其中之一。`iteration_references.json`另存两版 possible 集合及遍历宏的有限原文／条件上下文，不自动判定它们已适用于当前运行。

## 程序结果

两版 mapper 各得到两条结构终止路径和一条循环边界：

| 原始条件 | 程序记录的独立调用 | 状态 |
| --- | --- | --- |
| 首个否决条件为真 | clear → 向前跳转 → copy | 结构终止，未经过该函数的 set 语句 |
| 首条件为假、非HW条件为真 | clear → set → 向前跳转 → copy | 结构终止，未经过循环 |
| 首条件为假、非HW条件为假 | clear → set → CPU归一化语句 → for | 明确停止于未支持循环，不能接上copy |

旧版首条件是 `!cpu_online(cpu)`，修复版是 `!cpumask_test_cpu(cpu, &cpu_setup_mask)`。程序保留原始表达式及条件极性，不把二者改写为统一“必须上线”。这是单一已读案例的路径分类，不是六项缺陷，也不报告检测准确率。

两版 updater 各提取一个相邻词法候选，原 `257–258` 行：`topo=&cpu_topology[cpu]` 后传 `&topo->thread_mask` 与 `cpu` 给 mapper；外层头部原文为 `for_each_possible_cpu(cpu)`。它只是字段传递线索。

应区分三个对象层次：启动入口的局部 CPU，void updater 自己的循环变量，mapper 形参。updater 没有 CPU 实参，不能用名字相同证明循环迭代目标就是启动目标。源码里 first loop 是 possible 集合，后面的 online loop 处理其他统计；不可把后者错误地当成 thread_mask 写入入口。能否遍历目标、mapper守卫是否接受目标、helper是否完成相应效果、后来公共读取是否仍见该内容，均需另外的依据。

`entry_source_facts.json`保存旧／修复入口及公共入口的局部语法事实；其中 `calls` 是 AST 调用清单，可能包括互斥分支或嵌套表达式，**不是按时间排序的运行轨迹**。`forward_paths.json`的路径也只是有条件的源码结构，不能当作实际执行日志。
