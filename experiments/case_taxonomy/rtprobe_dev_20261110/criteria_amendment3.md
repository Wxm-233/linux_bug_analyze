## 为什么修订

原判据第五节写的是把上限提示值换成 `uaccess_top`(该架构) + δ。探测结果出来后发现 `uaccess_top` 是用长度 0 测的，当前版本三个内核上它都恰好比 `mmap_top` 大 1（arm64：2^52 + 1 对 2^52）。而静态常量 `TASK_SIZE_MAX` 的含义是“第一个不合法的地址”，在 arm64 上等于 2^52，也就是 `mmap_top`。照原文换算，arm64 自己的提示值会平白变大 1。

## 修订内容

- 每个内核的“实际上限” L 取 `mmap_top`，前提是 `uaccess_top` 等于 `mmap_top` 或 `mmap_top + 1`。不满足这个前提的内核（两种上限对不上，例如 A171 修复前的 riscv）不做换算，本轮只在当前版本三个内核上做，三个都满足。
- 换算：s + δ → L(该架构) + δ，δ ∈ {−1, 0, 1}。
- 自检：换算后 arm64 的清单必须与换算前逐字节相同（因为 s 就是 arm64 的值）。
- 其余不变。
