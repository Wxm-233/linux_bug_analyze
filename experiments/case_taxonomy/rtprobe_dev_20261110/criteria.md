# 判据：启动时探测各内核的实际边界值（rtprobe_dev_20261110）

2026-11-10，Claude 在写探测程序和运行之前写定，SHA 存入 `criteria_sha256.txt`。

## 一、目的

`anyarch_dev_20261110/runtime_requirements.md` 的第一类：有些边界值在编译期求不出来，要到启动时才定。最典型的是用户地址上限：常量表里三个架构只有 arm64 是常数。用户同意先做这一项。本轮回答三个问题：

1. 这些值能不能在运行的内核里可靠地测出来？
2. 用测出来的值，能不能机械地认出“地址空间大小不同”造成的差异（此前靠人工核对）？
3. 把提示值从“一个固定的数”改成“本架构实际上限的前后”，能不能消掉这类固有差异？

不构建内核，不改原执行器，不评价检出能力。

## 二、探测程序（写死）

独立的小程序 `harness/rt_probe.c`，作为 initramfs 里的 `/init`，输出与原执行器相同格式的探测行后关机。链接方式与原执行器相同（静态、统一加载地址）。探测项：

- `page_size`：页大小。
- `uaccess_top`：内核“用户指针合法性检查”的上限。方法：`read(零设备, P, 0)`，长度为 0 时内核只做合法性检查不访问内存；返回 0 记为合法，返回 EFAULT 记为不合法。在低 56 位范围内按位从高到低贪心，求最大的合法 P，上限 = P + 1。
- `top_byte_ignored`：把一个合法地址的第 63 位置 1 再做同样的调用，仍合法记 1，否则记 0。
- `mmap_top`：能映射的最高地址。方法：在指定地址用“不替换已有映射”的方式映射一页，成功或“已存在”都算可映射；按位贪心求最大的可映射页地址，上限 = 该地址 + 页大小。成功的映射立即解除。
- `mmap_default`：不指定地址时映射一页得到的地址。
- `hwcap`、`hwcap2`：辅助向量里的硬件能力位。
- `hugepage_sizes`：大页目录下的条目名。
- `nr_cpus_conf`：配置的 CPU 数。

按位贪心假设“合法地址是从 0 开始的一段连续区间”。程序另外抽查：上限以下的 3 个点必须合法、上限以上（56 位范围内）的 3 个点必须不合法，不满足就输出错误行，该内核的这个探测项作废。

## 三、运行

- 23 个内核（当前版本 3 个；5 个样本各 4 个：修复前、修复后、两个参照），启动方式与此前各轮完全相同（`casemodel_dev_20261110/harness/run_qemu.sh`）。
- 每个内核运行 2 次。两次的探测值必须相同，否则该项记为“不稳定”，不使用。

## 四、用法一：给地址类差异归类（只打标签，不剔除）

在 `anyarch_dev_20261110/runs/CURt` 的结果上做，不重新运行用例。

- 一个用例的“候选地址值”：每个整数参数（`i:`）的值；每个“缓冲区地址或上某一位”参数（`o:*:b`）取 2^b。
- 值 v 在内核 k 上“可作用户地址”：若 k 忽略最高字节，先把 v 的最高字节清零；然后 v < `uaccess_top`(k)。
- 用例标为 `addr_cap`：存在某个候选地址值，在比较组里的内核上“可作用户地址”的结论不全相同。
- 报告：每个架构“与众不同”的用例和簇里，带标签的各有多少；全部用例里带标签的比例；判为“三者相同”的用例里带标签的比例（标签打得太宽的话这个比例会高）。
- 对照：`oddarch_stats_20261110/review_CUR.json` 里人工归为“用户地址空间大小不同”“arm64 忽略地址最高字节”的簇，应当都带标签；人工归为其他原因的簇不应带标签。逐簇列出是否一致。

## 五、用法二：提示值改成“本架构实际上限的前后”

- 静态常量表里用户地址上限 `TASK_SIZE_MAX` 的已知取值集合记为 S（当前版本只有 arm64 的 2^52）。用例里整数参数的值若等于 s − 1、s、s + 1（s ∈ S），称为“上限提示值”。
- 从 CUR 的 8107 个用例里取出所有含上限提示值的用例，作为子集。
- 换算：把 s + δ 换成 `uaccess_top`(该架构) + δ，每个架构用自己探测到的值。其余参数不动（`anyarch` 轮确认的常数换算照常应用）。
- 子集在当前版本三个内核上各运行 3 次。与同一子集换算前的结果（取自 `anyarch_dev_20261110/runs/CURt`）比较各架构“与众不同”的用例数和簇数。
- 预期（事先写下，不作为通过条件）：arm64 方向因 2^52 造成的差异明显减少；不保证清零，因为同一个用例里可能还有别的参数造成差异。换算后新出现的簇全部人工核对。

## 六、对已知缺陷的一个观察（只记录）

A171 的修复改的是 riscv 的 `TASK_SIZE_MAX`。探测值里，A171 修复前、修复后两个 riscv 内核的 `uaccess_top` 如果不同，如实记录；这只是开发集上的观察，不计入任何检出统计。
