## 用法

都在 WSL 里运行：`MSYS_NO_PATHCONV=1 wsl.exe -u root bash /mnt/d/.../scan3_20261119/run.sh <命令>`。

| 命令 | 作用 |
|---|---|
| `scan <版本> [并行数]` | 在这个版本上跑 8 个引擎（缺缓存才跑，默认 8 个并行，约 5 分钟），然后出候选表 |
| `table <版本>` | 只用已有缓存出表 |
| `verify` | 验收：当前版本上各引擎条数与各轮正式输出对比 |
| `runall 4 4` / `stop` / `status` / `evalscore` | 整版模式的召回评测（见判据第三节），可暂停、可续跑，用法同 `heldout2_base_20261119` |

候选表写在 `tables/<版本前12位>.csv`（Excel 能直接打开）、`.json` 和 `.md`（汇总）。列为：序号、检查类、引擎、优先级、文件、行、函数、受影响架构、特征。排序依次按优先级、检查类、引擎、文件、行（修订 2；原来是检查类在前）。当前版本表的前 205 行就是全部优先级一：类型一致性 1～77，实现一致性 78～199，调用上下文 200～205。

**优先级二**只是排在后面，不删：
- WT 的窄化写法：随机抽查精度约 17%；
- CTX 的非少数派：第三版只报少数派；
- WK 的“替代做法”：第二版只用来降低排序。

### 分析集 12 个干净漏报的初步归因（只看了类别和修复函数，还没读补丁）

| 类别 | 个数 | 样本（修复函数） | 现有检查管不管 |
|---|---|---|---|
| 位宽 WIDTH | 1 | `do_pages_move`（compat move_pages） | WT 理应管，但没报到，要读补丁看形态 |
| 接口副作用 P4 | 3 | kasan 的 `__vmalloc_node_range`、GUP fast 的 `gup_pmd_range`、secretmem | 没有对应检查 |
| 调用时机 P5 | 2 | perf 调度进出、x86 poly1305 | 没有；poly1305 在 `lib/crypto/x86`，也不在扫描范围 |
| 大页形式 P3 | 2 | perf 的 `perf_get_pgtable_size`（两个正样本同一个修复） | 没有 |
| 地址区域 P6 | 2 | bpf `btf_sysfs_vmlinux_mmap`、zswap `zswap_decompress` | 没有 |
| 其他 | 2 | hugetlb 命令行参数、SMT 热插拔 | 没有 |

**初步结论**：漏报的主要原因是检查种类和扫描范围没覆盖，不是“没编译看不到”。修订 1 写的“≤ 4 就做编译对比”有个漏洞：编译信息按判据只能用来标注、降优先级，不会增加候选，所以提不了召回，最多把表变小。要提高召回，得按分析集的漏报补规则。这一点交给用户决定。

**局限**：
- 各架构对照表（编码表、阶数常量）只在 v7.3-rc2 上算过，修复前的老版本也用这张表；
- 命中只认“函数名属于 fix_funcs”，没有按 Fixes 反查。
