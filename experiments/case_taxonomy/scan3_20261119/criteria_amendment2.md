# 判据修订 2：候选表先按优先级排序（scan3_20261119）

2026-11-19，Claude。用户同意：“可以，那改一下吧”。

起因：核对已确认缺陷是否还在当前版本的候选表里时，我发现了一个问题。原排序依次按检查类、优先级、引擎、文件、行，结果类型一致性检查的 728 条优先级二夹在中间，实现一致性检查的优先级一要到第 806 行之后才出现。人工审查时一般先看全部优先级一，这样排不方便。

## 修改

判据第一节的排序改为依次按：**优先级 → 检查类（类型一致性 → 实现一致性 → 调用上下文）→ 引擎 → 文件 → 行**。

这样表的前 205 行（当前版本）就是全部优先级一，按三类检查分段；后面才是优先级二。

## 不变的

候选的内容、条数、优先级的划分、各列都不变。召回评测只看候选里有没有修复的函数，与顺序无关，所以正在运行的评测不受影响。
