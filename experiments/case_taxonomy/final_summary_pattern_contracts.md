# 最终总结前的四类 Pattern—接口契约映射底稿

日期：2026-09-28。此稿服务于 Windows 根目录《跨架构语义问题的初步 Pattern 与系统层机制总结.docx》的**后续**修订，目前不改 Word。材料来自[八项接口矩阵](interface_contract_matrix.md)、[固定 12 条源码复核](case_reviews.md)、[旧 13 张卡审计](legacy_13_causal_audit.md)、[历史原型](prototype_results.md)及本目录的表示类复核报告。不同清单存在重合，以下行数**不能相加为独立缺陷数**。四类是帮助描述检查位置的分析维度，不要求一项案例只能落入一类；本稿中的“旧/新”通常指历史源码或缩小原型，除非明确写出真实内核运行，均不等于已复现线上故障。

## 统一判据：先写条件契约，再考虑生成检查

每项用 `A — P — C —约束` 记录：**A** 是版本、构建配置、架构/设备模式及运行路径的合取；**P** 是该接口在这些条件下的参数来源、格式/ABI、状态提供者、设备规范或能力声明；**C** 是首次有意义的读取、写入、命令编码或向外导出。检查的权威来自**适用版本的接口约定与实际消费者**，不能通过多数架构投票，也不能从补丁修改哪一侧直接推出。若规范与实现、历史版本、运行配置相冲突，输出“待裁定/证据不足”，保留两侧证据和正常输入，而非生成全局强制规则。

证据层级在本稿中用文字而不用一个模糊的“验证成功”：①提交/历史源码链；②特化的函数、结构布局、命令或预处理条件原型；③真实内核的特定接口观测；④真实目标设备/历史内核完整路径及领域裁定。目前大量案例停在①②；NUMA 有当前 WSL 内核 i386 syscall 观测，但目标 ABI 裁定未完成。候选提取器的 `hit` 只表示**找到满足窄语法规则的复核点**，不是④。

| 初步 Pattern | 可检查的条件契约 | 适合优先放置的系统检查 |
|---|---|---|
| **P1 参数、数量与可表示边界** | `A ∧ reachable(C) ⇒ unit/width/range(C 的输入) 满足 P 的上限、对齐与编码约束`；单位必须写明是字节、页、页阶、缓存行还是设备命令字段。 | 在选择大页、分配缓冲区、DMA 布局、命令编码前作范围/溢出/对齐校验；按架构页大小和设备模式枚举边界值。 |
| **P2 数据表示与 ABI** | `A ∧ 跨界传递 ⇒ 生产者写入的位序、位宽、布局、字段名与消费者依据 P 解读的形式相同`；原始字节拷贝、零比较与同表示掩码另判。 | 端序类型追踪、显式转换与跨大小端编译；对共享格式、UAPI、native/compat 分别核对字段、布局和访问；不能只搜 `__le` 字样。 |
| **P3 首次消费前状态就绪** | `A ∧ reachable(C) ⇒ P 在 C **首次读取时**有效，并在下线/回滚期间满足所需存活区间`；只比较函数退出时的最终状态不足。 | 从真实调用图、CPUHP/通知状态、资源读写提取候选 `prepare → consume` 边；检查失败路径和逆向生命周期，加入“只改顺序/只改状态”的半修复。 |
| **P4 能力与模式判定** | `A ∧ advertise/use(feature) ⇒ P 所定义的原生能力在当前架构、设备分页模式、固件版本与 guest/裸机环境下成立`。 | 导出前用原生能力门控，按模式编码命令，跨配置枚举“有能力保留、无能力隐藏、不可构建/未知拒判”；通用 fallback 不自动证明原生支持。 |

## 八项主矩阵：逐项定位 A、P、C 与主/次 Pattern

此表只是原[八项矩阵](interface_contract_matrix.md)的四类重编排，不增加案例。固定 12 条的六条源码链（arch_topology、ARM SMMU range、virtio input、Hyper-V、shmem、die sysfs）与旧卡 C1 Btrfs、C5 s390 拓扑相交；旧卡和原型不另行相加。

| 历史修订与主类（次类） | A；权威 P → 首次消费者/边界 C | 旧 → 修复；正常/反例；当前证据 |
|---|---|---|
| **Btrfs `6f93e834fa7c`：P3（P1）** | A：64K 扇区且 `max_inline` 请求超过临时 4K 门槛。P：superblock 的真实 `sectorsize` 写入 `fs_info` → C：`btrfs_parse_options()` 用其裁剪。 | 旧顺序先以临时 4K 解析，修复先写真实几何；4K 扇区或请求不越临时上限是正常对照。**历史源码＋18 组/版本顺序投影，未真实挂载。**所以“参数未准备好”在此以 **P3 为主**，不能与纯范围问题混同。 |
| **s390 拓扑 `a052096bdd68`：P3** | A：s390 次级 CPU 启动/热插拔、`SCHED_CORE` 可达。P：`update_cpu_masks()` 和 `cpu_setup_mask` 包含未 online 的 CPU → C：`notify_cpu_starting()` 中调度回调读取 `cpu_smt_mask`。 | 旧版通知时 mask 未准备；完整修复同时改顺序与 mask。只改其中一项均不足；无调度消费链的配置为不适用。**源码链＋生命周期投影，未运行真实 notifier。** |
| **arch_topology `3fcbf1c77d08`：P3** | A：CPU 下线释放 cacheinfo、重新上线且共享 LLC。P：当前周期 `detect_cache_attributes()` → C：`update_siblings_masks()` 内 `last_level_cache_is_shared()`。 | 提取历史函数的两 CPU 原型中，旧 LLC mask `2`、修复 `3`，人工“读后才检测”仍 `2`；原已就绪且共享时旧新均 `3`，LLC 不同或检测失败均 `2`。**12 组函数替身，非历史 ARM64 热插拔实测。** |
| **ARM64 Hyper-V `52ae076c3a9b`：P3** | A：IRQ affinity 回调进入 vPCI 重定向且 per-CPU 页分配成功。P：`hv_common_cpu_init()` 分配输入页 → C：vPCI 中断重定向读取/清零；下线晚期仍需存活。 | 旧 CPUHP 动态注册点在 IRQ 状态之后；修复改为更早的 `HYPERV_ONLINE`。vPCI 不可达时这条消费契约不适用。**CPUHP 状态表/调用链顺序投影，未运行 Hyper-V。** |
| **shmem `9fd154ba926b`：P1** | A：可选 PMD 大页、ARM64 64K 普通配置。P：`HPAGE_PMD_ORDER=13`，页缓存 `MAX_PAGECACHE_ORDER=11` → C：`shmem_is_huge()` 选择供后续 xarray 拆分的 PMD 页。 | 旧版启用策略仍选择超过上限的页，修复拒绝；4K 普通配置 `9≤9` 时旧新均选择，禁用策略均不选。**20 组历史函数原型，9 组选择不同；未执行真实 `xas_split_alloc()`。** |
| **ARM SMMU range `eb6c97647be2`：P1（P4）** | A：range 特性开启、非叶 SVA 或 io-pgtable 范围。P：调用方的范围与非叶语义、目标模式 TLBI 字段约束 → C：`__arm_smmu_tlb_inv_range()` 编码 TTL/Num/Scale。 | 旧版对 1/33/65 页在三种页粒度下有 9 组全零非法字段，修复 0；只修 1 页仍漏 6 组，只补 TTL 则改变非叶语义。2/31/32/64 页、叶和 range 关闭为对照。**336 组历史函数/命令替身，未执行 SMMU 硬件。** |
| **virtio input `95c7b0ad6c69`：P2（P1）** | A：DMA 映射路径、实际非缓存一致性平台、目标 `ARCH_DMA_MINALIGN`。P：DMA 对缓存行独占的布局要求 → C：设备写 `evts` 与 CPU 写邻接字段 `lock/ready`。 | 旧结构两端可共用对齐单元，完整修复隔离；历史 64 项数组恰好 512B，仅加起始标记的人工半修复也通过，而人工 63 项扰动又暴露尾端共用。**16 组编译布局＋静态可达链，未观察真实设备损坏。**这里“表示”是 DMA/CPU 对共享缓存行的不同读写单元，不是端序。 |
| **die sysfs `2c4dcd7fd57b`：P4** | A：所查历史版本、架构和 `CONFIG_SMP`/sysfs。P：架构头在通用 fallback **之前**原生提供 `topology_die_id` 与 `topology_die_cpumask` → C：通用 `drivers/base/topology.c` 导出三项 die 属性。 | 旧版所列四组配置均导出 3 项；修复后 x86+SMP 保留 3，s390+SMP、ARM64+SMP、x86 非 SMP 为 0。**源码预处理条件矩阵，未启动历史内核查看实际 sysfs。**固定 12 条中可称“x86 需求→公共导出→其他架构”**横向源码候选**，不是旧 13 卡的已证横向计数。 |

每类均有至少一条“旧/修复/正常”对照，但**证据等级不同**。八项是目的性选例，不可据此估计四类在 Linux 总体中的比例，更不能以配置网格的 20/336 次测试替代独立案例数。

## 旧 13 张卡及后来表示类线索的归位与排除

旧 13 张卡按[逐卡因果审计](legacy_13_causal_audit.md)为 7 条条件性纵向、**0 条严格横向**、3 条待定、3 条当前核心范围外；首次发现日期 **0/13** 可证。“纵向”在该台账中包含平台、设备、ABI、模式与公共接口的条件性关系，不意味着七项都已证实跨 **CPU** 架构的真实回归。下表的“主类”只是便于提出检查，不改变纳入级别。

## 能从四类机制实际导出的检查，以及目前没导出的部分

1. **P1**：从配置/格式读出单位、上限和模式，再在首次选择/编码前生成断言，如 `order ≤ pagecache_limit`、DMA 两端对齐、非叶 range 命令合法。正常的 4K 页、禁用策略与范围内命令必须保留；fbnic 的配置外大页不得当阳性。现在有特化原型，没有对未知接口自动抽取上限的通用工具。
2. **P2**：从生产者字段类型和消费者运算联合提取转换要求：磁盘 `__le` 读到主机模式测试前转换；主机值写入端序字段前转换；共同格式的两端声明与共享消费者字段访问必须一致。零比较、同表示掩码、`u8` 上的**过度**转换与纯 UAPI 类型注释都要作反例。[已读 ocfs2](endian_consumer_single_revision_review.md)和 [PWM](endian_producer_single_revision_review.md) 有单旧版候选，但新选三项消费侧及三项生产侧留出均非同形阳性，**不能证明跨子系统泛化**。
3. **P3**：从配置可达的回调/状态表、赋值和首次读取组合 `A ∧ reachable(C) ⇒ ready(P,C)`；输出缺失的同一状态边及源码位置，分开测首次上线、再次上线、准备失败和下线存活。v1/v2 的纯文本搬移在新样本产生误候选或零目标阳性；既有热插拔探针仍由人预标 P/C，不是未知接口的自动发现。
4. **P4**：按具体接口、历史版本和配置收集原生能力声明、fallback、注册入口、消费者，再检验 `export/use ⇒ native_and_valid`。topology 专用事实提取器在**已读** die/cluster 条件网格中给出 4 hit、12 normal、1 insufficient、1 not applicable；网格是 18 个配置记录，非 18 个缺陷。[来源](topology_contract_extract_review.md)。新 book/drawer 等留出出现范围拒判/运行错误，尚未证明跨家族迁移。运行时 PPIN、ACPI 兼容政策、VT-d 不同页表模式均需各自权威，不可把 die 双宏规则硬套过去。

这些检查应统一输出 `hit / normal / not_applicable / insufficient / runner_error`，逐项带**规则版本、A/P/C 来源行号和正常反例**。命中需由人工源码复核，再区分函数原型、真实内核调用、硬件后果和领域裁定；对已读样本的回归通过不等于盲测成功。当前最可信的总体结论是：四类 Pattern 能帮助把隐含假设改写成**可检验的条件契约与候选检查**；它们尚未形成跨项目高召回、低误报的自动检测系统。
