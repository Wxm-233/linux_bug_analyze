# R5候选检查卡语义复核：从集合成员转向架构准备期限

2026-10-15。来源为研究侧对已读历史案例的源码复核，不是模型自动发现、专家金标准或独立泛化结果。本次仅新增本文，没有修改旧卡、旧账、原模型AST、原告警或原运行结果；没有API调用、密钥读取、构建、启动或重跑五输入原型。原版本为 `88b604263f3d6eedae0b1c2c3bbd602d1e2e8775`。

## 1. 可收束的候选与架构因果链

候选应表述为：**在有效配置和实际进入共同启动消费者的前提下，架构提供者应当在公共代码首次使用拓扑组之前，为同一目标CPU提供满足该消费路径要求的组信息。** 准备完成不等于已经online；成员身份、rq初始化、其他leader和组内一致性应分项核查。`contains(mask, cpu)`是有接口用途依据的必要窄候选，不是整个契约的充分条件。

公共包装 `S_interface:202–206` 返回架构的 `topology_sibling_cpumask(cpu)`。x86对象为 `S_x86_header:118` 的per-CPU sibling map；旧s390对象为 `S_s390_header:27–31` 的 `cpu_topology[cpu].thread_mask`。通知进入共同CPUHP回调的连接为 `S_notify:1257–1265` → `S_range:654–655` → `S_dispatch:175–180` → `S_table:1692–1695` → `S_starting:8834–8837`。实际CPUHP状态是否走到该回调还需运行或完整路径证据，不能仅凭函数存在确认。

两侧差异并非同一个公共判断写错了两次：x86以setup集合为准备资格，`S_x86_callin:188–192` 明确要求拓扑在通知前准备，192调用准备，208通知；`R_x86_prepare_complete:582–600` 先加入setup集合，再直接或通过 `S_x86_link:427–431` 建立self/兄弟关系。旧s390在 `S_s390_start:905–911` 先通知，再online，再更新；而 `S_s390_map:101–113` 对offline CPU输出空集合，`R_s390_update_complete:256–258` 将该输出写入实际提供对象。**公共消费者的期限早于旧s390准备资格成立的时点，x86却允许尚未online的目标先完成准备。** 只把旧update移早而不改变online过滤，不能消除这一条件冲突。

这条源码链支持跨架构准备期限候选；它本身不证明任意一次通知时必为空。静态对象无显式初始化见 `R_s390_topology_storage:62`；但早期路径也会调用更新（`R_s390_topology_early_init:571–573`、`R_s390_early_update:307–316`）。不能以最初的零值替代后续消费时的值，仍须核对外层顺序、其他writer和实际进入路径。

## 2. 卡片须拆开的条件

| 条件 | 本轮依据与逻辑地位 | 结论边界与缺证据处理 |
| --- | --- | --- |
| A. 有效配置及路径 | `X_core_kconfig:103–105`：CORE依赖SMT；`X_lock_guard_open:87`、`X_starting_guard_open:5342` 启用真实实现；`X_core_stubs:5851–5855` 给出!CORE空实现。x86定义受 `X_x86_topology:115–118` 的SMP条件控制；s390受 `X_s390_topology:11–31` 的SCHED_TOPOLOGY条件控制。 | `C_x86:1–7`、`C_s390:1–8` 是本案例配置见证，不是所有环境。CORE关闭为该检查不适用；配置未知是证据不足，不能算正常。SMT配置开启不证明真实SMT硬件覆盖，HOTPLUG开启不证明重入路径已验证。 |
| B. 对象与参数身份 | `S_core:5753–5756` 绑定目标参数、getter与目标rq；`X_rq_macro:1354–1356` 绑定per-CPU rq；`S_core:5760` 将同一cpu传给 `S_locks:240–242`。 | 配置固定后可建立局部静态别名链。两个位置调用相同getter不自动证明所有时点内容相同；对象或CPU不明则拒绝把另一个样本值移用过来。 |
| C. 组包含目标self | 目标所属SMT组身份以及目标rq保护/安装语义联合支持：`S_locks:246–247` 锁组成员，`S_core:5783–5787` 仅在成员等于目标时为目标安装leader。 | 是以“该组确为目标的SMT组”为前提的必要窄候选；不能从任意 `for_each_cpu` 语法推导。不是充分条件，不保证组完整、其他成员正确、leader有效或并发安全。缺少身份依据时输出待确认的候选，而非普遍规则。 |
| D. 目标rq初始状态 | `R_sched_init_prefix:9054–9058` 将循环变量绑定到各possible CPU的rq并初始化锁，9126–9129在CORE下令 `rq->core=rq`。`S_core:5762` 显式检查本目标初始自指。 | 自指是避免该处告警的条件，也解释合法单成员入口。新片段补齐了赋值作用域，但没有补齐 `sched_init` 的全部外层boot先后及中途改写；不能只见该赋值就宣告每次入口已满足。 |
| E. 分支与其他leader | `S_core:5765–5766` 仅判断weight等于1。其他路径第一轮5769–5775跳过目标，寻找其他成员的自指rq，5779在未找到时告警退出。 | weight==1不是self身份认证，也不是非空断言。进入非singleton路径时，存在该查找可选中的其他leader是避免5779及继续安装的局部必要条件；self本身不充分。不得再使用“第一轮靠self找到leader”的旧解释。 |
| F. 安装后组内一致性 | 第二轮 `S_core:5783–5789` 为目标安装leader，并检查所有遍历成员的 `rq->core` 是否等于选中leader。 | 满足先前条件仍可能在5789告警；还需核对其他成员状态。这个显式检查的通过也只是该遍历的局部一致性，不能认证组完整或物理拓扑真实性。 |
| G. 架构准备资格及期限 | x86见 `S_x86_callin:188–208`、`R_x86_prepare_complete:582–600`；旧s390见 `S_s390_start:905–911`、`S_s390_map:101–113`、`R_s390_update_complete:256–258`。共同消费链见第1节。 | 期限是公共内容消费之前，不是最终online时，更不能要求“先online再通知”来代替契约。要声称某架构实际违约，必须补有效提供者、同CPU、实际路径和当次状态证据。准备函数的文本顺序与具体状态均需保留。 |
| H. 时点和值对应 | 内容首先在 `S_locks:246` 的遍历被读取，247锁定实际成员；此后 `S_core:5765` 读weight，5769、5783和 `X_lock_functions:255–256` 再读集合。 | 不能从单个早期快照证明整个过程使用同一个值。移用样本值必须证明对应读取或受控区间的等价条件；不一定要求集合永远不可变，但必须知道同步/合法变化协议。当前其他writer、跨CPU并发和完整区间稳定性均未证。 |

这些条件在材料中分属显式告警条件、接口用途推断、配置/身份前提和观测映射前提。不能全部统称“内核规范”，也不能把一个条件满足记成整个检查通过。对完整拓扑与并发正确性，本轮没有已证明的充分条件。

## 3. 五个原函数逻辑输入应怎样使用

原型为同一已读消费者的用户态mock，目标CPU1，每项重置rq和WARN站点；不是新增五个架构案例，未证明所有构造的硬件可达性。

| 输入 | 对候选的约束 |
| --- | --- |
| 空组，初始rq自指 | 发生5779告警；支持空组在该局部路径无法找到其他leader。不能单凭这个逻辑输入断定某架构实际提供空组。 |
| 仅self `{1}` | 无告警、保持自指；与正确单成员初始状态相容。不能以此覆盖其他成员或运行中重入。 |
| 仅其他 `{0}` | 无告警但不含目标；weight==1提前返回。因此“没有WARN”不是self成立或整体正确的证据。 |
| `{0,1}`、CPU0不自指且无其他有效leader | 含self仍在5779告警。因此self不是避免WARN或完成初始化的充分条件。 |
| `{0,1}`、正常CPU0 leader | 无告警，目标由自指改接到CPU0；印证第二轮才安装目标，第一轮跳过目标。仍是固定输入、固定mock下的局部结果。 |

原始结果及提取/编译/单次执行收据在 `../claude_contract_resume_20261015/probe_results.json`、`probe_stdout.json`、`run_consumer_probe.py`。本文未重跑。不能把这些结果喂给源代码分析模型后，再声称模型独立提取出了同一结论。

## 4. 精确位置与已有四格观测应分别标注

1. `S_core:5755`：获取mask指针，不是完整成员快照；保留原模型first_read锚点，不回写成已测通过。
2. `S_locks:242`：callee再次获取指针；参数相同支持静态同对象，但未测地址，不能靠值相同反推地址相同。
3. 既有 `lock_snapshot`：观察代码在原 `local_irq_save` **之前** 分开读取mask/self/weight等字段，属于非原子pre_irq采样。日志在unlock之后打印不代表在unlock后重读。旧卡的 `phase=lock_snapshot` 不应继续描述成原循环的精确实际读取。
4. `S_locks:245–247`：原关本地中断后遍历并锁定真实成员。锁次数在调用后计数，支持已观察到的实际锁调用数量，但不是每次遍历所见完整集合的原子记录；关本地中断也不排除其他CPU改写。

既有独立复核 `../state_context_binding_20261015/source_consumption_review.md` 的第2–4节记录了这一差别。原四格普通2CPU初次启动中，旧s390的锁前采样为mask0/self0/锁调用0，修复s390及两版x86为mask2/self1/锁调用1，当时目标均offline。该历史证据支持限定的采样及实际调用对照，不补齐5755时刻、精确每次迭代的值或全区间稳定性。s390范围是SINGLE/facility0/mtid0，不是真实SMT覆盖。

## 5. 结果词与后续验证建议

建议卡片逐条件给出 `supported_candidate`、`observed_sample_violation`、`satisfied_at_observed_sample`、`not_applicable`、`insufficient` 等状态；再分别报告告警、目标rq变化和架构履约证据。缺配置、缺对象绑定、缺实际回调、缺值时点、缺leader/初始化或缺同步依据，都应具体列出缺口。只知道“不告警”时不输出整体通过，只知道某次采样违反self时不声称精确循环值已被测得。

若只在pre_irq采样求值，结果必须留在这一时点；若改为精确循环位置检查，须另行设计最小观测或静态/同步证明，不能改字段名把历史快照搬过去。新卡应保留旧AST、原锚点、旧正式协议状态，来源分为模型原提案、程序绑定、研究侧语义修正和历史运行见证；不得把补充源码、反例推导和研究侧调整统一计作模型自动产出。

下一步可以冻结这组分项检查及拒判规则，再登记未用于开发的同机制与正常对照；按架构提供者、共同消费者、准备资格和实际期限逐项检验，不能仅抽含类似循环的普通代码。当前所有收束仍在已读案例开发范围内，R3单独暂缓。
