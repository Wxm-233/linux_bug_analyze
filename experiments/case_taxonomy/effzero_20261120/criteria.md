## 一、检查什么

公共调用方要求一个对象在交给使用者前全零，满足它的工作由会变化的实现完成（不同架构、同名的替代定义、ops 回调）；某个实现在正常返回的路径上没做。三种写法：

- **E1 返回值形（D1、D3、D4、D5）**：同一接口的各实现都返回一块新内存。多数实现在所有正常返回路径上都把它清零，少数实现有正常返回路径不清零（不清零，或只在带 `__GFP_ZERO` 等请求时才清零，或依赖调用方传进来的 gfp）。报少数实现及其不清零的路径。
- **E2 调用方委托形（X1）**：调用方调用接口 `g(x)` 之后，无条件把一个局部开关设为假（`init = false;` 一类），而这个开关在同一函数后面守着调用方自己的清零。也就是说调用方把清零委托给了 `g`。`g` 的实现里，至少一个确实清零 `x`，至少一个不清零。报调用处，列出不清零的实现。
- **E3 请求标志形（K1）**：调用方把带“初始化/清零”含义的请求位（名字含 `INIT` 或 `ZERO`）传给接口，并且在同一函数里自己不再清零（去掉 `__GFP_ZERO`，或不调用清零）。接口的某个实现有正常返回路径在用到这个请求位之前就返回了。报这个实现及其提前返回的路径。

### 1. 实现组

- **同名定义组**：同一个名字在至少 2 个不同文件里有定义；`.c` 里的 `static` 定义不算（各文件私有），头文件里的 `static inline` 算（按 `#ifndef`/架构选择的替代定义）。
- **ops 组**：`struct T x = { .m = f, … }` 这类初始化里，同一个 `(T, m)` 下出现的不同函数，跨至少 2 个文件。
- 每个实现记下“有没有架构证据”：文件在 `arch/` 下，或组里至少一个实现在 `arch/` 下。排序时有架构证据的在前，没有的不删。

### 2. 路径和对象

- 用 `p1check` 的语句树（只读导入），逐条路径走函数体：`if` 两边分叉，循环和 `switch` 按“走或不走”分叉，`goto` 结束该路径且不算正常返回，路径数超过 512 记为未知。
- **正常返回**：返回指针的函数，`return E` 中 `E` 不是 `NULL`、`0`、`ERR_PTR(…)`、`ERR_CAST(…)`；`void` 函数的任何返回或走到末尾。
- **对象**：返回表达式去掉类型转换、`page_address()`、`page_to_virt()`、`phys_to_virt()`、`virt_to_page()`、`+ 偏移` 之后的变量；函数内按赋值 `a = 转换(b)` 把这类变量并成一类（不分先后）。
- **对象来源**（路径上最后一次赋值）：
  - **零**：`kzalloc`、`kvzalloc`、`vzalloc`、`kcalloc`、`kvcalloc`、`vcalloc`、`get_zeroed_page`、`dma_alloc_coherent` 一类（含 `_node`、`_noprof`、`devm_` 变体），或任何实参里有 `__GFP_ZERO` 的调用，或计算出“总返回零”的函数；
  - **原始**：`kmalloc*`、`vmalloc*`（非 z）、`alloc_pages*`、`alloc_page*`、`__get_free_page(s)`、`alloc_pages_exact*`、`folio_alloc*`、`kmem_cache_alloc*`、`dma_alloc_from_contiguous`、`cma_alloc`、`gen_pool_alloc*`、`gen_pool_dma_alloc*`、`memblock_alloc_raw`、`dma_common_contiguous_remap`、`dma_common_pages_remap`、`vmap`，以及计算出“总返回原始”的函数。gfp 实参是变量而不是含 `__GFP_ZERO` 的常量时，记为“随调用方 gfp”，按不清零算，单独标出；
  - 其余调用：查函数摘要；没有摘要的记为未知。
- **清零动作**（作用在对象类上）：`memset(x, 0, …)`、`memzero_explicit`、`clear_page`、`clear_highpage`、`clear_user_highpage`、`clear_highpage_kasan_tagged`、`zero_user*`、`folio_zero_range`、`memzero_page`，以及计算出“总清零第 k 个参数”的函数。
- **函数摘要**（全树按名字迭代到不动点，同名多份定义结论不一致时记为未知）：总返回零 / 总返回原始 / 总清零参数 k。

### 3. 报告条件

- **E1**：组里“所有正常返回路径都清零”的实现至少 2 个，且多于“有正常返回路径不清零”的实现；后者每个报一条。未知的实现不计数。
- **E2**：委托信号成立（见上）；接口 `g` 的实现里至少 1 个“总清零该参数”，至少 1 个有路径不清零（含空函数体）。
- **E3**：调用方信号成立（见上）；接口的实现里至少 1 个在某条路径上用到了请求位（测试它或把它传下去），被报的实现有正常返回路径在用到请求位之前返回。
- **排除**（对应反例）：R1 路径上调用的函数按摘要清零了对象；R2 接口的所有直接调用者在调用之后都对返回值清零（E1）；R3 E2 里开关置假的语句在测试接口返回值或能力（`if (…has_…/…supports…/返回值)`）的分支里，不算无条件。

### 4. 候选的列

检查形（E1/E2/E3）、组键、被报实现的文件、行、函数、不清零路径上的条件、对象来源、组里清零/不清零/未知各几个、架构证据，以及当前版本的配置证据（被报文件在三个 defconfig 编译数据库里各是否编入，复用 `buildattr_20261120.attr.compiled_sets()`）。

**排序**（事先定）：有架构证据在前；E2、E3 在 E1 前；E1 内按“清零实现个数 − 不清零实现个数”从大到小；再按文件、行。去重键：被报实现的（文件，函数）；E2 用调用处的（文件，函数）。
