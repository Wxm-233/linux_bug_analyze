## 程序实际做到了哪里

两组14份原始文件均与父版、选择和材料计划绑定；没有配置选择、预处理或运行证明。实际返回共有25个候选绑定项、12个局部顺序项，**全部不足**：候选停在材料身份/引用字段门槛，12局部项均停在`material_group_or_function_invalid`，尚未执行函数定位或词法顺序判断。

原因包括我们准备输入的错误：`prepare_packets.py`只传输出示例，没有传顶层`document/start_line/end_line`引用对象；身份保留`CASE_parent`占位，未实例化E/F。回答沿用了占位和`lines`字符串。这不能统一归因于模型推理失败。独立人工诊断发现24个callee都在给定原始行号，85段引用中22段另超过明确规定的24行；旧定位器/词法也有潜在支持边界，但没有通过改回答或重跑把它们算成已执行成绩。见[实际失败分层](actual_check_review.md)、[独立输入审查](packet_protocol_review.md)及原样`candidate_checks_E/F.json`。

模型内容的人工比较另见[语义复核](model_semantic_review.md)。人工保留的条件要求不回填为自动程序成功，也不将额外假说认定为新问题。
