# N2.19 限定的跨案例身份与映射挑战

## 目的和范围

N2.18已说明，仅数量正确不能证明成员身份正确，而且合法的架构重编号和选择数量限制必须保留。下一项把该关系拿到没有用于本轮规则开发的源码上检验，避免继续围绕同一 SPARC 案例增加替身组合。它服务于N1的条件要求推导和N2的有区分力对照，不把两个研究方向等同两种bug。

## 一个连续小闭环

1. **固定候选与正常参照。** 在既有500池及既有同用途来源中，以元数据目的性定位至多一项身份/集合/编号映射相关历史修复和一项同公共用途的正常实现。先记录题名定位依据、版本、目标路径和已做接触/家族搜索范围，再读新正文；初筛接触、目标源码开发接触和同修复家族分别记录。不能只因新hash或没有查到记录就称独立；也不能用工具是否支持选择样本。不符合研究范围或资格未知时记录，不反复补选凑结果。
2. **先界定可比较要求。** 保存N2.18的接口身份、数量限制、阶段和映射四方面要求作为待迁移假说；核对新接口是否真的承担相同角色。直接编号和显式硬件→逻辑编号均可合法，不能套用跨架构原始子集或全部present包含关系。正常样本需有同用途满足依据，功能关闭、无告警和函数成功返回不算正常证明。
3. **父版分析先于修复。** 输入含可承担判断的提供者、映射/选择、公共消费及版本化依据；按事前材料限额采集，不按答案追加整棵树。模型候选及程序支持/不支持先保存，再由不看候选的角色审必要修复。模型应指出要求依赖的源码事实、命名空间和阶段；不要把研究者填入的映射/规范记成自动提取。现有程序不能证明的关系保持不足，不为本例扩大通用解析器。
4. **完整保留评价对象。** 分开报告目标线索是否提出、要求是否过强、有限事实/关系是否可核、规范与真实配置是否足够。合格难例在分母内；有映射但不是原值相等的正常实现尤其检查误报。若两项都不足，明确本轮没有可评价的独立成功，不将其描述为全部通过。
5. **收束为迁移结论。** 若资格、材料或判定仍不够，给出原因和最小缺证，停止，不再返回SPARC扩规模。只有能被同一规则和证据流程处理的新案例，才可能支持跨案例有效性；新问题发现、真实运行及独立增益均另需证据。

## 执行时先登记的上限

源码新读前固定具体版本/路径和每项至多八份完整源；至多两次主分析任务，仍用当前Claude Code＋Opus入口，整轮可见/保守记账不超过100万token，未知内部费用单列，无自动格式重试或拒绝恢复。没有足够来源时可跳过付费任务，但保留跳过和资格不足。本项默认不完整构建/启动内核，不修改Word或推送；R3继续暂缓。N2.18十二次投影不得作为本项独立样本回填。
