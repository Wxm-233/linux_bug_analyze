## 接口用途和依据

SVA的MMU notifier提供字节范围，驱动把范围转换为SMMUv3失效命令；io-pgtable的walk失效也使用同一后端，但范围形状和用途不完全相同。消费者需要覆盖请求的失效范围，同时遵守命令字段及层级语义，单纯“计算出的范围足够大”并不充分。

本轮依据为固定版本源码及已知修复说明：非叶请求可能不知道实际叶层级，名义granule不能直接证明某个TTL；范围命令在TTL、Num、Scale全零的角落组合需要规避。修复说明允许额外失效一页，并指出改回非范围命令涉及errata。**这些是已知修复的开发依据，尚未逐条对照独立硬件规范证明所有编码、超范围失效许可及errata条件。** 测试自身的断言不能充当规范权威。

重新从Linux Git读取的两版驱动、头文件和SVA文件，与10月13日归档正文及Git blob逐项相符（source_audit.json）。旧归档部分中文字段存在乱码，本轮语义依据使用可核英文源码/修复文本及当前原文，不以乱码说明作事实依据。

## 范围、条件和提供者保证

输入模型：起始地址固定0x100000；页数1/2/31/32/33/64/65；page_shift为12/14/16；granule为单页；pgsize_bitmap仅一位；leaf与range_feature各两种。4种实现为旧版、修复版、只处理单页的构造变体、只改TTL的构造变体，总计4×3×7×2×2=336。

这是主机上编译的历史函数体，结构和队列函数为测试替身。range_feature为输入赋值，不是真实设备ID寄存器探测；输入CPU指令集也没有切换。4/16/64K是函数参数差异，不能称三次ARM64内核配置启动或跨CPU架构验证。SVA绑定、BTM门控、MMU notifier完整生命周期、真实cmdq位编码和设备可见完成均未执行。

提供者方面，SVA的小范围与io-pgtable整表范围不能互相替代为共同输入保证；PAGE_SIZE只是名义粒度，非叶的未知层级语义必须保留。调用链与功能条件须在后续迁移时重新绑定，函数测试不能自动证明每个合成组合可从真实调用者到达。

## 三项可分开的判定关系

| 关系 | 条件与判定 | 本轮证据 |
| --- | --- | --- |
| R1 请求覆盖 | 按登记的命令长度模型展开区间，区间并集覆盖请求 | 原始addr/num/scale；非范围模式按单页步进 |
| R2 命令组合 | 范围模式下排除TTL=Num=Scale=0 | 固定修复说明/源码依据，程序查字段；非范围时此项不适用 |
| R3 未知层级 | 范围模式且non-leaf时保留TTL=0 | 已读调用用途与源码解释；leaf或非范围时此项不适用 |

以上关系没有覆盖全部硬件合法性。旧测试中的num<=30是该算法在当前输入下的输出断言，不能直接推广成硬件字段的完整合法域。R1采用登记公式length=(num+1)×2^scale×page_size，公式及TG解释仍是人工语义输入，不是程序自动恢复硬件协议。

扩大范围可消除编码角落，但“覆盖”不自动证明扩大合法。程序始终另报hardware_execution和over_invalidation_safety不足；没有用R1/R2/R3均通过替代全路径安全。

## 实验结果与对照作用

原smmu_range_probe.py未改，重新执行的results.json与历史smmu_range_result.json逐字段一致。run.py保存四份实际编译C、编译参数/环境、Git源文本、336份原始stdout。audit.py不调用旧assess，重新解析字段并以区间并集核覆盖，输出relation_audit.json。它仍使用人工登记的同一命令语义，因此不是独立正确性金标准。

| 实现 | 组合数 | R1覆盖满足 | R2违规组合 | R3违规组合 | 扩大范围组合 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 旧版 | 84 | 84 | 9 | 0 | 0 |
| 只处理单页变体 | 84 | 84 | 6 | 0 | 3 |
| 只改TTL变体 | 84 | 84 | 0 | 21 | 0 |
| 修复版 | 84 | 84 | 0 | 0 | 9 |

违规数按输入组合计，不是缺陷个数或非法命令总数。旧版9组为三种页大小下non-leaf、范围模式、页数1/33/65；只处理单页会漏掉33/65，说明尾部余数条件比“总请求只有一页”更准确。只改TTL消除了全零组合，却在21组non-leaf范围输入中失去未知层级语义。修复在9组多覆盖一页，其许可依据仍限已知修复说明。

页数2/31/32/64以及leaf/non-range对照用于检验触发条件。模式关闭导致R2/R3不适用，不能把它作为“范围模式正确”的正常真值。旧/修复是版本轴，页大小/范围能力/leaf是输入与用途轴；本案例现有证据是架构相关设备协议边界，不是已证明的跨CPU架构逃逸。

## 判定流程与自动化分工

1. 固定源码版本、接口及调用用途，核实际来源，不从函数同名推断同条件。
2. 登记请求单位、粒度、层级是否已知、设备功能条件；缺用途或规范依据则保持不足。
3. 捕获命令构造结果，分别核范围覆盖、条件字段关系和层级语义；记录不适用与违规位置。
4. 再检查扩大范围许可、实际命令编码、提交/完成、设备效果；本轮缺证不升级结论。
5. 按触发条件选择边界与正常输入，保留构造变体的开发身份。

程序完成源码身份核验、函数编译/调用、原始字段记录、有限关系计算与旧结果比较。人工提供协议公式、规范依据、leaf意义、合法输入池和真实路径边界；本轮没有模型自动提取要求。通用候选是证据身份、条件关系、分层判定与边界对照；专用部分是命令解码、范围单位及硬件语义。未把此脚本接入统一检查器，也未声称自动N1/N2已完成。
