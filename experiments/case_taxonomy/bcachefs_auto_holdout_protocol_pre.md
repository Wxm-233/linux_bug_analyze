## 目的和样本

从本地 Linux Git 的 `fs/bcachefs/bcachefs_format.h` 非合并历史中，按提交标题筛查 `align|pack|endian|32 bit`，得到的元数据候选不等于已确认缺陷。选两项未读目标：

- `b07ce7262636fb294d786c17ec4e857b62c2970b`：标题涉及大端 `struct bkey` 对齐，检验定位器能否从已读 `bpos` 迁到另一声明与嵌入位置，或明确显示无候选/拒判。与已读案例高度同功能血缘，不能算独立机制发现。
- `2007d28ec0095c6db0a24fd8bb8fe280c65446cd`：标题涉及大端字段命名，作为可能的范围/误报对照。仅凭标题不能预先规定它“正常”。

每项固定比较父版与该提交的同一个头文件，运行 x86_64 小端 GCC 与 s390x 大端交叉 GCC + qemu 用户态；只计 **两项历史修订**，内嵌成员和编译次数是条件记录，不是独立缺陷。

## 冻结、运行、判读

1. 先冻结本 protocol、`bcachefs_auto_layout_extract.py` 与 `bcachefs_auto_holdout_runner.py` 的 SHA-256，再把选样、环境和哈希写入 JSON。runner 必须在读取目标历史源码前核哈希；异常留为 `runner_error`，不能变为 `insufficient` 或空结果。
2. 原始输出先保存并算哈希，随后才读目标提交及同版本的格式说明与消费者，按源码核对程序给的候选、正常对照、排除、拒判与零候选。如果脚本未定位某个真实变化，应报告范围遗漏；不因标题像“修复”就自动记命中或漏检。
3. `changed_layout_contract_candidate` 仅表示“旧版某编译 ABI 中内嵌偏移不满足该类型声明对齐，而新版所查 ABI 均满足”的定向复核条件，不等于漏洞、真实硬件故障或外部 ABI 裁定。packed 布局可有意不对齐。零候选表示程序未找到符合其窄入口的对象，**不等于正常**；`insufficient` 表示语法/依赖等证据不足。
4. 冻结试验后发现代码缺陷，可另开新版本修复，但不改本轮代码哈希、选样、原始输出或追溯性描述。按两项修订分别报告，不计算准确率或总体提速；代码/编译探针不是历史内核构建、btree I/O 或硬件验证。

人工源码复核开始和结束应分别记录 UTC 墙钟时间，说明工具等待和前置元数据工作未计入。样本是目的性同血缘挑选，不用来推断 Linux 跨架构问题分布。
